Headline findings

  1. The chrome, home page and content pages map almost one-to-one onto existing blocks: trust bar (marquee below 768), sticky blurred header with shrink, mega panels, brand strip, hero with Ken Burns and parallax, Google reviews slider, accordion with FAQ schema, business info, forms.
  2. The theme is the first job. The Eye Care site snapshot in the repo still sets DM Serif Display, DM Sans and a navy/gold palette; the design uses Playfair Display, Outfit and warm ink/taupe. Both fonts are already self-hosted in the theme, so this is a style-variation rewrite, not a font install.
  3. The product page is where the gaps concentrate. sgs/buybox has no InnerBlocks slot (the template itself records this), so the second CTA, the WhatsApp card and the assurance list cannot sit inside the buy column without a block change.
  4. The PDP content template is still the food-client version: Ingredients, Nutritional information and Allergens tabs, and a Trustpilot reviews block. It needs replacing for this client, not extending.
  5. Prescription upload cannot use WooCommerce's additional-checkout-fields API, which only supports text, select and checkbox. It needs a custom checkout inner block.

Suggested build order

  1. Client style variation. Replace the Eye Care snapshot: Playfair Display / Outfit, the ink–paper–taupe palette, square 52px buttons, section rhythm. Everything else inherits from it.
  2. WooCommerce data model. Brands taxonomy for the 40 brands, Colour as a Colour / Image attribute, shape, material, frame type, hinge and nose-pad attributes, per-variation measurements, RRP as its own meta, local pickup.
  3. Cross-cutting extensions. Open-modal-from-any-link, a buybox InnerBlocks slot, the WhatsApp card variant, a "product has reviews" visibility condition. Each unblocks several items.
  4. Templates. New PDP content part (Description / Details / Sizing), shop archive with the ten filter groups, checkout composition.
  5. New builds. Lens configurator module first (it drives revenue and the checkout step count), then prescription capture, then the measurement diagram, then wishlist.

What's verified and what isn't

Capabilities marked as existing were read from block.json attributes, templates and theme files at main. Where a block's behaviour depends on render or view code I didn't read (for example the exact mega-menu hover delay, nav underline indicator, or whether product-card swatches swap the card image), the fix says "confirm".

WooCommerce and third-party facts come from current documentation, linked below. The colour-swatch attribute type arrived in WooCommerce 10.9; a user reported a critical error configuring those terms on 11.0.1, so test on the installed version before relying on it.
