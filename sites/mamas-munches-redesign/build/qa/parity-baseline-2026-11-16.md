What the parity walker (`scripts/parity/draft-live-walk.mjs`) sees as different between the Claude Design draft and the site, for setting beside Bean's own issue register. It pairs each draft element with the block built from it and compares position, size and computed styles at 375, 768 and 1440, at rest and in each state the draft declares.

- **Open rows** count one property of one element at one width in one state, so one visible fault (a wrong font on six cards) is many rows. Read the element lists, not the totals.
- **Accepted rows** are differences the ledger `build/qa/divergences.json` already excuses. Its tap-target entries were withdrawn by Bean on 2026-11-15 (a clone sticks to the draft) and are still in the file, so they are listed here as differences again.
- The walker cannot see what it has no pair for: a section the draft has and the site lacks shows as "missing"; a block the site has and the draft lacks is not listed at all. Basket, checkout and account are compared through their template copies with an empty basket and signed out.
- **Paired on the site** is how many of the elements in the draft the walker found on the site at 1440. It finds them by a marker class the cloner writes on each block (`cr-ref-<surface>-<n>`); a section rebuilt by hand carries no marker, so its draft elements show as "not found" although the section is there. Where under a tenth are paired the walker cannot compare the surface at all, and no element list is given.
- A surface marked "not walked" kept an older report from another site and is not part of this check.
