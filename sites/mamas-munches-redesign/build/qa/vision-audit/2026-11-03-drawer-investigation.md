## R1-20 (cart pill accessible name)

- Live state today: the stored cart block in the header (post 178, `sgs/cart`) has `ariaLabel` "Open basket", `pillLabel` "Basket", `triggerStyle` pill, `triggerStyleTablet` icon. The rendered `<button>` has `aria-label="Open basket (0 items in cart)"` and, at 1440, the visible text "Basket" plus the count "0" (accessibility-tree snapshot: `button "Open basket (0 items in cart)"` containing `text: Basket`). At 375/768 it is the icon-only 48x48 button with the same name. The visible word is contained in the name (case-insensitive), so WCAG 2.5.3 passes on Mama's today. The catalogue row quotes the default "View your cart (0 items in cart)", which is the block default, not what Mama's stores.
- Cause: `plugins/sgs-blocks/src/blocks/cart/render.php` prefixes the visible word into the name only when `$trigger_mixed` (pill at some tiers, icon at others). A uniform pill (`pill` at every tier) skips the check, so any `ariaLabel` (including the default "View your cart") that lacks the pill word fails 2.5.3. Mama's passes only because its stored label happens to contain "basket".
- Fix (framework, small): run the word-in-name check when `'pill' === $trigger_style` as well as when `$trigger_mixed` (i.e. any tier shows the pill), keyed to `$pill_label` the same way. Content workaround already in place on Mama's: `ariaLabel` containing the pill word. The draft's own button has no aria-label (name "Basket 0").
