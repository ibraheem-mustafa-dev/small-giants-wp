# Second fix landed against sgs/hero today — item 3.16, per-tier alt text

verdict: PASS (live-verified, fix deployed 2026-09-08)
first_paint_capture_passed: true
source_sha: 27d7845b5bec9e1f

Covers the clone-fidelity programme's item 3.16: the mobile hero image carried the DESKTOP
image's alt text instead of its own, because `sgs/hero`'s split-media source is genuinely two
different photos (a close-up product shot on desktop, a lifestyle background shot on mobile),
not one subject at two crops — the assumption Spec 35 D5's "alt is NOT tiered" rule was built
on. WCAG 1.1.1 requires each to describe what it actually shows. Full root-cause, fix detail
and gate log: `reports/visual-diff/hero-alt-text-2026-09-08.md`.

## Root cause (re-verified against current code before fixing)

- `hero/block.json:345-356` already declares `splitMediaImageAlt`/`Tablet`/`Mobile`.
- `$sgs_hero_resolve_split_image()` in `hero/render.php` already resolved each tier's OWN alt
  into `$split_image['alt']` / `$split_image_tablet['alt']` / `$split_image_mobile['alt']` —
  the stored data was already correct.
- The bug was purely at the point these were collapsed into ONE render-time variable
  (`$sgs_hero_split_alt = (string) ( $split_image['alt'] ?? '' )`, desktop only), before
  handing that one string to the shared `sgs_tier_media_render()` helper, which applied it
  verbatim to every tier's `<img>`.

## What changed

1. `includes/helpers-tier-media.php` — `sgs_tier_media_render()`'s `$alt` param widened to
   `string|array`, with a per-tier fallback-UP cascade when an array is passed. A plain string
   (every other caller, e.g. `sgs/timeline`) is unaffected.
2. `hero/render.php` — `$sgs_hero_split_alt` now built as the per-tier array from the
   already-resolved values.
3. `src/components/media/HeroSplitMediaPanelLayout.js` — added a tier-aware "Alt text"
   `TextControl` (mirroring the existing tiered picker pattern), closing a genuine
   editor-control gap — the tiered attributes existed but had no manual override.
