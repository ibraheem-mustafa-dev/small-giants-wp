## What changed

`.sgs-hero--split` and `.sgs-hero--split .sgs-hero__media` previously shared one
`overflow: visible` rule. They now differ:

```css
.sgs-hero--split            { overflow-x: clip; overflow-y: visible; }
.sgs-hero--split .sgs-hero__media { overflow: visible; }
```

The split hero's hover-zoom (`transform: scale(1.05)` on `.sgs-hero__split-image`) is MEANT to
spill past its own media column. With the section also `visible`, and no horizontal clip
anywhere up the ancestor chain to `<html>`, that spill ran past the viewport edge and inflated
`document.scrollWidth`, giving the whole page a horizontal scrollbar on hover.

`overflow-x: clip` rather than `hidden`: `clip` does not create a scroll container, so it cannot
break `position: sticky` on any descendant (this site has sticky header behaviours), and it is
the one overflow value that may legally pair with a `visible` other axis — a `hidden`/`visible`
mix silently computes the visible axis to `auto`, which would reintroduce the scrollbar.

A stale comment was also corrected: it claimed the effect was "measured off the source draft".
It was not. `sites/mamas-munches/mockups/homepage/index.html` contains no hover rule and no
`scale()` in its hero, and sets `.sgs-hero`/`.sgs-hero__media` to `overflow: hidden`. The zoom
is a deliberate framework enhancement beyond the draft (Bean's call), and the comment now says
so, so nobody "restores" it to match a draft that never had it.

## Assertions — stated before measuring

1. Firing the zoom does NOT grow `document.documentElement.scrollWidth`.
2. The zoom still visually escapes its own media column — the effect must survive the fix.
3. The section clips in the inline axis; the media column does not.

## Live results — measured on the canary (page 2742), 1440px viewport

Playwright cannot trigger a CSS `:hover` synthetically, so the transform the `:hover` rule sets
was applied directly to `.sgs-hero__split-image` — the same method the original diagnosis used,
so the before/after numbers are directly comparable.

```
                        scrollWidth   (viewport 1440)
  before fix, at rest      1449
  before fix, zoom fired   1467        <- horizontal scrollbar grew
  AFTER fix,  at rest      1449
  AFTER fix,  zoom fired   1449        <- unchanged. assertion 1 holds.

escape still works (assertion 2):
  .sgs-hero__media  overflow: visible
  image right edge, at rest     1448.8
  image right edge, zoom fired  1467.2   <- 18.4px beyond its column, still spilling

clipping boundary (assertion 3):
  .sgs-hero--split  overflow-x: clip
```

All three assertions hold: the page no longer gains horizontal scroll, and the escape effect is
intact rather than being clipped away inside its column.
