## What changed

`render.php:957` emitted the block's `prefers-reduced-motion` rule as:

```php
'@media(prefers-reduced-motion:reduce){#' . $uid . ' .sgs-button{transition:none !important;transform:none !important;}}'
```

The uid and the class sit on the **same element** (`<button id="sgs-btn-…" class="sgs-button …">`),
so the descendant combinator (the space) required a `.sgs-button` *inside* the button. There isn't
one — the only child is `span.sgs-button__label`. The rule therefore matched nothing, and
`prefers-reduced-motion: reduce` was silently ignored for this block.

It also breached the requirement it sits under: Spec 32 §6.1(b) / D303 mandates class-level scoping
so a client's equal-specificity `sgsCustomCss` residual can still win; an ID selector at (1,0,0)
cannot be overridden.

Changed to the compound selector the same file already uses in seven other places (lines 413, 417,
422, 423, 441, 446, 477):

```php
"@media(prefers-reduced-motion:reduce){.{$uid}.sgs-button{transition:none !important;transform:none !important;}}"
```

Also in this commit: the file's single pre-existing WPCS error (a double-quoted `"}"`) and a `phpcbf`
pass over its equals-sign alignment. `git diff -w` confirms the only non-whitespace changes are the
selector fix and that quote.

## 3. Why before/after doesn't apply

The "before" state is a rule that rendered **nothing** — it matched zero elements, so a pixel diff
against it could only ever show "no change" and would have confirmed the bug rather than the fix.
The meaningful question is whether the current state matches the intent, which assertions 1–4 test
directly. Assertion 4 covers the visitor-visible surface: for anyone without a reduced-motion
preference the rendered output is byte-identical, by construction.
