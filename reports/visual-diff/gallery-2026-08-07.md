## Defect 1 — the responsive gap did nothing
`gapTablet` / `gapMobile` were declared and the shared wrapper DID emit tier rules
— but on the WRAPPER element, while gallery's grid is the CHILD
`.sgs-gallery__grid` reading `var(--sgs-gap)`. A `gap:` on a non-grid ancestor is
inert. Fixed by re-pointing `--sgs-gap` per tier at the block's own scoped rule
(0,2,0), which beats the wrapper's (0,1,0) on SPECIFICITY rather than depending on
stylesheet order, and covers grid, masonry and carousel in one change since all
three consume that property.

### Live measurement, three tiers
| viewport | expected | measured |

| 375 (mobile emulation) | 77px | **77px** |
| 900 (tablet) | 40px | **40px** |
| 1440 (desktop) | 16px | **16px** |

Emitted rules confirmed in the deployed stylesheet:
`@media (max-width:1023px){.sgs-gallery-b254f326.wp-block-sgs-gallery{--sgs-gap:40px}}`
`@media (max-width:767px){.sgs-gallery-b254f326.wp-block-sgs-gallery{--sgs-gap:77px}}`
Block root `style` attribute: **(none)** — Spec 32 clean.

### Negative control
At 1440 the gap is 16px, NOT 77px — proving the rule is tier-scoped rather than
unconditional. A single-viewport 77px reading would have proven nothing.
NOTE ON METHOD: window resizing was NOT sufficient — `outerWidth` changed to 516
while `innerWidth` stayed 1920 and `matchMedia('(max-width:767px)')` still
returned false, so the CSS never saw the narrow viewport. Real device emulation
was required. A measurement taken after a window resize alone would have been
silently wrong.

## Defect 2 — duplicate Layout/Columns controls, silent data loss
`<ContainerWrapperControls kind="layout">` rendered LayoutPanel's own Layout and
Columns controls, bound to the SAME attributes gallery already controls, with an
incompatible option set: Stack/Flex/Grid against gallery's
Grid/Masonry/Carousel enum. Measured round-trip: writing "flex" was accepted and
stored, then SILENTLY reverted to "grid" on reload by WordPress's enum coercion.

Fixed by composing the named panels instead of the aggregator — the precedent
`sgs/hero` and `sgs/cta-section` already follow — with a new `showLayout={false}`
prop on LayoutPanel so gallery keeps the shared responsive GAP while suppressing
the colliding Layout and Columns controls. `showLayout` defaults to true, so no
other consumer changes.

## Limits
The editor-side proof (one Layout control instead of two) is NOT captured here —
this report covers the rendered frontend. `sgs/post-grid` and `sgs/feature-grid`
still use `kind="layout"` and carry the SAME collision; they were out of scope and
remain unfixed.
