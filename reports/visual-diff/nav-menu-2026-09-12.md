## Why before/after (via the pipeline capture tool) doesn't apply

Both fixes are interaction-state changes (an `order` swap that only differs from the
CSS-cascade default under one mode class, and a click-triggered CSS transition keyed on
`aria-expanded`) — a static first-paint screenshot of the page in its resting state cannot
show either change; the meaningful "before"/"after" pair is the SAME element's own
resting-vs-interacted state, captured live, not two different page loads.
