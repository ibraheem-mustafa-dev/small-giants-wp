## What changed

`render.php` — the maxWidth block's `margin-inline:auto` pairing (added 2026-09-08 to fix
quote/testimonial/before-after/option-picker's identical "text is centred, the block isn't"
defect) is now gated on the nearest ancestor's own layout. sgs/text is a generic leaf used
everywhere, including inside a flex/grid ancestor that already controls its children's
horizontal position (sgs/hero's split content column: `display:flex; flex-direction:column;
align-items:stretch`). There, `margin-inline:auto` fought the ancestor's own alignment instead
of respecting it — the draft's own CSS (`sites/mamas-munches/mockups/homepage/index.html:272`,
`.sgs-hero__sub`) never declares a centring margin for the hero sub-headline, which sits flush
left. The gate reads the nearest ancestor's `layout` attribute off the PHP call stack
(`debug_backtrace()`, since neither `sgs/container` nor `sgs/hero` provides block context for
this) and skips the pairing when the ancestor is `flex`/`grid`/`stack`.
