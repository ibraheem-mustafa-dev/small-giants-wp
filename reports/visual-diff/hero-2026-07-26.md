# sgs/hero — gridItemPadding / gridItemBorderRadius box-object (deployed + live-verified)

**Verdict: PASS.** `sgs/hero` imports the same shared `GridItemDefaultsPanel` and renders its root via the
same `SGS_Container_Wrapper::render()` helper as `sgs/container`/`sgs/cta-section`/`sgs/trust-bar`
(composite-mirror rule, D152). Verified independently as a grid-CHILD consumer.

## What changed
Same shared box-object migration described in the `sgs/container` report.

## Evidence (live, sandybrown, editor + frontend)

### 1. Editor panel exists on hero's own inspector
`hero/edit.js` imports `GridItemDefaultsPanel` (confirmed by source read this session) — identical
component/UI to `sgs/container`.

### 2. Consumption as a GRID CHILD — asymmetric painting
Same 4-child grid-parent test setup as the container/cta-section reports (`sgs/container` parent,
`layout: 'grid'`, children: container / cta-section / **hero** / trust-bar). Parent set to:
```
gridItemPadding: { top: "40px" }
gridItemBorderRadius: { topLeft: "20px" }
```
`getComputedStyle` keyed on the rendered `sgs/hero` root (class `sgs-container sgs-hero ...`):
```
paddingTop: 40px | paddingRight: 0px | paddingBottom: 0px | paddingLeft: 0px
borderTopLeftRadius: 20px | borderTopRightRadius: 0px | borderBottomLeftRadius: 0px | borderBottomRightRadius: 0px
```
Identical to the sibling `sgs/container`/`sgs/cta-section` measurements in the same grid — the shared
wrapper mechanism behaves consistently for this consumer type too.

### 3. Neutrality
Parent's attrs cleared to `{}`; re-measured on hero's root: `paddingTop: 0px`, `paddingLeft: 0px`,
`borderTopLeftRadius: 0px` — genuinely absent (`--sgs-gi-padding`/`--sgs-gi-radius` not declared on the
parent at all).

### Console
No frontend console errors.
