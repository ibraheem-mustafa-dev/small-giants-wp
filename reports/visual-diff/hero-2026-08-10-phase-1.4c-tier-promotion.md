# sgs/hero — mobile-only orphans promoted to responsive triples

**Verdict: PASS.** This change is ADDITIVE ONLY. Five new attributes are introduced, every
one defaulting to inherit (`""` / `null`), and every new CSS emission is guarded so a blank
value emits nothing at all. **No existing hero instance can render differently** — the
first paint of every stored hero is byte-identical.

## Why

`splitImageMobileHeight`, `splitImageMobileObjectPosition` and `splitContentOrderMobile`
were mobile-only settings with NO desktop or tablet counterpart. The one global device
toggle could not drive them, and a "3 siblings → 1" codemod pointed at them would have
invented a tier pair that never existed — which is why D545 correctly refused to treat them
as a merge target and routed them to Bean as a design call instead.

## What changed

New attributes, all inherit-by-default:

| Attribute | Type / default |
|---|---|
| `imageObjectPositionTablet` | `string`, `""` |
| `splitImageHeight` | `number`, `null` |
| `splitImageHeightTablet` | `number`, `null` |
| `splitContentOrder` | `string`, `""` |
| `splitContentOrderTablet` | `string`, `""` |

The three existing mobile attributes keep their names AND defaults
(`splitImageMobileHeight` `null`, `splitImageMobileObjectPosition` `"center 20%"`,
`splitContentOrderMobile` `"media-first"`), so nothing stored is touched. Desktop
object-position reuses the already-wired `imageObjectPosition` rather than adding a
duplicate.

## The semantics genuinely differ per tier, and the UI says so

Per Bean's brief: at desktop/tablet the order control picks which COLUMN sits left/right
(the split is a 2-col grid at ≥768px); at mobile it picks which stacks ABOVE. Same
attribute family, different meaning — so each tier's options and help text state which,
rather than leaving a client to infer it. Desktop reads "Content left, image right";
tablet offers "Same as desktop" plus explicit choices with help noting "left/right if
side-by-side, top/bottom if stacked"; mobile is unchanged.

## Why the frontend cannot change for existing content

Every new emission is conditional — verified by reading `render.php`, not inferred:

- `splitImageHeight` / `splitImageHeightTablet`: `if ( $split_image_height_tablet )` etc.
  A `null` default is falsy, so nothing is emitted.
- `splitContentOrder`: emits only on `'media-first' === $split_order`. The `""` default
  emits NO CSS, because natural DOM order already puts content first — blank is not just
  "unset", it is the correct rendering.
- `splitContentOrderTablet`: emits only when non-blank.
- `imageObjectPositionTablet`: emits only when non-blank.
- The mobile branch is unchanged, including its pre-existing `else`.

Source order is base → `@media (max-width:1023px)` → `@media (max-width:767px)`, so
narrower tiers win by cascade with no `!important`, matching the 768/1024 device-tier lock.

## Control shape

One `<ResponsiveControl>` per setting with a computed key per tier, copying
`container/edit.js:207-213`. **No per-control device switcher** — the tier comes from the
one global toggle; `inspector-scan` rule 25 reports 0 findings for `sgs/hero`.

## Min-height divergence — left as-is, deliberately

`hero/edit.js` hand-rolls a min-height option list diverging from the shared
`MIN_HEIGHT_OPTIONS` (adds `80vh`/`360px`/`520px`, drops `200px`, relabels `Auto`). Kept,
with the reason recorded inline rather than silently normalised:

- Hero's own `minHeightMobile` default is `"360px"`, which is **not in the shared list at
  all** — aligning would make the block's own default unselectable.
- `80vh`/`520px` are realistic full-bleed hero heights the generic container list omits.
- `sgs/physics-canvas` already proves the shared list is not authoritative: its `minHeight`
  defaults to `"480px"`, a value in NEITHER list.

## ⚠ Naming judgement flagged, not decided unilaterally

The mobile tier keeps the irregular `splitImageMobileObjectPosition` alongside the
otherwise-regular `imageObjectPosition` / `imageObjectPositionTablet`. Renaming it for
consistency would hit WordPress's silent attribute-discard on any live hero instance
carrying the old name. Consistency here is a follow-up WITH a migration, not a free rename.
