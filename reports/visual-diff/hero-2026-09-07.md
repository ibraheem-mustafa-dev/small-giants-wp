## What changed

`sgs/hero`'s split-media border gained a hover colour + hover gradient pair
(`splitMediaBorderColourHover` / `splitMediaBorderColourHoverGradient`) — colour-only, matching
`sgs/button`'s/`sgs/container`'s own `states.hover.attrMap` convention. Unlike `sgs/media`,
split-media's border renders through a bespoke `render.php` mechanism (not the shared
`box-shape` atom's `css()` emitter), so this is a hero-specific implementation mirroring
`sgs/button`'s own `sgs_border_gradient_css()` hover-paint composition, including its accepted
limitation: the masked-gradient hover only applies when the resting state is already a
gradient.

## Why "before/after" doesn't apply

New, isolated capability — split-media never had a border-hover state before. The real
question is whether the new hover state renders correctly without disturbing the resting
state.

## Assertion(s)

1. With `splitMediaBorderColour:"#000000"` and `splitMediaBorderColourHover:"#ff0000"` set, the
   rendered split-media element's computed `border-color` is black at rest and flips to red on
   `:hover`.
2. Moving the pointer away restores the resting black border-color.
3. The pre-existing resting-state split-media border rendering is unaffected.
