## What changed

`supports.spacing` removed from `plugins/sgs-blocks/src/blocks/button/block.json`. Nothing
else. The block keeps `anchor`, `customClassName`, `html`, `color`, `__experimentalBorder`
and `sgs`.

## Why

Bean opened the Styles tab on a real `sgs/button` and found TWO spacing controls:

- **"Dimensions" -> Padding / Margin** — WordPress native, from `supports.spacing`
- **"Spacing" -> Padding / Margin** — the SGS panel

Both drive the same stored value. A duplicate control is a defect on its own terms; the
client sees two places to set one thing.

## The risk this was tested against

The surviving SGS control writes `style.spacing`, and `style` is registered only because
supports declare it. So removing `supports.spacing` might strand it — the D338/D683 class,
where WordPress silently drops what the schema does not declare, with no error and no
failing build. An earlier attempt at this change was REVERTED on that concern without it
being measured. This is the measurement.

**`oldshape-audit`, 397 posts, with a button storing
`style.spacing.padding = {top,bottom,left,right: 37px}` -> PASS, 0 NEW HIGH.**

`style` remains registered via `supports.color` and `supports.__experimentalBorder`, and
catching undeclared-attr loss is precisely what that audit does.

## Measured live — editor and frontend, page 2726, 1440px

| Check | Result |
|---|---|
| `supports.spacing` | removed |
| native "Dimensions" panel in Styles tab | **GONE** |
| SGS "Spacing" panel (Padding + Margin) | **still present** |
| stored `style.spacing.padding` after the change | **survived** — `{top,bottom,left,right: 37px}` |
| frontend computed padding | **`37px 37px 37px 37px`** |

The stored value was authored BEFORE the change and read back AFTER it, in the editor and
on the published page. That is the specific thing the revert was worried about.

## ⚠ Two probe failures, both mine, both caught by the gate rather than by me

- A probe authored `sgs/text {"content": ...}` — `sgs/text` declares no `content` attribute.
- A probe authored `sgs/button {"text": ...}` — `sgs/button` declares `label`, not `text`.

Each produced NEW HIGH `undeclared-attr` findings that looked like a stranding risk until
traced back to the probe. Guessing an attribute name is the same error class as guessing
anything else on this project — and on both occasions the audit caught it, which is the
gate working exactly as intended.

## What is NOT claimed

- Only `padding` was round-tripped end to end. `margin` shares the same `style.spacing`
  subtree and the same code path, but was not individually re-measured.
- The responsive tier attributes (`paddingTablet` / `paddingMobile` / `marginTablet` /
  `marginMobile`) were not exercised.
