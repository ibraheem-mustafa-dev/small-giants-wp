## What changed

Added a per-item `decorative` field (boolean, default `false`) to the `mediaItems[]`
repeater's item schema. `edit.js`'s `GalleryThumbnail` gets a `ToggleControl` per item;
`render.php` blanks that item's alt and adds `aria-hidden="true"` on the rendered
`<img>`/`<video>` for both the lightbox and non-lightbox render paths.

## ⛔ A real gap found and fixed during this session's QC pass

The first implementation correctly gated the STATIC thumbnail markup (`$img_alt`/
`aria-hidden` in the per-item render loop, `render.php:371-380`) but missed a SECOND,
independent place the same alt text is built: the Interactivity-API lightbox context
(`$context_images`, `render.php:152-187`), serialised into `data-wp-context` and read by
`view.js` via `data-wp-bind--alt` when the lightbox modal opens. That loop built `alt`
unconditionally — a decorative item's real alt text still reached the lightbox's client
state, even though the visible thumbnail was correctly hidden. Confirmed live (a REST
probe with `decorative: true` showed the authored alt text present verbatim inside
`data-wp-context`'s JSON), then fixed by mirroring the same `$img_decorative` gate already
proven correct three lines away in the per-item loop.

## Assertion

An unset item renders byte-identical (`decorative` defaults false). A decorative item's alt
text is blanked in BOTH the static thumbnail markup and the lightbox's client-side context
— not just one.
