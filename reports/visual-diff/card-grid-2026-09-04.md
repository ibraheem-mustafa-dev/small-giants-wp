## What changed

Spec 35 Part 4 (capability-routing doctrine, multi-image item-schema extension) — first of four
target blocks. Card-grid's object-fit/focal-point was one shared value applied to every card
(render.php's own prior comment admitted "items[] has no per-card object-fit field"). Adds a
stable per-item `_key` (client-generated, `src/utils/generateItemKey.js`), a per-item
`objectFit`/`focalPoint` control in each card's own repeater panel, and a per-item scoped CSS
rule in render.php keyed by a new `data-card-key` attribute — never `:nth-child`/array index.

## Why intent capture, not before/after

The new CSS only fires when an item sets a non-default `objectFit`/`focalPoint` — no existing
content has ever been able to set those fields (they didn't exist), so a before/after diff on
any real page would show no difference by construction. The real question is "does the new
per-item mechanism actually work", which needs one live instance with two distinct crop values,
not a before-state.
