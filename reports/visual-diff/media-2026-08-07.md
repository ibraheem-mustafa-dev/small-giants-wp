## TWO REAL BUGS THIS CAPTURE CAUGHT — both mine, both fixed before this verdict

Recorded because both shipped through a green build, and the live capture is the only thing
that found them.

**1. Naked mode discarded every tier image.** `sgs/media` renders the `<img>` AS the block
root when there is no caption/link (Spec 32's no-useless-wrapper rule) — and that path
REBUILDS the image HTML further down the file, silently throwing away the tier images built
earlier. Measured live: **1 `<img>` in the DOM where 3 were expected, 0 visible.** Fixed by
suppressing naked mode when tiers exist: with two or three real sibling images the wrapper is
STRUCTURAL, not the useless one Spec 32 bans.

**2. A descendant appended to a selector LIST bound to the last member only.** The tier CSS
was built as `$id_sel . ' .sgs-media__img--desktop'`, but `$id_sel` (render.php:252) is a
THREE-member list. The combinator attached to the third member alone, leaving the first two as
an unqualified `.scope .sgs-media__img{display:none}` — which hid **every image at every
width**. Measured live: **3 imgs in the DOM, 0 visible, at all three breakpoints.** Now built
from `$id_wrap`, the bare scope selector.

⚠ Bug 2 is the exact shape of an already-recorded project gotcha ("a pseudo-element appended
to a selector list attaches to the LAST selector only"). The lesson existed; it did not stop
the same mistake in a new place.

⚠ Bug 2 was also nearly missed by MY OWN measurement: a regex search of the page HTML for the
tier rules returned zero and I briefly read that as "the CSS never emitted". It was a false
negative twice over — the regex could not match nested `@media{…{…}}`, AND SGS lifts block CSS
into `uploads/sgs-css/*.css` rather than inlining it, so grepping page HTML proves nothing
(a documented trap). Reading the lifted stylesheet is what exposed the real selector.

# Part 2 — VIDEO-source + poster tiers (appended 2026-08-07, later same day)

⚠ This file already existed and documented Part 1 (the IMAGE tiers). It was very nearly

## Why this half needed a different mechanism

Part 1 tiers images by rendering three `<img>`s and letting CSS hide two. Video CANNOT:
three `<video>` elements each begin fetching, and three embeds each load a player. So the
source is swapped at runtime by `view.js`, reusing sgs/hero's `data-src-desktop/tablet/mobile`
contract with the same upward fallback. The DESKTOP source is still real server markup, so
a no-JS visitor gets a working video.

**Bean decided the scope, cost stated and accepted:** YouTube/Vimeo are INCLUDED, so
crossing a breakpoint mid-watch rebuilds the iframe and loses playback position. The swap
only fires when the resolved source genuinely differs from what is on screen.

## A real bug this capture caught — the swap was ONE-WAY

desktop→mobile swapped correctly (YouTube → Vimeo) and looked like a pass. It was not:
`buildVideoNode()`'s iframe branch set only `data-poster`, so the rebuilt node carried NO
`data-src-*`, `resolveTierSource()` returned null forever, and the block stuck on the
mobile source even back at 1364px. One observation in one direction would have shipped it.
Fixed by carrying the dataset on BOTH branches, then re-proven as a round trip.

Returning to the ORIGINAL desktop source is the assertion that would have failed before the

**PASS** for Part 2.

## Tier posters are proven PAINTED, not merely present as an attribute

At 364px the mobile poster was confirmed **fetched by the browser**
(`performance.getEntriesByType('resource')` contains its exact URL), with the `<video>` box measured
at 302×537 — so the image is being displayed, not just named in an attribute that nothing reads. This
is the check that separates "the attribute is correct" from "the visitor sees it".

**Both Part 2 limits are now closed.**

## One honest cost this measurement surfaced

On mobile, the DESKTOP poster is ALSO fetched (`cookies-stacked-1` appears in the resource list
alongside the mobile one). That is inherent to the design: the server renders the desktop poster as
real markup so a no-JS visitor gets one, and `view.js` swaps it afterwards. The waste is one image
request on non-desktop viewports. Recorded rather than hidden — it is a consequence of the
progressive-enhancement choice, and would only be removable by giving up the no-JS fallback.
