# sgs/gallery — reduced-motion hover standardised to transform:none (LANDED)

**Verdict: PASS.** The `@media (prefers-reduced-motion: reduce)` fallback for the gallery
hover-lift/zoom now sets `transform: none` (matching the already-shipped card-grid/post-grid
pattern), removing the residual resting scale/translate that survived under reduced motion.
First paint is unaffected (this change touches only the reduced-motion hover branch).

## What changed
`src/blocks/gallery/style.css` — added a same-specificity `transform: none` override inside the
existing `@media (prefers-reduced-motion: reduce)` block for `.sgs-gallery--hover-lift
.sgs-gallery__item:hover` (the lift transform previously escaped the reset because its
2-class-plus-pseudo selector out-specified the generic reset). Zoom + base-scale resets were
already correct.

## Evidence (deployed CSS + specificity — honest method)
- **Deployed CSS fetched directly from the sandybrown canary** (not local source), md5-confirmed
  local↔server (`e2c574653b14558b824116b2700cb13a`): the running
  `blocks/gallery/style-index.css` contains
  `@media (prefers-reduced-motion:reduce){ … .sgs-gallery--hover-lift .sgs-gallery__item:hover,
  .sgs-gallery__item:hover{transform:none} … .sgs-gallery--zoom … :hover .sgs-gallery__img{transform:none} … }`.
- **Specificity + source order**: the reduced-motion override has equal specificity to and later
  source order than the hover-lift rule it neutralises, so it wins under `reduce`.
- **Deliberate parity**: this is the exact pattern already shipped + working on `sgs/card-grid`
  (`style.css:338-356`) and `sgs/post-grid` (`style.css:473-478`).

already-verified card-grid/post-grid pattern — a sound logical proof, short of literal emulated
measurement. A live instance of `sgs/gallery` was not instantiated on the canary (team-member was
used as the live hover proxy for the sibling report); gallery's rule was verified by deployed-CSS
fetch only. Change is low-risk (reduced-motion-only, strict improvement).
