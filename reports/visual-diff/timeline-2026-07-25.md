# sgs/timeline — render declared `supports.typography.textAlign` (attr-gated dead-read fix)

**Verdict: PASS.** Fixes a latent dead-**read** bug: the block declared the support and had
alignment code, but read `textAlign` from the wrong place (`$attributes['style']['typography']`,
where WP never puts it — it delivers `textAlign` as a top-level attribute). The corrected read +
emission is **gated on `textAlign` being set**, so existing instances render byte-identically.
`first_paint_capture_passed: true`.

## What changed (frontend render.php, attr-gated)
`src/blocks/timeline/render.php` now reads the **top-level** `$attributes['textAlign']`, validates
it ∈ {left, center, right}, and emits a scoped `{$title_sel}{text-align:VALUE;}` rule **only when
non-empty**. Previously it looked inside `style.typography` (always absent), so the support was
inert. Unset/invalid → no rule (prior behaviour).

## Why (root cause)
`supports.typography.textAlign:true` + `__experimentalSkipSerialization`; the attr was read from a
location WP never populates, so alignment never applied — a dead control + a clone gap for the
converter's root-text-align fold. Reading the correct top-level attr closes both.
