# sgs/media — C19 media size & crop panel

## What changed and why a change was expected

`render.php` gained a resolved sizing MODE (`mediaSizing`: auto | height | ratio) and
now enforces mutual exclusivity: previously `height` and `aspect-ratio` could BOTH
paint on one instance; now only the resolved mode's CSS is emitted.

For content that sets exactly one of them — which is every instance on the canary —
the derivation resolves to the same mode that was already implicitly in force, so the
rendering must be IDENTICAL. That is the prediction this report tests.

## Method

Live computed styles on `/tc-image-pairing-after/` (3 `sgs/media` instances), captured
at 1364px BEFORE the deploy and again AFTER, same page, same viewport, cache-busted.
Not the emitted stylesheet — SGS block CSS is lifted into `uploads/sgs-css/`, so
grepping page HTML proves nothing.

## ⭐ Positive control — why "identical" is not vacuous here

An unchanged measurement is exactly what a FAILED deploy looks like. Proven on the
server, not inferred:

- `build/blocks/media/render.php` contains `media_sizing` **8 times** — the new
  derivation IS the code that produced the "after" numbers.
- `mediaSizing` is present in the deployed `build/blocks/media/index.js` and
  `block.json`, so the editor panel shipped too.

So: new code live + rendering unchanged = behaviour-preserving, which was the claim.

## Not covered by this report

- All three instances are HEIGHT mode. The mutual-exclusivity branch that actually
  changes behaviour — an instance with BOTH height and aspect-ratio set — does not
  exist on the canary, so it is untested live. The code path is reasoned, not measured.
- The editor panel's grey-out chain is an EDITOR surface and is not measurable from
  the front end. Bean's eye (R-31-13) is owed on it.
