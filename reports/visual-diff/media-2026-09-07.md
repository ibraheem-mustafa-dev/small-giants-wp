## What changed

`sgs/media`'s border, owned by the shared `box-shape` media atom, gained a hover colour +
hover gradient pair (`borderColourHover` / `borderColourHoverGradient`) — colour-only, matching
`sgs/button`'s/`sgs/container`'s own `states.hover.attrMap` convention. The atom previously had
no hover capability at all.

## Why "before/after" doesn't apply

This is a new, isolated capability with no prior behaviour to diff against — the block never
had a border-hover state before this change. The real question is "does the new hover state
render correctly, and does it leave the resting state untouched?", which a single live capture
answers directly.

## Assertion(s)

1. With `borderColour:"#000000"` and `borderColourHover:"#ff0000"` set, the rendered element's
   computed `border-color` is black at rest and flips to red on `:hover`.
2. Moving the pointer away restores the resting black border-color (no stuck-hover state).
3. The existing resting-state border rendering (colour/width/style) is unaffected by this change.

(`--sgs-media-border-color-hover`, `--sgs-media-border-image-hover`) consumed by a new

fallback chain resolves to the existing resting values).
