## What changed

Two live defects found on the Mama's Munches homepage re-clone (page 2849, sandybrown
canary), both in `render.php`/`style.css`:

1. **Touch-target regression.** `sgs/container`'s shrink-to-fit backstop
   (`class-sgs-container-wrapper.php`, `.{uid}>.sgs-container__inner>*{min-height:0}`,
   specificity (0,2,0)) always beat the button's own base `.sgs-button{min-height:48px}`
   rule (0,1,0) — silently zeroing the WCAG 44px floor on any button rendered as a direct
   flex/grid child of a container, which is the common case.
2. **Phantom border.** `style.css` hardcoded `border-width:2px;border-style:solid`
   unconditionally on the base `.sgs-button` rule, painting a visible border even with no
   preset and no operator-set border colour (a transparent border-colour still painted a
   solid line).

Both fixes were iterated live against the actual defect during this session — the FIRST

## Assertions (stated before measuring)

1. Both flagged buttons render `min-height` computed as their configured floor (48px /

2. "Find out more" (`sgs-btn-1e632d6d`) renders no border (`border-width:0`,

## The wrong first attempt, and why it's worth recording here

The first fix emitted `.{uid}.sgs-button{min-height:...}` — also (0,2,0), tied with the
container's rule. The button's own comment at the time asserted "this block's own
`<style>` always renders after its parent container's", which was never verified. A live
re-check on this same page, using the same CSSOM method as above, measured `min-height`
still computing to **0px** with that first fix deployed — the container's rule was
appearing later in that instance, so the tie went the other way. The two buttons still
*looked* fine (48.7px / 44.7px actual height) purely because their own padding and
line-height already exceeded 44px regardless of `min-height` — so the visible defect was
gone by coincidence while the underlying mechanism remained broken. Caught before this
report was written by re-measuring rather than trusting the first agent's claim.

**Fix:** repeat the uid class (`.{uid}.{uid}.sgs-button`) to reach (0,3,0), which beats
(0,2,0) unconditionally rather than depending on source order.
