## What changed

`block.json` only. `selectors.typography` was `.sgs-info-box__heading`; now
`.wp-block-sgs-info-box` (the block root).

## Why the change was needed

`.sgs-info-box__heading` is not rendered. The block's own `style.css:99` documents it:

> *"CG-9 audit (2026-07-05): the .sgs-info-box__heading / __description rules that lived here
> were DEAD CSS — the HC2 migration (2026-06-08) moved heading/subtitle/description to child
> InnerBlocks (sgs/heading, sgs/text), which no longer render these BEM classes."*

The CSS was deleted in that audit; the `block.json` selector pointing at the same class was
left behind. Confirmed live: `deadClass: false` — nothing renders it.

**No pixel change, and that is the expected result.** The selector governed rules that landed

change: it stops the block declaring a typography target that does not exist.

## ⚠ Known remaining gap — NOT fixed here, do not read this PASS as "typography works"

`sgs/info-box` declares `supports.typography` with `__experimentalSkipSerialization: true`,
which means WordPress does not emit the CSS and the block must do it itself. **It has no
emitter**: `grep -c "text-align" render.php` returns 0, and there is no scoped typography
rule either. So its typography controls remain non-functional after this change — the pointer
is now honest, but nothing consumes it.

Closing that needs an emitter modelled on `sgs/cta-section`'s (which emits to the block root and
was live-verified this session). Deliberately out of scope here: it is a behaviour addition, not
a dead-pointer removal, and belongs in its own change with its own capture.
