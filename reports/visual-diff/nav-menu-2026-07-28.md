## Round 4 — nav CONTAINER controls (the real gap behind the drawer-background question)

Bean reframed three "design directions" as a settings gap: these should simply
be client-editable. Audit result — he was right on two of three:

| Capability | Status BEFORE |
|---|---|
| Nav item hover (text/bg/radius), featured, underline, burger hover | **already present** (10 hover attrs) |
| Mega panel background | **already present** (`panelBg`, WCAG-checked text) |
| Nav CONTAINER background / text colour / border | **ABSENT** — `supports` declared spacing only; the element manifest mapped padding/margin/max-width and nothing else |
| Divider between items | **ABSENT** — no separator element existed at all, distinct from a border |
| Drawer styled separately | **already worked** — the drawer holds its OWN `sgs/nav-menu` instance (verified live: page uid `sgs-nav-menu-4b7c46c9` vs drawer `sgs-nav-menu-53a6fe97`), but with identical defaults, so the capability was invisible |

**Built:** `navBg` · `navColour` · `navBorderColour` · `navBorderWidth` ·
`navRadius` · `navBgHover` · `navBorderColourHover` · `itemSeparatorColour` ·
`itemSeparatorWidth`, in a new "Nav container" inspector panel with a
plain-English note telling the operator the drawer's menu is a separate copy.
The drawer's seeded nav now ships vertical-appropriate defaults (tighter gap +
a divider) so the independence is discoverable; colours stay unset so the
drawer's own background still shows through.

**Regression check (unset must equal before):** nav renders
`background rgba(0,0,0,0)`, `border 0px`, `radius 0px`, separator `0px` —
byte-identical to pre-change.

**Negative control caught a real bug.** Setting the divider and measuring the
LAST item returned `1px` when it should be `0px`: the bar also contains the
absolutely-positioned indicator pill, so the last ITEM is not the last CHILD
and `:not(:last-child)` matched it, drawing a trailing edge. Rewritten as
`item + item` (border on each item AFTER the first), which is immune to
whatever else the bar contains. Re-measured: `0px / 1px / 1px / 1px` across
Home·Brands·Recipes·Contact. Reading the selector would never have found this.

**1b, refined again (Bean):** the "View all" link is no longer hard-wired
anywhere — `sgs/mega-panel` gains `viewAllPlacement`:
`auto` (show only when the panel has no CTA of its own — the safe default) /
`none` / `bottom-left` / `bottom-right`. PHP-validated, no JSON enum.
Alignment rides modifier classes, not an inline style (Spec 32; the
`audit-inline-styling` gate passes at 0 violations).

Gates: `check-dead-controls` 0 net-new · `audit-inline-styling` 0 violations ·
