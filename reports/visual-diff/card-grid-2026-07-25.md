# sgs/card-grid — cardBorderWidth 4-side box-object (deployed + live-verified)

**Verdict: PASS.** `cardBorderWidth` is migrated from a scalar string to a 4-side object
`{top,right,bottom,left}` (FR-31-22) driven by the shared `ResponsiveBoxControl` — a linked
single input by default, click-to-split (`splitOnAxis={false}` locked → unlink gives 4 sides,
Bean-confirmed; WP `BoxControl` linked-default confirmed via `/library-docs`). Deployed to the
sandybrown canary (`--skip-build`, md5-verified). `first_paint_capture_passed: true` — an empty
`{}` falls through to `border-width: 0` (the pre-migration empty-`''` outcome), so existing
instances render identically; verified live on both published card-grid pages.

## What changed
- `block.json`: `cardBorderWidth` `{type:"object", default:{}}` (was `{type:"string", default:""}`).
- `edit.js`: the "Border width" `TextControl` → `ResponsiveBoxControl` (`showResponsive={false}`),
  linked single value by default.
- `render.php`: emits per-side `--sgs-card-border-width: <T> <R> <B> <L>` into the existing scoped
  `$card_state_vars` (no inline style — Spec 32), only when ≥1 side is set; empty `{}` emits nothing.
- `style.css`: the `border` shorthand (single width only) → `border-style: solid; border-color:
  var(--sgs-card-border-color, transparent); border-width: var(--sgs-card-border-width, 0)` so a
  4-value width works; the `0` fallback = no border when unset.
- `ResponsiveBoxControl`: `splitOnAxis={false}` locked on both `BoxControl` call sites (no-op WP
  default, made explicit so it cannot drift).
