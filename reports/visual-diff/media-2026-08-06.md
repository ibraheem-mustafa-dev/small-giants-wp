## What changed

`videoPoster` → `thumbnail`, `videoPosterId` → `thumbnailId`. In both cases the
value is the still shown before playback and while paused; "poster" is a print
term and a poor client-facing label. Editor labels updated to match.

The HTML5 `<video poster="…">` attribute is UNCHANGED — only the SGS attribute
names moved. `$poster_url` / `$poster_attr` / `data-poster=` in `render.php`
consume the resolved URL and never name the attribute, so they stayed as-is.

**Risk this carried.** WordPress silently discards an attribute `block.json`
does not declare, so a rename deletes stored values on the next editor save
(the D496 multi-button failure). The deploy's own `oldshape-audit` caught one
instance — canary post 2114 stored `posterMedia`/`posterAlt` on
`sgs/image-sequence` — and refused to deploy. Per the pre-production policy
(D270/D293: no migrations, no deprecations), that scratch canary page was
trashed rather than migrated, and the audit then passed. `sgs/media`'s own old
names were confirmed absent from all stored content by the same audit.
