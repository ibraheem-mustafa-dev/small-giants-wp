## The bug fix, proven by positive control

`gap` ("Item gap") was previously emitted by the wrapper at `$grid_sel`, which for this
block resolved to the ROOT. The root's flex children are the bar and the toggle, and the
block swaps those with `display:none` at the collapse point — so exactly ONE flex child
exists at any viewport and a flex gap between one item paints nothing. The control had a
label, a value and a reset, and changed the page not at all.

It now emits on `.sgs-nav-menu__bar`, whose flex children ARE the item links. Measured
live, two instances with DIFFERENT stored values rendering differently:

```
.sgs-nav-menu-6a66d0cf .sgs-nav-menu__bar { gap: 28px; }   -> computed 28px
.sgs-nav-menu-33f5502b .sgs-nav-menu__bar { gap:  8px; }   -> computed  8px
```

Two instances diverging by their own stored values is the positive control: a single
instance at one value would not distinguish "the rule works" from "something else paints
28px".

## Anti-vacuity

Both measured navs render 5 real links each. An empty or absent block scores a false PASS
on any sweep, so link presence was confirmed before any computed style was read. The
rules above were read from `document.styleSheets` by selector text, not inferred from the
computed value alone — so the PASS binds to THIS change's emitted CSS, not merely to the
block looking acceptable.
