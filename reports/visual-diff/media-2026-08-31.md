## ⛔ The first deploy of this wiring PASSED EVERY GATE AND PAINTED NOTHING

Recorded because it is the whole reason this report exists, and because the
failure is invisible to every static check.

The first deploy stored `contain` and `scale-down` correctly and rendered all
three images at `cover`. 82 build gates and 4 deploy gates were green.

How it narrowed:

| Step | Finding |
|---|---|
| `media-element.css` loaded? | yes, and the `.sgs-media-el` rule was present |
| marker on the elements? | yes, all three `<img>` carried `sgs-media-el` |
| lifted CSS emitting at all? | yes — each instance's own `height:200px` rule was there |
| `--sgs-media-object-fit` anywhere? | **in no stylesheet on the page** |
| attribute actually stored? | yes — `wp post get 3145` showed `contain`, `scale-down` |
| `SGS_Media_Element` class loaded? | yes |
| `sgs_media_atom_object_fit_css` defined? | **NO** |

**Root cause.** `render-helpers.php` required five of the ten atom PHP twins.
The five it did not require — `object-fit`, `focal-point`, `box-shape`,
`overlay`, `svg-presentation` — are every atom that emits CSS.
`sgs_media_element_style()` dispatches by naming convention and skips a missing
function *silently by design*, so a half-built atom cannot fatal a page. The
cost is that an unloaded twin is indistinguishable from an atom with nothing to
say.

**Why no gate saw it.** `test-media-atom-parity` compares each atom against its
own twin, and both halves existed **as files**. Existence is not reachability —
the repo's own recorded failure mode (D338, D493), reproduced inside the media
layer.

**Now gated.** `check-media-atom-purity.js` fails the build when a twin exists on
disk without a require in `render-helpers.php`, and fails closed on an empty
atoms directory so it cannot pass by having nothing to check. Negative control
run and shown red: removing the `object-fit` require fails naming that atom.

## One deliberate behaviour change

`style.css`'s `:where( .sgs-media__img ){ object-fit: cover }` was deleted in the
GUT step; the atom now carries the same measured `cover`. That old rule matched
`__img` **only**, so an unset `<video>` previously rendered at the browser
default `fill` and now resolves `cover`.

That is the standardisation being applied, not a regression: all four surfaces in
`media-element-census.json` measure `cover`. Recorded rather than left for
someone to discover.
