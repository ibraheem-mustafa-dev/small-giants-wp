# media — per-device SVG source (`svgContentTablet`/`svgContentMobile`), plus a cascade fix that also corrects the existing IMAGE tiers

**Verdict: PASS**, on a first-paint capture at three viewports against the live
canary. Every band shows exactly one tier element, the correct one.

⚠ **`source_sha` provenance — read this before trusting the field.** The gate's
`visual-report-sha.py` hashes the *staged* bytes of the block's `src/` dir. The
code landed first (commit `5727825e`, `--no-verify` with Bean's explicit
authorisation) because the capture requires a live deploy and the deploy refuses
to run while another track's unfinished work is dirty in deploy scope — so
nothing was staged by the time this report was written. The value above was
reproduced with the script's own algorithm (`sha256` over `name\0blob\0` per
file, sorted, truncated to 16) reading `HEAD:<path>` instead of `:<path>`. Those
blobs are byte-identical to what was staged at commit time, so the digest matches
what the gate would have computed — but it was NOT produced by the gate, and this
report therefore documents the change rather than having gated it.

## What was measured, and where

- **Page:** https://sandybrown-nightingale-600381.hostingersite.com/t1-svg-tier-probe/ (page 2332)
- **Deploy:** `5727825e`, blocks-only, from an isolated worktree so the other
  track's dirty `hero/*` + `includes/render-helpers.php` could not ship.
  `payload-verify` matched all 83 live `block.json` against the payload.
- **Method:** Playwright (chromium). **Fresh navigation per viewport**, never a
  resize-after-load — a resize scores a false pass, and markup presence proves
  nothing.
- **Assertion anchor:** each tier's SVG carries a unique inner `class`
  (`pa-desktop`, `pb-tablet`, …), and visibility is read from
  `el.closest('.sgs-media__svg')`. ⛔ Deliberately NOT a bare
  `document.querySelector('.sgs-media__svg')` — an unscoped query on a shared
  wrapper class returned the site header in a previous session and produced a
  confident false result.
- **Width assertion:** on the **measured** `window.innerWidth`, not the requested
  viewport. All three came back exact (375 / 800 / 1440), so no band was tested
  under the wrong label.
- **Positive control:** an injected `display:none` div was re-read via
  `getComputedStyle` at every width and returned `CAN_DETECT_HIDDEN`. Without it,
  "hidden" is indistinguishable from a dead measurement.

## Measurements — this block, not another

`VISIBLE` / `hidden` is the computed state of the tier wrapper containing that probe.

| probe | 375px | 800px | 1440px |
|---|---|---|---|
| `pa-desktop` | hidden | hidden | **VISIBLE** |
| `pa-tablet` | hidden | **VISIBLE** | hidden |

Exactly one visible per band.

### Fixture B — TABLET set, MOBILE empty (the cascade case)

| probe | 375px | 800px | 1440px |
|---|---|---|---|
| `pb-desktop` | hidden | hidden | **VISIBLE** |
| `pb-tablet` | **VISIBLE** | **VISIBLE** | hidden |

**This is the regression fix, proven on the real page.** Before the change,
375px showed `pb-desktop`: mobile fell back to DESKTOP, skipping the tablet value
it should have inherited. That contradicted `sgs_resolve_tier()`
(`includes/helpers-responsive.php:685-694`), whose mobile branch recurses to
tablet, and Spec 35 D3/D5 ("falls back UP: mobile → tablet → desktop").

The bug was **proven, not inferred**: the old rules replayed through the same
assertions fail exactly one of twelve cases — tablet-only at 375px — and the new
logic passes 12/12. That one-case failure is also the negative control proving
the assertions bite. The fix corrects the **existing image tiers** too, since both
families now call one shared closure.

`onload="window.SGS_XSS_ATTR=1"`, and a `<foreignObject>`.

| check | result |
|---|---|
| `window.SGS_XSS_TIER` set | **false** |
| `window.SGS_XSS_ATTR` set | **false** |
| `<script>` present in DOM | **false** |

The tier passes through the **same** `wp_kses()` allowlist as the base field. The

tier was processed rather than discarded wholesale — the negative and positive
halves of the same check.

## Cross-model review

Two independent reviewers (security lens, correctness lens), neither sharing the
implementer's model.

- **Correctness: 6/6 clean.** Independently hand-traced tablet-only at 375px to
  the same answer the unit test reached by a different method.
- **Security: sanitisation paths clean**, `phpcs:ignore` annotations accurate, no
  fatal vector, all class values enum-validated or literal and `esc_attr()`-wrapped.
- **One reported finding was checked and refuted.** A cross-tier `id`-collision
  hazard between sibling SVGs requires something referenceable by id; the allowlist
  contains no `use`, `linearGradient`, `radialGradient`, `stop`, `clipPath`, `mask`
  or `pattern`, so `fill="url(#x)"` resolves to nothing whether there is one SVG or
  three. Residual is duplicate `id` attributes — invalid HTML, cosmetic.
- **One finding CLOSED as not-a-vulnerability, on evidence.** `style` is
  allowlisted and `wp_kses()` does not filter an allowed `<style>`'s text content,
  so operator CSS is unfiltered and a nested `<style>` applies document-wide
  regardless of `display:none` on its wrapper — all correct. It is still not an
  escalation: **`sgsCustomCss` already gives every block a sanctioned raw-CSS
  `<style>` channel** (registered `extension-attributes.generated.php:53`, emitted
  `custom-css.php:25` / `class-sgs-css-registry.php:25`, load-bearing per Spec 31
  FR-31-5.2 and explicitly undeletable). Same actor, same privilege, same output.
  Removing `style` would break design-tool SVG exports, which routinely use
  `<style>` + classes, for no security gain.

## Residual risk

- **None from the `<style>` finding** — see above; equivalent capability is
  already sanctioned framework-wide.
- Duplicate `id` attributes across sibling tiers (cosmetic; nothing references them).
- This report documents rather than gates — see the `source_sha` provenance note.

## Correction to an earlier draft of this report

An earlier version listed the `<style>` item as a standing residual risk, on the
reasoning that removing it "could break live operator SVG". That was asserted, not
measured. Measured afterwards against the canary: **1332 live posts, 0 using
`<style>` inside SVG**, on a query carrying its own positive control
(`with_svgContent` returned 1 — this probe page — proving the query could match).
The blocker was false; the finding then closed for a different and better reason
(the sanctioned `sgsCustomCss` channel). Recorded because the failure mode —
parking something behind an unverified blocker — is worth more than the finding.
