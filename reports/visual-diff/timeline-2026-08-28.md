## What changed

`sgs/timeline` gains an optional scroll-driven connector: the line that joins the milestones fills
progressively 0→1 as the block scrolls through the viewport. Spec 38 **FR-38-35**, Tier V,
block-private (not an fx-panel effect — the FR-38-26 precedent, since fx injectors only stamp the
block ROOT and the connector is a descendant).

| File | Change |
|---|---|
| `block.json` | `+connectorProgressFill` (bool, default `false`), `+connectorFillColour` (string, default `accent`); `connector` element `attrMap` gains `"css:stroke"` |
| `edit.js` | `ToggleControl` in the existing Connector `PanelBody`; an `SgsColourPanel` row (`linked: true`, so it stores a palette SLUG not a hex); editor-canvas custom-property + class parity |
| `render.php` | Emits an `aria-hidden`/`focusable="false"` SVG with two `pathLength="1"` paths, plus the `sgs-timeline--connector-progress` class, only when the toggle is on. Colour routes to the scoped `<style>` via `sgs_colour_value()` — **no inline style** (Spec 32 FR-32-1 / D345) |
| `style.scss` | `@property` registration, the consumption rules, `::before` suppression, orientation + 767px handling, reduced-motion, and the native `@supports (animation-timeline: view())` driver |
| `view.js` | The vanilla rAF driver — the PRIMARY path for Firefox, which has no `animation-timeline` at all |
| Spec 38 | Corrected two false browser-support claims; added FR-38-35 + its §2/§9/§10 contract rows |

## Two defects found and fixed before commit

1. **`stroke-dasharray` was missing from the design.** `stroke-dasharray` defaults to `none`, and
   `stroke-dashoffset` has **no effect** on a line with no dash pattern — the connector would have
   rendered permanently 100% filled while the property animated perfectly and every gate stayed
   green. Found by a QC pass on the build plan, *after* the design had already survived one review
   that specified the dashoffset without it. This is C1's silent-failure shape arriving by a second
   route.
2. **The two drivers gated on different features.** The CSS driver shipped behind
   `@supports (animation-timeline: view())` while the JS driver feature-detected `scroll()`. On any
   engine shipping one without the other, the CSS would not apply *and* the JS would have already
   returned — nothing would fill the line. Both now gate on `view()`.
