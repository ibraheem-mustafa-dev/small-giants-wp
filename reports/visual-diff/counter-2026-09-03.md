## What changed

`labelColour` gained a gradient sibling and a gradient-capable paint path — the same
treatment its own `numberColour` sibling already had, in the same file, since commit
`778879732` (D636 Task 1b). That commit closed with an explicit note that it had NOT
finished: *"the remaining ~78 candidate text-colour attributes."* This is that tail,
starting with the block that already carries the worked example one row above.

Four changes, the complete current pattern:

| File | Change |
|---|---|
| `block.json` | new `labelColourGradient` string attr; `label` element gains `attrMap` `"css:background-image": "labelColourGradient"` |
| `render.php` | `sgs_resolve_text_colour_or_gradient()` → `sgs_text_colour_decl()` → `sgs_text_colour_gradient_fallback_rule()` |
| `edit.js` | row gains `gradientCapable: true` + `gradientValue`/`onGradientChange`; canvas preview swapped to `resolveTextColourPreviewStyle( flat, gradient, colourVar )` |

⚠ **The pattern is NOT the one commit `778879732` used, and reading that commit alone would
produce a broken result.** At that commit the gradient shared a single attribute and
`resolveTextColourPreviewStyle()` took two arguments. The storage model has since moved to a
separate `{attr}Gradient` sibling and the helper takes three. A first attempt here was built
from the reference commit, produced a two-argument call, and was reverted. Read the CURRENT
`numberColour` wiring in the same file, not the historical diff.
