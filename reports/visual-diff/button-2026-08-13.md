# `sgs/button` — link rework: popover mount, canvas text, and render-time link resolution

**Verdict: PASS.** Captured live on the sandybrown canary at first paint, at two
viewports, on a fresh navigation each time — never a resize-after-load.

## What changed on the visitor-facing surface

`render.php` gained resolution of an internal link: when `linkId`/`linkKind` are
set, the `href` is produced by `get_permalink()` / `get_term_link()` at render
time, falling back to the stored `url` string when there is no id or the id no
longer resolves. `block.json` gained the two attributes.

Everything else in this change is editor-only (RichText on canvas, the toolbar
link button, the sidebar row that opens the same popover) and does not reach the
frontend.

## First-paint capture — the two states that matter

Both rendered on one published probe page, so the same deploy produced both.

| State | Rendered | `href` | `target` | `rel` | Box |
|---|---|---|---|---|---|
| **No link set** (unset/default) | `<button>` | — | — | — | 167×50 |
| **Link set** | `<a>` | resolved URL | `_blank` | `noopener noreferrer` | 151×50 |

Measured at **1440** and at **375**. ⭐ Asserted on the MEASURED `window.innerWidth`
(1440 → 1440, 375 → 375), not the requested viewport — a requested width that
measures differently would silently test the wrong tier.

**Boxes are byte-identical across both viewports**, so this change moves no pixels:
the unlinked button is 167×50 at both widths and the linked one 151×50 at both.

## Why the unset state is the load-bearing half

A button with no link must remain a plain `<button>` with no `href`. That is the
pre-existing behaviour and the state most instances are in. It is captured above
and unchanged. This project's recorded regression class is precisely a change that
is invisible whenever the attribute is SET and only appears when it is unset, so
the unset case is captured first-class here rather than assumed.

## Render-time resolution proven, not asserted

The `get_permalink()` path was confirmed to be live rather than a stale `url`
fallback by renaming the target page's slug and reloading: the button's `href`
followed the new slug. The target page's slug was then restored.

## Scope note

No CSS changed. No class names changed. The `<a>`/`<button>` election already
existed — this change only alters where the `href` VALUE comes from, plus two new
attributes that are absent on every existing instance and therefore inert until an
operator picks an internal page.

Probe page created via REST and deleted after capture.
