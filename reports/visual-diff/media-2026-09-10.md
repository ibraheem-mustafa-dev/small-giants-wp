## What changed

`plugins/sgs-blocks/src/blocks/media/style.css` — removed `height`, `width`, and `max-width`
from the normal-mode selector (`.wp-block-sgs-media img, .wp-block-sgs-media .sgs-media__img`)
and removed `height`/`max-width` from the naked-mode twin (`.wp-block-sgs-media.sgs-media__img`).

Root cause: both rules sat at `(0,2,0)` specificity and beat
`assets/css/media-element.css::.sgs-media-el`'s box-shape atom rule (`(0,1,0)`), which reads
`var(--sgs-media-height, auto)` / `var(--sgs-media-width, auto)` / `var(--sgs-media-max-width,
100%)`. A configured height (e.g. `440px`) resolved correctly as a custom property but the
block's own competing `height: auto` still won the cascade, so the image rendered at its
natural aspect ratio instead of filling the configured box. Same collision class already fixed
for `object-fit` on these same two selectors earlier this session (see the code comment
immediately above, `style.css:40-48`).

The atom's own fallback chains reproduce the deleted defaults exactly for any instance with
nothing configured, so this is a no-op everywhere except a configured instance.

## Regression check — shared atom serving every `sgs/media` instance sitewide

Only one `sgs/media` block instance exists on the live homepage (the brand image itself), so no
second instance on this page could be spot-checked live. The `sgs-hero__split-media` image
elsewhere on the page is a different block (`sgs/hero`'s own split-media system, distinct class
names, never matched by the edited selectors) — confirmed unaffected by construction, not by
live comparison.

Regression safety for an UNCONFIGURED `sgs/media` instance (no height/width/max-width set) is
proven structurally instead: `media-element.css::.sgs-media-el` already declares
`height: var(--sgs-media-height, auto)`, `width: var(--sgs-media-width, auto)`,
`max-width: var(--sgs-media-max-width, 100%)` — the identical values the deleted block-level
rules supplied. An instance with no custom property set falls through to the same `auto`/`auto`/
`100%` defaults either way, so removing the competing declaration cannot change its rendering.
