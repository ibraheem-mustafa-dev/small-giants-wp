# hero — split media gains per-device TYPE (image / video / SVG), and the legacy `splitMedia` slot is deleted

**Verdict: PASS**, on a first-paint capture at two viewports plus a full editor
session against the live canary.

⚠ **This block's split media has been reworked and REVERTED TWICE** (`8598ac73`,
and D594 where the live editor was found broken — split squashed to quarter-width,
controls inert). Both prior attempts replaced the split media with a **child
block**. This one does not: it wires the already-declared typed attributes to the
shared `sgs_tier_media_render()` helper. The editor checks below exist
specifically because a passing front end did not catch either previous failure.

## What was wired

`splitMediaType` / `Tablet` / `Mobile`, `splitVideo*` and `splitSvg*` were
DECLARED in block.json and READ into PHP variables, then used by nothing — each
appeared exactly once (its own assignment), and `hero/edit.js` had zero controls
for any of them. The server could not render them and no client could set them.
All nine now resolve through `includes/helpers-tier-media.php`, and each has an
inspector control.

## Legacy REMOVED, not preserved (Bean, 2026-08-13)

Deleted outright — no deprecation, no fallback (D270: pre-production, nothing to
migrate; R-22-14 in this file's own header already said "NO legacy scalar
fallback"; R-31-14 bans exactly the `if ( empty($new) && !empty($legacy) )` shape):

- the `splitMedia` attribute, its `_comment_splitMedia`, and its editor picker
- the two synthesise/hydrate bridges keeping `splitMedia` and `splitImage` in sync
- the `splitMedia` → `splitVideo` alias bridge
- the alt-text fallback through `splitMedia`
- the type resolver's `'image'`-falls-through-to-inference branch, whose only
  justification was a legacy `splitMedia` video. `'image'` is now STRICT, exactly
  like `'video'` and `'svg'`. The `''` (inherit) inference stays — that is the
  canonical cascade, not legacy.

The client previously saw **two media pickers for one slot** ("Split media source"
and "Split image") writing different attributes and hand-synced. Now one.

**Verified before deleting, not assumed.** Across ALL post statuses the only rows
carrying `splitMedia`/`splitImage` were one leftover DRAFT from the reverted D594
session (2294, "D6 hero split-media QC") and this session's own probe, plus their
revisions — zero real content. 2294 was trashed on Bean's instruction; the
`oldshape-audit` gate then went from **1 NEW HIGH → 0** and the deploy proceeded.
⛔ That gate ABORTED the first deploy attempt, correctly: it is what stands between
removing an attribute and silently deleting stored content on next save (D338).
