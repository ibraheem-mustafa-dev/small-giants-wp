## What changed

`block.json` — `attributes.items.items.properties.media` was a bare
`{"type":"string"}`. `edit.js`'s `MediaPicker` (the only real editor path)
always writes the object shape `{url, type, id, alt, mime, width, height}`
(`MediaPicker.js`'s `normaliseMedia()`), and `addItem()`/the picker's Remove
action write `media: null`. WordPress's `WP_Block_Type::prepare_attributes_for_render()`
validates the WHOLE `items` array against this one schema on every server
render (`rest_validate_array_value_from_schema()` in WP core's
`wp-includes/rest-api.php` returns the FIRST `WP_Error` it hits across the
array), so any item authored through the real editor UI silently wiped the
**entire** grid back to its `[]` default — no PHP error, no console error,
just a blank grid on the live frontend. Fixed by declaring `media` as a
genuine `anyOf` across all three real shapes: bare string (pattern
back-compat), `null` (the empty/removed state), and the actual media object
(with real `properties`, not a bare catch-all `"object"`).

## Why "before/after" doesn't apply here

The "before" state is not a different rendered SHAPE to diff against — it is
**no render at all** (an empty `.sgs-card-grid` with a placeholder paragraph,
or in the multi-item case, a shorter grid than authored). A pixel diff against
that non-state proves nothing a live measurement of the fixed state can't
already show more directly: does object-shaped media now survive
`prepare_attributes_for_render()` and paint real `<img>`/`<video>` tags, and
does the pre-existing bare-string content stay exactly as it was. Same shape
of case as `info-box-2026-08-15.md`'s dead-CSS-selector removal.

## Assertions (stated before measuring)

1. An `items` array containing an item with the real MediaPicker object shape
   `{url, type, id, alt, mime, width, height}` survives
   `prepare_attributes_for_render()` intact (all items present, none dropped).
2. An item with `media: null` (the `addItem()`/Remove empty state) also
   survives — it was independently broken by the same mechanism before this
   fix.
3. The surviving object-shaped item renders a real `<img>`/`<video>` tag,
   title and subtitle on the live frontend, not a blank card.
4. Existing bare-string-shaped content already live on the canary
   (`sgs/card-grid` in post 3482, "Indus Brands Panel (Phase 2 port)", 12
   items) is unaffected — same item count, same rendered `<img>` tags, after
   deploying the fix.
