## What changed

Added `imageDecorative` (boolean, default `false`) — a SINGLE block-level toggle, not
per-post, since post-grid queries WordPress posts dynamically rather than authoring a fixed
list; "some posts' images are decorative, some aren't" isn't a coherent client choice for a
loop. Nested inside the existing "Show image" control in the Content ToolsPanel. Real teeth
live in `render.php` via a new `function_exists()`-guarded helper,
`sgs_post_grid_make_card_image_decorative()`, which post-processes each card's HTML
(built by `Post_Grid_REST::render_card()`) with a targeted regex that blanks `alt=""` and
adds `aria-hidden="true"` on the card's `<img>` when the toggle is on.

## Assertion

An unset grid renders byte-identical (`imageDecorative` defaults false). When on, EVERY
post's featured image in the grid is hidden from assistive tech, consistently.

## Known limitation (named, not silently dropped)

AJAX-paginated cards (subsequent pages fetched via the REST endpoint, which calls
`Post_Grid_REST::render_card()` directly, bypassing this block's own `render.php`) do NOT
get this post-processing — fixing that needs `includes/class-post-grid-rest.php`, out of
scope for this change. First-page/initial render is fully covered.
