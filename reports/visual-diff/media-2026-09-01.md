# sgs/media — wire box-shape/video-behaviour/overlay atoms, close Wave 5a gaps

## What changed and what is asserted

Three atoms wired into `sgs/media` (`box-shape`, `video-behaviour`, `overlay`),
replacing native border/aspect-ratio and the old hand-rolled sizing/playback
panels. This is an `intent_capture`, not a before/after diff: the three atoms
never rendered on this block before, so there is no meaningful "before" state
for the new border/overlay paint, and the "before" for playback tiering is a
*narrower* capability (flat non-tiered toggles), not a different visual state
to diff against.

**Assertions, stated before measuring:**

1. Setting `borderWidth`/`borderStyle`/`borderColour`/`borderRadius` (+
   `borderRadiusTablet`) on an image via `box-shape` paints a real border and
   radius on the `<img>`, tiering correctly at the tablet breakpoint.
2. Setting `overlayColour`/`overlayOpacity` via `overlay` paints a semi-
   transparent tint over the media, and the figure wrapper carries the new
   `sgs-media-box` marker class.
3. `videoAutoplay`/`videoAutoplayTablet` (set to `true`/`false` respectively)
   resolve correctly per-tier at render — desktop autoplay HTML attribute
   present, and a `data-autoplay-tablet="0"` override attribute present for
   `view.js`'s tablet runtime swap.
4. All three atoms' controls actually render as usable inspector UI ("Box &
   Border", "Playback", "Overlay" panels), not just correct storage — a
   client-usability check, not only a render check.

## Method

Live canary (`sandybrown-nightingale-600381.hostingersite.com`), REST-authored
probe page 3152 (deleted after capture — a temporary verification page, not a
standing fixture) with two `sgs/media` blocks: one image with
`borderWidth:{top:4,right:4,bottom:4,left:4}`, `borderStyle:"solid"`,
`borderColour:"#ff0000"`, `borderRadius:{...:30}`,
`borderRadiusTablet:{...:10}`, `overlayColour:"#0000ff"`, `overlayOpacity:50`;
one video with `videoAutoplay:true`, `videoAutoplayTablet:false`. Playwright:
navigate, `getComputedStyle()` on the painted `<img>`/`<video>` element and on
the wrapper's `::after`, resize to 800px for the tablet tier, then log into
`wp-admin` and open the block editor to confirm the inspector panels render.

## Result — assertion 1 (border/radius)

First pass caught a real defect (not this session's regression — a pre-
existing bug in `box-shape.js`/`box-shape.php`'s border shorthand builders,
first exercised live by this wiring): `--sgs-media-border-width`/
`-border-radius` were emitted UNITLESS (`"4 4 4 4"`, `"30 30 30 30"`), which
is invalid CSS — the browser discarded the whole declaration and fell back to
`border-width: medium` (~3px) / `border-radius: 0`.

| | before fix | after fix |
|---|---|---|
| computed `border-width` | `3px` (default fallback) | **`4px`** |
| computed `border-top-left-radius` | `0px` | **`30px`** |
| computed `border-color` | `rgb(255, 0, 0)` (unaffected) | `rgb(255, 0, 0)` |

Fixed by appending `px` to a bare number in both the JS (`toLengthValue()`)
and PHP (`sgs_media_atom_box_shape_to_length_value()`) shorthand builders —
`test-media-atom-parity.mjs` re-run clean after the fix (JS/PHP still agree).

**Tablet tier, resized to 800px:** computed `border-top-left-radius` = **`10px`**
(the authored `borderRadiusTablet` value), confirmed via the atom's own
mobile-first fallback chain in `box-shape.css`.

## Result — assertion 2 (overlay)

Figure wrapper carries `sgs-media-box` (confirmed via `outerHTML`:
`class="sgs-media sgs-media--align-left sgs-media-0445543c sgs-media-box
wp-block-sgs-media"`). `::after` computed styles:

| property | value |
|---|---|
| `background-color` | `rgb(0, 0, 255)` |
| `opacity` | `0.5` |
| `position` | `absolute` |

Matches the authored `overlayColour`/`overlayOpacity` exactly.

## Result — assertion 3 (video-behaviour tiering)

Desktop `<video>` element: `autoplay=true`, `muted=true`, `playsInline=true`
(the Autoplay->Muted/PlaysInline lock fired, matching
`sgs_media_atom_video_behaviour_requires()`'s server-side coupling). Tablet
override attribute present: `data-autoplay-tablet="0"` — proves the tiered
value (`videoAutoplayTablet:false`, differing from the resolved desktop
value) reached `sgs_media_tier_data_attrs()`'s "only emit when it differs"
gate correctly.

## Result — assertion 4 (editor UI, not just storage)

Logged into `wp-admin`, opened the block editor for the probe page, selected
each block, confirmed via accessibility-tree snapshot:

- **"Box & Border" panel** (image block): Box shape radio group (Auto/Fixed
  height/Aspect ratio), Height field (correctly `disabled` with reason "Not
  used — the box shape is set by the ratio, not a fixed height" while in
  `auto` mode), Ratio dropdown (correctly disabled, inverse reason), Shape
  dropdown, and a Border row (width+unit spinner, radius slider, colour
  swatch) — all real, interactive controls.
- **"Playback" panel** (video block, video-only per the `mediaType` gate):
  all 6 boolean bases (Autoplay/Muted/Plays inline/Loop/Show controls/
  Lazy-load) render as `BooleanResponsiveControl`s. On the Desktop tier,
  Muted and Plays inline show as `checked` + `disabled`, with the help text
  "Locked on while Autoplay is on…" — the lock is visible and explained, not
  just silently enforced. Switching to the Tablet tier surfaces the 3-way
  Inherit/On/Off radiogroup per control, with "Inherit (Desktop: On)" /
  "Off" states correctly reflecting the authored desktop/tablet values.
- **"Overlay" panel** (video block, no overlay colour set on this instance):
  colour picker present, Opacity/Blend-mode both correctly `disabled` with
  the reason "Opacity and blend mode only apply once an overlay colour or
  gradient is set" — the `requires` gate visible in the UI, not just enforced
  silently at render.

## Minor finding, not fixed this session (named, not silently dropped)

On the Tablet/Mobile tier, the Muted/Plays-inline `ToggleGroupControl`'s
`isDisabled` prop did not visibly mark the individual radio options as
`[disabled]` in the accessibility tree, even though the Desktop tier's plain
`ToggleControl` correctly showed `[disabled]`. This does not affect the
STORED/rendered result — `sgs_media_atom_video_behaviour_requires()` always
re-couples Muted/PlaysInline to Autoplay server-side regardless of what the
editor stored — so a client could theoretically store an inconsistent tablet
override in the editor, but the frontend never renders the unplayable
combination. Worth a follow-up UI polish, not a correctness defect.

## Not asserted

- The visual appearance/aesthetic of the border/overlay/radius values chosen
  for this probe — arbitrary values picked to prove the mechanism, not a
  design decision. Bean's eye (R-31-13) is not engaged by this report.
- Naked-mode removal for images that declare no overlay value: `overlay`
  being permanently declared in `sgs/media`'s atom list means
  `SGS_Media_Element::requires_box()` is now always `true`, so every image
  always gets a `<figure>` wrapper (naked `<img>`-as-root mode is now
  unreachable for this block). This is a deliberate architectural
  consequence of wiring a box-attaching atom (documented in
  `class-sgs-media-element.php`'s own docblock as the reason
  `requires_box()` exists), not a regression discovered by measurement — but
  it IS a real behaviour change from before this session, named here rather
  than silently accepted.
