# sgs/media — value-aware box-wrapper decision (naked-mode restored)

## Why before/after doesn't apply

The prior state ("always wraps in `<figure>` once `overlay` is declared") is not a
meaningful "before" to diff against — it was itself an unintended regression from an
earlier commit on this same branch, not a stable baseline worth preserving evidence of.
The real question is whether the CURRENT rendered output matches the intended contract:
naked `<img>` when no box atom actually produces CSS, `<figure>` wrapper only when one
does.

## Assertions (stated before measuring)

1. A plain `sgs/media` image block with no caption/link/tiers and **no overlay colour
   set** renders as a bare `<img>` (naked mode) — no `<figure>`, no `sgs-media-box`
   marker class.
2. The same block **with an overlay colour set** renders the `<figure>` wrapper, carries
   the `sgs-media-box` marker class, and the `--sgs-media-overlay-colour` custom property
   resolves to the set value (the overlay actually paints).
3. An existing `sgs/media` instance already live on the canary (no overlay set) is
   unaffected — still renders naked, zero console errors.

## Live result (measured against the sandybrown canary)

Probe page created via REST (`wp/v2/pages`, id 3154, deleted after capture) with two
`sgs/media` blocks — image id 3048, one with no `overlayColour`, one with
`"overlayColour":"#cc0000cc"`.

1. **No overlay:** rendered element is `<img class="sgs-media sgs-media--align-left
   sgs-media-XXXXXXXX wp-block-sgs-media sgs-media__img sgs-media-el" …>` — a bare `<img>`
   as the block root, no `<figure>`, `sgs-media-box` absent. **Matches assertion 1.**
2. **With overlay:** rendered element is `<figure class="sgs-media sgs-media--align-left
   sgs-media-1f1e486e sgs-media-box wp-block-sgs-media">`, `getComputedStyle(figure)
   .getPropertyValue('--sgs-media-overlay-colour')` returns `#cc0000cc`, and the
   screenshot shows the red overlay tint painted over the image (via
   `.sgs-media-box::after`). **Matches assertion 2.**
3. Homepage's existing `sgs/media` instance (`sgs-media-006599cd`, no overlay) still
   renders as `<img class="… sgs-media__img sgs-media-el">` with no wrapper.
   `browser_console_messages({level:'error'})` on both the probe page and the homepage
   returned 0 errors, 0 warnings. **Matches assertion 3.**

## Change description

`SGS_Media_Element::requires_box()`/`box_classes()` (`includes/class-sgs-media-element.php`)
changed from checking whether a box atom (`overlay`/`source`) appears in the block's
DECLARED atom list to computing whether that atom's PHP twin (`sgs_media_atom_<id>_css()`)
actually emits a non-empty CSS declaration for the current attribute values. Call site
updated in `src/blocks/media/render.php` to pass `$attributes`/prefix/slug. No change to
`before-after`, which never calls `requires_box()`/`box_classes()` (confirmed by grep —
only `::style()`).

Deployed to sandybrown at commit `b7e515b60` (payload-verify PASS: all 83 block.json
checksums matched).
