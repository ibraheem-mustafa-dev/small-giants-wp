# Visual-diff — sgs/media Wave 5a media-panel wiring — 2026-09-01

**Change:** New `src/components/media/MediaPanelLayout.js` assembles the media atom layer
into sgs/media's inspector — a Media Type switch (`media-type` atom), a Source section
(`source` + `meaning` + `svg-presentation`, self-gated by media type), and an Image
Styling section (`object-fit` + `focal-point` + `motion`). Widened `block.json`'s
`supports.sgs.mediaElements[0].atoms` and `render.php`'s CSS-emitting atom list to match.
Superseded hand-rolled equivalents (media-type ButtonGroup, Image panel Replace/Remove +
art-direction + decorative/alt, SVG content/animation dropdowns, Video source/URL/poster
workflow) removed from `edit.js` in the same change. `box-shape`, `video-behaviour` and
`overlay` deliberately NOT wired — see `block.json`'s `_comment_mediaElements` for the
three documented findings.

**Real bug found and fixed during this verification (not a pre-existing issue):**
`MediaTypeControl.js` and `MediaBoxShapeControls.js` imported `ToggleGroupControl`/
`ToggleGroupControlOption` directly from `@wordpress/components`. Live-verified via
`browser_evaluate` on the sandybrown canary that `window.wp.components.ToggleGroupControl`
is `undefined` on this WP core version — only the `__experimental`-prefixed names exist.
This produced React error #130 ("element type is invalid... got: undefined") and crashed
the block's editor entirely ("This block has encountered an error and cannot be
previewed") the moment the block was selected. Root-caused by bisection (reduced
`MediaPanelLayout.js` to only the `media-type` atom, confirmed the crash persisted,
then diffed against the codebase's own established pattern:
`src/components/primitives/index.js` already re-exports
`__experimentalToggleGroupControl as ToggleGroupControl` for exactly this reason, and
`hero/edit.js` imports from there rather than `@wordpress/components` directly). Fixed
both files to import from `'../../primitives'` instead. Confirmed fixed live — the block
selects and renders normally with zero console errors (bar an unrelated 404 for a
deliberately-fake placeholder image used in the probe).
