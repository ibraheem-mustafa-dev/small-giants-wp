## What changed

Phase 3 (golden-colour text-gradient rollout, finishing commit `778879732`). `submitColour`
gained a `submitColourGradient` sibling (new attribute, default `""`) so rule 31
(`missing-gradient`) stops flagging it. Render now resolves via
`sgs_resolve_text_colour_or_gradient( $submit_colour, $submit_colour_gradient )` →
`sgs_text_colour_decl()` (same helper trio `sgs/counter` uses), plus the mandatory
`sgs_text_colour_gradient_fallback_rule()` `@supports` companion, on the existing
`.uid .sgs-form__button--submit` scoped rule.

This block already had the groundwork for this exact addition: a 2026-09-03 comment
(D942 recipe item 2, render.php) explicitly says the `background-color:transparent`
cancellation "frees `submitColour` for a future `submitColourGradient` sibling" — this
session is that follow-up, not a fresh design.

**No `attrMap` entry added for `submitColourGradient`.** `submit-button`'s `attrMap` already
maps `css:background-image` → `submitBackgroundGradient`; JSON object keys are unique, so a
second attribute cannot claim the same key on the same element. This is documented on the new
attribute's `description` in block.json rather than silently omitted.

**Residual risk, disclosed, not silently shipped:** if an operator sets BOTH
`submitColourGradient` AND `submitBackground`/`submitBackgroundGradient` at the same time, both
ultimately want to write `background-image` on `.uid .sgs-form__button--submit`. The existing
`$sgs_form_submit_decls` array pushes the colour decl first and the background decl second, so
in that specific combination the background paint wins and the text-gradient clip is visually
inert (not broken/invisible — just superseded). This is the same combination the pre-existing
`background-color:transparent` cancellation was written to guard against for the common case
(colour-only, no background) — the code already handles that correctly; the both-set edge case is
a documented trade-off, not a defect, since no CSS mechanism lets one element paint two different
gradients on the same property simultaneously.

Editor canvas preview (`edit.js`, hand-built — this block has no `<ServerSideRender>` for the
submit button) updated to match: `submitButtonStyle` now spreads
`resolveTextColourPreviewStyle( submitColour, submitColourGradient, resolveColourToken-wrapped )`
before the background-colour override, so the gradient previews live in the editor exactly as
render.php will paint it on the frontend.
