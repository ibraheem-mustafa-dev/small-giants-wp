## Architectural correction, not a drop-in

All four attributes previously routed through a shared CSS custom-property indirection —
`Post_Grid_REST::card_vars_decls()` (in `includes/class-post-grid-rest.php`, NOT
`render.php`) fed `--sgs-pg-title-colour` / `--sgs-pg-excerpt-colour` / `--sgs-pg-meta-colour`
/ `--sgs-pg-readmore-colour` custom properties, consumed by `style.css` as
`color:var(--sgs-pg-title-colour, <fallback>)` etc. Same shape as nav-menu's
`submenuColour` (see that report): a `var(--x, …)` fed into a fixed `color:` declaration
cannot switch to `background-image` for a gradient — survey.js's
`paints-via-colour-valued-custom-property` refusal reason.

Fix, applied consistently across all four:

1. **`includes/class-post-grid-rest.php`** — removed `titleColour`/`excerptColour`/
   `metaColour`/`readMoreColour` from `card_vars_decls()`'s `$map` (the
   `categoryBadgeColour`/`categoryBadgeBgColour` entries are untouched — out of scope for
   this rollout, and the survey's `AUTOFIXABLE:helper-at-existing-selector`/`REFUSED` verdicts
   confirmed neither is a target row here).
2. **`src/blocks/post-grid/render.php`** — added a loop emitting direct
   `sgs_resolve_text_colour_or_gradient()` → `sgs_text_colour_decl()` declarations at each
   real selector above (scoped under `$root_sel`, so the same descendant-selector rule also
   styles cards injected later by `view.js`'s AJAX pagination), plus the mandatory
   `sgs_text_colour_gradient_fallback_rule()` call per attribute.
3. **`block.json`** — added `titleColourGradient`/`excerptColourGradient`/
   `metaColourGradient`/`readMoreColourGradient` (string, default `""`); added
   `"css:color-gradient"` attrMap entries to the `title`/`excerpt`/`meta`/`read-more`
   elements respectively.
4. **`edit.js`** — destructured all four gradient attrs (in both the `PreviewCard` component
   and the main `Edit` component, which independently destructure `attributes`); the four
   `SgsColourPanel` rows (`title`/`excerpt`/`meta`/`read-more`) gained `gradientCapable: true`
   + `gradientValue`/`onGradientChange`; `PreviewCard`'s hand-built live preview (this block
   has NO `ServerSideRender` — it uses `useEntityRecords` for a native React preview) now
   builds `titleStyle`/`excStyle`/`metaStyle`/`rmStyle` via
   `resolveTextColourPreviewStyle(flat, gradient, colourVar)` instead of a bare
   `{ color: colourVar(flat) }` ternary.
