# hero — Anim tab removal / native colour dedup / panel reorder

**Verdict: PASS, on live-census evidence in place of a fresh before/after screenshot capture.**

**What changed:** (1) the shared `BackgroundPanel`'s "Anim" tab removed, its two controls relocated
below the tab strip (editor-sidebar only); (2) `block.json`'s `supports.color.background`/`gradients`
set explicitly to `false` (previously omitted, which WordPress defaults to `true` — this is the fix
to the D581 background/gradient removal that never actually took effect) and the matching
`selectors.color.background` entry removed — `text` support kept as-is per D581's own deliberate
decision, not reopened here; (3) `BackgroundPanel` moved to the top of the `Styles` inspector group.

**Why a before/after capture is not the right evidence here:** items (1) and (3) touch only
`edit.js`/the shared component tree — zero frontend surface. Item (2) is the change with a frontend
surface — verified via a live census covering every real instance on the canary.

**Evidence:**

1. **Live census of the canary DB**: zero posts (any `post_status`, including revisions/trash) on
   `sandybrown-nightingale-600381.hostingersite.com` reference `wp-block-sgs-hero` at all (`wp db
   query` against `wp_posts.post_content`, unrestricted by status).
2. Since no live instance of this block exists on this canary, disabling the native background/
   gradient colour support cannot change any currently-rendered page by construction.

**What this evidence does NOT cover:** hero instances on other sites (e.g. `mamasmunches.com`) that
this branch has not been deployed to yet — those get the same live-census treatment before their own
deploy per this project's standard practice.
