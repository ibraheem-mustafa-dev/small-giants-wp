# sgs/gallery — `--sgs-item-aspect` / `--sgs-item-index` — VERIFIED LIVE ON A NEW CANARY INSTANCE

**Verdict: PASS.** A new canary page (`sgs-gate-canary-2`, page ID 2071) was built with a
`sgs/gallery` instance carrying 3 real media items (`mediaItems`, real attachment IDs on the
canary), a custom `aspectRatio:"4/3"` and a non-zero `staggerDelay:100`, so both changed
per-item custom properties emit. Captured live via Playwright at 1440px and 375px: no `style`
attribute on the item, correct computed values for both properties.

## What changed
`plugins/sgs-blocks/src/blocks/gallery/render.php` (inside the per-item loop):
```php
// Before
$item_style = '';
if ( $aspect_ratio ) {
    $item_style .= '--sgs-item-aspect:' . $sgs_css_ratio( $aspect_ratio ) . ';';
}
if ( $stagger_delay > 0 ) {
    $item_style .= '--sgs-item-index:' . $index . ';';
}
...
<figure class="sgs-gallery__item" style="<?php echo esc_attr( $item_style ); ?>">

// After
$item_style_decls = array();
if ( $aspect_ratio ) {
    $item_style_decls[] = '--sgs-item-aspect:' . $sgs_css_ratio( $aspect_ratio );
}
if ( $stagger_delay > 0 ) {
    $item_style_decls[] = '--sgs-item-index:' . absint( $index );
}
if ( ! empty( $item_style_decls ) ) {
    $gallery_responsive_css .= $root_sel . ' .sgs-gallery__item:nth-child(' . ( absint( $index ) + 1 ) . '){' . implode( ';', $item_style_decls ) . ';}';
}
...
<figure class="sgs-gallery__item">
```
Note the pre-fix code also had a documented secondary defect: when NEITHER
`aspect_ratio` nor `stagger_delay` was set, it still printed a bare `style=""` attribute —
itself an FR-32-1 breach independent of the custom-property question. The fix removes the
`style` attribute from the item tag entirely.

## Canary instance

## Evidence
- **Element found live:** 3 `.sgs-gallery__item` figures render (real images, not the empty
  state) at both viewports.
- **No-inline contract holds:** `element.getAttribute('style')` === `null` on item 1 at both
  1440px and 375px.
- **Computed values correct:**
  `getComputedStyle(el).getPropertyValue('--sgs-item-aspect')` === `"4/3"` and
  `getComputedStyle(el).getPropertyValue('--sgs-item-index')` === `"0"` (item 1, zero-based) —
  both at both viewports.
- **CSS lands in the LIFTED stylesheet, not inline `<style>` on the page** — fetched
  `wp-content/uploads/sgs-css/sgs-1003-175717f0a7396f78658cc3d7873ff1fd.css` and confirmed:
  ```css
  .sgs-gallery-a4f4679d.wp-block-sgs-gallery .sgs-gallery__item:nth-child(1){--sgs-item-aspect:4/3;--sgs-item-index:0;}
  ```
  (both properties land in the SAME `:nth-child(N)` rule, matching the `$item_style_decls`
  array being imploded together per item, as the source diff shows.)
