# sgs/cart — focus indicator joins the shared token family

## What changed

`.sgs-cart__trigger:focus-visible` read `var(--wp--preset--color--primary)` directly — the only
focusable element on the page belonging to **no** focus-token family at all. It now reads the shared
`--sgs-focus-color` / `--sgs-focus-glow` family like everything else, with the same accent glow.

The `outline-offset: 4px` is deliberate and unchanged — the trigger is an icon with its own padding,
so a tighter ring sits on top of the glyph.

## Live verification (measured, not inferred)

| | Before | After |
|---|---|---|
| Outline colour | `#e68a95` (`primary`, the mid-tone) | **`#c56a7a`** (`--sgs-focus-color` → `primary-dark`) |
| Glow | present | present, unchanged |
| Offset | 4px | 4px (unchanged, deliberate) |

Measured via `getComputedStyle` on the focused element on the live canary. `#c56a7a` is Mama's own
`primary-dark` token, so the ring now follows the client palette rather than diverging from it.

**Contrast is deliberately NOT the gate here.** Bean ruled 2026-08-02 that the focus ring is a
default that must be *accurate to the site's global colours*, and that a focus indicator is not text
— his bar is clear discernability (~2:1), not the 3:1 text-adjacent figure. The change is validated
on palette accuracy, which is the stated requirement. (It also happens to move the ring from 2.25:1
to 3.32:1, but that is a side effect, not the acceptance criterion.)
