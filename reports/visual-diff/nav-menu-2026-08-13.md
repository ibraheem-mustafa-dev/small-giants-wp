## A real bug found and fixed during this verification pass

A **synthetic** JS-dispatched click on the drill-down Back button passed on the first deploy, but a
**genuine Playwright pointer click failed** ("`<div class="sgs-nav-drawer__body">` intercepts
pointer events"; the Back button measured at `left: -279px`, off-screen). Root cause: the CSS rule
sliding the top-level list away (`transform: translateX(-100%)` on every top-level `<li>`) also
matched the `<li>` containing the currently OPEN accordion — and `transform` on an element creates
a NEW containing block for `position: absolute` descendants (CSS Transforms spec), so the submenu
panel (meant to be positioned against `.sgs-nav-menu__bar`) was dragged off-screen along with its
now-transformed parent `<li>`. Fixed in `nav-menu/style.css` by excluding the active item from the
slide-out rule: `> .sgs-nav-menu__item:not(:has(.sgs-nav-menu__accordion[open]))`. This is exactly
the case the "measurement vs eye" rule exists for: `getComputedStyle()` on the submenu element
ALONE reported the correct `translateX(0)` throughout the whole investigation — the defect was only
observable via a real pointer hit-test, never via a property readout.

## Anti-vacuity

Both canary pages render real, non-empty menu content driven by an independently-confirmed
non-empty classic menu (`wp menu item list`). The interaction was driven end-to-end (open → expand
→ real child-link click / real Back-button click → dialog cancel) rather than asserting a single
attribute in isolation.

## Residual, declared gap

A mega-menu item inside the drawer degrades to a plain link rather than rendering its panel inline
(FR-36-5's "the same panel renders inside the drawer" mega-in-drawer capability). Not exercised by
this verification pass (the T1 Dropdown Test menu carries no mega items); documented in this
block's own `render_items_drawer()` docblock and in Spec 36 FR-36-6.
