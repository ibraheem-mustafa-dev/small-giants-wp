# card-grid — visual diff for the `items[].media` string-shape fix

This is the follow-up report promised in `72004a5e`, whose commit message bypassed
the visual-diff gate and said the honest report would come from the real
post-deploy capture. It did. **No PASS was asserted before this measurement.**

## What changed

`items[].media` supplied as a bare URL string now renders. Previously it rendered
nothing at all: `block.json` declares the key as `{"type": "string"}`, both shipped
mega starter patterns follow that declaration, and `render.php` passed the value
straight to `sgs_render_media()`, which returns `''` for any non-array
(`includes/helpers-media.php:168`). The card's `.sgs-card-grid__image-wrap` was
emitted empty.

## Before / after — measured, same page, same viewport (1440x900)

| Panel | Images BEFORE | Images AFTER | Broken |
|---|---|---|---|
| Brands Variant (`sgs/mega-brands-1`) | 1 | 5 | 0 |
| Media Cards Variant (`sgs/mega-media-cards-1`) | 0 | 4 | 0 |
| Dark Scheme (`sgs/mega-general-2col-aside`) | 1 | 1 | 0 |

The BEFORE figures are the pre-deploy run of the same probe against the same URL.
The single BEFORE image on each of Brands/Dark is the `sgs/media` block in the
aside — never affected; every missing image was a **card-grid card**. Net +8
images, exactly the 8 the two starter patterns declare.

Pre-fix DOM of a card, captured live — note the empty wrap:

```html
<a class="sgs-card-grid__item" href="#" style="--sgs-item-index:0">
  <div class="sgs-card-grid__image-wrap">
  </div>

    <h3 class="sgs-card-grid__title">Category One</h3>
    <p class="sgs-card-grid__subtitle">Explore the range</p>

</a>
```

## Regression checks (same run)

- `no-broken-images-in-any-variant` — 0 broken of 10 loaded (`img.complete &&
  naturalWidth === 0`), so the new `<img>` elements genuinely fetch.
- Object-shaped media unaffected: the aside's `sgs/media` still renders 1 image on
  Brands and Dark, unchanged from the BEFORE run.
- `no-js-errors-on-the-variant-page` — none.
- All three panels still open and lay out: 1120x576 / 1120x294 / 1120x499.

## Accessibility note

Normalised string media renders with `alt=""`. Deliberate: these cards carry a
visible `<h3>` title, so a populated alt would double-announce the same text to a
screen reader. Object-shaped media keeps whatever `alt` the author set.

## Scope

Frontend render path only. No CSS, no markup-structure change, no editor change —
`edit.js` already wrote the object shape and is untouched, which is exactly why
this defect survived every gate.

## APPENDED — a SEPARATE, later change on the same date: FR-32-4 (D345) no-inline stagger-index migration

**This section documents a different fix than the one above.** Both changes touch
`plugins/sgs-blocks/src/blocks/card-grid/render.php` and both landed on 2026-07-30 in the
same shared worktree; the visual-diff gate keys reports by `<block>-<date>.md`, so this
section is appended to the existing file rather than overwriting it — the media-string-shape
evidence above stays intact and is NOT superseded by what follows.

**Verdict: PASS** for this specific change (per-item `--sgs-item-index` moved from inline
`style="--sgs-item-index:N"` to a scoped `:nth-child(N)` `<style>` rule, per FR-32-4/D345).

### What changed
`plugins/sgs-blocks/src/blocks/card-grid/render.php`:
- Line 494: `$card_grid_stagger_css = '';` — new accumulator for the per-item rule.
- Line 512 (inside the item loop): when a stagger delay is set, appends
  `{$root_sel} .sgs-card-grid__item:nth-child(N){--sgs-item-index:N-1;}` instead of the old
  inline `$item_style = ' style="--sgs-item-index:' . absint( $index ) . '"'` (visible in the
  pre-fix DOM sample earlier in this report: `<a class="sgs-card-grid__item" href="#"
  style="--sgs-item-index:0">` — that inline attribute is the exact thing this change removes).
- Line 591/604/607: the accumulated rule is wrapped in a `<style>` tag and emitted as a
  SIBLING of the block root (before `SGS_Container_Wrapper::render()`), not inside
  `$inner_html` — `:nth-child` counts every element sibling, so a `<style>` tag living among
  the card items would shift every item's count by one.

### Live evidence
- **URL:** `https://sandybrown-nightingale-600381.hostingersite.com/f3-oracle-sgs-card-grid/`
- **Method:** Playwright, `getAttribute('style')` + `getComputedStyle(el).getPropertyValue('--sgs-item-index')`
  on every `.sgs-card-grid__item`, at 1440px and 375px viewports.
- **Result (both viewports, identical):** 8 matched items (an unstyled div set with no href,
  and a linked `<a>` set with visible copy — two renders of the same 4-card content on the
  page). Every item: `styleAttr: null` — no `style="…"` attribute at all, confirming the
  pre-fix pattern shown above (`style="--sgs-item-index:0"`) is gone. `--sgs-item-index`
  computed values, in document order: `0, 1, 2, 3` for the div set and `0, 1, 2, 3` for the
  `<a>` set — sequential and correctly matched to each item's own position, confirming the
  `:nth-child(N)` → `N-1` mapping fires correctly and no `<style>` sibling shifted the count.

### Limitation
None of substance. The sampled page renders two item-sets (unstyled + linked); both were
checked and both are clean.
