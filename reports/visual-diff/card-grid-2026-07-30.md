# card-grid — visual diff for the `items[].media` string-shape fix

This is the follow-up report promised in `72004a5e`, whose commit message bypassed
the visual-diff gate and said the honest report would come from the real
post-deploy capture. It did. **No PASS was asserted before this measurement.**

## What changed

`items[].media` supplied as a bare URL string now renders. Previously it rendered
nothing at all: `block.json` declares the key as `{"type": "string"}`, both shipped
mega starter patterns follow that declaration, and `render.php` passed the value
straight to `sgs_render_media()`, which returns `''` for any non-array
(`includes/helpers-media.php:168`). The card's `.sgs-card-grid__image-wrap` was
emitted empty.

## Before / after — measured, same page, same viewport (1440x900)

| Panel | Images BEFORE | Images AFTER | Broken |
|---|---|---|---|
| Brands Variant (`sgs/mega-brands-1`) | 1 | 5 | 0 |
| Media Cards Variant (`sgs/mega-media-cards-1`) | 0 | 4 | 0 |
| Dark Scheme (`sgs/mega-general-2col-aside`) | 1 | 1 | 0 |

The BEFORE figures are the pre-deploy run of the same probe against the same URL.
The single BEFORE image on each of Brands/Dark is the `sgs/media` block in the
aside — never affected; every missing image was a **card-grid card**. Net +8
images, exactly the 8 the two starter patterns declare.

## Regression checks (same run)

- `no-broken-images-in-any-variant` — 0 broken of 10 loaded (`img.complete &&
  naturalWidth === 0`), so the new `<img>` elements genuinely fetch.
- Object-shaped media unaffected: the aside's `sgs/media` still renders 1 image on
  Brands and Dark, unchanged from the BEFORE run.
- `no-js-errors-on-the-variant-page` — none.
- All three panels still open and lay out: 1120x576 / 1120x294 / 1120x499.

## Accessibility note

Normalised string media renders with `alt=""`. Deliberate: these cards carry a
visible `<h3>` title, so a populated alt would double-announce the same text to a
screen reader. Object-shaped media keeps whatever `alt` the author set.

## Scope

Frontend render path only. No CSS, no markup-structure change, no editor change —
`edit.js` already wrote the object shape and is untouched, which is exactly why
this defect survived every gate.
