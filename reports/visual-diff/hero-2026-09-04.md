## Original finding (historical — the block this note describes is now deleted)

`render.php:905-906` (unchanged by the textAlign migration itself) read a bare
`$attributes['textAlign']` expecting a flat scalar (`'left'|'center'|'right'`) to paint
`.sgs-hero__headline` directly. This attribute name was never declared bare in block.json
before the migration, so this line had always been dead (isset() false). After the
migration `isset()` returned true (the object exists), but `in_array($object, [...strings],
true)` still evaluated false (strict type mismatch) — so it remained a silent no-op, never a
live defect at any point. No editor control ever wrote to it (confirmed via git history), so
removing it drops no client-facing capability.
