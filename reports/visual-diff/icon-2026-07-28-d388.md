## Finding: "Open in new tab" toggle is missing (structural bug, affects all 6 blocks under test)

`SgsLinkControl.js` passes a custom `settings` prop (`REL_SETTINGS = [nofollow, sponsored]`) to WP core's `LinkControl`. WordPress's `LinkControl` `settings` prop **replaces** its own default settings array — which is where the "Open in new tab" toggle normally lives — rather than appending to it. The component's own docstring claims it provides "an open-in-new-tab toggle", and it silently accepts/stores `opensInNewTab` in its value object, but **the UI control to set it does not render anywhere**.

Confirmed via DOM text search on the full page: zero occurrences of "new tab" in the rendered inspector (`document.body.innerText.includes('new tab')` → `false`). Only "Mark as nofollow" / "Mark as sponsored" checkboxes appear under "Advanced".

This means: **the "toggle new-tab" checklist item could not be exercised for any of the 6 blocks** — not because of tester error, but because the control does not exist in the shipped UI. Operators have no way to make a link open in a new tab through any of these 6 blocks' Link panels.

Not fixed as part of this verification dispatch (QA/report task only, per instructions) — flagging for a follow-up fix in `plugins/sgs-blocks/src/components/SgsLinkControl.js` (pass a `settings` array that includes the `opensInNewTab` entry, e.g. `[{ id: 'opensInNewTab', title: __('Open in new tab') }, ...REL_SETTINGS]`).
