## What changed

`splitImageTablet` was declared in `block.json` and read by **nothing** — no render, no
control. `splitImageMobile` rendered but also had **no editor control**. So the tablet tier did
not exist, and neither tier could be set by a client: only the cloning pipeline could write
them. The `--desktop` marker also moved OUT of the mobile arm — it used to be written only when
a MOBILE image existed, so a tablet-only hero would have emitted tier CSS targeting a class
that was never written, and both images would have shown at once.

## First paint (no JS, no browser)

Plain HTTP fetch — no browser, so JS cannot be a factor. All three tier classes present in the

## Anti-vacuity

Attributes were read back out of the editor after saving. WordPress silently discards any attr
a `block.json` does not declare (D338), so surviving that round-trip proves the declaration is
live on the deployed build — otherwise the capture would have measured a hero with no tiers set.
