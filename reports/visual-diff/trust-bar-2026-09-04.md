## What changed

Spec 35 Part 4, third of four target blocks. `image-badge` variant only gets a per-item
`objectFit` control (Cover/Contain) — no focal-point/crosshair, matching the established
convention that logo-shaped content (badges, certification marks) never gets a crop, only a fit
choice (same rule as `sgs/testimonial`'s `orgLogo` and this project's own `logoFit` precedent).
`icon-circle` and `text-only` variants are untouched — the feature is meaningless for them.
Per-item CSS is keyed by a new `data-badge-key` attribute, reusing `sgs_media_position_css()`.

## A real regression caught and fixed before deploy

The build introduced a genuine `check-editor-render-parity.js` finding (ceiling 211 → 212):
switching the editor-canvas preview from reading the block-wide `badgeImageObjectFit` default to
`item.objectFit` dropped the only in-file reference to `badgeImageObjectFit`. Fixed by falling
back to it (`item.objectFit || badgeImageObjectFit`) rather than a hardcoded literal — this also
makes the canvas preview correctly reflect what render.php actually does for an item with no
per-item override. Verified: ceiling back to 211/211 after the fix, confirmed against the
pre-change file via a non-destructive swap-and-diff (not assumed).
