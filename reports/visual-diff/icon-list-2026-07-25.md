# sgs/icon-list — render declared `supports.typography.textAlign` (attr-gated)

**Verdict: PASS.** Makes the block honour a support it already declared but never rendered.
The added frontend rule is **gated on `textAlign` being set**, so existing instances (no
`textAlign` value) render byte-identically. `first_paint_capture_passed: true`.

## What changed (frontend render.php, attr-gated)
`src/blocks/icon-list/render.php` now reads `$attributes['textAlign']`, validates it
∈ {left, center, right}, and emits a scoped `{$text_sel}{text-align:VALUE;}` rule **only when
non-empty** (alongside the existing colour/typography scoped rules on `.sgs-icon-list__text`).
Unset/invalid → no rule emitted (prior behaviour).

## Why (root cause)
Declared `supports.typography.textAlign:true` + `__experimentalSkipSerialization`, so WP never
auto-applied it and render.php never read it — a dead editor control, and a clone gap for the
converter's root-text-align fold. Rendering the attr closes both.

## Evidence
- **Existing instances unchanged**: guarded `if ('' !== $text_align)`; unset → identical first paint.
- Converter suite green (1034 pass); `audit-inline-styling --check` 0 violations.
