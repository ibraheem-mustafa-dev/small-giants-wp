## Fix 1 — dropdown + mega panels had no block-axis bound

`.sgs-nav-menu__submenu-wrap` and `.sgs-nav-menu__mega-panel-wrap` are emitted as uid-scoped CSS
in `plugins/sgs-blocks/src/blocks/nav-menu/render.php` (NOT in `style.css` — the original council
finding pointed at the wrong file; the defect was real, the location was not). Both were
`position:absolute; top:100%` with no `max-height` and no `overflow`.

Verified absent before: `grep -c "max-height"` returned 0 for both `render.php` and `style.css`,
with a positive control of 1 in `mega-panel/style.css` proving the search would have found it.

Consequence: a long panel rendered past the viewport bottom with nothing to scroll, on a surface
that closes on pointer-leave. The links were simply unreachable.

**After, measured live on the canary:**

| | Value |
|---|---|
| `max-height` | `741px` (was `none`) |
| `overflow-y` | `auto` (was `visible`) |
| `overscroll-behavior` | `contain` |

741px reconciles: `calc(100dvh - var(--sgs-header-height, 80px) - 16px)` against the live inner
height. The header term uses the theme's own published variable; `overscroll-behavior: contain`
stops a scroll reaching the panel's end from chaining to the page behind it, matching what the
drawer already does.

## Fix 2 — drawer labels could not wrap

The drawer reuses `.sgs-nav-menu__link`, which carries `white-space: nowrap`. That is correct for
the HORIZONTAL bar (which is `flex-wrap: wrap`, so a long label keeps its item intact and the ITEM
moves to a second row) and wrong for the drawer's VERTICAL stacked list, which has no second row
to move to — the label could only push sideways.

**Before, measured live at 375px** with one ordinary label ("Frequently Asked Questions About
Delivery And Returns"): drawer `scrollWidth` **460** against `clientWidth` **360** — 100px of menu
outside its own box, painted over the page behind it, reachable only via a horizontal scrollbar
the drawer should not have. In drill-down mode the bar is `overflow: hidden`, so the same label is
CLIPPED with no scrollbar at all.
Capture: `drawer-long-label-375.png`.

**After, same label, same viewport:**

| | Before | After |
|---|---|---|
| `white-space` | `nowrap` | `normal` |
| `overflow-wrap` | (unset) | `break-word` |
| Drawer horizontal overflow | **100px** | **0px** |
| Link height | 44px | 67px (wrapped to two lines) |

Capture: `drawer-long-label-AFTER-375.png` — label wraps to two lines inside the drawer, and the
horizontal scrollbar present in the before-shot is gone.

Specificity is deliberate: the override is `:where(.sgs-nav-menu__bar--drawer) .sgs-nav-menu__link`,
which keeps it at 0,1,0 — identical to the base rule, so it wins on source order alone and never
competes with the operator's `itemTextWrap` control, which `render.php` emits at 0,2,0.
