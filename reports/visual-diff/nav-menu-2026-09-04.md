## What changed

Phase 3 of the golden-colour staged rollout. Wires gradient siblings onto two of
`sgs/nav-menu`'s text-colour attributes — `burgerColour` (burger-icon colour) and
`submenuColour` (dropdown link colour) — so both rows stop being flagged by inspector
rule 31 (`missing-gradient`).

### burgerColour → burgerColourGradient

- `block.json` — added `burgerColourGradient` (string, default `""`); added
  `"css:color-gradient": "burgerColourGradient"` to the `burger` element's `attrMap`.
- `render.php` — replaced the bare `sgs_colour_value( $burger_colour )` call with
  `sgs_resolve_text_colour_or_gradient()` → `sgs_text_colour_decl()` on the existing
  `.{uid} .sgs-nav-menu__burger` selector, plus the mandatory
  `sgs_text_colour_gradient_fallback_rule()` call.
- `edit.js` — destructured `burgerColourGradient`; the `burger-icon` row gained
  `gradientCapable: true` + `gradientValue`/`onGradientChange`. No hand-built canvas preview
  to update — this block uses `ServerSideRender`, so the render.php change alone covers the
  editor canvas.

**Known edge case (flagged, not fixed here):** `.sgs-nav-menu__burger` also receives
`background-color` from the separate `burgerBg` attribute, on a different rule block but the
SAME selector. Setting both `burgerColourGradient` and `burgerBg` will clip the burger
button's own background fill to the glyph shapes (`background-clip:text` clips the whole
element's background, not just the text). Same class of interaction as the modal trigger
(see that report); real but only reachable when an operator sets both at once.

### submenuColour → submenuColourGradient

- `block.json` — added `submenuColourGradient` (string, default `""`); added
  `"css:color-gradient": "submenuColourGradient"` to the `sublink` element's `attrMap`.
- `render.php` — **architectural correction, not a drop-in.** `submenuColour` previously
  routed through a CSS custom-property indirection (`--sgs-nm-submenu-colour`, set in the
  `$sgs_nm_submenu_vars` foreach loop, consumed as `color:var(--sgs-nm-submenu-colour)` on
  `.sgs-nav-menu__sublink`). A `var(--x, …)` fed into a fixed `color:` declaration cannot
  switch to `background-image` for a gradient — this is exactly survey.js's
  `paints-via-colour-valued-custom-property` refusal reason, and 19 of 24 rows in the prior
  Task 2 pass were refused for precisely this shape. Removed `submenuColour` from the
  custom-property map entirely and replaced the consuming rule with a direct
  `sgs_resolve_text_colour_or_gradient()` → `sgs_text_colour_decl()` emission plus the
  mandatory fallback rule, at the same `.{uid} .sgs-nav-menu__sublink` selector. Confirmed
  safe: `.sgs-nav-menu__sublink` carries no background of its own (the submenu panel's
  background lives on the ANCESTOR `.sgs-nav-menu__submenu-wrap` via the separate
  `submenuBg`/`--sgs-nm-submenu-bg` custom property, a different element).
- `edit.js` — destructured `submenuColourGradient`; the `submenu-text` row gained
  `gradientCapable: true` + `gradientValue`/`onGradientChange`. `ServerSideRender` covers
  the canvas.
