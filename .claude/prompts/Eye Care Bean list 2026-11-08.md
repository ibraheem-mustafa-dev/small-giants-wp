Then check `sgs_mega_menu` 186 `cr-ref-mega-help-21` (`colourText:"success"`) stays green with a green sweep.

Form buttons never read the site's button preset lift (`--wp--custom--button-presets--default--hover-lift`, which every `sgs/button` takes); they lift only with their own `submitLiftHover`. Fix (written and reverted 2026-11-08, not committed): `form/style.css` `.sgs-form__button:not(:disabled):hover{transform:var(--sgs-form-btn-lift, var(--wp--custom--button-presets--default--hover-lift,))}` plus `transform` in its transition and a reduced-motion reset; `helpers-form-submit-motion.php::sgs_form_submit_motion_css` prints `--sgs-form-btn-lift:none` when the button has its own lift and adds `transform .2s` to its transition. It failed two build gates, both still to do: `check-wiring-fingerprint` L7 (the editor canvas must set the same lift: the form's editor preview, `submit-motion-preview.js`) and `check-state-exhaustiveness` (register the new `:hover` selector). Fix: replay a short opacity and scale entrance on the main photo when `imageSrc` changes, skipped under reduced motion, as a buybox setting any client can switch on.
- **2 (accordion icon close spin and bounce):** both accordions' `turning-icon` layer is a state entrance (expanded, rotate 45, `easing.default`) with no `close` block, so `extensions/motion/canvas/trigger-rules.js::stateRule` emits no close animation (it snaps back in about 90ms); `easing.default` has no overshoot. Fix: on the `turning-icon` layer of the Help accordion (page 171) and the product FAQ, set easing `token:easing.spring` (or `spring-bouncy`) and add a `close` block (rotate back to 0, same duration, spring easing).
