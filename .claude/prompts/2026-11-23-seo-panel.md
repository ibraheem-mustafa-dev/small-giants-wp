Build an SEO panel into the SGS framework so a client site needs no SEO plugin. Today every live site runs Slim SEO only for what the framework lacks: a page's own search title, meta description and social image, and the sharing tags built from them. Bean wants that inside the framework, after the MIC event (2026-11-28), in one session.

Where things stand:
- The framework already prints structured data, canonicals, its sitemap rules and noindex rules, and steps aside when an SEO plugin is active: `plugins/sgs-blocks/includes/class-sgs-schema.php`, `class-org-website-schema.php` (it checks `SLIM_SEO_VER`), `class-product-canonical.php`, `class-product-sitemap.php`, `class-sitemap-exclusions.php`, `class-product-schema*.php`, `product-faq-schema.php`, `review-schema.php`. Spec 27 FR-27-E1 and its "Which SEO plugin states make SGS step aside (SEC-9)" paragraph say how the hand-off works today.
- How a live site sets up Slim SEO now: `.claude/dev-setup.md` (search "Slim SEO") and `.claude/specs/go-live-checklist.md` rows SR-1 to SR-5. Mama's live settings were written by `sites/mamas-munches-redesign/build/seo/` scripts.
- Read the project's `CLAUDE.md`, `plugins/sgs-blocks/CLAUDE.md` and the governing spec before building: every customisable value needs an inspector control, no inline styles, security baseline for anything stored or printed.

Done when:
- A page, post, product and product category each carry a search title, a meta description and a social image, set in the block editor's document panel, with sensible defaults (the page title and excerpt, the site's default image) and a site-wide default image and title pattern in a settings screen.
- The front end prints the title, description, canonical, Open Graph and Twitter tags once, never alongside an active SEO plugin's (reuse the step-aside rule), and the sitemap and noindex behaviour are unchanged.
- An importer copies Slim SEO's per-post values (post meta `slim_seo`: `title`, `description`, `facebook_image`, `twitter_image`) and its site defaults (option `slim_seo`) into the new fields, with a dry run that lists every value, so Mama's, Indus and Eye Care can switch with no loss. Proved on a scratch copy of a mirror (`scripts/local-wp/scratch-mirror.sh`): the head tags of every page byte-compared before (Slim SEO) and after (framework, Slim SEO deactivated).
- A new requirement in the governing spec with a Status line, and the go-live checklist's SR rows updated.

Boundaries: build and prove on scratch copies only; switching a live site (deactivating Slim SEO, running the importer) is a deploy step Bean approves per site, after a database backup (`bash scripts/local-wp/backup-remote-db.sh <target> <label>`).
