# Gate, reseed and patch tooling speed and safety

## Why

On 2026-11-03/04 three parallel client streams spent most of their wall time waiting: each framework batch needed a shared-DB reseed (about 10 minutes at the time; 331s now), a hand-run full gate tier (6 to 15 minutes, run one gate at a time), then a deploy that ran the same full tier again, and every session held the others' reseeds and deploys meanwhile. Two shipped faults (an editor crash on every form and checkbox block, then on every block holding a multi-button) passed every gate because no gate loads the block editor. A patch script accepted a setting the block does not declare, so a fix silently did nothing.

## Done

- Reseed timing (2026-11-04): `sgs-update-v2.py` prints a per-stage table after every run. A full run on a private copy of the framework DB (`--db`, nothing skipped) takes 331s: Stage 1 220s (66%), Stage 12 63s, Stage 14 43s, every other stage under 2s.
- Private-copy reseed (2026-11-04): every script the reseed runs asks `lib/framework_db.py::framework_db_path()` (JavaScript twin `lib/framework-db.js`) for its database; `check-framework-db-resolver.py` (a `fast` gate; 302 scripts in its closure, imports followed) fails one that builds the shared path by hand, and the `--db` guard skips only such a script, so a `--db` run skips none. The audit found 112 scripts that open the framework DB and 34 that honoured `$SGS_FRAMEWORK_DB`; 19 reseed children moved. Tripwire: the same full run with the home folder pointed at an empty folder created no database file there. Detail in `.claude/dev-setup.md` (Reseeding on a private copy).
- Identity proof (2026-11-04): `plugins/sgs-blocks/scripts/verify-reseed-identity.py` seeds two worktrees on two copies of one starting DB and compares every table (as multisets, ignoring time-of-writing columns and `schema_metadata.last_*`), the repository files each run changed (deletions included) and the Stage 12/13 finding lines. Same code on both sides: IDENTICAL. `--plant-difference` is the negative control and fails if it planted nothing; `--stage 12 --shared-readonly` proves the report-only stage on the shared DB without `--db` and reports inconclusive if the DB changed during the run.
- Upstream scrape cache (2026-11-04): Stage 2 skips the ten-source scrape when `schema_metadata.last_full_refresh_ts` is under 24 hours old and `wp_version_indexed` equals the requested version (`--refresh-upstream` or `--stage 2` forces it) and stamps a refresh only when a source succeeded. Old against new on a private copy: IDENTICAL; Stage 2 51s to 0s.
- Scanner pool (2026-11-04): Stage 12 runs `build-roster` first and alone, then the other 23 scanners six at a time (240s each), and parses serially in scanner order. Old against new on the shared DB, read-only: IDENTICAL repo files and finding lines; Stage 12 251s to 80s. Tests: `scripts/tests/test_stage_speedups.py`.
- Full tier once per commit (2026-11-04): `build-deploy.py --gate-only` builds and runs `gate:full` for HEAD in the isolated worktree and records the pass (it refuses `--skip-gate-full`, `--no-cache` and `--built-by-parent` and aborts unless a pass is on record); `deploy_cache.py` keys on the database the gates read. The second run of one commit took 14s, the first 742s. See `.claude/deploy-architecture.md` (Deploy cache).
- Patch script (2026-11-04): `scripts/local-wp/patch-block-attrs.php` refuses a `set` of an attribute the block type does not declare, in a dry run too; `scripts/local-wp/test-patch-block-attrs.py` passes 4 of 4, and extension attributes (`sgsCustomCss`, `sgsMotion`) are accepted.
- Editor-crash gate (2026-11-04): `plugins/sgs-blocks/scripts/editor-crash/check-editor-loads.mjs --site local-<mirror>` opens every page, post, template and template part of a local mirror in the block editor and fails on a crashed block, a console error or a content write; it also checks every named import from a runtime-provided `@wordpress/*` package against the live `wp.*` global, and each run proves its detector with a planted crash. `build-deploy.py --editor-check local-<mirror>` runs it after `gate:full` and aborts before upload (opt-in, Bean 2026-11-04). Negative control on `local-indus` (57 targets): with the flexDirection crash of `3b47804e6` reverted 21 pages failed with `c.indexOf is not a function`; on current code 56 pass. Its first real finding, a `stripHTML` import `@wordpress/dom` does not export, crashed `sgs/product-search` on `sgs-theme//archive-product` and is fixed by Mama's Track A, which owns it; `check-wp-package-exports.mjs` found it and no other of 887 checked imports.
- A cold review of the wave's 12 commits found fault in the first drafts of `--gate-only`, `deploy_cache.py`, the identity proof, Stage 2's stamp and the resolver gate; each verified finding is fixed and tested.
- Private-copy reseed, second half (2026-11-04): the last 33 live scripts ask `framework_db_path()` / `frameworkDbPath()` (an ES-module twin `scripts/computed-route/lib/framework-db.mjs` loads the CommonJS one), and `check-framework-db-resolver.py --check` now covers every live script under `plugins/sgs-blocks/scripts/` and `scripts/` (1440, 0 violations; dated migrations, tests and fixtures excluded) with a planted-violation self-test case. The Stage 13 CSV export of a `--db` run writes `<copy name> db data/` beside the copy.
- Stage 1 overlap (2026-11-04): Stage 1 prints its sub-step timings. The component-adoption scan starts at the top of Stage 1 and the content-role detectors run side by side. Old against new on two copies under the same load: Stage 1 328s to 230s, whole run 533s to 438s, identity proof IDENTICAL, planted difference caught; tests `scripts/tests/test_stage1_overlap.py`. - Locked publish step (2026-11-04, Bean chose compare-and-swap): `plugins/sgs-blocks/scripts/publish-framework-db.py` (`begin`, `publish`, `regenerate --restore-first`); a private copy replaces the shared DB only when the shared sha256 is unchanged, otherwise exit 3 and reseed again; tests `scripts/tests/test_publish_framework_db.py` (11, including conflict, corrupt copy, foreign copy, held and stale lock). - Stage 1 second round (2026-11-04): early content-role detectors handed to canonical assignment by file, a per-run memo of PHP scans (31.4s to 5.6s for the tier-evidence loop), and side-by-side block readers. Old against new on two copies under the same load: Stage 1 260s to 171s (whole run 473s to 439s), identity proof IDENTICAL, planted difference caught; tests `scripts/tests/test_stage1_early_detectors_and_memo.py`. Full-run time idle is still above the 180s target: Stage 12 (about 63s idle) and Stage 14 (about 43s idle) are now as large as Stage 1's remainder.

## Steps

Next levers, each behind `verify-reseed-identity.py`: time Stage 12 and Stage 14 on an idle machine and overlap them with the end of Stage 1 where they only read; reduce what canonical assignment does after the detectors. A cross-run cache of `BlockSource.read` was not built: a whole-tree hash hits only when no block changed.
2. **Locked publish step: built** (see Done). Stage 7's shared CSV write stays (Bean: he does not use that data).
3. **Register `check-wp-package-exports.mjs --check` in `scripts/gates.json`** (fast tier) when the fix to the `stripHTML` import in `src/utils/authored-text.js` is on main; until then it reports that one import and would turn every build red.

## Done when

A typical framework batch (1-5 blocks) reseeds in under 3 minutes with the identity proof green (331s idle on 2026-11-04; the overlap took 95s off a loaded side-by-side run; Stage 1 step 1 is the remaining lever), and sessions reseed without holding each other (private copies work completely; the locked publish step is step 2).
