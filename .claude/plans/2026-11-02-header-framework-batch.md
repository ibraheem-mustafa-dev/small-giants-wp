## Rules for every addition (council convergence)

1. **Tier shape and inheritance.** A per-breakpoint setting is a `{desktop, tablet, mobile}` object, default `{}` (no `default` key beyond `{}`). An empty tier inherits the tier above (`sgs_resolve_tier`). Emission is mobile-first through the shared tier emitter: the desktop value is the base rule, a tablet value applies `max-width:1023px`, a mobile value `max-width:767px`, so a desktop-only value covers every width exactly as the old scalar did.
2. **Saved old shapes are re-saved, never read back (FP-14, ruling B).** No scalar fallback in `render.php`. In the same commit as each type change: every saved tree in the repo holding the old shape is rewritten to the object (a detector greps every saved `sgs/nav-bar-menu` `justifyContent` and `sgs/cart` `showZero` / `iconSize` in `sites/*/build/trees`, `theme/sgs-theme/parts`, `theme/sgs-theme/patterns`, `plugins/sgs-blocks/tests` fixtures and `scripts/computed-route` tests and writers), then the live posts are rebuilt from their trees. The clone route follows the new type through the reseeded DB.
3. **Mixed-tier carts.** Every new pill or icon rule prints bare in a block with one trigger style, and inside each `render.php::$trigger_ranges['pill' | 'icon']` media range in a mixed block, exactly as the existing pill rules do. No new breakpoint set. A per-tier value (`iconSize`, `pillPadding`) is emitted per tier first, then wrapped in the matching style range.
4. **Editor canvas preview per addition.** Each value resolves for the previewed device through `resolveTier( value, previewTier )` in `cart/edit.js::CartEdit` and `cart/panel-preview-style.js::triggerStyles`, and in the nav's `edit.js`; `--sgs-focus-under` and the tap floor reach the canvas too.
5. **Controls.** Per-breakpoint settings use `ResponsiveControl` (with Inherit and reset), `ResponsiveLengthControl` for lengths, `BooleanResponsiveControl` for `showZero`; colours go in the existing `SgsColourPanel` rows; shadows use `ShadowControl` with `shadowAttrKeys()`; padding uses the shared box control with its presets and a `tierBoxLonghands` canvas twin. Pill-only and icon-only controls carry a one-line note saying where they apply. No duplicate controls.
6. **Gates named.** `audit-inline-styling.js --check`, `check-element-manifest-conformance.js`, `check-wiring-fingerprint.py`, `check-dead-controls.js`, `check-duplicate-controls.js`, `check-empty-inspector-containers.js`, `check-shadow-sources.py`, `check-shadow-fallback-php.py`, `check-custom-colour-survives.py`, `lint-responsive-controls.py`; reseed from HEAD, then `generate-attr-role-map.py`; all 204 build gates.
7. **Negative controls (named).** Before/after computed styles at 375, 768 and 1440 for: the Indus header (`sites/indus-foods/build/trees/sgs_header/header.json`), a default `sgs/cart` (icon), a uniform pill cart, a mixed cart with none of the new settings, and the theme's WooCommerce templates holding `sgs/cart`. Each must be unchanged; each new value must change exactly the one property it names.

## The seven additions

1. **`sgs/nav-bar-menu` `justifyContent` per breakpoint (R2-H1).** Object of the existing enum keys (`render.php::$sgs_nm_justify_allowed`), printed through `sgs_emit_tier_rules_map` with an empty fallback, so an unset tier keeps `style.css`'s `:where()` `space-between`. Control: the existing row in `SplitPanel.js` wrapped in `ResponsiveControl`, relabelled "Align items (per device)" with help "the menu button sits in this row below the collapse point". Re-saved: Indus `{desktop: "flex-start"}`, Mama's `{desktop: "center", tablet: "flex-start", mobile: "flex-start"}`. Negative control: the Indus header's computed `justify-content` and burger x at 375, 768 and 1440.
2. **`sgs/cart` icon-trigger background (R2-H4).** Attributes `iconBg`, `iconBgGradient`, `iconBgHover`, `iconBgHoverGradient` (the `pillBgColour*` naming), painted on `.sgs-cart__trigger` in icon tiers on the trigger's own `::after` layer (the pill's and badge's pattern, so a stroke gradient never meets `background-clip:text`), through `sgs_fill_states_css` and touch-guarded `sgs_hover_state_rules`. Manifest: `css:background-color`, `css:background-image` and a `hover` state on the `icon` element. Control: a Normal/Hover fill row in `SgsColourPanel`, note "icon button only".
3. **`sgs/cart` pill shadow (R2-H5, R2-H8).** `pillShadow`, `pillShadowColour`, `pillShadowHover`, `pillShadowColourHover` through `sgs_shadow_decls()` (the `sgs/button` pattern), pill tiers only per rule 3; `--sgs-focus-under` printed with it and only in pill tiers, so an icon tier's focus ring never reads the pill's shadow. `supports.sgs.shadowLift` stays `false`. Mama's Round 1 pill shadow Custom CSS is removed in the same edit that sets these, with a computed `box-shadow` check at 1440 (rest, hover, keyboard focus).
4. **`sgs/cart` `showZero` per breakpoint (R2-H7).** Object of booleans. `view.js` sets `sgs-cart__badge--visible` when the count is above 0 or any tier shows zero (it reads `data-show-zero-any`); `render.php` prints, per tier whose value is false, `@media (tier){.{uid}:not(.sgs-cart--has-items) .sgs-cart__badge{display:none}}` at a specificity above `.sgs-cart__badge--visible`. The server's first paint uses the same rule (SSR count 0). `hideWhenEmpty` stays a separate, untiered setting. Canvas: the preview counts as an empty cart and shows or hides the badge from the previewed tier (help text says so).
5. **`sgs/cart` `iconSize` per breakpoint (R2-H11).** Object of numbers, printed per tier as `--sgs-cart-icon-size`. The tap floor follows rule 11 per tier: `--sgs-cart-tap-min:0px` only in a tier that is an icon tier and has its own size; elsewhere the 44px floor stays. Updates `block.json`'s example value and the `iconSize` `_note`.
6. **`sgs/cart` pill padding and badge size (R2-H12).** `pillPadding`: a `boxFamilies` entry plus a `css:padding` member on the pill element, per tier through `sgs_box_object_longhands()`, pill tiers only; empty prints nothing, so the existing pill rules stay. Badge size: `badgeSize` (icon overlay badge, default 18px, `var(--sgs-cart-badge-size, 18px)`) and `pillBadgeSize` (pill count bubble, default 20px, `var(--sgs-cart-pill-badge-size, 20px)`), each a per-breakpoint length driving width, height, min-width and line-height; manifest `css:width`, `css:height` on the badge element.
7. **`sgs/cart` custom SVG icon (R2-H13).** The shared `IconPicker` already has a custom source with a live sanitiser; the cart passes `value={{ source: iconSource, name: iconName }}` and its `onChange` writes `iconSource`, `iconName` and `iconSvg` together (as `sgs/icon` stores them). Server: `wp_kses( $svg, sgs_svg_kses_allowed_tags() )`; an empty or rejected SVG falls back to the Lucide `iconName`. The stroke gradient maps a custom SVG onto the Lucide stroke path in `sgs_icon_gradient_css` (the sanitiser keeps `stroke="currentColor"`); the canvas `IconPreview` receives the source and SVG.
