## Rules for every addition

1. **Tier shape and inheritance.** A per-breakpoint setting is a `{desktop, tablet, mobile}` object, default `{}`. An empty tier inherits the tier above (`sgs_resolve_tier`). Emission is mobile-first: desktop is the base rule, tablet applies `max-width:1023px`, mobile `max-width:767px` (`SGS_Breakpoints`), so a desktop-only value covers every width exactly as the old scalar did. Container-aware where the block can sit in a narrow column: `sgs_emit_responsive_css` with `array( 'container' => true )`.
2. **Saved old shapes are re-saved, never read back (FP-14).** No scalar fallback in any `render.php`. In the same commit as each type change, every saved tree holding the old shape is rewritten by a detector: `sites/*/build/trees`, `sites/*/build` intake and skeleton JSON, `theme/sgs-theme/parts`, `theme/sgs-theme/patterns`, `plugins/sgs-blocks/tests` fixtures, `scripts/computed-route` tests and writers. Then live posts are rebuilt from their trees.
3. **Editor canvas preview per addition.** Each value resolves for the previewed device through `resolveTier( value, previewTier )` in the block's `edit.js` and `preview-style.js`; the canvas twin of every changed emitter changes in the same commit.
4. **Controls.** `ResponsiveControl` (with Inherit and reset) for per-breakpoint values, `ResponsiveLengthControl` for lengths, existing shared controls reused (`LinkUnderlineControl`, `TypographyControls`, `AngleAtom`). No duplicate controls.
5. **Gates named.** `node plugins/sgs-blocks/scripts/audit-inline-styling.js --check`, `check-element-manifest-conformance.js`, `check-wiring-fingerprint.py`, `check-dead-controls.js`, `check-duplicate-controls.js`, `check-empty-inspector-containers.js`, `lint-responsive-controls.py`, `find-scalar-tier-attrs.py --check`, `check-tier-storage-shape.py`, `check-tier-object-cast.py`, `run-motion-gates.py` for FW-A and FW-D; reseed from HEAD then `generate-attr-role-map.py`; all build gates. No gate is baselined to get green.
6. **Negative controls (named).** Before and after computed styles at 375, 768 and 1440 for each item's list below. Each must be unchanged; each new value must change exactly the one property it names. Positive control per item on local-mamas.
7. **Cite code by symbol.** No line numbers anywhere in commits or docs.

8. **Every new control has a reset** (the control's own reset or `ResponsiveControl`'s Inherit and reset), and a customised value shows its dot.

## FW-A (R3-FWA) sgs/button: a motion hover movement replaces only the matching part of the preset's hover transform

**Today.** `src/blocks/button/style.css` prints the preset hover as one declaration inside `.sgs-button:hover, .sgs-button:focus-visible`: `transform: var(--sgs-btn-transform-hover, var(--wp--custom--button-presets--default--hover-transform, none))`, with `--sgs-btn-transform-hover` set per preset class from `--wp--custom--button-presets--<preset>--hover-transform`; `.sgs-button--link` sets it to `none`. The token is one transform string written by `scripts/theme-extractor/presets.py` into `sites/<client>/theme-snapshot.json`. The values in use today (`grep hover-transform sites/*/theme-snapshot.json theme/sgs-theme/theme.json`) are `matrix(1, 0, 0, 1, 0, -3)` (lift 3px), `matrix(1, 0, 0, 1, -3, -3)` (lift diagonally) and `matrix(1.05, 0, 0, 1.05, 0, -2.1)` (Indus: scale 1.05 plus lift 2.1px). The motion hover state writes the `translate`, `scale` and `rotate` properties through `[data-sgs-mc~="translate"]` and its siblings in `assets/css/motion.css`, which compose with `transform`, so a button with both lifts twice.

**Rule (Bean).** Zoom and lift are different settings. A button's own Motion hover `translateX` or `translateY` replaces only the preset's lift; its own hover `scale` replaces only the preset's scale; its own hover `rotate` replaces only a preset rotate. A hover scale alone never removes the preset lift.

**Design.**
- **Split the token into parts.** `includes/class-button-presets-customiser.php` (the filter that publishes the preset tokens) derives, from each preset's `hover-transform`, three part tokens beside it: `hover-lift` (`translate(<tx>px, <ty>px)`), `hover-scale` (`scale(<s>)`) and `hover-rotate` (`rotate(<a>deg)`), each emitted only when non-identity. One parser covers `matrix(a, b, c, d, tx, ty)` with `b = c = 0` and `a = d` (scale `a`, lift `tx ty`), `matrix` with a rotation (`b`, `c` non-zero), `translate`, `translateX`, `translateY`, `scale`, `rotate` and combinations of those. Any other form is left whole in `hover-transform` and never nulled. `hover-transform` itself stays. The parser is unit-tested against every value found in `sites/*/theme-snapshot.json` and `theme/sgs-theme/theme.json` (the three above) plus the other forms. The theme-extractor keeps writing `hover-transform` only (no re-extraction, no snapshot re-push). The builder confirms where the customiser publishes tokens (the filter that feeds `settings.custom.button-presets`) before editing.
- **Compose in the stylesheet.** The preset classes set `--sgs-btn-lift-hover`, `--sgs-btn-scale-hover` and `--sgs-btn-rotate-hover` from the part tokens (falling back to the site `default` preset's part tokens, as the whole token does today), and the hover rule composes `transform: var(--sgs-btn-lift-hover) var(--sgs-btn-scale-hover) var(--sgs-btn-rotate-hover)` with the same `none` result when no part is set. The builder proves with computed styles that a preset with no part resolves `transform: none` (an identity function would create a containing block); if the empty composition does not behave, each part gets its own `:where()` hover rule instead. `.sgs-button--link` nulls all three.
- **Markers.** In `includes/motion/class-sgs-motion-emitter.php` (beside `data-sgs-mh`), only when the hover state's `source` is `self` (a hover driven by the root, an item or a group is another element's hover): `data-sgs-mh-move` when `translateX` or `translateY` is set, `data-sgs-mh-scale` when `scale` is set, `data-sgs-mh-rotate` when `rotate` is set. Register the three in `Sgs_Motion_Renderer`'s known-attribute list and `Sgs_Motion_Markup`, and document them in the header of `assets/css/motion.css`. Narrow on purpose: `data-sgs-mc` tokens are also written for parallax, magnet and rest effects, which must not remove a preset part.
- **Nulling.** `style.css`: `.sgs-button[data-sgs-mh-move]{--sgs-btn-lift-hover:translate(0,0);}`, `.sgs-button[data-sgs-mh-scale]{--sgs-btn-scale-hover:scale(1);}`, `.sgs-button[data-sgs-mh-rotate]{--sgs-btn-rotate-hover:rotate(0deg);}` (specificity 0,2,0 beats the preset class and the per-instance `.uid` rule). Only a button with a motion hover gets an identity function; every other button keeps `none`.
- **Opt-out of the built-in lift.** Attribute `builtInHoverLift`: boolean, default `true` in `block.json`. When `false`, `render.php` adds class `sgs-button--hover-still`, and `style.css` nulls all three parts exactly like the markers. Control: a toggle row "Button style's built-in lift" inside the Motion hover panel, shown only on `sgs/button`, help "Your button style lifts slightly on hover. Turn off to use only the movement set here." The panel is the shared extension, so the block declares the row through `supports.sgs.motion.hoverToggle` (`{ attribute, label, help }`) read by `src/blocks/extensions/motion/hover/hover-fields.js`; no other block declares it. Manifest mapping: `supports.sgs.elements.button.states.hover.attrMap` gains `"css:transform": "builtInHoverLift"`, because the attribute governs the hover `transform`; if `check-element-manifest-conformance.js` rejects a boolean on that key, the attribute is declared as a class toggle in the manifest's class-toggle list and the check is taught that list. Resets to on.
- Canvas: the motion canvas writer and `preview-style.js` write the same markers and honour `builtInHoverLift`.

**Files.** `includes/class-button-presets-customiser.php`, `includes/motion/{class-sgs-motion-emitter.php,class-sgs-motion-renderer.php,class-sgs-motion-markup.php}`, `assets/css/motion.css`, `src/blocks/extensions/motion/{hover/hover-fields.js,canvas/*}`, `src/blocks/button/{block.json,render.php,style.css,preview-style.js}`, `.claude/specs/38A-SGS-MOTION-MODEL.md`, tests for the parser and the markers.

**Migration.** None. **Reseed.** Yes (`builtInHoverLift`, manifest row).

**Negative controls (computed `transform`, `translate`, `scale` on hover at 375/768/1440, identical before and after).** A default button of each preset (primary, secondary, outline, link, default) with no motion, under each token above (3px lift, diagonal lift, Indus `matrix(1.05, 0, 0, 1.05, 0, -2.1)`). The Eye Care buttons in `sites/eye-care-ward-end/build/trees/template/single-product.json`, which carry a hover scale of 1.25 and must keep their -3px preset lift (a scale alone never removes the lift). Indus header, footer and drawer buttons. A button with a rest rotation or parallax and no hover movement keeps every preset part. Positive: hover `translateY: -2px` gives a 2px lift and the preset's scale remains; hover `scale: 1.25` gives scale 1.25 and the preset's lift remains; `builtInHoverLift` off gives only the motion movement.

## FW-B (R3-FWB) sgs/button: the shared link-underline settings

**Today.** The button has `textDecoration` (rest, `css:text-decoration`) and `textDecorationHover` (`none|underline`; `render.php::$text_decoration_hover` prints `text-decoration:underline` on hover; it is saved in `sites/eye-care-ward-end/build/*.tree.json` and the calibration fixtures, so it stays). `style.css` resets the decoration with `.sgs-button:hover, .sgs-button:focus-visible { text-decoration: none }` and `.sgs-button:focus:not(:focus-visible)` (specificity 0,3,0). The five `linkUnderline*` attributes exist on text, heading, label, icon-list, business-info, testimonial and collapsible-text, written by `src/components/LinkUnderlineControl.js`, printed by `includes/helpers-link-underline.php::sgs_link_underline_css` (canvas twin `src/utils/link-underline.js::linkUnderlinePreviewCss`). The helper styles `selector + ' a'`; a button is itself the `<a>`. `colourBackgroundHover` already exists on the button.

**Design.**
- Attributes, copied from `src/blocks/heading/block.json`: `linkUnderline` (string, enum `["", "none", "always", "hover", "sweep"]`, default `""`), `linkUnderlineThickness`, `linkUnderlineColour`, `linkUnderlineColourHover`, `linkUnderlineOffset` (string, default `""`).
- `sgs_link_underline_css( array $attributes, $prefix, $selector, $paint = '', $self = false )`: in self mode `$link = $selector` (`.{uid}.sgs-button`). The rest rule must beat the stylesheet resets, so self mode prints the longhands (`text-decoration-line`, thickness, colour, offset) in four variants: rest, `:hover`, `:focus-visible` and `:focus:not(:focus-visible)`, each at a specificity above 0,3,0. `always` in self mode always prints the hover and focus variants. `none` prints `text-decoration-line:none` in the same variants. `hover` prints the line on `:hover` and `:focus-visible` only.
- `sweep` in self mode paints on `.sgs-button__label` (the span `render.php` already wraps the label in; `$paint` is `' .sgs-button__label'`), and is skipped when `colourBackgroundHover` or a background image or gradient is set on the button.
- **Precedence by mechanism.** When `linkUnderline !== ''` (`'none'` counts as set), `render.php` omits both the `textDecoration` output and the `textDecorationHover` output. A PHP test covers three combinations: `linkUnderline` set with `textDecoration` set; `linkUnderline` set with `textDecorationHover: underline`; `linkUnderline` empty with both set (today's output, unchanged).
- Manifest keys reuse the heading vocabulary on the `button` element (`css:text-decoration-link`, `css:text-decoration-thickness-link`, `css:text-decoration-color-link`, `css:text-decoration-offset-link`; hover `css:text-decoration-color-link`), distinct from `css:text-decoration`. If `check-duplicate-controls.js` flags the pair, the manifest keys are fixed, never baselined.
- **Editor (one group "Underline").** `LinkUnderlineControl` gets a `wording="button"` prop (its `MODE_HELP` says "links inside the text"; the button wording says "the whole button"). In the button's typography panel the group "Underline" starts with the "Button underline" select (Theme default, None, Always, Shows on hover, Slides in on hover), then thickness, colour, hover colour and offset. The old "Text decoration" select is relabelled "Overline / strike-through" and loses its Underline option; it and the hover decoration are disabled with "Controlled by Button underline above" when `linkUnderline` is set. `textDecorationHover` is hidden in the UI (attribute kept for saved content). Canvas: `linkUnderlinePreviewCss` gets a `self` option.
- **Mama's use.** Style "link", `linkUnderline: always`, `linkUnderlineColour` pink, `linkUnderlineThickness: 2px`, `linkUnderlineOffset: 4px`, plus the existing `colourBackgroundHover` and `padding` (the link style's `padding: 0` and transparent hover are overridden by per-instance settings).

**Files.** `includes/helpers-link-underline.php`, `src/utils/link-underline.js`, `src/components/LinkUnderlineControl.js`, `src/blocks/button/{block.json,render.php,edit.js,preview-style.js}`, PHP tests for the helper and the precedence.

**Migration.** None. **Reseed.** Yes.

**Negative controls.** Byte-diff gate: `sgs_link_underline_css` output for a fixed attribute set on each of the seven existing blocks (text, heading, label, icon-list, business-info, testimonial, collapsible-text) is identical before and after. A default button of each preset with `textDecoration` unset, and one with `textDecorationHover: underline`: computed `text-decoration-*` at rest, hover, `:focus-visible` and mouse focus unchanged. Indus and Eye Care buttons. Positive: the Mama's link button computes a 2px pink underline at 4px offset at rest, on hover, on keyboard focus and after a mouse click.

## FW-C (R3-FWC) sgs/icon-list: the link fills its row

**Today.** `render.php` prints `<li class="sgs-icon-list__item">{marker}<span class="sgs-icon-list__text"><a class="sgs-icon-list__item-link">...</a></span></li>`. `itemPaddingBlock` (string, default `""`) pads the `<li>` through `$item_row_sel`. In the default marker mode the `<li>` is `display:flex; align-items:center`; the `bullet`, `numbered` and `none` marker modes use `display:list-item` rows. The link is text height. The typed and menu sources share one loop.

**Design.** For linked items in the flex-marker mode only, move the row's vertical padding onto the link; `display:list-item` rows and unlinked items are untouched.
- `render.php` adds `sgs-icon-list__item--linked` to the `<li>` when the item has a URL (class only), and prints the scoped rules only when `itemPaddingBlock` is set and the marker mode is the flex one: `{$item_row_sel}.sgs-icon-list__item--linked{padding-block:0;}`, `{$item_row_sel}.sgs-icon-list__item--linked .sgs-icon-list__text{align-self:stretch;display:flex;align-items:center;}`, `{$item_row_sel} .sgs-icon-list__item-link{display:block;padding-block:{$item_padding_block};}`. The `<li>` keeps `align-items:center` (confirmed in `style.css`), so `align-self:stretch` on the text span is what makes the span as tall as the row; the marker stays centred on the same line.
- **The `<li>` hover zone must not shrink.** The `<li>` keeps its box height (the stretched span plus the link's padding sum to the old padded height), so `.sgs-icon-list__item:hover`, `:focus-within` and `sgs_sibling_dim_css` fire over the same area as today; a test measures the `<li>` rect and its hover hit area before and after.
- The marker stays outside the link (today's behaviour); the click target is the padded text zone.
- Canvas: `edit.js` renders the same class and rules (`editor.css`, `preview-style.js`).

**Files.** `src/blocks/icon-list/{render.php,style.css,edit.js,editor.css,preview-style.js}`; no `block.json` change.

**Migration.** None. **Reseed.** No (no attribute or manifest change).

**Negative controls.** A default icon-list (no `itemPaddingBlock`): unchanged. `bullet`, `numbered` and `none` lists with links and `itemPaddingBlock`: `<li>` rect, marker x and y, text rect and hover hit area unchanged. A flex-marker list with `itemPaddingBlock` and no links: unchanged. Indus drawer and mega-menu `source: menu` lists: focus ring rect and `<li>` hover background unchanged. Positive: a linked flex-marker row with `itemPaddingBlock` has link rect height equal to row height, with the `<li>` rect, marker position and text position unchanged at 375/768/1440.

## FW-D (R3-FWD) motion: rest rotation as an angle list cycled per repeated item

**Today.** The hover state's `restRotate` (`schemas/motion.schema.json::$defs.HoverStateValues.restRotate`, scalar `angle`, `cssProperty: --sgs-rot-rest`, `state: rest`, `perDevice: true`) is written by `includes/motion/class-sgs-motion-rotation.php::hover_angles` and composed into `rotate` by `[data-sgs-mc~="rotate"]` in `assets/css/motion.css`. The hover angle is stored as `--sgs-mh-to-rot` = hover minus rest. A target that is a repeated item resolves through `Sgs_Motion_Targets::resolve` and `::item_matches`. `data-sgs-loop-i` is printed only where a stagger is set, so `:nth-child` is the universal index.

**Design.** One field, two shapes: `restRotate` accepts a number or an array of 2 to 12 numbers.
- Storage: `sgsMotion.elements.<target>.hover.state.values.restRotate: [-2, 1.5, -1, 2, -1.5, 1]`, and per device `devices.<tier>.restRotate`. `schemas/motion.schema.json` gains `$defs.angleList` (array, minItems 2, maxItems 12, items `#/$defs/angle`) and `restRotate` becomes `oneOf` angle or angleList; `motion_fields` gets a list field type (`fieldType: angleList`); `scripts/generate-motion-editor-defs.py` regenerates `generated-motion-defs.json`. The validator in `includes/motion/class-sgs-motion-field-types.php` clamps each value to the angle field's existing range, drops non-numbers, caps the length at 12 and collapses a list of fewer than 2 to a number.
- **Emission and specificity.** `<cls>` is the item class from `Sgs_Motion_Targets::item_matches`. When a tier's effective rest value is a list of length L, the base `--sgs-rot-rest` is the first angle (also the degradation value) and one rule per position k is appended inside that tier's wrapper: `<target selector>:nth-child(Ln+k of .<cls>){--sgs-rot-rest:<angle>}`. Rule: any tier that follows a list at a wider tier emits the nth family at equal specificity, in tier order (a scalar there is written as `:nth-child(n of .<cls>)`; another list as its own positions), so the narrower tier wins by source order. A scalar with no list at any tier emits the legacy output byte for byte with zero nth rules (named parity test).
- **Root-matched targets** (a block whose target is the root itself) have no siblings: a list there is refused and the first value is used (a refusal id in `x-sgs-refusals`, shown in the panel).
- **Hover still overrides rest.** In the list case `--sgs-mh-to-rot` is written as `calc(<hover> - var(--sgs-rot-rest))`, per tier where the hover or the rest value changes, so the engaged hover reads the hover angle for every item (Mama's gallery: hover rotate 0 straightens all six). The scalar case keeps its literal difference.
- **Carousel loop clones.** A cloned item (`data-sgs-loop-clone`, appended by `view.js`) continues the document-order cycle, so a clone's angle may differ from the original it copies; the help text says so.
- **Browser floor.** `:nth-child(An+B of S)` needs Chrome 111, Safari 9 and Firefox 113. Older browsers drop the nth rules and every item takes the base angle (the first angle): visible, harmless, stated in the spec.
- **Reduced motion.** A rest rotation is a static pose, not motion, so it stays under reduced motion; the hover straightening follows the existing reduced-motion rule. Stated in the help.
- **Editor.** Row label "Tilt at rest, per item (Z)" in the Rotate group of `hover/hover-fields.js`, help "Item 1 gets the first angle, item 2 the second, and so on, starting again after the last". The switch "Same for all items" shows only for repeated-item targets (an `item_matches` twin in the editor); off shows a chip list of small number fields (an add button, a remove button on each, minimum 2) with a live "Pattern repeats every N items" note and an inline red message when a value is clamped. Chips are an ordered group with an accessible name, each field labelled "Angle for item N", add and remove announced to screen readers, arrow keys move between chips. `AngleAtom.js` and `src/components/motion/field-types/` carry it; `ResponsiveControl` gives per-device lists with Inherit and reset. Canvas twin `canvas/emit-rotation.js` mirrors the nth rules and the `calc` to-value; the canvas is checked at each device tier.

**Files.** `schemas/motion.schema.json`, generated defs, `includes/motion/{class-sgs-motion-rotation.php,class-sgs-motion-emitter.php,class-sgs-motion-field-types.php,field-types/*}`, `src/components/motion/{AngleAtom.js,field-types.js,field-types/*}`, `src/blocks/extensions/motion/{hover/hover-fields.js,canvas/emit-rotation.js}`, `.claude/specs/38A-SGS-MOTION-MODEL.md` (FR-38A-42), fixtures in `tests/fixtures/motion/`, `tests/php/MotionRendererChannelsTest.php`, `tests/js/motion-hover-panel-schema.test.js`.

**Migration.** None. **Reseed.** Yes.

**Negative controls.** Every fixture in `tests/fixtures/motion/` renders identical CSS (the PHP and JS parity cases in `canvas-parity-cases.json` pass unchanged); a scalar `restRotate` on a gallery, card-grid and post-grid has no nth rule and an unchanged computed `rotate` at 375/768/1440. Positive: six gallery items resolve to -2, 1.5, -1, 2, -1.5 and 1 degrees at rest and 0 on hover; a seventh takes -2; masonry and carousel keep the cycle in document order.

## FW-E (R3-FWE) sgs/gallery: layout per breakpoint

**Today.** `block.json::attributes.layout` is a string enum `grid|masonry|carousel`, default `grid`. `render.php::$layout` feeds the wrapper class `sgs-gallery--<layout>`, the carousel controls, `data-autoplay`, `sgs_gallery_grid_layout_css` (grid only) and the separators call. `style.css` keys every layout rule on that class; `carousel` is `grid-auto-flow: column` with native scroll-snap, and `view.js::initCarousel` binds at load to `.sgs-gallery--carousel` (arrows, dots, autoplay, loop clones, drag). `includes/helpers-responsive.php::sgs_emit_tier_rules_map` emits `@media` only; `sgs_emit_responsive_css` takes `array( 'container' => true )` for `@container`.

**Design.**
- `layout`: object `{desktop, tablet, mobile}`, default `{}` (empty resolves to `grid` through `sgs_resolve_tier( $value, $tier, 'grid' )`). Values: `grid`, `masonry`, `scroll` (new, CSS only), `carousel`.
- **Mixed-set rewrite, before anything reads the layout.** `carousel` is whole-block: it is honoured only when all three tiers resolve to `carousel`; otherwise every `carousel` tier is rewritten to `scroll` first, and everything downstream reads the rewritten set. The wrapper class is `sgs-gallery--<desktop resolved layout>` after that rewrite, and the carousel markup (arrows, dots, pause button, `data-autoplay`, `data-speed`) is printed only when all three tiers resolve `carousel`, so `view.js` binds exactly as today for a uniform carousel.
- `style.css` gains a static base `.sgs-gallery--scroll .sgs-gallery__grid` (the swipe row: `display:grid; grid-auto-flow:column; grid-auto-columns:var(--sgs-scroll-item-width, <one column>); overflow-x:auto; scroll-snap-type:x mandatory; scrollbar-width:none`) and `.sgs-gallery--scroll .sgs-gallery__item{scroll-snap-align:start}`; no JS layer.
- Attributes `scrollItemWidth` (object, default `{}`, a CSS length or percentage, printed as `--sgs-scroll-item-width`) and `scrollInset` (object, default `{}`, printed as `padding-inline` and `scroll-padding-inline` on the grid), through `sgs_emit_responsive_css` with `array( 'container' => true )`.
- **Layout override sets.** `sgs_emit_tier_rules_map` gains `$opts['container']` (default off: output byte-identical, proven by a PHP test with the option off); the gallery uses it for the per-tier override sets on `.{uid} .sgs-gallery__grid`, so a gallery in a container narrower than 768px takes its mobile layout. Uniform layouts print no override. Each override resets exactly the properties the other modes set: a masonry-to-grid reset clears `column-count` and `column-gap`; a scroll-to-grid reset restores `grid-auto-flow:row`, `overflow-x:visible`, `scroll-snap-type:none` and the track template.
- **Container query anchor.** An `@container` rule needs a container ancestor. The builder checks which element carries `container-type` for the gallery (the container wrapper's own, `SGS_Container_Wrapper`) and verifies that adding `container-type` to the gallery wrapper would change its layout; the override sets query the nearest existing container and add none.
- **Swipe row accessibility.** In `scroll` tiers the grid is a scrollable region: `tabindex="0"`, `role="region"` and an `aria-label` ("Gallery, swipe row"), so axe's `scrollable-region-focusable` passes and the arrow keys scroll it; items keep their own focus order.
