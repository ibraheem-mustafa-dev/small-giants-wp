# Spec 49 Stage B: the media system switch-over

**Goal:** every media slot in the framework renders through the Stage A system, every site's saved content carries only the new attributes, and the old media code is deleted, in one release (Spec 49 §14.1). Stage A built everything dormant on `main` (closed at `7aa0a65d3`); nothing changes for a block until its `supports.sgs.mediaElements` entry declares `kinds`.

**Bean's rulings that bind this plan (Spec 49 §17, AC-25, FR-49-42):** resized copies are AVIF q60 with a WebP q82 fallback and uploads stay JPEG or PNG; the Integrator checks all five sites for regressions and Bean checks by eye only `eye-care-test` (darkcyan) and `indus-test` (lavender-dinosaur); page load speed belongs to `plans/2026-11-03-page-weight-budget.md`; sandybrown's deploy is retried once at the release.

## How it runs

- **One session runs every wave (Bean, 2026-11-11):** a single main session integrates, reseeds, migrates and gates, and delegates each wave's block work to subagents (one or many per wave). The limits are dependency order and the roughly 25-minute gate, not context.
- **Integrator:** the main thread, working in `E:/sgs-tmp/wt-media`. Only it reseeds, publishes, regenerates tracked files, edits baselines and deploys (§14.0). Package agents each work in their own worktree under `E:/sgs-tmp/wt-sb-*`, detached on the integration branch's tip, and never create branches.
- **Integration branch:** `feature/media-stage-b`, opened after the setup package lands. Adoption is re-run by script against fresh `main` at each wave, so the branch can be deleted and rebuilt if it has not merged within three sessions (§14.1). It merges to `main` in three or more commits (FP-5).
- **Coordination:** before any reseed or publish, message the Eye Care session (`small-giants-wp-59`) and wait for its "starting" and "done" in both directions.
- **Gate:** `python plugins/sgs-blocks/scripts/build-deploy.py --gate-only --editor-check local-indus`. After a failed tier, `python plugins/sgs-blocks/scripts/run-gates.py --only-failed` checks a fix; it never counts as a pass.

## Decisions taken in planning

- **The framework DB is reseeded on a private copy for the whole branch and published only at the merge.** Publishing adopted attributes before they are on `main` gives every other session's tree rogue seeds (`.claude/dev-setup.md`, "Publish only what main declares"). Branch gates run with `SGS_FRAMEWORK_DB=<copy>`.
- **Waves migrate scratch copies of the mirrors, not the mirrors themselves.** The four mirrors (`local-sandybrown`, `local-indus`, `local-mamas`, `local-eye-care`) serve other sessions' editor checks on `main`'s code; migrated content would break them. Each wave migrates `local-mediatest-<site>` copies running the branch build. The real mirrors migrate with the merge.
- **Deploy and migrate are one step per site, built at the release.** The setup package's refusal makes `build-deploy.py` refuse a post-cutover build on any target whose detector check is not clean; the release package adds the step that backs up, deploys, runs the fix and check on the server, purges, or restores (§13), which is what passes that check.
