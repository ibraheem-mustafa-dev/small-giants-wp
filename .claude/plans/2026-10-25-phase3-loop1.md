# Phase 3 loop 1: fix the route's own faults, then re-clone every surface

**Goal:** every surface of the three clients Fills, builds and walks, and the census hands Bean a cause table whose framework rows are real missing settings, not the route's own recognition faults.

**Why now (Bean, 2026-10-25):** Phase 2's first Indus pass (25 of 40 surfaces) showed that about 80% of Fill's 6,912 `no-setting` rows are route faults and about 8% genuine missing settings (`.claude/reports/2026-10-25-no-setting-diagnosis.md`). Each cause already has hundreds of instances, so fixing before cloning Mama's and Eye Care saves re-counting the same faults. This is the first loop of the parent plan's Phase 3/Phase 4 cycle, run early.

**Decisions this plan carries (Bean, 2026-10-25):**
- Fill keeps reading the draft through its own runtime in the sandbox (Spec 48 FR-48-24); a Node parse-only Fill was rejected by a unanimous council (it would close about 7 of 531 Indus home rows; the Indus logic touches the DOM). Fill gains a state opener instead.
- The Floating layer (`sgs/decorative-image`) draws decorative rings itself: it adopts the shared `box-shape` and `shadow` atoms (as `sgs/media` does through `block.json::supports.sgs.mediaElements`) and the shared background panel.
- The container gets its hover shadow shape through the shared `ShadowControl` (`shadowHover`), and an overflow control (visible, hidden, clip).
- The button declares `fontWeightHover` from the shared `TypographyControls` hover trio.
- The shared `TypographyControls` gains a number style row (`font-variant-numeric`) and a text shadow row.
- Cursor needs no setting: the draft's pointer follows clickability, which a link or button gives natively. The click-a-row-to-prefill-the-form behaviour is a behaviour item for the census.
- Forms are `sgs_form` posts placed by the form block on their page; blog posts are one cloned single-post template plus an optional per-post content clone (only the post content is editable).

**How every unit is measured:** before any unit starts, `scripts/computed-route/tools/no-setting-count.mjs` (built first, U00) prints the `no-setting` rows of named Fill runs grouped by the report's cause signatures. Each route unit records its baseline (Fill re-run on the Indus home, header, footer and careers surfaces, same invocation) in this plan's Status, predicts the drop for its own causes as a number, and its done-when is that number reached within 10%, run with the same command. The route suite's failing test names are recorded before the first merge; a gate fails on any new name, not on a count.

**Commits and deploys:** each unit commits straight to `main` with explicit pathspecs from its own worktree, merged by the orchestrator (`git merge --no-ff`), with a queue line; three or more commits per mechanism change (FP-5). Framework changes deploy with `build-deploy.py --target all` because the three clients' test sites must render the new controls for the re-clone; that is in scope.

**Scope boundary:** not included: new behaviour recognisers (row click to form), Mama's and Eye Care framework gaps that their own runs reveal (they enter the census), the walker comparison gaps the parent plan already gives Phase 3, and any fix whose cause is not proven with a reproduction.

**Estimate:** about 5 hours of machine time over two sessions, plus 70 to 90 minutes of Bean's own time (reviews and eye checks). Session A: U0 to U8 and G1, G2. Session B: U9, U10, G3 to G5. The split sits at Bean's skeleton reviews (G4); U9's Eye Care intake starts in session A so the review is ready.
