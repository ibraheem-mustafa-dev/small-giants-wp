# States wave (FR-48-81)

## Why now
- **Problem:** `node scripts/computed-route/capabilities.mjs --gaps` listed 71 capabilities in wave "states" (50 CSS pseudo-classes, 10 ARIA attributes, 7 state/open motion presets, `block-setting:motion:motion`, the `sc-if` and `style-hover` constructs, `svg:set`). The route reads hover only, at rest it reads nothing under any other state, and nothing checks a state on the live page.
- **Effect:** a draft's focus, open, current, disabled and pressed looks are dropped, and Indus step 20 (the header slice) cannot start: Indus has 10 states rows (hover, focus, focus-visible, popover-open, aria-expanded/pressed/checked/hidden, `sc-if`, `style-hover`), Mama's 10.
- **Solution:** make the framework DB the one home for states, have the route read it instead of hand-written lists, and build the state reader, writer and check. With step 4.0 (done) this unblocks Indus step 20.

**Where the DB holds states today:** the `states` table (the vocabulary, 117 rows); `block_attributes.css_state` (hover, current, open, scrolled, shrunk); `modifier_suffixes` kind `state` (Hover, Active, Focus, Disabled); `block_supports.sgs` JSON (`elements.*.states`, `motion.states`); `motion_presets.trigger`, `motion_fields.state`, `fx_effects.triggers`. The `sgsMotion` object has no `block_attributes` row; its field states live in `motion_fields`.

**Root causes found by the survey, and where they stand:**
1. The route and the seeder kept their own state lists (against FP-1). Fixed: the classifier and intake read the `states` table; calibration keeps dedicated triggers only for states that need a real pointer, focus, scroll or fixture, and probes the rest from the vocabulary (step 3).
2. Under-tagging: the classifier mapped only `:hover` and `[aria-selected=true]`. Fixed by step 2: 14 settings gained a state (account `menuActive*`, language-switch `currentColour`, nav-drawer-menu `itemColourOpen`, `caretBoxBgOpen(+Gradient)`, `caretBoxBorderColourOpen`, `submenuAnimationEasing`, both menus' `itemDisabledColour`, collapsible-text `collapsedLines`), no existing tag changed. `sgs/choice-flow.stepperActiveColour` is in no manifest and stays untagged.
3. Ripple's presets stamped `click` while the runtime default is `pointerdown`. Fixed: the presets stamp `pointerdown` (7615ae66c).

## Motion timings and states

A timing on the resting rule times both directions of a state change; one on a state rule times entering that state only. `css_state` records which state's rule a setting sits in, so direction follows CSS semantics.

- **Close reverses open (Bean, 2026-10-20; Spec 38A's default).** An `open` entrance's close values fall back to its from-values, duration and easing (`includes/motion/class-sgs-motion-trigger-open-state.php`, `assets/css/motion-triggers.css`); optional close values are the only override. Resting-rule transitions reverse on the same timing. The state reader treats a draft's close as the reverse of its open unless the draft declares a different close.
- **Exceptions:** named-`state` entrances snap back when no close values are stored; the cart drawer (below); the nav-drawer-menu accordion's explicit in/out pair (`submenuAnimationDuration`, `submenuExitDuration`).
- **Cart drawer:** `panelSlideDuration`/`panelSlideEasing` are emitted as `animation-*` on `.{uid}.sgs-cart__panel[open]`, which the dialog keeps while `src/shared/nav-interactivity/store.js::runClose` adds `.is-closing`. The close plays the open's keyframes reversed (`src/blocks/cart/style.css`, `.sgs-cart__panel--drawer.is-closing`), so it runs on the same duration and curve whether the settings are set or not (probed in Chromium on the compiled stylesheet: before, unset was 250ms ease-out in and 200ms ease-in out, and a set value ran the out forwards on the set curve). Inspector labels: "Slide time", "Slide speed curve". Its manifest row still names `transition-*` on `panelFrame`: the motion cluster has no `animation-*` member, so the row is corrected when the cart moves onto the motion model's `open` trigger (Later wave, below).
- **Both directions:** hover transitions (gallery, hero, info-box, post-grid, process-steps, team-member, testimonial), `itemMotion*` (icon-list, both menus), mega-panel `groupTransitionDuration`, `submenuCaretTurn*`, `scrimFade*`, site-header `ink*`, row `rowShrink*`, cart `freeDeliveryFill*`.
- **Not state timings:** counter `duration`, nav-drawer-menu `itemOrnamentFrameDuration` and `submenuAnimation`, testimonial-slider `transition*` (slide change).
- sgs/tabs `transitionDuration` times the tab button's colour, background and indicator-shadow change (`tabs/style.css`).
- **Declarations (fixed 2026-10-20, 7615ae66c and a411a4e99):** testimonial-slider `transition*` on the `list` element (the JS-built `__list`), process-steps `transition*` on `step`, hero `transition*` on `wrapper` as longhands, nav-drawer-menu `itemMotion*` on `item`. Still open: cart `panelSlide*` (above); info-box and testimonial `transition*` list the `transition` shorthand beside the longhand because their hover lift reads the same custom properties inside a `transition` shorthand (harmless: Solve writes style rows, never the walker's motion row).

## Decisions (Bean, 2026-10-20)

- Form-field states (`:valid :invalid :user-valid :user-invalid :required :optional :placeholder-shown :in-range :out-of-range :read-only :read-write :default :indeterminate :autofill :enabled`, aria-invalid, aria-disabled, aria-busy) belong to wave "shop, forms and data": sgs/form draws them. `:disabled` and `:checked` stay here (pickers, menus, buybox).
- A draft popover maps to the existing SGS surfaces (modal, nav-drawer, mega-menu).
- Excluded, signed by Bean: media playback states (`:playing :paused :buffering :seeking :stalled :muted :volume-locked`), caption-cue timing (`:past :future :current`), `:fullscreen :picture-in-picture`, Web Components states (`:has-slotted :state()`), `:blank`. The view-transition states (`:active-view-transition`, `-type`, `:navigation-source`) belong to "site and surfaces" beside `fx:page-transitions`. `:empty` matches at rest, so the rest declared read covers it (step 7 records its refs).
- The framework DB is the one home for states, with these state words: hover, focus, active (press), current (with pressed, selected, checked), open, disabled, scrolled, shrunk.
- Focus looks equal to hover go through hover settings; a different focus look and `:active` on buttons go to the theme tokens (`settings.custom.focus`, `buttonPresets.*.active-*`) through a minimal token writer.
- Closing reverses opening on the same timing unless a close override is set.
- sgs/tabs `transitionDuration` is wired, not removed.
- **Behaviour that follows a real state is not a state look (Bean, 2026-10-21).** An icon that turns or swaps when an item opens follows the element's own state (`aria-expanded`, `[open]`); its setting (`sgs/accordion.iconRotation`, degrees) is a resting amount, never a state setting, and no gate baseline is raised to file it under a state. `behavioural-analyser/state_exhaustiveness.py` classifies such rules by rule (category `behaviour`: transform-only declarations fed by an untagged published setting). Accordion and FAQ open-state looks get at most 15 minutes of work: almost every accordion opens its first item by default.
