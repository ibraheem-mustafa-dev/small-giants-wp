# One icon block (sgs/icon) + sgs/social-icons rebuilt as its wrapper + a rebuilt Spacing control

## Context
`sgs/social-icons` is a poorly built scoped copy of `sgs/icon`. Bean wants `sgs/icon` to be the one icon block, with social-icons' code deleted and its name reused for a thin wrapper built like `sgs/multi-button`: real `sgs/icon` children, group defaults on the parent, children filled from Site Info (socials and contact: call, email, map). Bean's list also covers the shared Spacing control (`SgsBoxControl`) every block's padding/margin uses. Outcome: one icon block Site Info drives (a blank Site Info link falls back to the icon's own link and hides only when there is none, a brand colours itself), a Spacing control that looks and behaves like core's with theme-preset defaults, and the Eye Care footer and drawer rebuilt on it. The 2D research (market: icon size + shape padding) is in `~/.claude/memory/research/2026-10-08-icon-shape-padding-controls.md`; Bean chose icon size + shape size.

## Bean's decisions (2026-10-08)
- **D1 Spacing default:** an untouched side's default is a theme spacing PRESET (the one nearest the block's current measurement). The dropdown preselects that preset's name and the value box beside it shows its measurement, untied: typing flips the dropdown to Custom. A client re-scales by reassigning the default to another size or by changing the theme's spacing scale. **Mechanism (council C1):** the preset is declared, never stored: `block.json::supports.sgs.spacingDefaults` names it per attribute and side, the stylesheet paints it as the last fallback, and the control shows it preselected through its existing `inherited` display. The attribute default stays `{"desktop":{}}`, because an object default is written into a block on its first save and would freeze the preset there.
  **Refined by Bean 2026-10-09 after the cart pilot:** a default becomes a preset only when it equals a preset's size exactly; any other value stays the literal length it is (no snapping, no tie rule). Every governed default is still declared in `supports.sgs.spacingDefaults` (a preset var or a literal length), so the control shows the real default ("Default (M)" or "Default (20px)") and nothing is stored.
- **D2 Shape list:** square/rectangle (the only shape with a radius control), circle, pill, then custom outlines with no radius: hexagon, diamond, octagon, star, blob (a fixed list; star added by Bean 2026-10-09). Custom outlines are an inline SVG behind the glyph (fill = background, stroke = border), painted through CSS classes and custom properties, stroke inset by half its width; gradients apply to box shapes only.
- **D3 Icon-to-edge space:** icon size + shape size (width and height, linked by default; circle and custom outlines use width only), both per device, each a theme preset or any unit; icon centred. The block's Spacing padding/margin are space OUTSIDE the shape.
- **D4 Social row:** `sgs/social-icons` keeps its name; every line of its current code is deleted and it is rebuilt as a thin wrapper of `sgs/icon` children that fills itself from Site Info: the 8 socials plus phone (call), email and address (map).
- **D5 Brand colours (Bean's item 2F):** brand colours are the default for an icon bound to a brand's Site Info key or showing a brand glyph; a colour the client sets wins. A brand colour that fails 3:1 against its ground falls back automatically (white glyph on a brand disc when that pair passes, else the theme colour).

## Phase E: declared spacing defaults across blocks (D1 as refined 2026-10-09), detector first (migration-method)
**Rule (Bean 2026-10-09):** a governed side's default is declared in `block.json::supports.sgs.spacingDefaults`: the preset `var(--wp--preset--spacing--N)` when the stylesheet value equals that preset's theme.json size exactly (1rem = 16px), otherwise the literal length it already paints (no snapping, no tie rule, nothing moves). The stylesheet paints an exact match as `var(--wp--preset--spacing--N, <theme size>)` (the fallback keeps the minifier's folded shorthand valid) and keeps a literal as it was. Nothing is stored.
**Mechanism (built):** `src/utils/spacing-defaults.js::spacingDefaultsFor( name, '<attr>', { attributes, tier } )` reads the declaration; every declared attribute's mount passes it as `defaults` to `SgsBoxControl` (directly, through `ResponsiveBoxControl`, or through google-reviews' `TierBox`). An untouched side shows "Default (M)" with the preset size as placeholder, or "Default (20px)" with the length; without presets the value box shows the same placeholder (a declared preset as its size). A wider tier's value beats the declaration. **Device + setting shape (2026-10-09):** one attribute's declaration is the base (`top|right|bottom|left`, every tier, every setting) plus optional `tablet` / `mobile` partial overrides and a `when` list, e.g. `"tabPadding": { "top": "12px", …, "when": [ { "attrs": { "orientation": "horizontal", "mobileLayout": "stack" }, "classes": [ "sgs-tabs--horizontal", "!sgs-tabs--mobile-row" ], "mobile": { "top": "0.875rem", … } } ] }`. A `when` entry is `{ attrs (all must equal the block's attributes), classes (the variant classes the stylesheet keys on; "!x" for a :not()), top|right|bottom|left, tablet, mobile }`, the first match wins. The effective value at a tier is layered per side: base, the match's sides, then (tablet, mobile) the declaration's tier override and the match's tier override; tablet inherits desktop and mobile inherits tablet as a stored value does. A call with no context returns the base, so every flat declaration resolves as before.
