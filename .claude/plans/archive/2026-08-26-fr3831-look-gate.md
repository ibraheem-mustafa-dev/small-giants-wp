**Almost every task in this phase touches the same two files** (`fx-wave-gradient.js`,
`wave-gradient.js`). Parallel agents on those files WILL clobber each other — this project has that
failure recorded four separate ways. Therefore:

- The **enumeration/classification** step is read-only and parallel-safe.
- **All edits to those two files happen in ONE dispatched agent, in one commit.** Do not split
  "three bug fixes" across three agents because they sound independent. They are not.

## Key Judgement Calls

### KJC-1 — What happens if the look is still rejected after Step 5?
- **Options:** (A) stop and go to client builds · (B) add the detail field · (C) full shader rework
  per the technique spec
- **Recommendation:** **(A) by default**, (B) only on a specific "flat/lifeless" verdict.

- **Cost of wrong choice:** choosing (C) early burns days on vertex maths toward a shape nobody has
  drawn, with an acceptance criterion of one person's eye. That is the stall shape this project has
  recorded repeatedly.
- **Who decides:** Bean, at QA Gate C.

### KJC-2 — Does the CSS fallback still owe the shader a visual match?
- **Options:** (A) keep "same layer count and composition" · (B) downgrade to "same ground + one
  soft bounded shape" · (C) drop the contract
- **Recommendation:** **(B)**, written into Spec 38 §1.2b and the CSS header in the same commit.
- **Why:** Spec 38 binds the fallback to the shader "FOREVER". Striations and a folded ribbon are
  not expressible in CSS, so taken literally the obligation is unsatisfiable and will be silently

- **Cost of wrong choice:** (A) leaves a promise nobody can keep; (C) loses the no-WebGL visitor.
- **Who decides:** Bean (it amends a Spec 38 clause).

### KJC-3 — Two council findings I am NOT accepting as given

### KJC-4 — Legal framing in the technique spec
- **Decision:** correct three overstatements before that document is relied on.
- **Options:** (A) correct now · (B) correct during the Phase 3 rewrite · (C) leave it
- **Recommendation:** **(A)** — it is ~20 minutes and the document is tracked forever.
- **Why:** s.50BA permits *studying*, not making and keeping copies; it covers **computer

### Pre-emptive decisions (Hidden Decisions pass — two cold reviewers, Sonnet + Haiku)

Every item below was **verified in code before being accepted** — the reviewers are hypothesis
generators, not evidence. Decisions are pre-made so nothing pauses mid-step.

**PD-1 — ⭐ The capability fix is TWO changes, not one. (Sonnet; VERIFIED)**
`capability.js:109` calls `getContext('webgl2')` with **no options at all** — so `probeSurface()`
does not set `failIfMajorPerformanceCaveat` either. "Route it through the existing probe" therefore
closes only half the bug.
**Decision:** do both — wire `probeSurface()` as a gate before `createWaveGradient()` runs, **and**
add `failIfMajorPerformanceCaveat: true` to `wave-gradient.js`'s own context creation (~line 268).
Also reconsider `powerPreference: 'low-power'` there, which contradicts the "declines rather than
runs badly" posture.

**PD-2 — ⭐ Scope the attribute removal to the `onLost` closure ONLY. (Sonnet; VERIFIED)**
`stop()` has **six** call sites (lines 125, 155, 199, 206, 227, 243) — pause, off-screen,
tab-hidden, draw-failure. Putting `removeAttribute('data-sgs-wave-active')` inside `stop()` would
flash the CSS fallback every time the user pauses or scrolls away.
**Decision:** the removal goes in the `onLost` callback, never in `stop()`. A reviewer must check
this explicitly — it is a silent behaviour regression that looks like a correct fix.

**PD-3 — Colour parsing: test the ASSIGNMENT, not the computed value. (Sonnet; correct as reasoned)**
The obvious `el.style.color = raw; getComputedStyle(el).color` trick **cannot distinguish an invalid
value from a legitimate black** — an invalid assignment leaves the property unset and the browser
reports its own default.
**Decision:** assign, then check `el.style.color === ''` **before** reading the computed value. Test
against `oklch(70% 0.1 200)`, `hsl(210 80% 50%)`, `red`, and `notacolour`.
⚠ Getting this backwards converts a silent-kill-switch bug into a silently-paints-black bug — a
regression that presents as a fix.

**PD-4 — `probeSurface()` is expensive; cache it page-level. (Sonnet)**
It creates a canvas and compiles+links a real program. `boot()` iterates `querySelectorAll`, so a
page can hold several instances.
**Decision:** hoist the probe result to module scope in `fx-wave-gradient.js` and reuse it. This
diverges from the sibling effect's per-call pattern — note the divergence in the commit rather than
"fixing" the sibling in the same change (shared-mechanism edits are design-gated).

**PD-5 — `console.warn` once per element per `attach()`.** Not once globally (hides a second broken
block) and not once per bad colour (up to four warnings for one element).

**PD-6 — ⭐ Step 3 must emit a FILE, not a conversation. (BOTH reviewers — convergent)**
Step 4 takes "Step 3 sign-off" as input, but Step 3 as written only produces an
`AskUserQuestion` exchange. A cold Step-4 agent cannot read that.
**Decision:** Step 3 writes `.claude/reports/2026-08-26-third-party-reference-sign-off.md` as a
ready-to-apply list of `file:line → exact replacement text`. ⚠ Reviewer A separately flagged that
Step 1's edits and Step 4's bug fixes both touch `wave-gradient.js`'s docblock — so the sign-off
must be precise enough to apply without re-interpretation, or the two edit sets collide inside the
one file the serialisation rule exists to protect.

**PD-7 — ⭐ Gate C's target is canary page 2740. (Haiku flagged the gap; I resolved it live)**
Verified on the canary: page **2740**, `[GATE — DO NOT DELETE] Flowing gradient — FR-38-31`,
status `publish`, is the only post containing the effect.
**This also closes a long-standing open question** — the effect *is* authored somewhere, so it is
not dead code. FR-38-31 still defaults to `off`, so no client page is affected.

**PD-8 — The context-loss test needs a procedure, not an aspiration. (Haiku; fair)**
**Decision:** the Gate C check is:
1. Load canary page 2740; wait for `[data-sgs-wave-active="1"]`.
2. `canvas.getContext('webgl2').getExtension('WEBGL_lose_context').loseContext()`.
3. Within 500 ms assert `data-sgs-wave-active` is **absent** and the canvas computed `opacity` is `0`.
4. Assert the CSS fallback element is visible.
If `WEBGL_lose_context` is unavailable on the canary browser, say so and mark the test **not run** —
do not substitute a weaker check and call it passed.

**PD-9 — Thresholds, so no gate is a matter of opinion. (Haiku; fair)**

  pixels differ from the page background by >20/255 on any channel**.

  ⚠ Reference figure: on white the current toggle measures **3.36:1** (not 2.7:1 — a council seat
  overstated this; the corrected number is in KJC-3).
