# Indus delivery

**This is the approved plan for its units (Bean, 2026-10-21).** A session working a unit proceeds without a separate plan-mode approval. It stops for Bean only for a decision this plan does not already record, or a shared-mechanism change (the wrapper, the walker, Solve) this plan does not name. Bean's rulings (below) also approve the shared-mechanism changes they list.

## Goal
The Indus Foods clone signed off: every Indus surface built on indus-test from the draft, checked by the route and by Bean's eye at 375, 768 and 1440 and at the header's own thresholds, with a `gaps.json` naming only differences Bean accepted (Spec 48 Appendix B step 25). Every capability and every live behaviour the Indus draft holds is cloned through a shared mechanism recorded in `scripts/computed-route/data/clone-coverage.json` with a test, never a one-off. The clone is accessible to WCAG 2.1 AA even where the draft is not.

This plan holds every open Indus item; the Indus build's and clone coverage's finished steps are in `plans/archive/2026-10-11-spec48-indus-build.md` and `plans/archive/2026-10-12-clone-coverage-foundation.md`. Framework leftovers no Indus unit needs are Spec 48 §5.4 Residual rows. Mama's Munches follows after Indus sign-off: `plans/2026-10-22-mamas-delivery.md`.

## How this plan was built (2026-10-21)
Read in full: Spec 38, 38A, 48, 48A, both handoff folders' guides and tokens; by three Sonnet readers with the specs' facts as their brief, the Indus draft, its two form drafts, `indus-logo.js`, `animations.json` (217 records: 210 live, 7 dead code) and `surfaces.json` (61 surfaces), and every Mama's draft and inventory. Framework facts from `sgs-framework.db` (read-only). Then an adversarial council of four (claim fact-checker, delivery lead, spec lawyer, design fidelity): every finding is applied below. Then a QC council of three code-path tracers re-checked every built and not-built claim against the code, the DB and the draft (motion; SVGs, forms and the slider; this plan's tables), and Bean ruled on each draft difference (Rulings, below). Units are numbered U0 to U18; the gaps in the numbering (U1, U3, U4, U12) are units finished on 2026-10-21 (Built ahead).

## The closing standard (every unit)
1. **A shared mechanism** in `scripts/computed-route/lib/` (route) or the owning block (framework), for any draft (FP-9). Refs and tests never under `sites/`, never naming a client (`python scripts/check-no-client-names.py --check`).
2. **Its coverage entry** carries `recognise`, `write`, `check` and `test` and a `note` saying how it is solved; `capabilities.mjs --like <id>` finds worked examples. A `check` nothing calls is not a check.
3. **Proof:** a MUST FAIL test, a mutation check that turns it red (`node scripts/computed-route/tools/mutate.mjs <route dir> <mutations.json> <test file>`; mutations JSON is an array of `{file, find, replace, why}`, `file` relative to the route dir), `node capabilities.mjs --gate` exit 0, and per session a planted-draft test, `scripts/computed-route/tests/<session>-planted-draft.test.mjs`, that raises its gaps again with one write ref nulled.
4. **Reduced motion:** every effect written carries its record's reduced-motion behaviour and the matching `fx_effects.reduced_motion` value, probed by `plugins/sgs-blocks/scripts/motion-qa/probe-motion-model.mjs`'s `reduced-*` checks. Rulings: autoplay is off under reduce; a marquee stops and wraps to show every logo; the pinned track keeps its information-only progress writes; the logo and About hero end on their final frame.
5. **No SGS setting for what the draft does:** build the real control (attribute, inspector control, render) in the owning spec; a whole new block is Bean's decision; what cannot be built is a named `gaps.json` row with the rule it breaks.
6. **Before claiming anything is missing or built,** query the framework DB and read the code; a spec Status line is a dated claim.
7. **More than 3 blocks or files getting the same change:** the migration-method skill, detector first. A migration or walker phase never ships as one commit (FP-5).
8. **Commits** name their unit (`feat(U13a): …`). A bug found on the way goes in its FR's Status line and the commit message.

## The delivery map (the tracking file)
`sites/indus-foods/build/qa/delivery-map.json`: one key per coverage id the Indus intake review names (`coverage:<id>`), per active `animations.json` record (`animation:<id>`) and per `handoff/surfaces.json` state (`state:<surface>:<name>`). An open key names its unit (`"animation:A-38": "U14"`); a finished key is `{ "done": "<commit>", "unit": "U14" }` (or `"prior"` for a coverage id covered before this plan), and a difference Bean accepted is `{ "accepted": "<reason naming the rule>", "unit": "U14" }`. `node scripts/computed-route/delivery-map.mjs indus-foods --check` fails on a missing, duplicated or unknown key, a unit not in the work table, a done commit that does not exist, and a coverage key whose mark disagrees with `clone-coverage.json` (an accepted coverage id must be excluded there, signed by Bean); `--status` prints the open keys per unit. A unit's session flips every key it owns before its gate. U2b, U7 and U16 own no keys: their tests track them.
