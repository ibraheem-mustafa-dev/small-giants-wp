## Rules for every addition

1. **Off by default.** A new attribute defaults to a value that emits nothing. The negative control is the block's rendered HTML before and after (PHP render harness, `tests/php`) plus computed styles at 375, 768 and 1440 on every page and fixture using the block. **Known exception, handled once:** about 40 `render.php` files build their per-instance class from `md5( wp_json_encode( $attributes ) )` (`accordion`, `choice-flow`, `choice-flow-question`, `heading`, `container`, `icon`, `cart` and others), and WordPress passes block.json defaults in `$attributes`, so a new attribute changes that eight-character suffix. The byte-identical comparison normalises the suffix `sgs-<block>-[0-9a-f]{8}` on both sides; the builder proves nothing outside the same render keys on it (rules and class are printed together). If that proves false for a block, the hash is computed from `$attributes` minus the new keys at their default.
2. **Per-device values** are `{desktop, tablet, mobile}` objects, default `{}`, an empty tier inherits (`sgs_resolve_tier`), mobile-first. A saved shape is re-saved, never read back (FP-14): no scalar fallback in any `render.php`.
3. **No inline `style=""`** (`node plugins/sgs-blocks/scripts/audit-inline-styling.js --check` exits 0). Values reach CSS through the generated per-instance rule and custom properties.
4. **Editor canvas twin** changes in the same commit as each emitter (`preview-style.js` or the motion canvas writer). Every control has a reset and shows its dot when changed.
5. **Dynamic blocks only.** Before editing, confirm each touched `save.js` returns `null` or is already dynamic; a changed static `save.js` needs a deprecation, which FP-14 forbids on a migrated block, so stop and report instead.
6. **Stop rule.** Any negative control fails, any gate fails, or any live check differs from its "Done when": stop, report the exact output, never baseline a gate or edit a test to pass.
7. **Cite by symbol, UK English, no client name in code** (`python scripts/check-no-client-names.py --check`). After any spec edit run `python scripts/lint-spec-drift.py` and `python scripts/check-md-wrap.py --write <file>`.

## B5: the old-shape audit misses a string stored where a per-device box is expected (ships first)

**Today.** `scripts/lib/scalar_tier_rules.py` derives tier-object attributes (`tier_object_attrs_from_db`, framework DB `block_attributes.tier_shape = 'tier_object'`) and flags a saved scalar there. A per-device box attribute (DB `tier_shape = 'box_only'`) saved as `{"desktop":"40px","tablet":"24px","mobile":"16px"}` is a valid object, so the audit passes while the renderer, which needs `top|right|bottom|left`, emits no rule (cause A1, six pages unnoticed).

**Step 1: dump the box attributes and check each reader.** `python ~/.claude/skills/sgs-wp-engine/scripts/sgs-db.py sql "SELECT block_slug, attr_name FROM block_attributes WHERE tier_shape='box_only' ORDER BY 2,1"`. For each distinct name, read its reader in the block's `render.php` or the helper it calls and record in `scripts/data/box-string-rules.json`: `include` (the reader needs four sides named `top|right|bottom|left`), or `exclude` with the reason. Exclude any whose keys are not those four (the `*BorderRadius` family uses corner keys) and any whose reader accepts a string (the builder proves by reading the reader, not by name). The rule applies to the included list only. The list is data, derived once from the DB and the readers, with a test that every `box_only` row is classified (a new row fails the test).

**Step 2: count before any refusal exists (no cached counts in docs).** For every site in `TARGETS` (`deploy_common.py`): the local trees and fixtures with `python plugins/sgs-blocks/scripts/find-scalar-tier-attrs.py --check` (new rule, report-only), and the live content with the dry run `wp eval-file ~/migrate-scalar-tier-live.php dry-run ~/rules.json` over SSH on each target (method in `.claude/dev-setup.md`). The per-site counts go in the sweep commit message and the hit-list file, not this plan.

**Step 3: the rule (report-only first).** In `scalar_tier_rules.py` add `box_attrs_from_db()` (read-only, same shape as `tier_object_attrs_from_db`, filtered through `box-string-rules.json`) and rule `box-string`: in a saved included box attribute, a tier whose value is a string or number, or an object with none of the four side keys, or a bare scalar for the whole attribute, is a defect. `find-scalar-tier-attrs.py --check` prints it under its own heading and exits 0 for this rule while report-only. Kill switch for the refusal once on: env `SGS_BOX_STRING_RULE=report` (and `build-deploy.py --box-string-report-only`) downgrades it to a report; the flip to refusing is one constant `BOX_STRING_ENFORCED` in `scalar_tier_rules.py`, changed only in the final commit after every target's sweep reports zero.

**Step 4: the conversion (Python expands, PHP substitutes).** `find-scalar-tier-attrs.py --fix` and `--rules` convert only values that are certain: one length token (`40px`, `2.5rem`, `0`, `0px`, a `var(...)` or `var:preset|spacing|<slug>` token with balanced parentheses) becomes four equal sides; a 1 to 4 token CSS shorthand converts only when every token is such a length or token: 1 value `a` gives top, right, bottom, left all `a`; 2 values `a b` give top and bottom `a`, right and left `b`; 3 values `a b c` give top `a`, right and left `b`, bottom `c`; 4 values `a b c d` give top, right, bottom, left in that order. `calc()`, `clamp()` and `min()`/`max()` containing spaces, percentages inside shorthand, `auto`, and anything unparseable are never guessed: they are written to `sites/<client>/build/box-string-refused.json` (path, block, attribute, tier, value) and listed in the report. Python writes the expanded objects into `rules.json`; `migrate-scalar-tier-live.php` only substitutes them text-level (every other byte kept), re-counts, and errors if any included value remains that is not in the refused file.

**Files.** `scripts/lib/scalar_tier_rules.py`, `scripts/find-scalar-tier-attrs.py`, `scripts/migrate-scalar-tier-live.php`, `scripts/data/box-string-rules.json`, `scripts/tests/` fixtures, `.claude/dev-setup.md` (one sentence naming both rule types).

**Tests.** Red before: a fixture tree with `sgs/container` `padding: {"desktop":"40px"}` makes `find-scalar-tier-attrs.py --check` report it (today: nothing). `--fix` fixture: `40px` gives four sides; `10px 20px` gives top/bottom 10, right/left 20; `10px 20px 30px` and four-token cases per the mapping; `calc(1rem + 2px)` and `1rem calc(1px + 2px)` are refused and listed. Negative controls: a correct box, an excluded attribute (a `*BorderRadius` string, a reader that accepts a string), an ordinary `tier_object` scalar and a non-box string leave the result unchanged; a classification test fails when a `box_only` row is unlisted.

**Done when (live).** Per site: the dry run reports a count; after apply it reports 0 and the refused file holds only the unconvertible; with the flip on the audit refuses a seeded string-in-box fixture and a clean tree passes; the affected container's computed padding on the live page equals the intended sides at 375, 768 and 1440.

**Commits.** (1) rule, data file, report-only wiring, tests. (2) the per-site count and hit-list review (read by the main thread before sweeping). (3) the sweep of `sites/*/build/trees`, `theme/sgs-theme/parts` and `patterns`, `tests` fixtures, and the live apply per target. (4) the flip to refusing and the dev-setup sentence.

## B4: filter an accordion by category chips and a search box (Help)
