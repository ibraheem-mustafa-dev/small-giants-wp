# Cloning tool spec audit: the verified gap register (2026-10-28)

**What this is:** the single list the next cloning fix pass works from, instead of fixes guessed one at a time. Bean asked for it after the second full re-clone (2026-10-28) kept surfacing gaps that the specs already plan. An adversarial council of 10 Sonnet raters, one per surface family or layer, audited `scripts/computed-route/`, `scripts/parity/`, `scripts/local-wp/` and the plugin pieces they place, against Spec 48, Spec 48A, `.claude/claude-design-handoff/` (CLAUDE.md, PROMPT.txt, handoff-schema: METHOD.md, READING-DC-FILES.example.md, README.template.md, the three schemas) and each surface type's own spec (01, 02, 04, 27, 36, 37, 38A, 42, 43). A row counted only with a quoted spec line proving the behaviour is planned and code or artefact proof that it is missing. Four independent Sonnet verifiers then re-ran both halves of every row, and the main thread re-ran one piece of evidence for each of 12 top rows (all 12 reproduced). Rejected, unproven and out-of-scope rows are not listed.

**Scope rulings (Bean, 2026-10-28):** reduced motion is the visitor's browser setting, not a reason anything is dropped: its census rows are a bookkeeping fix only (D4). Posts are draft display content: post bodies, metadata and the blog/single template fidelity are out of scope, with one watch item: a draft that shows categories prominently and loses them in the clone. Cloning means recognising each draft part and placing the working SGS/WordPress/WooCommerce block in its place with the draft's content and look; a static copy where the spec names a working block is a bug, never a design question.

**Already fixed on `main`, applied by the next re-clone:** Eye Care checkout region from entry fields (`fc1db770f`), catalogue rewrite flush (`f3c2e62ee`), product menu links, flow slug marker, filter-not-flow (`4e2e35f81`), mega panels split per tab (current intake code returns the four panels; Eye Care's skeletons were built from a stale inventory: re-run Eye Care intake), the hollow gift-finder flow (re-run, then delete post 159 on local-mamas).

Each row below: what is wrong, the spec that requires it, the code at fault, the evidence, and the fix as one shared mechanism. IDs are the council's (rater prefix + number) so the evidence files can be traced. Every fix lands with a MUST FAIL test, a negative control and a mutation list (the route's standard).

## A. Working pieces in the right place (the clone does not work)

**A1. Draft buttons that open something open nothing (modals, choice flows, form prefill).** ICA-1, ICA-6, ICA-2, ICA-10. Spec 48 §recognised structures ("Not built: a modal-opened flow's trigger is not proposed on the page that opens it"), Spec 02 `sgs/modal` (opened by its trigger or any link to its anchor, `data-sgs-modal-open`), Spec 48 FR-48-55 scope (every surface the draft shows, modals included). Code: no writer of a modal opener anywhere (`grep sgs-modal-open scripts/computed-route/lib` finds only the checker `lib/site-check-parts.mjs`); the page map knows only `opensFlow` (`lib/intake-pagemap-flow-openers.mjs`). Evidence: Eye Care's size-guide modal post 118 is published and on no page; "Which size am I?" and "Add my prescription" are plain buttons/text; Indus careers "Apply for this role" ×3 are dead buttons (draft `toForm({role, team})`). Fix: generalise the page map's opener to `opens: [{kind, slug}]` (modal, flow, form target), a skeleton rule beside `skeleton-rules.mjs::blockPartOpener` turning a control whose handler writes the target's open state into an `sgs/button` linking `#<anchor>` (with `?param` for a form prefill and `valueFromParam` on the fields), and the `sgs/modal` frame placed once on the page or template that holds the trigger, its backdrop and panel written as the frame's scrim and dialog settings (the draft's dialog body only inside the post). Site-check: `missingFlowRows` covers `sgs_modal` rows, and a walk whose live element is absent is a failed walk, never "ok" (`site-run.mjs`). Covers every client.

**A2. Product pages cannot sell.** CO-3 (FATAL), shop-parts unconsumed. Spec 48 FR-48-60 (the buy box in `sgs-pdp-buybox`; its Mama's fallback: "ships on the `sgs/buybox` composite with its existing settings plus listed custom CSS"), FR-48-56. Code: nothing places `sgs/buybox` or product bindings (`grep buybox lib/skeleton*.mjs lib/fill*.mjs data/skeleton-decisions.json` = a comment only); `fill-shop-parts.mjs::valueParts` writes only parts with literal values. **A3. Draft links on single-file drafts link nowhere.** PC-1, NAV-3. Spec 48 FR-48-30 ("every link in the draft resolves to a row or a gap row"), FR-48-38 (write page-map links), §3.4 links rule. ## S. Spec gaps and contradictions (Bean rules on each; then the spec text changes)

- **S1** FR-48-56 contradicts itself: the body says a template copy is the draft's page shell "the regions above and below the content"; its Status and the code narrow it to a single-child wrapper chain plus a fixed whole-tree list (`archive-product`, `single-product`, `cart`, `checkout`). **Ruled (Bean, 2026-10-28):** the wording was poorly written and misread: the whole draft page is the template. Where one template serves many instances (product pages, blog posts), the fixed outer structure is the template's own design and only the areas with variable content (the product's or post's title, price, description, gallery, body) become the working, bound pieces; the rest is not re-decided per instance.
- **S2** FR-48-92: the shop must show "the real range instead of the fixture products", yet fixtures are "never touched", so calibration and fixture products are on both live shops (CO-6). **Ruled (Bean, 2026-10-28):** fixtures are deleted only after a clone is confirmed complete and accurate (they stay while the clone is being built and checked).
