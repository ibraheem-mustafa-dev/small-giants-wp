# Cloning tool spec audit: the verified gap register (2026-10-28)

**What this is:** the single list the next cloning fix pass works from, instead of fixes guessed one at a time. Bean asked for it after the second full re-clone (2026-10-28) kept surfacing gaps that the specs already plan. An adversarial council of 10 Sonnet raters, one per surface family or layer, audited `scripts/computed-route/`, `scripts/parity/`, `scripts/local-wp/` and the plugin pieces they place, against Spec 48, Spec 48A, `.claude/claude-design-handoff/` (CLAUDE.md, PROMPT.txt, handoff-schema: METHOD.md, READING-DC-FILES.example.md, README.template.md, the three schemas) and each surface type's own spec (01, 02, 04, 27, 36, 37, 38A, 42, 43). A row counted only with a quoted spec line proving the behaviour is planned and code or artefact proof that it is missing. Four independent Sonnet verifiers then re-ran both halves of every row, and the main thread re-ran one piece of evidence for each of 12 top rows (all 12 reproduced). Rejected, unproven and out-of-scope rows are not listed.

**Scope rulings (Bean, 2026-10-28):** reduced motion is the visitor's browser setting, not a reason anything is dropped: its census rows are a bookkeeping fix only (D4). Posts are draft display content: post bodies, metadata and the blog/single template fidelity are out of scope, with one watch item: a draft that shows categories prominently and loses them in the clone. Cloning means recognising each draft part and placing the working SGS/WordPress/WooCommerce block in its place with the draft's content and look; a static copy where the spec names a working block is a bug, never a design question.

**Already fixed on `main`, applied by the next re-clone:** Eye Care checkout region from entry fields (`fc1db770f`), catalogue rewrite flush (`f3c2e62ee`), product menu links, flow slug marker, filter-not-flow (`4e2e35f81`), mega panels split per tab (current intake code returns the four panels; Eye Care's skeletons were built from a stale inventory: re-run Eye Care intake), the hollow gift-finder flow (re-run, then delete post 159 on local-mamas).

Each row below: what is wrong, the spec that requires it, the code at fault, the evidence, and the fix as one shared mechanism. IDs are the council's (rater prefix + number) so the evidence files can be traced. Every fix lands with a MUST FAIL test, a negative control and a mutation list (the route's standard).

## A. Working pieces in the right place (the clone does not work)

**A1. Draft buttons that open something open nothing (modals, choice flows, form prefill).** ICA-1, ICA-6, ICA-2, ICA-10. Spec 48 §recognised structures ("Not built: a modal-opened flow's trigger is not proposed on the page that opens it"), Spec 02 `sgs/modal` (opened by its trigger or any link to its anchor, `data-sgs-modal-open`), Spec 48 FR-48-55 scope (every surface the draft shows, modals included). Code: no writer of a modal opener anywhere (`grep sgs-modal-open scripts/computed-route/lib` finds only the checker `lib/site-check-parts.mjs`); the page map knows only `opensFlow` (`lib/intake-pagemap-flow-openers.mjs`). Evidence: Eye Care's size-guide modal post 118 is published and on no page; "Which size am I?" and "Add my prescription" are plain buttons/text; Indus careers "Apply for this role" ×3 are dead buttons (draft `toForm({role, team})`). Fix: generalise the page map's opener to `opens: [{kind, slug}]` (modal, flow, form target), a skeleton rule beside `skeleton-rules.mjs::blockPartOpener` turning a control whose handler writes the target's open state into an `sgs/button` linking `#<anchor>` (with `?param` for a form prefill and `valueFromParam` on the fields), and the `sgs/modal` frame placed once on the page or template that holds the trigger, its backdrop and panel written as the frame's scrim and dialog settings (the draft's dialog body only inside the post). Site-check: `missingFlowRows` covers `sgs_modal` rows, and a walk whose live element is absent is a failed walk, never "ok" (`site-run.mjs`). Covers every client.

**A2. Product pages cannot sell.** CO-3 (FATAL), shop-parts unconsumed. Spec 48 FR-48-60 (the buy box in `sgs-pdp-buybox`; its Mama's fallback: "ships on the `sgs/buybox` composite with its existing settings plus listed custom CSS"), FR-48-56. Code: nothing places `sgs/buybox` or product bindings (`grep buybox lib/skeleton*.mjs lib/fill*.mjs data/skeleton-decisions.json` = a comment only); `fill-shop-parts.mjs::valueParts` writes only parts with literal values. Evidence: 0 `sgs/buybox` in both shops' `single-product.json`; every product page prints the draft's sample product; no add-to-basket. Fix: a `product` role in `lib/skeleton-commerce-region.mjs` placing `sgs/buybox` (with the settings `shop-parts.json` already maps) and `sgs-product/field`-bound title, price, description and gallery at the region `shop-parts-read.mjs::buyboxRegions` finds, with the draft's layout around it; the draft's part order inside the buy box waits on the Spec 27 parts split (S13), so the single-buybox form is the stated fallback until then.

**A3. Draft links on single-file drafts link nowhere.** PC-1, NAV-3. Spec 48 FR-48-30 ("every link in the draft resolves to a row or a gap row"), FR-48-38 (write page-map links), §3.4 links rule. Code: `lib/draft-link.mjs::elementFile` builds `${e.template}.dc.html` = `Root.dc.html`, while `linkContext` keys routes by the real file; `lib/skeleton-write-content.mjs::contentAttrs` resolves only elements with an `href`, so a handler button is never resolved and no handover row is written. Evidence: as coded `{"kind":"none"}`, with the real file `{"address":"/shop/"}`; Eye Care home 3 of 79 buttons have a url; every Eye Care footer link and the header About/Help/account are dead. Fix: key by the entry draft's file (`lib/skeleton-record.mjs` knows it); resolve handler buttons with no href; a handover row when nothing resolves; an account trigger whose routes include the account page links to it.

**A4. A container's own words are never carried, and list copy held in the logic is not read.** PI-1 (FATAL on the Indus FAQ page), NAV-14, ICA-7, PC-7, FA-4. Spec 48 §3.4 ("the skeleton carries the draft's words in each block's content settings … including copy held in the logic's arrays"), FR-48-38 (Status: logic-as-data reading not built), FR-48-6 element map (a link or button holding a label and an icon is one button). Code: `contentAttrs` returns only `tagName` and `layout` for wrapper shells; `lib/skeleton-choice-flow.mjs` drops capped option lists with a note; an `<a>` with one block child is read as a wrapper shell. Evidence: 140 containers end with their draft words absent (Indus FAQ questions and answers all missing), Mama's Zookie flavours 0 of 11, Indus brands mega gallery empty, Eye Care "Message me" links gone, Eye Care 13 reviews show "Body paragraph…" with the review text in the attribution. Fix: own words become an `sgs/text`/`sgs/label` child in DOM order; loop holes and capped lists read through `lib/fill-list-items.mjs::listItems` (the FR-48-38 logic-as-data reader); an `a`/`button` with words is `sgs/button` with its icon in the icon slot; a blockquote's body becomes the quote's inner text and its cite the attribution.

**A5. Drawer menus and drawer close.** NAV-4, NAV-8. Spec 48 FR-48-55 (the drawer's menu bound to the drawer menu), Spec 36 FR-36-6 (close is the drawer's own chrome). Code: `lib/site-build-map.mjs::boundMenu` falls back to the header menu unless a menu is named exactly `drawer`; no rule absorbs the draft's close control. Evidence: Eye Care's drawer shows the header menu twice and none of its own two menus (29, 31 unused); both shop drawers have a second, dead × button. Fix: bind each drawer `<nav>` group to the menu the page map made for it by surface kind and order; a skeleton rule mapping the draft close control onto `sgs/nav-drawer`'s close settings.

**A6. A commerce page with no recognised region silently becomes a static imitation.** CO-2. Spec 48 FR-48-87 (never SGS blocks imitating WooCommerce's forms). Code: `commerceRegion` returns null and `skeleton-propose.mjs` raises no problem. Fix: a problem row, and Fill/build refuse a commerce-role surface with no region.

## B. Content carried over

**B1. Forms: success message, validation, conditional fields, product binding.** HR-1/ICA-3, ICA-5, ICA-12, ICA-8. Spec 48 FR-48-57 (success state from the draft's result surface; validation copy; conditional fields), Spec 43 FR-43-10 (`flowProductId`). Evidence: every client's forms show the block default success text; Indus enquiry accepts a blank submission although `requiredCopyOf` reads its validation copy (where it is lost is unproven: trace `copyFor`); Mama's contact shows the order-number field always and drops the cookie-count field; Mama's Zookie flow has `data-flow-product-id="0"`. Fix: write `successMessage` from the result record or the form's sent state; trace and fix the validation hand-off; read `sc-if` fields tied to a field value as conditional fields; site build sets `flowProductId` from the catalogue product.

**B2. Headings keep their level.** PC-2, CO-11. Spec 48 FR-48-6 ("headings keep their level"). Code: nothing writes `sgs/heading` `level` (default h2). Evidence: no live page on any client has an `<h1>`. Fix: write `level` from the draft tag in `contentAttrs` for any block with a level setting.

**B3. Default text survives.** FA-3, MISS-1. Evidence: "Click Here" ×25 on Eye Care's home, ×10 on Mama's (wordless swatches and dots); Mama's footer copyright and credit lines vanish because Fill overwrites `sgs/business-info` `displayType` with "address" (`qa/fill/footer/2026-10-28T06-44-59/fill-report.md`). Fix: a wordless control writes an empty/icon-only label; content-selector enums (`displayType`) are excluded from look writes.

**B4. Product listings on ordinary pages are static text.** CO-7, HR-5 (a regression: Eye Care's home had product, brand and review blocks on 2026-10-27). Spec 48 FR-48-83, Spec 27 FR-24-4 (`sgs/card-grid` collection mode, built). Fix (stage: skeleton recognition, from the code, Spec 48A FR-48A-8 "cloning reads the code"): a loop (`sc-for`) over the logic's product data whose items show a price and link to product pages places the product collection on any page; a loop whose items link to brand pages places `sgs/brand-strip`; a loop of rating, author and quote places the reviews block. The section heading is a supporting signal only (never a decision by words, FR-48-30); Eye Care's embedded `data-sgs-manifest` is outside the handoff contract (no other client has one) and stays review evidence.

**B5. CSS background photos never placed; the draft preview server's address written instead.** FA-2, PI-7. Spec 48 FR-48-39 (attachment IDs from the upload map). Code: `lib/fill-read-collect.mjs` reads only `<img>`; `lib/resolve.mjs::formatValue` writes a string `url()` as measured. Evidence: Mama's home 4 cards "no image set"; posts hold `url("http://127.0.0.1:59003/assets/photo-pair-love.jpg")` in a gradient setting. Fix: read computed `background-image: url()`, route every `url()` through `fill-media.mjs::mapEntries` to an image setting, and choose a block with a background image setting for an element that paints one picture; a gradient setting never takes a url.

**B6. Labels from the draft's own words.** NAV-11, CO-9. Spec 48 FR-48-55 part 3 (a menu label is the draft link's text), FR-48-62. Evidence: Mama's menu says "Gifts for new mums" for the draft's "Gifts"; basket drawer "View cart" for "View full basket" (`shop-parts.json` maps `viewCartLabel` with `write: null`). Fix: read static nav link text; write the mapped drawer labels.

**B7. Shop sorting and category chips are dead imitations.** CO-5. Spec 48 FR-48-61, FR-48-87 (WooCommerce's sorting inside the SGS layout). Fix: place `woocommerce/catalog-sorting`, `product-results-count` and a `product_cat` filter for category chips; an unsupported sort option is a missing-features row.

## C. The look carried over

**C1. Box values written flat, so sides overwrite each other (padding, margin, radius, border width).** RL-1, FA-1 (two raters, top structural finding). Spec 48 FR-48-52 (per-side values into `{top, right, bottom, left}`), FR-48-8. Code: `lib/fill-width-ladder.mjs` rung 2 writes a string per tier with `merge: 'deep'`. Evidence: Indus about-9 padding `{desktop: 40px…}` (draft 64/40/64/40), live 0; 208 such writes across the three clients. Fix: build `{tier: {side: value}}` for every `box_family` setting through the resolver's existing `boxed()`; refuse a string tier on a box setting.

**C2. Fill settles "equal" against the wrong reference.** RL-2, RL-3, RL-4, PI-5, PI-3, PI-2. Spec 48 FR-48-42/43, §3.4 step 3, FR-48-36. Code: `lib/fill-prop.mjs::resolveProperty` stops at the root slot before the inner band; the inner band's layout is never read (`fill-unread.mjs`: ~1,900 rows); the wrapper's default side gutter survives a draft 0; `fill-resolve-state.mjs::baselineFn` compares against the calibration fixture's tag and the parent's draft value, not the live inheritance (Eye Care h2 renders 46px for a draft 20px); `fill-spacing.mjs::decideRendered` hands a margin to a parent gap that paints nothing on a block parent; `fill-confirm.mjs` marks values confirmed without comparing what the setting emits (FR-48-76 not built). Fix: judge "equal" across every candidate slot and against the live inheritance (tag-keyed paint, enclosing block's emitted colour, theme element styles); a draftSlots finder for the inner band; write an explicit 0 over the gutter; give the margin to the children unless the parent is flex or grid; a setting-level predictor before `confirmed`.

**C3. Header behaviour, wordmark and nav states.** NAV-5, NAV-6, NAV-7, NAV-10. Spec 48 §3.4 rules 3 and 6, Spec 37 §4 (sticky, transparent, shrink, hide-on-scroll), Spec 36 Part 14, FR-48-46. Evidence: Eye Care's header is not sticky, blurred or shrinking (`headerSticky` written only by the shadow recogniser; `headerShrink`, `surfaceBlur` have no writer); its "EYE CARE BIRMINGHAM" wordmark renders nothing because the skeleton places the image-only `sgs/responsive-logo` for typed text; its About and Help links are buttons; Mama's nav has no hover or current-page look. The blocks have every capability here (`sgs/site-header` `headerSticky`, `headerShrink`, `surfaceBlur`; `sgs/nav-bar-menu` hover and current settings; `core/site-title` renders the site name as text): every fault is in the route. Fix (stages: Fill behaviour writers and the skeleton's block choice): write sticky from the computed position per tier and the scrolled-state values; the skeleton places a typed brand name on a block that renders the site name as text (see S14); the navigation rule covers header links outside `<nav>`; write `itemBgHover` and the current-state settings from the draft.

**C4. Template shells and the order confirmation.** T-01, T-02/CO-4, NAV-2. Spec 48 FR-48-56. Code: `lib/template-copies.mjs::sameNode` compares whole attributes, and each page's wrapper carries its own `cr-ref-*` class, so the common shell is always empty and every derived template (404, search …) is identical across clients; `lib/manifest-build.mjs::matchRecord` maps a `template` row to kind `page`, so Mama's "Order confirmed" draft never builds its template; Eye Care's Sunglasses mega panel keeps titles only. Fix: ignore `cr-ref-*` in `sameNode`; match `template` rows to `result` records and build `order-confirmation` from the draft's layout around WooCommerce's order-confirmation blocks (see S1, S4); a block that draws its children keeps each child's link and image.

**C5. Motion the draft runs that the cloning route does not carry.** MF-1, MF-2, MF-3, MF-4, SF-1, SF-2, RL-5. Spec 48 FR-48-47, FR-48-48 (never a silent drop), FR-48-77, FR-48-78, FR-48-80. **The framework has every capability involved** (framework DB `fx_effects`: `parallax`, `marquee`, `ambient-float`, `carousel-loop`, `draggable`, `split-reveal`, `scrub`, `page-transitions`; the motion model's scroll entrances with stagger; `sgs/testimonial-slider` `autoplay`, `autoplaySpeed`, `dragToScroll`, `showArrows`, `showDots`; `sgs/timeline` pinned-horizontal): each fault below is in a named stage of the cloning route, never a missing block or theme feature.

- **Intake (reading the draft):** Eye Care's scroll reveals (460 ms, easeOutCubic, staggered `min(i,7)*70`) are recorded with CSS defaults because `lib/intake-inventory-sample.mjs::sampleTargets` samples only interval/loop script writers and `lib/intake-inventory-anim.mjs` never reads the script's constants; mobile-only and code-built loops (Mama's trust bar 24 s and footer tagline, Eye Care's ticker below 768) are recorded at desktop where they do not run, or without a template element.
- **Recognition (`lib/motion-behaviours.mjs::recogniseBehaviour`):** no recogniser maps a script-written reveal to the scroll entrance; `scrollOf` requires the literal word `scrollY` in the formula, so Eye Care's hero parallax (the scroll value passed in as a parameter) is not recognised; Mama's carousel (drag, arrows, dots, 6 s autoplay) is never mapped to the slider's settings.
- **Fill (writing settings):** `lib/fill-motion-account.mjs::silentRows` returns nothing for a record with no template element, so the carousel and parallax leave no row at all; `lib/fill-motion-element.mjs::elementEffects` judges loops at 1440 only; `lib/motion-layers.mjs::matchByPose` calls identical entrances ambiguous; `lib/motion-loops.mjs` refuses a three-keyframe symmetric float; `lib/motion-behaviour-settings.mjs` writes the timeline's pinned-horizontal effect without the `orientation: horizontal` it depends on.
- **Skeleton (block choice):** Eye Care's brand marquee lands on `sgs/multi-button`, which does not offer `marquee`; the refusal is reported but never fed back to choose `sgs/brand-strip` or `sgs/trust-bar`, which do; Mama's review carousel is proposed as a sideways `sgs/container`, not `sgs/testimonial-slider`.

Fix: per stage as above: sample and read script reveal constants; recognisers for script reveals, parameter-bound scroll values and carousels; place records through their nearest element (or a handover row, never silence); judge loops at a width where they run; treat identical candidates as one; accept the symmetric float; recognisers carry the settings their effect depends on; an effect refusal re-chooses the block.

## S. Spec gaps and contradictions (Bean rules on each; then the spec text changes)

- **S1** FR-48-56 contradicts itself: the body says a template copy is the draft's page shell "the regions above and below the content"; its Status and the code narrow it to a single-child wrapper chain plus a fixed whole-tree list (`archive-product`, `single-product`, `cart`, `checkout`). **Ruled (Bean, 2026-10-28):** the wording was poorly written and misread: the whole draft page is the template. Where one template serves many instances (product pages, blog posts), the fixed outer structure is the template's own design and only the areas with variable content (the product's or post's title, price, description, gallery, body) become the working, bound pieces; the rest is not re-decided per instance.
- **S2** FR-48-92: the shop must show "the real range instead of the fixture products", yet fixtures are "never touched", so calibration and fixture products are on both live shops (CO-6). **Ruled (Bean, 2026-10-28):** fixtures are deleted only after a clone is confirmed complete and accurate (they stay while the clone is being built and checked).
- **S3** Status lines wrong: FR-33-15 (README as palette source; the code skips it), FR-48A-1 (Eye Care fails FR-48A-7; it passes).
- **S4** FR-48-87 names cart, checkout and account but not the order confirmation that FR-48-56 places. Proposal: add it (WooCommerce's order-confirmation blocks where the draft's order summary is).
- **S5** Spec 48A §3 keeps the embedded manifest's repeated groups and behavioural rules as review evidence only, yet they declare exactly what a loop is ("live product query", "live query: Brand taxonomy terms", "build the zero-reviews state first"). **Resolved (Bean asked where 48A and the handoff docs say this comes from):** no contract file declares a section's data source (`surfaces.schema.json` has no such field; the README never maps to blocks, FR-48A-8; the embedded manifest is outside the contract, present only in Eye Care's pre-contract draft). Spec 48A's rule "cloning reads the code" (Bean, 2026-10-11) is the reliable source: the loop's data and what each item shows and links to decide the live block (B4). No spec change; the manifest stays review evidence.
- **S6** FR-48-65 has no class for a walker row with no Fill row (the code's `unassessed`). Proposal: define it, with the box-geometry and technique-difference rules that move rows to W-walker.
- **S7** Spec 48 §recognised structures accepts the Zookie flavours as "8 of 11 labels" with an editor note. Proposal: list content is never dropped; the source list is read (A4).
- **S8** No requirement turns a draft dialog's backdrop and panel into the modal frame's settings (part of A1).
- **S9** The opener for a modal, a flow or a form target is listed as "not built" without a binding requirement. Proposal: make it a requirement (A1).
- **S10** FR-48-40 "exactly" vs R-47-7's colour snap ΔE ≤ 2. Proposal: keep the tolerance and fix FR-48-40's wording.
- **S11** §3.4 step 3 is ambiguous when rendered gaps are equal on a block (non-flex) parent (PI-3). Proposal: the gap owns an axis only on a flex or grid parent.
- **S12** FR-48-57 names only a `result` surface for the success state; Eye Care's lives in a form state. Proposal: either.
- **S13** Spec 27 FR-30-18 (shared field look on WooCommerce's forms, CO-8) and the Spec 27 parts split (the draft's order inside the buy box, A2) are not built and gate FR-48-87's field look and FR-48-60 step 1.
- **S14** Spec 48 §3.4 rule 6 says a typed brand name is "the logo block reading Site Info", but the image-only `sgs/responsive-logo` cannot render text, while `core/site-title` (in the framework DB) renders the site name. Proposal: rule 6 names the block that renders the site name as text, styled from the draft, and the skeleton places it.
