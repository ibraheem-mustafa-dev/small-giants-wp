# The cloning tool: handoff readers, the writers that use them, and the Indus proof

**This is the approved plan for everything in it (Bean, 2026-10-21 and 2026-10-22).** An orchestrator working a wave proceeds without a separate plan-mode approval. It stops for Bean only for a decision this plan does not record, or a shared-mechanism change (the wrapper, the walker, Solve) this plan does not name; Bean's Rulings below approve the shared-mechanism changes they list.

## Purpose

Every cloning stage takes its facts from the file that states them, mostly the client's handoff folder (the template, the logic, `surfaces.json`, `animations.json`, `tokens/*.css`, `assets/`, the README), through one fact record, the render only confirming (Spec 48 R-47-4, FR-48-7; Spec 48A §3). The writers that turn those facts into SGS settings are built on top of the readers, and the framework gains the block features the writers need. The Indus Foods clone is the proving ground: its site work is where the tooling is tested against the draft and refined, every hand fix becoming a standing rule (the ratchet).

**The Indus goal.** The Indus Foods clone signed off: every Indus surface built on indus-test from the draft, checked by the route and by Bean's eye at 375, 768 and 1440 and at the header's own thresholds, with a `gaps.json` naming only differences Bean accepted (Spec 48 Appendix B step 25). Every capability and every live behaviour the Indus draft holds is cloned through a shared mechanism recorded in `scripts/computed-route/data/clone-coverage.json` with a test, never a one-off. The clone is accessible to WCAG 2.1 AA even where the draft is not.

This plan holds every open Indus item; the Indus build's and clone coverage's finished steps are in `plans/archive/2026-10-11-spec48-indus-build.md` and `plans/archive/2026-10-12-clone-coverage-foundation.md`. Framework leftovers no Indus unit needs are Spec 48 §5.4 Residual rows. Mama's Munches follows after Indus sign-off: `plans/2026-10-22-mamas-delivery.md`.

## How the work runs
Two orchestrators run in parallel, each an Opus main thread with its own session: **Track T, the tooling** (the handoff readers session; `scripts/computed-route/`, `scripts/wp-build-page.js`, `sites/<client>/build/`, Spec 48 and 48A, this plan's Track T and Stage S) and **Track F, the framework** (started from `.claude/prompts/2026-10-22-track-f-framework.md`; `plugins/`, `theme/`, the block specs they change: 01, 02, 04, 32, 36, 38, 38A; this plan's Track F). Stage S runs in the Track T session after both tracks finish.

**One session per track, compacted between waves (Bean, 2026-10-22).** Neither track starts a fresh session. When a wave is fully done (its units merged, its review's fixes applied, its docs updated), the orchestrator runs `/handoff` in `local` mode, the session is compacted (`/compact`), and the next wave continues in the same session from the prompt that handoff wrote (named `.claude/prompts/<date>-track-t-<wave>.md` or `-track-f-<wave>.md`, deleted when used). Nothing carries across a compaction except the docs, the queue file and that prompt, so a wave is not done until this plan's Status, the delivery map, the FR Status lines and the queue file say what it did.

**The wave loop** (the skills: `/delegate` routes each dispatch and supplies the three brief lines every brief carries word for word; `/subagent-prompt` writes each brief; `/dispatching-parallel-agents` sends a batch; `/qc-council` reviews):
1. State the wave's dispatch count first (implementers, one reviewer, at most one fix agent). Each session allows 4 subagents at once: at most 3 implementers, leaving a slot for the reviewer; about 12 dispatches per wave between compactions.
2. Group the wave's items so no two implementers edit the same file; each works in its own worktree (`npm ci` in `scripts/computed-route` first, never a junction to the main checkout's `node_modules`) and commits only if its unit's tests and `node scripts/computed-route/capabilities.mjs --gate` exit 0 (the commit gate, written into every brief).
3. The orchestrator reads every diff, checks `git diff --cached --name-only` is empty, merges with `git merge --no-ff`, then runs the full route suite (`node --test "tests/*.test.mjs"` in `scripts/computed-route`) and the gates in the main checkout (five lint and solve-held tests fail in any worktree, so the main checkout is the real gate).
4. Review: one reviewer for the whole wave's diff (`/qc-council` Stage 7.5, Sonnet at medium effort routed by `/delegate`; `--high-complexity` for security, data migration and shared mechanisms: the SVG allowlist, `wp-build-page.js`, the wrapper); a wave that changes a shared mechanism, or carries competing fix proposals, gets the full three-rater `/qc-council` instead. One fix agent takes the whole findings list.
5. The docs (this plan's Status lines for the wave's own items, the delivery-map keys, the FR Status lines, `scripts/computed-route/README.md`), then the between-waves step above. A full three-rater `/qc-council` closes each track before Stage S.

**The queue file** (`.claude/queue.md`, append-only, committed and pushed with each line): the cross-track signal, because a compaction forgets the other session. Lines: `F reseed-start <sha>`, `F reseed-done <sha> blocks: <slugs> settings: <names>`, `F built <unit> <sha>`, `T site-run-start <what>`, `T site-run-end`, `T effect-settings complete <sha>`, `T svg-screen change <sha>`. Each orchestrator reads it before any reseed, deploy, calibration, Fill run or framework-DB read, and never reads the DB between a `reseed-start` and its `reseed-done`. After a `reseed-done`, Track T recalibrates the listed blocks (`calibrate.mjs --site local-indus --client indus-foods --blocks <list> --recalibrate`, refusals checked, a loss allowed only by name) before writing the new settings. `ListAgents` and a message to a busy peer stay the courtesy layer on top.

**Ownership.** Track T edits only its paths, Track F only its own. A unit whose Track column names both halves: Track F builds the control and appends `F built <unit> <sha>` to the queue; Track T writes the setting, then flips the unit's delivery-map keys. Track F flips keys only for units whose Track is F alone (U10's 3 keys; U11 and U17 have none). Each track edits only its own units' entries in `scripts/computed-route/data/clone-coverage.json`, `data/coverage-test-baseline.json` and `sites/indus-foods/build/qa/delivery-map.json`, in its own commit, rebased before pushing. Spec Status lines: Track F edits the block spec's FR (FR-4-N, FR-38-19 and so on); Track T edits the Spec 48 FR when its writer lands. This plan: each track ticks only its own items. LEDGER: one line per track in the cloning front, each `/handoff` editing only its own track's line after a rebase. A gate red on entries the other track owns: commit with `[gates-ok:<reason>]` naming it. The fact record: readers in one wave add their own fields and never bump `FACTS_SCHEMA_VERSION`; the orchestrator bumps it once after the wave's merges, then regenerates both clients' `facts.json` (`node scripts/computed-route/intake.mjs --facts <client>`) and runs the freeze diff once. A change to `lib/svg-screen.mjs::svgProblem` (Track T) is queued for Track F, whose PHP upload allowlist mirrors it; Track F's allowlist test runs the same refused cases.

**Terms.** The ratchet: every hand fix becomes a standing rule at once (a universal signal, a MUST FAIL test, a red mutation, `taughtBy` naming the client, element key and export hash it was taught on, and Bean's one-line confirm; Spec 48 FR-48-7). The refresh loop: reseed, deploy to indus-test, mirror refresh (`scripts/local-wp/sync-build.sh`), recalibrate. G0 to G7: the gate chain each surface passes before Bean's eye (Spec 48 §14, FR-48-64). The closing standard: below.

### The closing standard (every unit)
1. **A shared mechanism** in `scripts/computed-route/lib/` (route) or the owning block (framework), for any draft (FP-9). Refs and tests never under `sites/`, never naming a client (`python scripts/check-no-client-names.py --check`).
2. **Its coverage entry** carries `recognise`, `write`, `check` and `test` and a `note` saying how it is solved; `capabilities.mjs --like <id>` finds worked examples. A `check` nothing calls is not a check.
3. **Proof:** a MUST FAIL test, a mutation check that turns it red (`node scripts/computed-route/tools/mutate.mjs <route dir> <mutations.json> <test file>`; mutations JSON is an array of `{file, find, replace, why}`, `file` relative to the route dir), `node capabilities.mjs --gate` exit 0. Each Track T writer wave also adds a planted-draft test, `scripts/computed-route/tests/<wave>-planted-draft.test.mjs` (e.g. `t3-planted-draft.test.mjs`; the existing ones are `css-`, `motion-` and `states-planted-draft.test.mjs`), that raises the wave's gaps again with one write ref nulled. Track F writes none; its proof is the FR's own test, red under mutation where the code allows, and the live check.
4. **Reduced motion:** every effect written carries its record's reduced-motion behaviour and the matching `fx_effects.reduced_motion` value, probed by `plugins/sgs-blocks/scripts/motion-qa/probe-motion-model.mjs`'s `reduced-*` checks. Rulings: autoplay is off under reduce; a marquee stops and wraps to show every logo; the pinned track keeps its information-only progress writes; the logo and About hero end on their final frame.
5. **No SGS setting for what the draft does:** build the real control (attribute, inspector control, render) in the owning spec; a whole new block is Bean's decision; what cannot be built is a named `gaps.json` row with the rule it breaks.
6. **Before claiming anything is missing or built,** query the framework DB and read the code; a spec Status line is a dated claim.
7. **More than 3 blocks or files getting the same change:** the migration-method skill, detector first. A migration or walker phase never ships as one commit (FP-5).
8. **Commits** name their unit (`feat(U13a): …`). A bug found on the way goes in its FR's Status line and the commit message.

### The delivery map (the tracking file)
`sites/indus-foods/build/qa/delivery-map.json`: one key per coverage id the Indus intake review names (`coverage:<id>`), per active `animations.json` record (`animation:<id>`) and per `handoff/surfaces.json` state (`state:<surface>:<name>`). An open key names its unit (`"animation:A-38": "U14"`); a finished key is `{ "done": "<commit>", "unit": "U14" }` (or `"prior"` for a coverage id covered before this plan), and a difference Bean accepted is `{ "accepted": "<reason naming the rule>", "unit": "U14" }`. `node scripts/computed-route/delivery-map.mjs indus-foods --check` fails on a missing, duplicated or unknown key, a unit not in the work table, a done commit that does not exist, and a coverage key whose mark disagrees with `clone-coverage.json` (an accepted coverage id must be excluded there, signed by Bean); `--status` prints the open keys per unit. A unit's track flips every key it owns before its gate. U2b, U7 and U16 own no keys: their tests track them.

### Rulings (Bean, 2026-10-21)
The standing rule: clone what the draft does. No safeguard, exclusion or design-taste rule the draft lacks is added (hover may darken; the header changes where its content needs; WCAG 2.2 items such as a pause button follow the draft, except the 44px touch targets the project's CLAUDE.md requires). A block behaviour the draft lacks is switched off where a setting allows, or else recorded as an accepted difference.
1. **Clip reveals:** no radius build; the existing clip reveal plus each image's own radius (U13b).
2. **Logo and About hero:** the original SVG files keep and play their own animation once upload stops stripping it; the logo prints inline and its hover lives in its custom CSS as a registered one-off (U13c).
3. **Setting meanings:** an `sgs.meaning` object on each attribute in `block.json`, seeded into the DB (U11).
4. **Trade application saved progress:** saves every field and the step in the browser (`localStorage`), restores with the draft's notice, cleared on submit; no field is left out (U10).
5. **Route fade:** presets never stand in for a custom value (as in the effects controls, font sizes and padding): the page transition keeps its style presets and gains a custom duration and easing that win, set to 380ms (U14).
6. **Careers "Apply for this role":** a link to the form with the team and role in it, preselecting both selects; the gold ring in custom CSS (U9, U10).
7. **Darkening hovers:** cloned as drawn; not a difference.
8. **The peek reveal:** reveals fully on keyboard focus and on tap; the mouse follow stays mouse-only (U13).
9. **The Heritage track:** the timeline's existing pinned-horizontal and carousel with SGS's own switch point; the draft's 1024 switch is an accepted difference (its strip below 1024 is touch-only), to revisit after sign-off; the active-year look is built (U13a).
10. **Testimonials:** the existing slider with one card visible; its slide change and always-on hover pause are accepted differences (U14).

Shared-mechanism changes these rulings approve: the SVG upload allowlist (Spec 01) and the logo's inline option (Spec 36), the page-transition settings (Spec 38 FR-38-19), the timeline active-entry settings, the field-from-link and saved-progress form settings (Spec 04), the cursor-field focus and tap reveal (Spec 38A), the walker half of FR-48-11 and the gate chain (Spec 48 §14).

## Context

The cloning route reads structure and values from the rendered draft where the handoff files already state them. Checked: `lib/skeleton-rules.mjs` reads `surface.kind` and `surface.name` only; `lib/intake-skeletons.mjs::surfaceRoots` saves panel, accordion and form-step records to `intake.json` `parts` and nothing reads them; `lib/fill-spacing.mjs` takes spacing "never from the draft's CSS"; spacing tokens are parsed then dropped; the skeleton takes nesting from the DOM (`skeleton-inventory.mjs::readInventory`). Bean's direction: the handoff files are the primary source at every stage (Spec 48 R-47-4, Spec 48A §1). Every hand fix becomes a rule at the moment of fixing (the ratchet: MUST FAIL test, mutation check, Bean's one-line confirm, the row that taught it). Hand-picked IDs (`logoId`, menu `ref`) are carried from site-build. README block hints are evidence only. READING-DC-FILES and METHOD.md are the contract the readers implement, not data. All of it is done in this session.

Docs are written as current truth: stale text removed, new text in place, no dated decision, superseded or change notes. This plan's Status is updated in the same commit as each item it records. ListAgents and message every busy peer before any reseed, `npm run build`, calibration or deploy; on a host 403 (Hostinger's firewall after heavy editor traffic) calibrate and Solve on the WSL mirror (`--site local-indus`, after `scripts/local-wp/sync-build.sh`).

### The readers and the shared fact record (the design)

Each reader takes one handoff family and writes its part of the fact record; the census and the construct readers stay the sources they already are, and nothing below reads a draft by regex or runs draft logic in Node (FR-48-24).
- `lib/read-template.mjs`: per draft, the element records of the runtime's annotated template, read in the sandboxed page through `__dcAnnotatedTemplate` as the census does (`lib/intake-census-template.mjs::draftSources`, `::readStamped`): tag and real tag, every attribute, the static declarations and `style-*` rules, each hole with its logic path, the template parent chain, `sc-if`, `sc-for` (list and item names) and `dc-import` membership, ref, hooks and events.
- `lib/read-logic.mjs`: in the sandboxed page, for each read width set by the viewport (so a draft that measures its own container, Eye Care, sets its own tier), the value each hole resolves to through the live logic instance's `renderVals()` (READING-DC-FILES §1), for every element, including those the width does not render; the width condition of every `sc-if` from the syntax tree (`lib/intake-ast-eval.mjs::evalDeep`, `::staticTruth`).
- `lib/read-surfaces.mjs`: each element's surfaces (`surfaces.json` id, kind, parent, the states whose `sc_if_tpl_ids` contain it or an ancestor, part roots).
- `lib/read-animations.mjs`: the effects that target the element or a descendant (`animations.json` ids, by containment), with their triggers, breakpoints and routes.
- `lib/tokens.mjs` (built): the token each literal equals by value.
- `lib/read-assets.mjs`: each asset's intrinsic ratio (SVG viewBox, raster size) and the element that uses it.
- `lib/read-readme.mjs`: the README's sections split by `README.template.md`'s headings, its judgement calls, open items and platform intent kept as evidence (FR-48A-8, FR-48A-10).
- `lib/fact-record.mjs`: joins them into `sites/<client>/build/intake/facts.json`, one entry per template key with its instance keys per state, its fingerprint, and a `sources` header (`assertCurrent` refuses a stale record), written by intake only and re-aligned to a new export by fingerprint. Every stage reads its facts through this loader; each wave names the old read it retires.
