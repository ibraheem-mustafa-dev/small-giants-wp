**The evidence that matters more than the counts:** all three rules built this session were BLIND on
first build.

- item 1 (tab group) reported **0** violations; true population **65**. It counted
  `<InspectorControls>` elements instead of panels, so it skipped every block that wraps all its
  panels in one — including `hero`, 15 panels deep, the exact block Bean called unusable.
- item 18 (decorative image) reported **12**; true **15**. It could not see an `<img>` rendered by a
  shared component imported outside the barrel export.
- item 20 (pattern templateLock) reported **43**; true **23**. It excluded chrome patterns by
  filename prefix and wrongly cleared 20 real ones.

Each was corrected only because a suspicious number was challenged. **Base rate of first-build
blindness in the measured sample: 100%.** "Has a script" and "is enforced" are different claims, and
the gap between them is where this project keeps losing time.

## Corrections recorded — five, four of them mine

1. **`derived_selector` is a DRAFT-side matcher** (D484). My gate measured against block render
   output. Bean caught the premise before it drove a rework. Gate deleted.
2. **`text-content` vs `content`** — I claimed `text-content` licenses promotion to a standalone
   `sgs/text` block. False; promotion gates on `canonical_slot`. They differ in exactly one place.
3. **The "live defect on client sites"** — inherited from a peer handover and repeated by me. Not
   reproducible: those buttons use `inheritStyle` through the theme preset chain and render real
   borders. Latent defect, correctly fixed, wrongly ranked as an emergency.
4. **The inline `"role": "content"` key** — I confirmed Bean's "deterministic fingerprint"
   hypothesis with a perfect 99/99 correlation. The correlation was real; the mechanism was not. It
   is WordPress 7.0's own content-editability marker (commit `d307c8b0`), colliding on the key name.
   Reading it into the SGS role column would corrupt 8 attributes.
5. **Bean's occupied-slot hypothesis** (D481) — false, and the truth was better news: 4 alias rows
   instead of 7 destructive deletions.

**The pattern across all five: a real correlation with an unverified mechanism.** Twice in one day I
confirmed a pattern and got the cause wrong. Both times the correction came from reading the thing
rather than reasoning about it.
