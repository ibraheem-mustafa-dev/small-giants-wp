## Limits of this audit

- **Method:** an automated first pass (do each commit's new identifiers, added lines and tests exist on main), then a read of each commit's diff and of main's code for the behaviour, with `git grep`, `git log -S` and `git log --grep=<hash>`. Five parallel readers took 50 commits each. I re-checked the top-ranked claims myself (`066238eef`: main's `site-run.mjs::liveAddress` has no `openerRow` and `surfaceReach` has no opener lookup; `c4da71285`: `scripts/parity/lib/auto-walk.mjs` still awaits `img.decode()` in the page with no `clipUnread`) and read every superseded and present evidence line. The other missing rows rest on the readers' greps. No code, test or route command was run.
- **Part pairing is judged superseded, not compared behaviour by behaviour:** `af3fce031`, `bdb4ea893`, `210fb3b0a`, `3e47a6c8f`, `0b9e42a5a`, `1d21de08a`, `7ac971b40` are marked superseded by Fill-time pairing (`lib/refresh-pairs.mjs`, `lib/pair-wrappers.mjs`, `lib/pair-text.mjs`, `lib/fill-part-pairing.mjs`) from those modules' own descriptions plus a few greps. Bean's RC1 ruling (part pairing, one mechanism for every block) is the test: if it must hold at skeleton time, `6e19ca963`, `1421f7f46`, `92a96456b`, `7cea805dd`, `90bfa232d` and `9d9ea856c` (all marked missing) are the part of that series main lacks. `7ac971b40` also added a one-node-per-element guard that main lacks (listed under `5ba6ed8a1`).
- **`4f2c77669` is present only in part:** main's `lib/template-live-address.mjs::liveFactsPhp` picks the product page address as the draft's product slug, else the first visible product, and applies the purchasable, in-stock, no-fixture, no-gift-card test to the basket-priming candidates only. An all-variable shop whose first visible product is a gift card would still read the wrong product page. Kept as present because the owners treat that commit as rebuilt.
- **Bundled WIP commits:** `cbc4bc2a6` and `0111d72ab` are unfinished WIP snapshots holding several features (platform look, injected-SVG fill, hover-motion held check, filter rail at a page hero, page-map leaving rows); their parts were not checked one by one. `0111d72ab` is superseded by the residual Custom CSS writer; `cbc4bc2a6` is marked missing as a bundle.
- **The applier may overrule some Fill-side rows:** several missing Fill rows (the C2 and C3 series, rank 2) are scored on the assumption that Fill is still the live path. Where the new applier (`apply.mjs`, `lib/apply-*.mjs`) re-writes the same settings from the live page they matter less. I did not trace each one through the applier.
- **Rank is a judgement from the commit and the sites it names, not from a clone run.** Indus and Mama's were hand-finished, so their mismatches score 2 unless the loss hits the walk or build for any client.
- **Nothing is `unclear`.** Where only part of a behaviour is on main, the commit is marked missing and the covered part is named in the readers' evidence.
