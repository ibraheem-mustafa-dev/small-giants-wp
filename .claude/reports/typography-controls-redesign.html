What changed: Preset size and Font size now share one row (they're the same property, so pairing them halves that row's height rather than stacking two full-width fields). Font family is a genuinely new control — SGS's typography panel had none before; it's sourced from the theme's registered font families, same opt-in pattern as the existing font-size presets. Weight, Style, Line height and Letter spacing default collapsed behind a toggle (WordPress's own native panel does the same thing via its ⋮ menu). No per-field device switcher anywhere — that's the one global toggle at the bottom of the sidebar, unchanged. Every attribute, onChange handler, and the responsive-tier/hover mechanism underneath is unchanged; this is layout + one new opt-in field, not a rebuild.

Evidence, not guesswork

  • The "before" panel is the real live component — captured from the SGS Heading block's Typography panel on the sandybrown canary, not a guess from the source.
  • WordPress's own native panel (core Paragraph block) is already compact by default — a single "Font size" row plus a ⋮ options menu where every other sub-control is opt-in. SGS's version renders all 8 unconditionally.
  • Confirmed in the real component's source — ResponsiveControl.js explicitly documents that it renders no switcher at all ("Spec 35 Phase 1.2") and that inspector-scan rule 25 exists specifically to catch anyone re-adding a per-control one. The device tier comes from one global toggle only.
  • Two build passes compiled clean — npx wp-scripts build against the edited TypographyControls.js, zero errors both times, run locally in an isolated worktree (no shared build/ touched, no deploy to the canary).
  • Nothing behind the existing fields changed — same attribute keys, same onChange logic, same tiered/responsive/hover branches. Font family is the one genuinely new attribute ({prefix}FontFamily), opt-in only — no block gets it unless it declares the attr and passes showFontFamily.
