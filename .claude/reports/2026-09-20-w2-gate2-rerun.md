# GATE 2 re-run — the CPT-rendered drawer against the block-rendered drawer

**Gate 2 asks one thing:** with the drawer OPEN, is the default `sgs_drawer`
CPT-rendered drawer property-identical to the default block-rendered drawer?
**Measured answer: yes**, at the only viewport where an open state exists.

Everything below was measured live on the sandybrown canary on 2026-09-20 against
the already-deployed HEAD. **No build, no deploy, no option change.** Every
front-end fetch carried a `?cb=<epoch>` cache-buster and every one returned
`x-hcdn-cache-status: MISS` (checked with
`curl -s -D - "<url>?cb=$(date +%s)"`), so these are deploy readings, not CDN
readings.

## The two paths, and the proof that each page really exercises the one claimed

| Path | Page | Evidence it is that path |
|---|---|---|
| **CPT** (subject) | homepage `/` | The single `<dialog>` appears **after `</main>`** in the served HTML (byte offset 130882 vs `</main` at 124409) — i.e. printed on `wp_footer` by the CPT renderer |
| **BLOCK** (reference) | **page 3692** `/qa-w2u-gate2-block-path-drawer/` | The single `<dialog>` appears **inside `<main>`** (86876, between `entry-content` at 84013 and `</main` at 93495) — i.e. from `post_content` |

Each page serves **exactly one** `<dialog>` (`grep -c '<dialog'` = 1), so the
landmark guard is still doing its job and neither page is measuring a duplicate.

**Which one wins on a mixed page is proven, not assumed.** Page **3694**
(`/qa-w2u-nonmodal-drawer/`) carries an in-content drawer block with
`modality:"non-modal"` while the site's Active CPT drawer (3593) is `modal`. The
served page reports `data-sgs-nav-modality="non-modal"`, so the in-content BLOCK
drawer is the one rendered and the CPT one is suppressed. That is what makes page
3692 a valid block-path reference rather than a second view of the CPT drawer.

## Attribute identity, independent of any style measurement

Both pages emit the uid **`sgs-nav-drawer-e6cadd86`**
(`grep -o 'sgs-nav-drawer-[0-9a-f]\{8\}' | sort -u` on each saved response). The
uid is `md5( wp_json_encode( $attributes ) . $anchor )`, so an identical uid means
the two paths received byte-identical attributes. This is a separate line of
evidence from the computed-style diff, not a restatement of it.

## What this does NOT claim

- **Not visual fidelity.** Property-identical is not "looks right". How the drawer
  looks closes on Bean's eye (R-31-13), never on this report.
- **Not a claim about the seven looks.** The subject is the DEFAULT drawer only.
  Posts 3685–3691 (the pattern-seeded looks) were not measured here.
- **Not a claim about 768/1440.** Row 10 is an absence, deliberately not rounded
  up into a pass.

## What the comparison tool reports

`scripts/parity/extract-css-diff.js` prints how much it compared: a
`Compared: N element record(s), M property comparison(s)` line in the Markdown
report, a `compared` object in the `--json` output, and the totals on the stderr
coverage line. It exits `3` (EMPTY) when a measured breakpoint compared zero
records, so `0 mismatches` cannot be read as `0 records compared`. Row 2's run
prints `MEASURED 1/1 breakpoint(s), 8 element record(s) / 400 property
comparison(s) compared`. The EMPTY branch itself was not reached in a live run:
the one scope tried (`dialog.sgs-nav-drawer .sgs-nav-drawer__close`) failed the
openness guard first and exited 3 as VACUOUS.

The tool records only text-bearing elements, so its 8 records are fewer than the
27 element records the extended probe (`scripts/nav-qa/extended-probe.mjs`,
row 3) measures. Pair the two on any Gate 2 run.
