## 1. G6 — burger bar size

**Problem.** `.sgs-nav-bar-menu__burger-icon` is a fixed 24x18 box (`nav-bar-menu/style.css`, zero-
specificity defaults, no attribute). The bars span its width and are spaced over its height.

**Design.** Two per-tier length objects on `sgs/nav-bar-menu`: `burgerIconWidth` and `burgerIconHeight`
(`{"type":"object","default":{}}`, empty = today's 24/18). `nav-menu-trigger-css.php` emits
`.{uid} .sgs-nav-bar-menu__burger-icon{width:X;--sgs-nbm-icon-h:Y}` per tier (tier-diffed like
`burgerWidth`), only when set, so an untouched burger (and the two-bar default of 8.5px) is unchanged.
The stylesheet already reads `height:var(--sgs-nbm-icon-h)` and the `line` and two-bar poses derive
their travel from it. The `x` and `x-rotate` poses hard-code `translateY(8px)` (a twin of the 18px
default); they change to `calc((var(--sgs-nbm-icon-h, 18px) - 2px) / 2)`, identical at the default, so
every pose follows the stack height. Controls: "Bar
length" and "Bar stack height" beside Width/Height in the burger panel, on the global device toggle.

## 2. G7 — drawer content at full width

**Problem.** `drawerAlign` (left, center, right) maps to `align-items` on `.sgs-nav-drawer__body`, a
column flexbox, so a container or button row shrinks to its content; nothing can span the drawer.

**Design.** Add `stretch` ("Full width") to the enum and the PHP allow-list in the same commit
(`nav-drawer/render.php` `$allowed_aligns`, `$align_items_map` -> `stretch`, `$text_align_map` -> `start`)
and to `edit.js`'s `ALIGN_ITEMS` map and control. Default stays `left`.

## 3. G8 — a card pinned to a screen corner

**Problem.** Nothing pins an ordinary block to the viewport. The only fixed placements are the
header's own float, `sgs/notice-banner::stickyPosition` and the WhatsApp button.

**Design (recommended A).** `sgs/container` gains `pinToScreen`, a per-tier object whose values are
`off`, `top-left`, `top-right`, `bottom-left`, `bottom-right` (default `{}` = off), and `pinInset`, a
per-tier box (`{top,right,bottom,left}`, default 16px on the pinned sides). Rendered through
`SGS_Container_Wrapper` as `position:fixed` plus the two insets for that corner and
`z-index:calc(var(--sgs-header-z,100) + 1)` (the popover layer the drawer's trigger panel uses).
**Printed at the end of `<body>`, not in place:** a blurred or transformed ancestor (any wrapped block
with `surfaceBlur`, `helpers-surface-ground.php` says so) turns `position:fixed` into ancestor-relative,
so a pinned container's HTML is lifted by a `render_block` filter and printed at `wp_footer`, the same
portal the scrim uses (`helpers-scrim.php`). Works without JavaScript. Hiding
at a tier stays the existing device-visibility settings. Editor: a "Pin to a screen corner" control in
the container's layout panel; the editor canvas shows it in place (not fixed) with a small "pinned"
label, so it never covers the canvas.

**Option B (not recommended).** A header "side card" slot: only works inside the header, and lamalama's
card is independent of the pill (different width, top-right while the pill is centred).

**Risk.** `SGS_Container_Wrapper` renders ~40 blocks (hand-back #9 in THE-MIGRATION-METHOD): the new
output is emitted ONLY when `pinToScreen` resolves to a corner on some tier, so every existing container
renders byte-identical CSS (proved by rendering the canary's container fixtures before and after).
A pinned card can cover content: the corner layer sits under the header's own layer, keeps its own
44px targets, and does not trap focus.

## 4. G9 — scrim over the open panel: NOT a defect (measured 2026-09-27)

With the Indus copy swapped in as the ACTIVE header (header 4461, trapped command, 3777 restored),
every panel (About, Sectors, Brands, Trade, More) is on top at its centre (`elementFromPoint` inside
the panel; panel z-index 100, scrim 99). The agent's reading came from the in-page copy, which is not
the header driving the scrim layer. The hard-coded 101 below is kept as hardening only.

### Original note

The Indus composition agent measured the mega scrim painting ABOVE the open panel on page 4465.
That page shows the copy as page CONTENT, not as the active header; the scrim's z-index is placed one
below `--sgs-header-z`, which the in-page copy does not set. To be re-measured with the copy swapped
in as the active header before anything is designed (rules: prove the cause before the fix), checking
that the open panel carries `[data-sgs-nav-fixed]`. Found regardless: that fixed panel's layer is a
hard-coded `z-index:101` (`nav-bar-menu/style.css`), while the scrim sits at `--sgs-header-z - 1`; a
header with a layer above 100 puts the scrim over the panel. Fix: `calc(var(--sgs-header-z, 100) + 1)`,
identical at the default.

## 7. Two bugs found finishing the Indus panels (causes proven from the code; no design choice)

**G10 — a narrow desktop mega panel stacks its aside below its links.** Every `sgs/mega-panel` root is
an inline-size container (`mega-panel/render.php`, `container-type:inline-size`), and the drawer's
reflow rule is `@container (max-width: 640px){…aside{flex:none;width:100%}}`. A desktop panel of 620px
(Indus About and Trade) is therefore its own "narrow container" and stacks. Fix: emit the
`@container` reflow only when the panel renders inside the drawer (`$sgs_mm_in_drawer`, already known
server-side); the viewport `@media (max-width: 1023px)` reflow is unchanged. Proof: About and Trade's
aside at 300px beside the links at 1440, and still stacked inside the 375 drawer.

**G11 — group-heading rules reach every heading inside a group.** `mega-panel/render.php`
`$heading_sel` and three `mega-panel/style.css` rules use `.sgs-mega-group .wp-block-sgs-heading`
(descendant), so any heading nested deeper in a group takes the group label's style or is visually
hidden. The group's own heading is always a direct child (`mega-group/edit.js` TEMPLATE, printed
straight inside the wrapper by `mega-group/render.php`), so the selectors become `> .wp-block-sgs-heading`.
Proof: a heading nested in a group keeps its own font, size and case; the group label is unchanged.
The Indus copy's row labels then move back from `sgs/text` to `sgs/heading`.
