# U-9 + U-11 design: how a menu closes

## 1. The problem, in plain English

Every way a menu or drawer shuts is currently fixed in code, and some of it is wrong for the
references:

1. **The drawer always prints its own × button**, even where the reference swaps the burger in
   place and the burger is still visible above the drawer (9 of 13 references). Spec 36 FR-36-6 was
   already amended (Step 0b, DEC-15) to allow omitting it in exactly one safe case; the code never
   followed, and the four Step 0b PHP tests were never written.
2. **The × has one fixed position** (top-right, 12px in). halcyon and indus-foods put it over the
   burger's own spot, nudged by a few pixels; butcherbox puts it at the opposite end.
3. **The burger's morph is fixed** at an X in 200ms `ease`. dogstudio spins the X 180 degrees over
   0.6s; lamalama flattens three bars onto one line over 0.45s. No control exists.
4. **`closeStyle` is one value for every screen size.** Spec 36 already says it must be a per-device
   value.
5. **Nothing reacts when the window is resized across the collapse width** with the drawer open
   (`store.js` has no resize handling). DEC-09 fixed the rule: close on crossing, else stay and reflow.
6. **lamalama closes its menu when the page scrolls 30px.** DEC-02 allows this one carve-out. Today
   the drawer always locks page scroll, so a scroll-close could never fire.
7. **Drawer submenus are always one-open-at-a-time** (a named `<details>` group). away opens two at
   once. ENG-02: an `accordionExclusive` switch, default on.
8. **The bar item magnet is on/off only**, at a fixed factor 0.15 capped at 8px. halcyon measures
   0.16, indus-foods 0.14.

M-36 (trigger semantics) and most of M-34 / M-35 (Escape, focus trap, dialog semantics) need no
build: SGS emits the accessible version by design, and DEC-02 records the difference at clone time.

## 4. The design (revised after the council)

All names were checked free in the framework DB (`sgs-db.py sql`, 2026-09-24; only `sgs/modal::closeOnOverlay` is near, and unrelated). `itemMagnetRadius` was dropped (§8).

### 4.1 `closeStyle` becomes a tier object (nav-drawer)

- Values: `separate-x`, `text-swap`, `burger-morph`, `icon-and-text`, and NEW `trigger` ("the menu
  button closes it", §4.2). `block.json`: `{"type":"object","default":{}}`; the PHP allow-list
  `$sgs_nd_allowed_close_styles` validates each tier; a standalone test asserts it equals the option
  list in `edit.js`.
- Cascade: desktop, tablet inherits desktop, mobile inherits tablet; fallback `separate-x`.
- **Stored flat strings are migrated, not assumed to fall through.** WordPress replaces a
  schema-invalid value with the default before `render.php` or the editor sees it (FR-36-6's own
  `object-typed-attr-coerces-flat-to-default` warning), so a flat `"separate-x"` would silently become
  `{}`. The same push runs `scripts/migrate-stored-tier-scalars.py` (the existing Spec 35 S5 tool)
  over stored `sgs/nav-drawer` blocks, rewriting `"closeStyle":"x"` to `{"desktop":"x"}`, with a
  survey before and a zero-remaining check after. The test feeds the real WordPress path
  (`WP_Block_Type::prepare_attributes_for_render`) where the harness allows, otherwise asserts the
  migrator's output shape; no "fallthrough, tested" claim without it.
- Markup: the button renders the inner for each DISTINCT style used across tiers, each in
  `<span class="sgs-nav-drawer__close-variant sgs-nav-drawer__close-variant--{style}">`; scoped CSS
  shows only the active tier's variant. One style everywhere renders exactly today's markup.
- **Per-tier sizing, not only per-tier spans.** Width (`width:auto` for text styles, the `closeSize`
  square for glyph styles), padding and text-transform are emitted per tier inside the 768/1024
  media queries, so a desktop `text-swap` never leaks `width:auto` onto a mobile icon button. Test:
  desktop `text-swap` + mobile `separate-x` gives a mobile computed width of at least 44px.
- Accessible name: if any tier shows a word, `aria-label` is that word (SC 2.5.3 on text tiers, a
  truthful name on icon tiers); otherwise "Close menu". Hidden variants are `display:none`, so they
  leave the accessibility tree.

### 4.2 Presence: the revised FR-36-6 predicate

DEC-15 (b), Bean-approved, says the drawer's × is required "only when no other visible,
keyboard-reachable close control is live". The Step 0b text narrowed that to `closeStyle =
burger-morph`, which misses the three references whose trigger swaps its LABEL (fantasy, lusion,
studionamma). Revised predicate, per tier: the × is omitted only when (1) `modality` is `non-modal`,
(2) `closeStyle` at that tier is `trigger`, and (3) the opener is LIVE. Spec 36 FR-36-6 is amended
to this wording in the same push; the old three-clause text is replaced, not kept beside it.

- **PHP (eligibility, (1) and (2))**: for each tier where both hold, emit inside that tier's media
  query `.{uid}[data-sgs-nav-opener-live] .sgs-nav-drawer__close{display:none}`. Where the × must
  render under `trigger` (not eligible, or not live), it shows the `separate-x` glyph.
- **store.js (liveness, (3))**: the opener is live when its centre point hit-tests to itself:
  `document.elementsFromPoint(cx, cy)[0]` is the trigger or inside it, AND it has client rects. A
  burger painted under the drawer, `visibility:hidden`, `opacity:0` or off-screen fails. This covers
  the two reachable traps the council found: a plain theme header with no `--sgs-header-z`, and a
  site-header `zIndex` of 0 to 2.
- **Order in `openDrawerFor`**: `show()`, then the liveness test and the flag, THEN focus.
  `focusFirstIn` switches to `getFocusable(container)[0]` (the visibility-filtered list), so a hidden
  × is never the focus target (today's raw `querySelector` would pick it and silently fail).
- **Re-checked while open** on `resize` (rAF-throttled): the flag follows liveness. If the ×
  becomes visible it simply appears; if focus sits on the × when it hides, focus moves to the opener.
- **Removed synchronously in `runClose`**, before the exit-animation teardown, so a fast
  close-reopen never sees a stale flag.
- Fail-safe: no JS, no open; JS but no flag, the × shows. Negative control: a header with
  `zIndex: 1` keeps the ×.

### 4.3 Placement (nav-drawer)

- `closePlacement` tier object: `top-row-end` (default, today), `top-row-start`, `same-slot`.
- `same-slot` places the ×'s centre on the opener's centre. store.js measures the opener in
  viewport space and the dialog's REST box (`offsetLeft/offsetTop` of the fixed dialog, which the
  entry transform does not change), writes `--sgs-nav-close-x/-y` on the dialog, and re-measures on
  `resize` and, when the page is not scroll-locked (§4.6), on `scroll`. The precedent is the
  existing `--sgs-drawer-trigger-top` write. No measurement → `var()` fallback to `top-row-end`.
- **`same-slot` requires `modal`.** Under `non-modal` the header paints above the drawer, so a ×
  under the burger would be unreachable by pointer. PHP resolves `same-slot` to `top-row-end` when
  modality is `non-modal`; the editor shows a help line saying so.
- `closeOffset` tier object `{x, y}`, px, -40 to 40. `x` is on the inline axis (mirrors under RTL),
  applied as `translate()` after placement.

### 4.4 Morph motion (nav-bar-menu)

- `burgerMorph`: `x` (default, today), `x-rotate` (X plus a 180 degree turn of the icon box), `line`
  (top and bottom bars move onto the middle bar; the distance is derived from the icon box with
  `calc()`, not a constant), `none` (static).
- `burgerMorphDuration`: ms, default 200, 0 to 1200.
- `burgerMorphEasing`: a NAMED curve from a select, default `ease` (exactly today's value). Options:
  Standard (`ease`), Smooth (theme `default`), Expo out (theme `ease-out`, cubic-bezier(0.16, 1,
  0.3, 1)), Quart out (cubic-bezier(0.165, 0.84, 0.44, 1), dogstudio), Ease in (theme `ease-in`),
  Spring (theme `spring`), Linear; plus "Custom curve" under an Advanced toggle. The custom value is
  validated by an anchored numeric regex (four numbers `-?\d*\.?\d+`, no exponent, x1 and x2 in
  0 to 1) in PHP, and the same regex in `edit.js` shows an inline error instead of silently falling
  back. Labels reuse `AnimationControl.js::EASINGS` where they exist.
- Duration and easing arrive as custom properties in the bar's scoped CSS; the base `transition`
  reads them. The `prefers-reduced-motion` rule keeps winning over a scoped rule. Negative control:
  duration 600 under reduced motion reads `0.01ms`.
- Default glyph only, as today.

### 4.5 Resize across the collapse width (DEC-09)

- The rule keys on the OPENER, not on a media flip: `nav-menu-markup.php` passes `collapsePoint`
  into `sgs_nav_bar_menu_burger_toggle_markup()` (new parameter) and emits
  `data-sgs-nav-collapse="{N}"`; while the drawer is open, store.js watches
  `matchMedia('(min-width: {N}px)')`, and on a change re-runs the §4.2 liveness test and closes
  through `runClose` only if the opener is no longer live. An always-burger bar (collapse above
  every width) never closes on a resize.
- **Focus fallback lives in `onNativeClose`**, so every close route gets it: return focus to the
  trigger if it is live, else to the first live focusable in the header region
  (`HEADER_REGION_SELECTOR`), else the bar's first link. Focus never drops to `<body>`.
- Width only, so iOS address-bar height changes never fire it.
- Guidance (help text on `collapsePoint`): a split menu (buck's two instances) should give both
  instances the same collapse width. Liveness makes a mismatch harmless for the drawer.
- Mega and dropdown panels: out of this rule; `mega-disclosure.js` already closes a reparented panel
  on resize, and a bar that hides takes its panel with it.

### 4.6 Close on scroll (DEC-02 carve-out)

- `closeOnScrollDistance` on nav-drawer, a plain number in px, 0 to 200, default 0 (off). One
  reference, one value: not a tier object.
- When above 0: the page is not scroll-locked (a locked page cannot scroll, so the route could never
  fire; DEC-02's text is amended to say the carve-out drops the lock). The close fires only on
  user-intended pointer scrolling: a `wheel` event, or a `touchmove`/pointer drag, within 150ms
  before the scroll; keyboard scrolling, scroll anchoring and programmatic scrolls never close it;
  `scrollY` is clamped at 0 (iOS overscroll).
- Skipped when `motion-utils.js::isTouchInput()` is true: lamalama's reference closes on scroll with
  a mouse at 768/1440 and did not in its touch context. An input-type rule, not a device tier.
- lamalama's clone: 24 (closes at 30, stays at 8).

### 4.7 `accordionExclusive` (ENG-02)

- `sgs/nav-drawer` boolean, default `true`, passed as context `sgs/navDrawerAccordionExclusive` (the
  existing `submenuModel` route); `sgs_nav_drawer_menu_render_items` omits `name=` when false.
- The control shows only when `submenuModel` is `accordion`; drill-down never reads `name`.

### 4.8 Item magnet strength (M-10)

- `itemMagnetStrength`: the pull factor, 0.02 to 0.5; unset means today's behaviour exactly
  (`initMagnet(el)` with no options: factor 0.15, cap 8px).
- When set: `data-magnet-strength` on the bar `<ul>`; `view.js::initBarEffects` passes
  `{ factor, maxPull: Infinity }`. The pointer is inside the item (the listener is on the item), so
  the pull is naturally bounded by half the item width times the factor, which is what the
  references measure; no invented cap.
- Shown only while `itemMagnetEnabled` is on.

### 4.10 `closeRadius` (nav-drawer, Bean 2026-09-24)

- Tier object of CSS lengths (`sgs_css_length_value`), default `{}` = today's 4px from
  `style.css::.sgs-nav-drawer__close`. Emitted per tier in the scoped CSS on `.sgs-nav-drawer__close`
  (and its focus ring follows the box). Control: `ResponsiveControl` + `SgsLengthControl` in the
  "Close button" panel. halcyon 12px, indus-foods 8px.

### 4.9 Editor controls (same commit as each render)

- nav-drawer "Close button": `closeStyle`, `closePlacement`, `closeOffset` under `ResponsiveControl`
  (global device toggle); help lines: "In a modal drawer the × always shows" (on `trigger`) and
  "Over the menu button needs a modal drawer" (on `same-slot` under non-modal). "Behaviour":
  `closeOnScrollDistance` (`RangeControl`, help naming the trade-off), `accordionExclusive`
  (`ToggleControl`, accordion only).
- nav-bar-menu "Burger": `burgerMorph`, `burgerMorphDuration`, `burgerMorphEasing`; "Effects":
  `itemMagnetStrength` under `itemMagnetEnabled`.
- Canvas preview: the × preview follows the active editor device's `closeStyle`.

## 5. Tests (each with a negative control that fails on the old code)

PHP standalone `tests/php/run-close-control-standalone.php` (the extraction pattern of
`run-nav-drawer-surface-standalone.php`):
- Predicate: modal + `trigger` → no hide rule; non-modal + `separate-x` → no hide rule; non-modal +
  `trigger` → hide rule inside that tier's media query, scoped to `[data-sgs-nav-opener-live]`;
  `trigger` renders the `separate-x` glyph.
- Tier cascade, variant spans, per-tier width (desktop text-swap + mobile separate-x), aria-label.
- Allow-list parity with `edit.js`; `same-slot` under non-modal resolves to `top-row-end`; offset
  clamp; logical-axis offset.
- `accordionExclusive` false drops `name=`, true keeps it.
- Easing: each named option, a valid custom curve, rejected junk (`red;}body{...`, exponents,
  x out of range).
- Magnet: unset emits nothing; set emits the attribute.
- Migration: `migrate-stored-tier-scalars.py` survey/fix on a fixture post turns a flat
  `closeStyle` into `{desktop}`; zero remaining after.

JS (`scripts/tests/`, minimal DOM stub): liveness (covered opener fails, visible passes); resize
crossing closes only when the opener is gone (always-burger stays open); scroll close fires on
wheel-led scroll past the distance, not on a keyboard scroll or an 8px scroll; focus fallback when
the trigger is hidden.
