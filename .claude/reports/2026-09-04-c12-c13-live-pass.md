# C12/C13 — completed

The first attempt (documented in the superseded version of this report) was blocked by the
shared Playwright MCP browser being locked by another concurrent session. Re-run using a
separate Chrome instance (the `superpowers-chrome` browsing skill, its own profile/port —
does not contend with Playwright's shared profile), against a scratch draft page
(`page_id=3265`, created via REST API, deleted after the pass — never touched live content).

## Method

Created a draft page carrying all 15 C12 target blocks (the 10 C6 `ToolsPanel` conversions +
the 4 C7 decorative-image/ARIA blocks + `sgs/hero`), opened it in the block editor, and ran a
JS a11y audit function against each block's `InspectorControls` panel in turn (focusable-element
enumeration, contrast computation via WCAG relative luminance, `aria-describedby` wiring
check). Followed with live CDP keyboard `Tab` presses (not just static attribute inspection)
on the most complex sample block to confirm real traversal. For C13, added the 5 remaining
direct-panel blocks from the earlier ground-truth table (`sgs/form-field-email`,
`sgs/business-info`, `sgs/quote`, `sgs/process-steps`, `sgs/nav-menu`) and extracted the live
DOM order of panel headings for all 12 direct-panel blocks.

## C12 — keyboard, contrast, aria-describedby: PASS with one real, correctly-attributed finding

**Keyboard navigation**: 0 positive `tabindex` values (the real anti-pattern) across all 15
blocks. Every "negative tabindex on a visible control" hit was a legitimate WAI-ARIA
roving-tabindex widget — either a `role="tab"` in a tablist (WP core's own Styles/Settings
tab switcher) or a `ToggleGroupControlOptionBase` button (WP core's `ToggleGroupControl`) —
both correct, standard patterns where only the active option is tabbable and the rest are
reached via arrow keys, not bugs. Live-verified with 5 real CDP `Tab` key presses on
`sgs/nav-drawer` (18 focusable elements, includes a `ToggleGroupControl`): focus moved
forward through 5 distinct elements (variation-transforms button → style tab → toggle-group
option → further into the panel → a text input), staying inside the panel throughout, no
trap, no escape to `<body>`.

**Contrast**: 0 findings across all 15 blocks, sampled across every distinct label/button/
heading class combination in each panel (WP core's own admin UI palette; no SGS control
introduces a custom low-contrast text/background pairing).

**`aria-describedby`**: 1 real finding — `sgs/multi-button`'s max-width `UnitControl` has a
help-text paragraph with an `id`, but the control's own unit `<select>` (px/%/em/rem
dropdown) doesn't reference it via `aria-describedby`. **Correctly attributed**: this is WP
core's own `@wordpress/components` `UnitControl` internal sub-element, not something SGS's
`SgsLengthControl` wrapper built or can fix without patching a core component — the MAIN
number input of the same control does carry the association correctly. Worth a note upstream
if raised with the Gutenberg project; not an SGS defect to "fix" locally.

## C13 — panel ordering: the one currently-ENFORCED rule PASSES on all 12 sampled blocks

Sampled: `sgs/form-field-email`, `sgs/form-field-checkbox`, `sgs/form-field-date`,
`sgs/form-field-select`, `sgs/info-box`, `sgs/text`, `sgs/decorative-image`,
`sgs/social-icons`, `sgs/business-info`, `sgs/quote`, `sgs/process-steps`, `sgs/nav-menu`.

**Rule 3 (Advanced always last, Visibility conditions always second-from-last) — the only
rule Spec 35's own convention currently enforces (via `rules/35-pinned-panel-position.js`)
— holds live on all 12/12 blocks, no exceptions.**

**Rules 1-2 (DOM top-to-bottom element order; root Styles→Colour→Typography) are recorded
but deliberately UNENFORCED** per Spec 35 §"THE ORDER CONVENTION" and CO-28, pending the
placement backlog (58 of 83 blocks still lack a `group` prop). Live panel composition
confirms this is the current, expected, known state — most sampled blocks render
property-family panels (Width / Spacing / Layout / Appearance) rather than the full
per-element breakdown named in the earlier ground-truth table (Card box / Card content /
Icon-media, etc.) — this is the documented backlog, not a regression this pass found. Full
live composition, for reference against a future re-run once more of the backlog closes:
