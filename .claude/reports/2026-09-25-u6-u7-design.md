# U-6 + U-7 design: new item markup

Wave 3C, lane A, pair U-6 + U-7 (plan `.claude/plans/2026-09-21-wave-3c-implementation-plan.md` section 4,
"Pairs and lanes"). Families M-30, M-24, M-25 (U-6) and M-22, M-15 (U-7). Bean column: `eye` for U-6, `none`
for U-7; the gate is this note, the council (section 7) and Bean's sign-off on the pair.

Bean's standing direction (2026-09-24, U-3 + U-8): a mega panel post (`sgs_mega_menu`) and the drawer body take
any blocks, so anything that is really a layout ships as a structured starter pattern, never as a new
attribute. Only what the menu blocks themselves draw gets settings. Every cell below is routed one of three
ways: **attribute** (the menu or list block draws it), **pattern** (a layout of existing blocks), or
**residue** (named, with an owner).

## 1. The problem

Five things a reference does to its menu items cannot be expressed today:

1. **A mega item in the drawer shows its panel.** `nav-menu-markup.php::sgs_nav_drawer_menu_render_items`
   turns a mega item into a plain link (Spec 36 FR-36-6 "Mega items in the drawer": NOT BUILT). away's drawer
   opens NEW ARRIVALS into a titled link group plus two image tiles, which is exactly the content of its
   desktop mega panel post.
2. **Sibling dim.** Every hover attribute repaints the item being hovered. wearecollins and resn change the
   *other* items: the hovered one holds, its siblings dim. Nothing repaints a sibling.
3. **Two-copy label roll.** lusion's drawer text rolls up to a copy of itself; studionamma's trigger rolls
   MENU to OPEN on hover and to CLOSE when open; studionamma's footer links carry two copies of their text. No
   menu or list block emits a second label.
4. **Per-item ornament.** An index number (dogstudio's drawer 01–05 at 1440 only), a decorative leading glyph
   on every primary drawer row (buck, lamalama), a chosen expander glyph (lamalama's asterisk; today the
   drawer's expander is a hardcoded `chevron-down`), and leading-zero numbers on panel rows (indus-foods).
5. **Per-item media.** studionamma's drawer grows a thumbnail beside the hovered link. No menu item carries
   an image.

Row separators (M-30) turned out to need no new setting: Spec 41 FR-41-36 already defines the drawer's
bottom `itemBorderWidth` edge as the row separator and gives dropdown rows a 1px `submenuLinkBorder*`
separator by default. M-30's work is to prove that live.

## 3. The design

### 3a. The mega panel inside the drawer (route 1; Spec 36 FR-36-5, FR-36-6)

Spec 36 says this "needs its own JS-driven build". It does not: the panel is server-rendered block content, and
the drawer's accordion is a `<details>`. Rendering the panel into the `<details>` body needs no new JS.

- **Markup.** For a mega item, `sgs_nav_drawer_menu_render_items` builds the same accordion row a dropdown item
  gets (label or link, `<summary>` expander, `<details name>` honouring `accordionExclusive`), and its body is
  `<ul class="sgs-nav-drawer-menu__submenu" data-sgs-drill-panel><li class="sgs-nav-drawer-menu__mega-body">{panel}</li></ul>`.
  Keeping the `ul.sgs-nav-drawer-menu__submenu` means `shared/effects/nav-drilldown.js` (which requires that
  element and prepends a Back `<li>` to it) works unchanged in drill-down mode.
- **One path for both forks.** The bar's mega branch builds its "View all" fallback, registers the
  `sgs_mega_panel_footer_html` filter, renders and removes the filter inline. That moves into one helper in
  `includes/helpers-mega-render.php`, `sgs_mega_render_item_panel( array $item, string $viewall_class, string $context )`,
  called by both forks. `nav-menu-markup.php` (already over length) shrinks rather than grows.
- **The panel drops its floating shell in the drawer.** `mega-panel/render.php` names its instance class from a
  hash of its attributes, so a bar copy and a drawer copy would share one class and one stylesheet. The render
  context (`''` for the bar, `drawer` for the drawer) is a second parameter,
  `sgs_mega_render_panel_content( int $panel_id, string $context = '' )`, pushed onto a static stack before
  `do_blocks()` and popped in the same `finally` that clears the recursion guard (the same shape as
  `$sgs_mega_rendering`), and read by `mega-panel/render.php` through `sgs_mega_render_context()` (top of the
  stack). A stack, not a set-and-reset, so a panel nested inside a panel with a different context cannot leak.
  `mega-panel/render.php` then (a) folds a non-empty context into the hash, so the drawer copy gets its own
  class and the bar copy's class is unchanged (the CSS registry dedupes by the hash of the whole CSS string,
  `class-sgs-css-registry.php::sgs_collect_css`, so both copies emit), and (b) in the drawer context emits no
  shell: no fill (including the gradient and both dark-scheme fill rules), border, border-gradient `::before`,
  radius, shadow, backdrop, `max-width` or panel padding, and no `cards` group hover glow
  (`$style_crd . $rel_group . '::after'`). `container-type:inline-size` STAYS: the `@container (max-width: 640px)`
  stack rule in `mega-panel/style.css` depends on it. The content shape (columns, cards, aside) and the accent
  colours stay. Text colour follows the drawer
  (`--sgs-mm-text` and `--sgs-mm-muted` resolve from `currentColor`), so a dark-scheme panel never paints
  light text on a light drawer.
- **Two kinds of panel post, one rule each.** The shell removal above applies to a post rooted in
  `sgs/mega-panel`. The U-8 patterns (`sgs/mega-links-with-tiles`, `sgs/mega-compact-links`) are rooted in an
  `sgs/container` that carries its own paint, which the context branch never sees. They are drawer-safe by an
  authoring rule, written into every mega pattern's header comment and Spec 36: paint (padding, width cap,
  fill) on the desktop tier only, never an explicit text colour, and `columns` set per tier including mobile.
  A container authored desktop-only resolves its mobile columns through `sgs_resolve_tier()`; the test asserts
  the fallback a four-card grid gets at the mobile tier. The `sgs/mega-panel` preset already stacks itself
  narrow through its `@container (max-width: 640px)` rule; the drawer branch leaves that rule alone.
- **Markers follow the drawer.** `sgs/icon-list` paints its number marker as
  `var(--sgs-list-marker-colour, <numberColour>)`; the drawer sets `--sgs-list-marker-colour` on
  `.sgs-nav-drawer-menu__mega-body` from its existing `sublinkMarkerColour` when that is set. The drawer's "sub
  item marker colour" then governs every marker drawn as a sub-item, its own chevrons and an embedded panel's
  numbers alike (row 19). Two consequences: the drawer's value beats the list's own `numberColour` (the only
  channel for one post showing blue numbers on desktop and gold in the drawer), and `numberColour`'s help text
  says so; and the `sublinkMarkerColour` row, which `nav-drawer-menu/edit.js::sublinkMarkerIconIsCustom` reveals
  only once the chevron glyph is changed, is also revealed when `megaDrawerMode` is `panel`.
- **The setting.** `nav-drawer-menu.megaDrawerMode`: `panel` (default) | `link` (today's behaviour). Precedence:
  an item listed in `megaDrawerFallbackIds` that has real nested children keeps its children accordion; else
  `panel`; a panel that resolves to null (trashed, recursion guard) degrades to a plain link as today. PHP
  allow-list mirrors the JSON enum. Inspector: a `ToggleGroupControl` in the drawer menu's settings panel.
- **Recursion.** Both copies go through `sgs_mega_render_panel_content`, whose static guard is per call stack,
  so the bar render and the drawer render are sequential, not nested, and the guard behaves as today.

### 3c. Sibling dim (M-24) — one shared rule on three blocks

New `includes/helpers-item-effects.php` (bootstrap-loaded through `render-helpers.php`, `function_exists`-guarded):

`sgs_sibling_dim_css( string $list_sel, string $item_sel, string $paint_sel, array $attributes ): string` emits,
only when `siblingDimColour` or `siblingDimOpacity` is set:

```
/* hover: touch-guarded */
sgs_hover_media_wrap( SGS_HOVER_NOT_TOUCH . ' ' . '{list_sel}:has(> {item_sel}:hover) > {item_sel}:not(:hover) {paint_sel}' . '{…}' )
/* keyboard: its own rule, unguarded */
{list_sel}:has(> {item_sel}:has(:focus-visible)) > {item_sel}:not(:has(:focus-visible)) {paint_sel} { … }
/* both */
{list_sel} > {item_sel} {paint_sel} { transition: color <d>ms <easing>, opacity <d>ms <easing>; }
```

Declarations: `color: <siblingDimColour>; opacity: <siblingDimOpacity>` (each only when set). The hover rule is
built by hand and wrapped with `sgs_hover_media_wrap()`, never passed to `sgs_hover_guarded_rule()`: that helper
`explode()`s its selector on every comma, so a comma inside `:has()`/`:not()` would split mid-selector
(`includes/helpers-hover-state.php::sgs_hover_guarded_rule`). This is the precedent in
`button/render.php` and `nav-menu-css.php`'s FR-41-13 keyboard `:has()` rule. The keyboard half is a separate,
unguarded rule keyed on `:focus-visible`, never `:focus-within`: tapping an accordion `<summary>` leaves focus
inside its `<li>`, and a `:focus-within` rule would hold every other row dimmed while that accordion is open. The rule is list-scoped by
construction (`> item`), which is exactly wearecollins' "each group dims independently". Colour through
`sgs_colour_value()`; duration through the same clamp U-5 uses; easing through
`helpers-motion-easing.php::sgs_motion_easing_css`.

Attributes, identical names on `sgs/nav-drawer-menu` and `sgs/icon-list` (`itemMotionDuration`/`itemMotionEasing`
also on `sgs/nav-bar-menu`, where they time the label roll):

| Attribute | Type / default | Meaning |
|---|---|---|
| `siblingDimColour` | string, `""` | Text colour of the non-hovered siblings. Colour row via `SgsColourPanel` |
| `siblingDimOpacity` | number, unset | 0 to 1 opacity of the non-hovered siblings |
| `itemMotionDuration` | number (ms), unset → 300 | ONE item-motion time shared by sibling dim, label roll and the ornament crossfade |
| `itemMotionEasing` + `itemMotionEasingCustom` | string, `""` | The shared speed-curve list (U-5 pattern, as `burgerMorphEasing`) |

Neither menu block has any item hover duration today, so the shared pair is new, not a duplicate; one pair
instead of one per effect saves three attributes and gives lamalama's glyph crossfade (row 20) its 0.65s.

**Not on the bar (Bean, 2026-09-25):** no reference dims bar items, so `sgs/nav-bar-menu` gets no sibling-dim
attributes. They live on `sgs/nav-drawer-menu` and `sgs/icon-list` only.

### 3d. Label roll (M-25) — a second copy, drawn only when asked for

Same helper file: `sgs_label_roll_markup( string $text, string $roll, string $alt_hover = '', string $alt_open = '' ): string`
returns the plain escaped text when `$roll` is empty (no DOM cost for everyone else), else the copies below.
Copy `b` is emitted on menu items always (it repeats the text), but on the trigger only when `triggerHoverLabel`
is set (lusion's trigger has no hover roll, and MENU rolling to MENU would be noise). Copy `c` exists only on
the trigger when `triggerOpenLabel` is set.

```
<span class="sgs-roll sgs-roll--{up|up-scale}">
  <span class="sgs-roll__a">Text</span>
  <span class="sgs-roll__b" aria-hidden="true">{alt_hover ?: Text}</span>
  [<span class="sgs-roll__c" aria-hidden="true">{alt_open}</span>]
</span>
```

and `sgs_label_roll_css( string $scope_sel, string $hover_sel, string $open_sel, array $attributes )` emits the
per-instance motion: `.sgs-roll` is `display:inline-grid; overflow:clip` with every copy in one grid cell, so
the box is exactly one line tall, descenders stay inside, and no absolute positioning is needed; the copies sit
at `translateY(0 / 100% / 100%)`. On hover (guarded) or focus-visible of `$hover_sel`, `a` goes to
`translateY(-100%)` (`up-scale` adds `scale(0.8)`; origin from the live capture, row 14) and `b` comes to 0.
When `$open_sel` matches (the trigger's `[aria-expanded="true"]`), `c` comes to 0 and `a`/`b` leave, and open
beats hover (studionamma's "CLOSE CLOSE"): the open rules out-specify the hover rules. Under
`prefers-reduced-motion: reduce` the copies swap with no transform (`transition: none`).

Accessible name (WCAG 2.5.3 Label in Name): on menu items the copies repeat the same text, so copy `a` is the
name and `b` is `aria-hidden`. On the trigger the visible word changes, so the name must follow it: `store.js`,
which already sets `aria-expanded` on the trigger, also moves `aria-hidden` from `c` to `a` on open and back on
close; the button carries no `aria-label` in `text` mode, so its name is whichever copy is not hidden. The hover
word (`b`) stays `aria-hidden`: hover does not change the control's meaning, and a keyboard user never sees it
without focus, where the name is still the resting word.

Where it renders:

| Surface | Block | Label passed through the helper |
|---|---|---|
| Bar items | `sgs/nav-bar-menu` | the three `__link-text` / `__label` spans in `sgs_nav_bar_menu_render_items` (inside the magnet target, so the magnet moves the whole roll) |
| Trigger | `sgs/nav-bar-menu` | the visible word in `sgs_nav_bar_menu_burger_toggle_markup`, with `triggerHoverLabel` and `triggerOpenLabel` |
| Drawer items | `sgs/nav-drawer-menu` | the `__link-text` spans in `sgs_nav_drawer_menu_render_items` |
| Footer and any list | `sgs/icon-list` | each item's text |

Attributes (identical names on the three blocks): `labelRoll` (`""` | `up` | `up-scale`, default `""`,
PHP-validated), timed by the shared `itemMotionDuration`/`itemMotionEasing` (3c). On `sgs/nav-bar-menu` only:
`triggerHoverLabel` and `triggerOpenLabel` (strings, `""`; empty means no such copy), shown in the trigger panel
when `triggerMode` shows text. `triggerOpenLabel` is the name Spec 36 FR-36-27 already reserves; this pair
builds FR-36-27's `swap-label` open style as "set `triggerOpenLabel`" and amends FR-36-27 to say so.

### 3e. Ornament and expander (M-22) — `sgs/nav-drawer-menu` only

No reference draws an ornament on the bar, so only the drawer menu gets these (the bar keeps `submenuCaret`).

| Attribute | Type / default | Meaning |
|---|---|---|
| `itemOrnament` | tier object `{}` of `none` / `index` / `icon` | What leads each primary row, per tier (dogstudio: index at desktop only) |
| `itemOrnamentIcon` | icon object, `{}` | The glyph for `icon` (source-aware resolver, as `sublinkMarkerIcon`) |
| `itemOrnamentIconHover` | icon object, `{}` | Optional hover glyph; the two crossfade (lamalama) |
| `itemOrnamentSize` | tier object `{}` of lengths | Glyph box, or the number's font size for `index` |

| `itemOrnamentGap` | string, `""` | Space between the ornament and the label |

### 3f. Per-item media (M-15, M-22) — `sgs/nav-drawer-menu` only

The data source is the one each menu item already carries: a link to a page or post has `type` and
`object_id` (`from_link()`), so its thumbnail is that post's featured image. No new per-item data, and a client
changes a thumbnail by changing the page's featured image. Custom links have none and render no media.

| Attribute | Type / default | Meaning |
|---|---|---|
| `itemMedia` | `""` / `featured-image`, default `""` | Source |

Markup: `<span class="sgs-nav-drawer-menu__media" aria-hidden="true"><img alt="" loading="lazy" …></span>` after

## 7. Risks

1. **Two renders of one panel.** A panel now renders in the bar and in the drawer on the same page: an HTML
   `id` inside panel content (a block anchor, a form) appears twice, and interactive blocks inside a panel
   initialise twice. CSS: the registry lifts every sgs block's `<style>` and dedupes by the hash of the CSS text
   (`class-sgs-css-registry.php::sgs_collect_css`), so inner blocks with identical settings emit once; only the
   `sgs/mega-panel` root's CSS (a different class in the drawer) is added. Section 8 measures the page's CSS
   against the 100 KB budget on the away fixture. Mitigation: the drawer copy's content is inside a closed `<details>` and `inert` handling
   is the drawer's; the test asserts no duplicate `id` in the rendered page with the away fixture's panel. A
   panel that holds a form is named as unsupported in the drawer in Spec 36 (set `megaDrawerMode = link`).
2. **Contrast of dimmed siblings.** `#4c4c4c` on wearecollins' black is about 2.5:1 while another item is
   hovered. It is a transient state, the hovered item keeps full contrast, and a11y checks are informational
   here (memory: a11y validation informational), so the inspector shows the contrast warning the colour row
   already shows; no clamp.
3. **Roll clipping.** `overflow: clip` on the roll box could clip a focus ring or the magnet. The ring sits on
   the link, outside the roll box; the roll box sits inside the magnet target, so the magnet moves it whole.
   Checked live at 1440 with keyboard focus.
4. **Hover-only media.** Bean's taste rule says nothing should appear only on hover. The media is decorative,
   defaults to `none`, `always` is offered, and keyboard focus reveals it too. Named so Bean can veto `hover`.
5. **Drawer text colour in an embedded panel.** Making the panel's text follow the drawer changes a dark-scheme
   panel's text in the drawer. That is the intent (a drawer is one surface), and the accent colours (icon
   chips, numbers via `numberColour` unless the drawer overrides) stay.
6. **Scope.** About twenty-four new attributes across four blocks (after merging the per-effect motion pairs
   and dropping the bar's sibling dim) is the largest pair so far. Every one traces to a cell above.
