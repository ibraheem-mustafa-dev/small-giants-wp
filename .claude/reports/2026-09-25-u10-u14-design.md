# U-10 + U-14 design: header-row structure

Wave 3C lane A, pair U-10 + U-14 (plan `.claude/plans/2026-09-21-wave-3c-implementation-plan.md` §4 rows 9 and 12).
Families: M-19 (U-10), M-52, M-39 residue (b), M-08 (U-14). Crosses the Spec 36 / Spec 37 boundary, so both
specs change in the build commit. Status: **council GO WITH FIXES (fixes folded in, §7); awaiting Bean's sign-off.**

## 1. The problems

1. **M-19, role migration.** A non-menu header block (a CTA, a search icon, Help/Log in links) moves into the drawer
   at some widths. Bean's route (plan row 9): a copy of the block in the drawer body, the header copy hidden with the
   device-visibility extension (`includes/device-visibility.php::inject_device_visibility_classes`,
   `sgsHideOnMobile/Tablet/Desktop`). That works whenever the burger appears at a device-tier edge (767/1023). It
   cannot express "hide it when the burger shows" at any other collapse point: Eye Care collapses at 1060px
   (`sites/eye-care-ward-end/build/header.tree.json`, `collapsePoint: 1060`).
2. **M-52, band pass-through.** dogstudio, lamalama, resn and studionamma float the header over the page: the band
   takes no space and no clicks, only its own controls do. `sgs/site-header` has no such mode: Transparent is
   `position:absolute` (overlays, but scrolls away), Sticky/Float are `position:sticky` (pinned, but take their height
   in the page), and there are zero `pointer-events` rules.
3. **M-39 residue (b), the surface trigger (DEC-14).** lamalama: "the whole 50px pill is one click target:
   div.absolute.inset-0.js-menu-toggle covers the bar; cursor pointer". SGS's trigger is always a discrete button.
   Residue (a), per-tier `triggerMode`, is already built (44c949301).
4. **M-08, the detaching chip.** buck: "The header is not the sticky element, the burger is." The header scrolls away;
   past a threshold the burger reappears as a fixed round chip. Every SGS scroll behaviour acts on the header or a row.

## 3. The design

### 3a. U-10: "When the menu collapses to a burger" visibility

One new universal attribute beside the three device toggles, registered in
`src/blocks/extensions/responsive-visibility.js::addVisibilityAttributes` (and so in
`includes/extension-attributes.generated.php` by the `prebuild` generator `scripts/generate-extension-attributes.js`):

- `sgsCollapseVisibility`: string, `''` (default, always shown) | `hide` (hidden while the header's menu shows its
  burger) | `only` (shown only while it does). PHP allow-list in `device-visibility.php`.
- **Class.** `device-visibility.php::inject_device_visibility_classes` adds `sgs-hide-collapsed` or
  `sgs-only-collapsed` to the wrapper, the same way as the tier classes (the Tag Processor path, skipping leading
  `<style>`). Static blocks get it from `addVisibilityClasses`.
- **The rule is written by the header, from its own menu.** `sgs/site-header`'s `render.php` walks
  `$block->parsed_block['innerBlocks']` recursively for the `sgs/nav-bar-menu` that owns the burger (`showBurger`
  true; `collapsePoint` sanitised exactly as `render.php::$sgs_nm_collapse_point`, default 768) and appends to its
  own scoped CSS: `@media (max-width:N-1px){.{header-uid} .sgs-hide-collapsed{display:none !important}}` and
  `@media (min-width:Npx){.{header-uid} .sgs-only-collapsed{display:none !important}}`. No `:has()`, one width, and
  the rule lives in the header's own `<style>`, which `class-sgs-css-registry.php::sgs_lift_block_css` lifts to
  `<head>` (no flash). No burger-owning menu: no rule, everything shows (more content, never less). Not emitted
  from the shared `nav-menu-submenu-css.php::sgs_nav_shared_submenu_css`, which `sgs/nav-drawer-menu` also calls.
- **Scope.** The drawer lives in `wp_footer`, outside the header, so drawer copies are never hidden by it.
- **Editor.** A `SelectControl` "When the menu collapses to a burger" (Always show / Hide / Show only then) under the
  device toggles in `conditional-visibility.js`, shown only when the block has an `sgs/site-header` ancestor
  (`getBlockParentsByBlockName`). Like the tier toggles, the canvas does not hide the block; the existing hidden-block
  indicator (reduced opacity, dashed outline) marks it. Both copies of the indicator predicate
  (`responsive-visibility.js` and `conditional-visibility.js`) learn the new attribute.
- `scripts/check-universal-fit.js` lists the attribute under the `responsiveVisibility` extension.
- Tier-aligned migrations (every reference cell above) keep using `sgsHideOnMobile/Tablet/Desktop`.
- Site Info blocks (`sgs/business-info`, `sgs/button` `linkSource`) read one source, so two copies carry no duplicate
  data.

### 3b. U-14 part 1: `headerPassThrough` (M-52)

`sgs/site-header` gains `headerPassThrough`, a tier tri-state object `{desktop,tablet,mobile}` of `on`/`off`, the
same shape and `ResponsiveTriStateControl` as `headerSticky`. Label "Float over the page"; help "The header takes no
space and pins to the top. Clicks on its empty band reach the page underneath; its blocks still work."

At an ON tier:
- **Takes no space and stays pinned.** A new first entry in the `sgs_merge_tri_state_declarations` list (precedence
  Pass-through > Float > Sticky > Transparent; first listed wins a shared property, and Transparent still adds its own
  `background`): `position:fixed; top:calc(var(--wp-admin--admin-bar--height, 0px) + var(--sgs-header-float-inset-top, 0px));
  left:0; right:0`. The admin-bar term only exists when the bar renders, so visitors are untouched and a logged-in
  operator's header is not hidden under it. Float's width and centring survive; Hide on scroll's `translateY` works
  (`header-behaviours/view.js::isHeaderPinned` already counts `fixed`), and `--sgs-header-height` keeps publishing.
  `view.js::findStickyBreakingAncestor`'s warning is extended to pass-through tiers (a `data-sgs-header-pass-through`
  flag beside `data-sgs-header-sticky`), since a transformed ancestor breaks `fixed` too.
- **Lets clicks through, structurally.** Only the structure passes clicks: `pointer-events:none` on the header root,
  `.sgs-site-header-row`, `.sgs-container__inner`, and the menu's own frame (`.sgs-nav-bar-menu`, `__bar`, its list).
  `pointer-events:auto` returns on every row child that is not the menu (`.sgs-site-header-row > :not(.sgs-nav-bar-menu)`,
  `.sgs-container__inner > :not(.sgs-nav-bar-menu)`) and on the menu's `__item`, `__toggle-wrap`, `__submenu-wrap`
  and `__mega-panel-wrap`. Any block a client drops in keeps its whole box (search results, a cart flyout, a custom
  block); only the empty band and the gaps between menu items pass through: dogstudio's "none on the band, auto on
  logo and burger". Keyboard access, landmarks and focus are untouched.

### 3c. U-14 part 2: `triggerSurface` (M-39, DEC-14 amended)

**Amendment to DEC-14 (both council members agree):** a separate attribute instead of a fourth `triggerMode` value.
`triggerMode` chooses what the button SHOWS (icon, word, both); the surface chooses how big its HIT AREA is. A fourth
value would force one presentation and collide with `block.json`'s `disallowedValues: ["icon"]` gating.
`sgs/nav-bar-menu` gains `triggerSurface`, a tier object of `on`/`off`, label "Whole row opens the menu", help "The
whole header row becomes the menu button; other blocks in the row keep their own clicks", in `BurgerPanel.js`.

At an ON tier, below the collapse point (the only place the burger shows, so the bar's panels are not in play; all
rules below sit inside the collapse media query and the tier's media query):
- The burger's `::after` stretches over its `.sgs-site-header-row` (`content:""; position:absolute; inset:0;
  cursor:pointer`), lamalama's `inset-0` overlay. Being part of the button, a click on it IS a click on the button:
  the same `toggleDrawer`, focus return and `aria-expanded`; no JS. The row is the containing block
  (`position:relative`); `__toggle-wrap` and the nav root are `position:static`.
- **Magnet.** A transform on the burger would make the button itself the `::after`'s containing block
  (`assets/css/fx-magnet.css` puts `transform: translate(var(--magnet-x), var(--magnet-y))` and `will-change` on
  `[data-sgs-fx="magnet"]`, even at rest). At surface tiers the burger gets `transform:none; will-change:auto` and the
  translate moves to its `__burger-icon` and `__burger-text` children; the runtime writes custom properties, which
  inherit, so no JS change.
- Other row children sit above the overlay: `.sgs-site-header-row > :not(.sgs-nav-bar-menu)` and
  `.sgs-container__inner > :not(.sgs-nav-bar-menu)` get `position:relative; z-index:1` (the menu is excluded, or it
  would become the containing block again).
- With pass-through on, the overlay inherits the button's `pointer-events:auto`, so the whole row catches clicks:
  right for a pill, and the help text says so.

### 3d. U-14 part 3: the detaching chip (M-08)

`sgs/nav-bar-menu` gains:

| Attribute | Type / default | Meaning |
|---|---|---|
| `triggerDetach` | tier object `on`/`off`, `{}` | The burger reappears as a fixed chip once its header scrolls away |
| `triggerDetachAfter` | tier object px, `{}` | Also wait until this far down the page (unset: as soon as the burger leaves the screen) |
| `triggerDetachSize` | tier object px, `{}` (56) | Chip diameter; never below 44 |
| `triggerDetachOffset` | tier object `{x,y}` px, `{}` (`{x:20,y:20}`) | Distance from the top (`y`) and the inline-end edge (`x`, emitted as `inset-inline-end`) |
| `triggerDetachRadius` | string, `9999px` | Corner rounding |
| `triggerDetachBackground`, `triggerDetachBackgroundHover` | colour slug strings, `''` | Chip fill (`SgsColourPanel`, `linked` wired); the glyph keeps the burger's own colours |
| `triggerDetachZIndex` | number, 110 | Stacking; above the header's default 100 |

- **Rendered outside the header, from the burger's own markup.** Rows carry `will-change: transform`
  (`assets/css/header-behaviours.css::.sgs-row-behaviour`) and Hide on scroll uses `transform`; either makes a
  `position:fixed` child scroll with the header. So the menu's `render.php` builds a second copy by calling
  `sgs_nav_bar_menu_burger_toggle_markup()` with a new wrapper-class parameter (`sgs-nav-bar-menu__detach-wrap`
  instead of `__toggle-wrap`, so the collapse switch never shows it), wraps it in `<div class="{uid} sgs-nav-bar-menu">`
  so every uid-scoped burger rule (colour, size, morph, label roll) applies, and hands it to a new
  `includes/nav-detach-chip.php` collector printed on `wp_footer` (the `helpers-scrim.php::sgs_scrim_queue` /
  `sgs_scrim_print_footer` pattern) through `wp_interactivity_process_directives()` (first use in the plugin; WP core,
  the canary runs 7.1). One markup path means the chip carries `data-sgs-nav-collapse` (DEC-09 resize-close),
  `data-wp-init="callbacks.pruneDanglingAriaControls"`, `aria-controls`, the accessible name and the 44px floor.
  **Not** `class-sgs-floating-ui-renderer.php`: its container is `aria-hidden`.
- **One open state per drawer.** Today `store.js::state.isOpen` reads each opener's own context, so a second opener
  would read `aria-expanded="false"` while the drawer is open (WCAG 4.1.2). The store gains `state.openByRef`, keyed
  by `drawerRef` and set in `openDrawerFor` and the close path; `get isOpen()` returns `!! state.openByRef[ctx.drawerRef]`;
  `openDrawerFor`'s early return checks `drawer.open`. Every opener of one drawer (burger, chip) reads one truth.
- **Shown only when needed.** `src/shared/nav-interactivity/detach-chip.js` (imported by the store) runs one
  `requestAnimationFrame`-batched predicate from an `IntersectionObserver` on the header burger plus the scroll
  position: the chip wrapper gets `is-detached` when the burger is off screen AND `scrollY >= triggerDetachAfter` at
  the current tier. CSS keeps the wrapper `display:none` otherwise, at tiers where `triggerDetach` is off, and under
  `@media (min-width:N)` (at or above the collapse point the header burger is `display:none`, which the observer
  would read as "off screen"). `top` adds `var(--wp-admin--admin-bar--height, 0px)`. No transition unless outside
  `prefers-reduced-motion`. A sticky header's burger never leaves the screen, so the chip never shows there. No JS:
  the chip never shows and the header burger still works.
- **Focus.** The store returns focus to its `trigger` argument, so closing returns to the chip; while hidden the
  chip is `display:none`, out of the tab order. `close-control.js::isOpenerLive` is geometry-based, so under a
  non-modal drawer the chip above the panel counts as a live opener and the × rule works unchanged (buck's
  close-in-place).

## 6. Risks

1. **Pass-through covers the page top** where the page has no top padding: the reference's intent (dogstudio,
   lamalama); the hero's own padding is the operator's lever, stated in the help text.
2. **`position:static` on the nav root at surface tiers** is safe only because the bar and its panels are hidden
   below the collapse point; test (4) asserts the rule sits inside the collapse query.
3. **`wp_interactivity_process_directives()` has no precedent here**; live test (d) proves the chip's directives
   fire (the drawer opens and `aria-expanded` binds), not only that the markup is right.
4. **`openByRef` touches the shared store**; every existing opener keeps working because it only changes where
   `isOpen` is read. The U-9/U-11 PHP and JS tests re-run in the build.

## 8. Bean's decisions (2026-09-25)

1. §3 signed off: go.
2. DEC-14 amended: the separate `triggerSurface` attribute, not a fourth `triggerMode` value.
3. Eye Care's phone keeps its 1160px rule in Additional CSS. That width is where its bar stops fitting (no overlap,
   wrap or overflow), a content-width fact, not the collapse point (1060px), and a rare one-off, which is what
   Additional CSS is for; `sgsCollapseVisibility` is the wrong tool for it.
