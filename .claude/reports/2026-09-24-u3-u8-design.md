# U-3 + U-8 design: where a surface sits

Wave 3C, lane A, pair U-3 + U-8 (plan `.claude/plans/2026-09-21-wave-3c-implementation-plan.md` section 4,
"Pairs and lanes"). Families M-17, M-46 (U-3) and M-16, M-20 (U-8). Bean column: `none` for both units; the gate is
this note, the council (section 7) and Bean's sign-off on the pair.

## 1. The problem

A drawer or a panel has to be able to sit where each reference puts it. Five things cannot be expressed today:

1. **A side drawer.** The drawer's `anchor` allow-list is exactly `full-screen | header | trigger | centred`
   (`nav-drawer/render.php::$sgs_nd_allowed_anchors`). away at 768 opens a 390px, full-height panel from the left
   edge; no value gives a partial-width, full-height edge panel.
2. **A drawer inset to the header's content.** lusion at 375 and 768 opens a column whose left and right edges
   equal the header container's insets (15/15, 25/25), directly under the header. `header` spans the viewport,
   `centred` and `trigger` are capped cards, so none tracks the header's content band.
3. **The gap between the burger and a hanging panel.** `store.js` places the `trigger` panel at the burger's bottom
   plus a hardcoded 8px. lusion at 1440 hangs 12.8px below its trigger (trigger bottom 94.8, panel top 107.6), so
   today's panel lands 4.8px high, outside the 2px tolerance.
4. **Row pitch per tier.** `gap` on `sgs/nav-drawer-menu` and `sgs/nav-bar-menu` (one shared renderer,
   `includes/nav-menu-submenu-link-css.php`) is a single string, so lusion's 43.5px pitch at 375 against 58px above
   needs a tier object.
5. **Panel geometry.** Panel placement is JavaScript (`src/shared/nav-interactivity/mega-disclosure.js::repositionPanel`):
   a dropdown aligns to its item (`submenuAlign` start/center/end), a mega panel always centres on the page (or follows
   a floating pill). Neither fork can take the other's placement, and neither can go full width. `submenuTopOffset`
   reaches the dropdown fork only, so halcyon's 10px and indus-foods' 12px mega gaps have no control. The offset is
   also measured from the menu ITEM's bottom, while all three measuring references take the gap from the HEADER
   element's bottom (halcyon header 73 high, panel at 83; indus-foods header 79, panel at 91; away panel top minus
   header bottom 0).
6. **away's callout row.** Two or three image tiles (273.6 x 350.8) side by side at the right of a mega panel. A mega
   panel is a `sgs_mega_menu` post with no template lock, so its content is any blocks; `sgs/mega-panel` is one optional
   preset inside it (link groups plus one side card, children restricted to `sgs/mega-group` and `sgs/mega-aside`). The
   callout row needs no new attribute: it is a layout built from `sgs/container` grids. What is missing is a starter
   pattern that sets that layout up properly, so a client inserts a structured panel and swaps content.

## 3. The design

### 3a. Drawer anchor: three new values and an offset (M-17)

`anchor` gains `side-start`, `side-end` and `container`, in `$sgs_nd_allowed_anchors`, the editor control, the U-5
motion `auto` map and the edge closure, all in the same commit.

| Value | Geometry emitted by `$sgs_nd_geometry_for_anchor` | Stacking | Edge (`$sgs_nd_edge_for`) |
|---|---|---|---|
| `side-start` | `position:fixed; inset-block:0; inset-inline-start:0; inset-inline-end:auto; width:min(<panelSize or 400px>, 100vw); height:100dvh; max-height:100dvh` | under the header (a modal dialog is top layer anyway) | shadow, square corners, a 1px primary line on the open (inline-end) edge |
| `side-end` | the mirror (`inset-inline-end:0`) | same | line on the inline-start edge |
| `container` | modal: `top:calc(var(--sgs-drawer-header-offset, var(--sgs-header-height, 0px)) + <anchorOffset>)`; non-modal: `top:calc(var(--sgs-drawer-opener-row-bottom, 0px) + <anchorOffset>)`; both `left:var(--sgs-drawer-container-left, 16px); right:var(--sgs-drawer-container-right, 16px); width:auto; height:auto; max-height:calc(100dvh - <top> - 16px)` | under the header when modal, above it when non-modal (the full-screen non-modal rule) | card: shadow, 20px corners, 1px line (the `trigger`/`centred` card rule) |

- **Non-modal side drawer** follows the rule the non-modal full-screen drawer already follows: top becomes
  `var(--sgs-drawer-opener-row-bottom, 0px)` and it paints above the header, so the burger row stays the close control.
- **`anchorOffset`** (NEW, `sgs/nav-drawer`, `{"type":"object","default":{}}`, per tier, unset resolves to `8px` for
  `trigger` and `0px` for `container`): the gap between what the panel hangs from and its top edge. `store.js` stops
  adding a hardcoded 8 and publishes the trigger's raw bottom; the offset is added in CSS. Consulted by `trigger` and
  `container`; the editor shows it for those two. `ResponsiveControl`, length input.
- **`panelSize`** is consulted by `side-*` as the width cap (today by `trigger` and `centred` only); the editor shows it
  for those four values.
- **Measuring the header's content box.** `store.js` publishes `--sgs-drawer-container-left/-right` at open, next to the
  existing trigger and opener-row measurements. The rule: the opener's `.sgs-site-header-row`; inside it the
  `.sgs-container__inner` band when the row renders one (it does only when the row has band settings,
  `class-sgs-container-wrapper.php` `$has_band_props`), otherwise the row itself; the element's rect minus its computed
  inline padding; `right` taken against `documentElement.clientWidth` (the trigger note explains why). With no row, both
  properties are removed and the 16px fallbacks govern. The same measurement re-runs in the drawer's viewport-change
  handler, so a rotate or resize while open keeps the insets true.
- **Motion:** `helpers-nav-drawer-motion.php` `auto` maps `side-start` to `slide-start`, `side-end` to `slide-end`,
  `container` to the `header` shape (expand down). The slide keyframes already exist (`nav-drawer/style.css`) and are
  width-agnostic (`translate` by the panel's own size).
- **Editor:** seven values pass the segmented threshold, so the control becomes a `SelectControl` inside the same
  `ResponsiveOverride` ("Full screen", "Below the header", "Side panel from the start edge", "Side panel from the end
  edge", "Lined up with the header's content", "Corner panel under the menu button", "Centred card"). The canvas
  preview shell in `edit.js` gains the side and inset shapes.

### 3b. Row pitch per tier (M-46)

`gap` on `sgs/nav-drawer-menu` AND `sgs/nav-bar-menu` becomes `{"type":"object","default":{}}`: they share one
renderer and one attribute name, so both move together. The renderer resolves it per tier and writes `--sgs-nm-gap`
per tier; the bar's `gap` and the item separator's centring (`includes/nav-menu-item-border-featured-css.php`, which
today casts `(string) $attributes['gap']` and would print `Array` for an object) both read that variable, so the
separator stays centred at every tier. Unset keeps today's 8px. The editor control becomes a `ResponsiveControl`.

**Migration is load-bearing, not best effort.** `sgs_resolve_tier()` returns the default for a non-array value
(`includes/helpers-responsive.php::sgs_resolve_tier`), and WordPress coerces a stored string against an object type,
so any flat `gap` the migration misses silently becomes 8px. Before the type change lands:
1. `scripts/migrate-stored-tier-scalars.py` for stored posts on sandybrown (both blocks), dry run first, then apply;
2. `scripts/migrate-theme-tier-scalars.py` for theme patterns (the `drawer-*.php` and `header-*.php` patterns that carry
   a nav `gap`; the script finds them by block name);
3. `scripts/nav-qa/build-header-fixtures.py` (three flat `"gap":"28px"` writes on `sgs/nav-bar-menu`) edited to write
   `{"desktop":"28px"}`;
4. every converter emitter of a nav `gap` found by grep, switched to the tier shape;
5. a detector run after the migration: zero stored or pattern `gap` strings on either block (the scripts' own
   `--check`, or a grep over pattern files and a `wp db query` count on sandybrown).

buck's column offset (rows 9, 10) is the drawer's inline-start padding per tier in `vw`. It is continuous between
tiers because buck's own 8-column grid is viewport-proportional (150.516 x 8 = 1204 = 1440 - 236), so `vw` is the honest
expression, not a workaround. Its footer row is residue (section 2).

### 3c. Panel placement: one vocabulary for both forks (M-16)

- **`submenuAlign`** (dropdown fork) widens from `start | center | end` to `start | center | end | page-centred |
  full-width`. It stays flat: no reference's dropdown cell differs per tier (loop rule 0(a)), and making it a tier
  object would add a migration with no cell behind it.
- **`megaAlign`** (NEW, `sgs/nav-bar-menu`, `{"type":"object","default":{}}`, per tier, unset resolves to
  `page-centred`) takes the same five values for the mega fork. It is a tier object from birth: the bar shows from its
  collapse point (768 by default), where `page-centred` clamps to `100vw - 56px` and an operator may want `full-width`.
  `page-centred` is today's behaviour exactly (centred on the page, or on the pill), so an untouched bar renders unchanged.
- Labels: "Left edge of the menu item", "Centred under the menu item", "Right edge of the menu item", "Centred on the
  page", "Full width". PHP allow-lists in `nav-bar-menu/render.php` carry the same values in the same commit; the new
  attribute has no JSON enum (FR-41-8), the existing `submenuAlign` enum is widened in place.
- **Resolving the tier in JS.** render.php writes `--sgs-nbm-mega-align` per tier (`@media` rules, a keyword as a
  custom-property value); `repositionPanel` reads it with `getComputedStyle(root)` on each open. The dropdown keeps its
  `data-sgs-nav-submenu-align` attribute.
- `start`, `center` and `end` run the existing item arithmetic for either fork, `page-centred` the existing centring,
  `full-width` sets the width to the bounds' width (the page, or the pill) with no gutter. A dropdown keeps its own
  width and centres on the page (indus-foods' More: `panelCentre_minus_viewportCentre 0`); a mega panel takes the band.
  Collision clamping stays always on. The mega panel's own `maxWidth` caps the content inside a full-width band.

### 3d. Gap below the header, for both forks (M-16)

- `submenuTopOffset` reaches the mega fork too. One attribute, both forks: indus-foods uses 12px for both kinds, and
  halcyon has no dropdowns.
- **The reference point is the header's bottom**, what every reference measured. `repositionPanel` publishes
  `--sgs-mm-panel-top` for both forks from the bar's `.sgs-site-header` bottom (the node `store.js` already measures for
  `--sgs-drawer-header-offset`), falling back to the bar's `.sgs-site-header-row`, then to nothing (the stylesheet's
  `100%`), relative to the wrap's offset parent. Both wraps' `top` becomes `calc(var(--sgs-mm-panel-top, 100%) +
  <offset>)`. A floating pill keeps its own bottom (`panel-bounds.js::boundsFromHeaderRect`, `floating:true`) and is
  unaffected. The comment in `repositionPanel` that says a dropdown's top edge is never republished is rewritten to
  the new rule.
- **Hover bridge, both wraps.** The pointer now crosses the header's bottom padding plus the offset between the item and
  the panel. Two mechanisms, two different jobs, no overlap:
  - *Openness* is held by the existing close grace (the disclosure root contains the panel; `mouseleave` defers the close
    by `submenuCloseGrace`, CF-13). Unchanged.
  - *The parent item's hover paint* is not held by the grace: in the gap the pointer is over neither element, so `:hover`
    drops and the item flickers to its resting paint mid-journey (the FR-41-13 defect). The `::before` bridge fixes paint
    only. Today it exists on the dropdown wrap, sized from the offset alone. It moves to both wraps, sized from
    `--sgs-mm-bridge-h` (the panel's top minus the item's bottom, published by `repositionPanel` after positioning), and
    is present whenever that distance is above 0.
  The safe-triangle (FR-36-4) is unchanged: it reads `activePanelRect`, which is re-captured after the move.
- The vertical bound (`--sgs-mm-panel-max-h`) already measures the panel's final top, so it follows automatically.

### 3e. Structured panel layouts, as starter patterns (M-20, and M-16 row 14a)

- **No new attribute.** A mega panel post takes any blocks, so away's panel and indus-foods' narrow panels are layouts.
  They are built with structure, never as loose single blocks: `sgs/container` grids set the columns, nested
  containers hold each group and each tile, and the layout lives in the containers' own grid and width settings.
- **Two starter patterns** in `theme/sgs-theme/patterns/`, registered like the five existing mega starters
  (`Post Types: sgs_mega_menu`, `Block Types: core/post-content`):
  - `mega-links-with-tiles.php` ("Mega: link columns with image tiles"): outer grid container, `1fr auto`; left, a grid
    container of link columns (heading plus link list each); right, a grid container of two tiles (a third is one
    duplicate away), each tile a container of image (cover), short text and a pill button. Paint (fill, padding) sits on
    the outer container.
  - `mega-compact-links.php` ("Mega: compact link list"): one container, `maxWidth.desktop = 620px`, grid layout, a
    heading and a link list, for a narrow page-centred panel.
- **Authored in the real editor, not by hand** (the never-hand-author-block-markup lesson): each pattern is built in a
  `sgs_mega_menu` post on sandybrown, serialised from the saved post, and copied into the pattern file.
- `sgs/mega-panel` stays as it is, the preset for link groups plus one side card; its 170px aside image cap is that
  preset's own default and is unchanged.
- The M-20 family note ("a mega-panel renders exactly one aside column") is corrected in `families-master.json`: the
  preset renders one aside, and a callout row is a container layout inside the panel post.
- **Check at build:** the mega wrap is `min(1120px, 100vw - 56px)` wide whatever its content, so a 620px panel sits in a
  wider, transparent wrap. That is today's behaviour for any `mega-panel` with a smaller `maxWidth`, but the live check
  confirms the transparent sides do not hold the panel open or block the page; if they do, the wrap drops pointer
  events outside its content in this unit.

## 6. Risks

1. **Every existing panel's top moves** to the header's bottom plus the offset. Pre-production, and it is what every
   reference measures; the live check measures a dropdown and a mega panel on `/qa-scrim/`.
2. **`gap` type change.** A missed writer drops a value to 8px silently. Mitigation: section 3b's five-step migration
   with a zero-count check before deploy.
3. **The container anchor depends on a header row.** Outside a header it falls back to 16px insets and the static
   header height; stated in Spec 36.
4. **The trigger panel's top moves from `+8` in JS to `+anchorOffset` in CSS.** The default stays 8px, so an untouched
   drawer is unchanged; a standalone assertion pins it.
5. **The bridge height is JS-published.** A panel cannot open without JS, so there is nothing to bridge before the first open.
