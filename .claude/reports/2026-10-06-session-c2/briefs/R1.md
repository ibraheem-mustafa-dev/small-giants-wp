# R1 - canvasSettable must respect the emission selector, not the property name alone

## Why this exists

Added 2026-10-06 by Bean's decision to close every open point. **The plan already depended on it**: Wave 4's
180-claim test is specified to run "after P2a and the `canvasSettable` fix land", but no lane built it.

## Diagnosis

`scripts/computed-route/lib/triage.mjs::canvasSettable` matches a row to a candidate control on
**`css_property` equality**, and treats a control whose DB `css_element` is NULL as able to reach **any**
descendant. Both halves are too loose.

The proof is a named class of claim. **All 20 claims citing `sgs/container::bgHoverZoomDuration`,
`::bgHoverZoomEasing` or `::bgHoverZoomScale` sit on a form input, a social icon item, a tab button, a
buybox gallery div or a filter input - never on the background layer those controls paint.**

`plugins/sgs-blocks/includes/container-bg-hover-zoom.php::sgs_container_bg_hover_zoom_css` emits **only** to
`.<uid> > .sgs-container__image-bg` or `.<uid>::before`, and sets `transition-property: transform`
alongside. It can therefore **never** hold an arbitrary descendant's transition. Those 20 rows are classed
`W/canvas-settable` when they are genuinely **F**.

## The fix

Respect the **emission selector**, not the property name alone. A control may only be credited with reaching
a row's element if the selector that control actually emits to can match that element.

## Why the mechanism matters more than the 20 rows

18 of the 20 already fall under the existing transition exclusion, so the immediate row count is small.
**The mechanism is the point** - as written it would mask non-transition gaps on the next client, which is
exactly the reusability goal this cleanup exists to serve. Do not scope the fix to transitions.

## Owned files

`scripts/computed-route/lib/triage.mjs`, `scripts/computed-route/tests/triage.test.mjs`,
`scripts/computed-route/tests/solve.test.mjs` (it asserts `canvasSettable` on a gap, so expect to adjust it).

**Your lane also owns P3d** in the same file - do both, then run the lane's tests once.

## Negative control

- **Red on revert:** a case with a `bgHoverZoom*` control cited against an element the emission selector
  cannot match (a form input, say), asserting the row is **NOT** `canvasSettable`. Reverting must turn it
  red.
- **Not over-suppressing:** a control whose emission selector **does** match the row's element must still be
  credited as `canvasSettable`. Include a genuine case on `.sgs-container__image-bg` itself. If the fix
  refuses everything, every canvas-settable row becomes a false finding and the sweep's F count inflates.
