# H2 - sgs_transition_vars must refuse a non-integer, not strip it

## Do this one FIRST in your lane. It is a live bug.

## Diagnosis

`plugins/sgs-blocks/includes/helpers-tokens.php::sgs_transition_vars` reduces the attribute to digits:

```php
$duration    = $attributes['transitionDuration'] ?? '';
$duration_ms = preg_replace( '/[^0-9]/', '', $duration );
```

Every non-digit character is deleted rather than rejected, so the surviving digits are re-read as a
millisecond count:

| Input | Emitted | Meant |
|---|---|---|
| `"0.25s"` | `--sgs-transition-duration:025ms` -> **25ms** | 250ms |
| `"0.3"` | **3ms** | 300ms |
| `"1s"` | **1ms** | 1000ms |
| `"250"` | 250ms | 250ms (the only shape that survives) |

**This is LIVE, not latent.** An earlier note called it latent because `transitionDuration` is declared
`type: number` on `sgs/button`, `sgs/heading` and `sgs/text` - but **those three blocks do not call this
helper.** All eight blocks that DO call it declare `transitionDuration` as **`type: "string"`, default
`"300"`**: `sgs/hero`, `sgs/brand-strip`, `sgs/cta-section`, `sgs/gallery`, `sgs/info-box`, `sgs/post-grid`,
`sgs/team-member`, `sgs/testimonial-slider`. A string type accepts a decimal from the inspector, so any
client typing `0.3` gets a tenth of the duration they asked for.

Eye Care's trees use `"250"`, so no client is damaged today. That is luck, not safety.

Separately, `scripts/computed-route/lib/resolve.mjs::formatValue` has **no time branch at all** - verified,
no seconds or millisecond handling anywhere in it. A draft value of `0.25s` is therefore either refused for
a number setting or written through as the string `"0.25s"`, which the helper then mangles to 25ms.

## The fix

1. **`sgs_transition_vars`: refuse, do not strip.** A value that is not a non-negative integer number of
   milliseconds must be rejected - fall back to the declared default rather than emitting a mangled number.
   Do not silently coerce. A pure-digit string and an integer both remain valid.
2. **`resolve.mjs::formatValue`: add a time branch** converting seconds to **integer** milliseconds
   (`0.25s` -> `250`, `1s` -> `1000`), so the route can never hand the helper a decimal or a unit suffix.
   Round to an integer; never emit a fractional millisecond.

## Why it matters beyond the bug

This is the hard gate for **P4** (transition calibration, Wave 3). Enabling the route to write transitions
before this lands means it writes 25ms where 250ms was intended.

## Negative control (both halves required)

- **Red on revert, PHP:** a case asserting a decimal input is **REFUSED** - assert the emitted value is the
  default, *not* the stripped `3`/`25`. Restoring the `preg_replace` must turn this red. **Do not write a
  test that merely asserts the stripped value is wrong; assert the refusal.**
- **Red on revert, JS:** a `tests/resolve.test.mjs` case asserting `formatValue` turns `0.25s` into `250`.
- **Not over-suppressing:** a valid integer (`"250"`, `250`) must still emit `250ms` unchanged, and a
  legitimate zero must survive. Prove the refusal path does not swallow good input.
