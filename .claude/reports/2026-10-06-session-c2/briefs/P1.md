# P1 - iconKind per side + normalised icon-colour; suppress text props across a glyph/SVG mismatch

## Diagnosis

The walker has **no icon abstraction**, so a draft glyph against a live SVG manufactures phantom text rows.

Three mechanics combine:
- `scripts/parity/lib/collect.mjs` reads text properties from `paint.mjs::textCarrier` and guards them with
  `if ( src && ! /^icon-/.test( p ) )`.
- `scripts/parity/lib/compare.mjs::sameValue` returns false when **either** side is `undefined`.
- `scripts/parity/lib/compare.mjs::partIrrelevant` ends
  `return /^icon-/.test( p ) && ( undefined === d[ p ] || undefined === l[ p ] )` - the **only** icon
  exemption. It rescues `icon-*` keys missing on one side and **never** text keys.

So a draft `+` glyph yields 8 text keys, the live SVG yields none, and every one becomes a row - 11 on the
help accordion.

The framework already models this correctly and the walker is the only layer that does not know:
`sgs/icon/block.json` declares `iconSource` enum `['lucide','wp-icon','dashicon','emoji','custom']`, plus
`iconSvg`, `emojiChar` and one `iconSize`. **An emoji icon IS text; a lucide icon IS an SVG, by design.**

## The fix

1. An **`iconKind` per side** - `svg` / `glyph` / `dashicon` / `null`.
2. A **normalised `icon-colour`**, so a glyph's `color` and an SVG's `fill`/`stroke` compare as one concept.
3. **Suppress text properties, and `icon-fill`/`icon-stroke`, when the kinds differ and one side is a
   glyph.**

## Three QC modifications - these are binding

1. **NO `icon-size`.** The original proposal compared a glyph's `font-size` em box against an SVG's box
   width and conceded it is a convention, not pixel parity. The pair's `box` `w`/`h` rows already carry the
   pixel check, so the convention buys nothing and can mislead. **Compare `icon-colour` only.**
2. **Tighten the glyph detector.** A single non-alphanumeric grapheme alone would catch a stand-alone
   bullet separator and silently drop its text comparison. Require the single-grapheme test **PLUS an icon
   context** - an icon-ish class (`__icon`, `sgs-icon`) or a control parent (`button`, `summary`).
3. **Scope is narrower than first claimed.** Verified against the walk reports:

| Pair | Reality | Covered? |
|---|---|---|
| `help` `faq-icon-1`/`-2` | draft 8 text keys, live 0, live has all 4 `icon-*` | **YES** - the genuine case |
| `footer` `social-whatsapp` | **both** sides have all 4 `icon-*` | **NO** - svg-vs-svg; its rows are a real 40x40 vs 44x44 touch-target difference |
| `lens` `gen-lens-0` | both sides have `icon-*` and 5 text keys | **NO** - svg-vs-svg |
| `product` `gen-product-4` | draft has `icon-*`, live none; root is the buybox grid | **NO** - that is P2b3 |

**P1's real payoff is the 11 help accordion rows, not the ~15 implied.** Do not widen it to reach the others.

## Negative control

- **Red on revert:** a glyph-vs-SVG pair asserting its text rows are suppressed and a single normalised
  `icon-colour` row remains. Reverting must turn it red.
- **Not over-suppressing (three required):** (a) an **svg-vs-svg** pair must keep **all** its rows -
  `footer` `social-whatsapp`'s 40x40 vs 44x44 difference is REAL and must survive, it is a touch-target
  finding; (b) a stand-alone bullet separator with no icon context must keep its text comparison; (c) no
  `icon-size` row is emitted for a mixed pair.
