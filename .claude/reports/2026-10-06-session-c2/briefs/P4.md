# P4 - Transition markers: integer-millisecond duration, easing from the PHP whitelist minus ease-in-out

## HARD GATE: H2 must have landed first. Check it before you start.

If `resolve.mjs::formatValue` has no seconds-to-integer-ms branch yet, **stop**. Enabling transition
calibration before H2 means the route writes **25ms where 250ms was intended** on eight blocks.

## Diagnosis - two corrections to earlier claims

1. **"No `transition,*` row calibrates anywhere" is too strong.** 7 transition rows carry `enum_values` and
   already take the enum branch: `sgs/heading`, `sgs/text`, `sgs/nav-bar-menu` x3, `sgs/icon-list`. An
   earlier note said 12; **the DB says 7.**
2. **Most of Eye Care's transition rows are not a route gap at all.** `sgs/google-reviews`,
   `sgs/accordion-item`, `sgs/media` and `sgs/choice-flow-question` have **no `transition*` attribute in the
   DB**. Their rows are a *framework* gap - no control exists - and a marker would not make them actionable.
   Of 107 transition rows in the sweep, roughly **19 are plausibly actionable.** Size the work to 19.

## The fix

Add transition markers to calibration, under two constraints both traced to PHP:

- **The duration marker must be an integer millisecond** (e.g. `437`), **never a CSS time** - because of
  H2's strip. A distinctive value like `437` makes the marker unmistakable in a computed read.
- **The easing marker must come from the whitelist** `['ease','ease-in','ease-out','ease-in-out','linear']`
  and **must NOT be `ease-in-out`**, which is both the PHP fallback and the default on some blocks. An
  `ease-in-out` marker would read dead for the wrong reason - indistinguishable from "nothing happened".
- `slotFor` compares TIMING via **`timingSet`, exported from `scripts/parity/lib/compare.mjs` by W2-D**.
  Import it; do not re-declare a local copy, or the two will drift.

## Owned files

`scripts/computed-route/lib/calibrate-markers.mjs`, `scripts/computed-route/lib/calibrate.mjs`, tests in
`scripts/computed-route/tests/calibrate.test.mjs`.

## Negative control

- **Red on revert:** a case asserting the duration marker is emitted as the integer `437` and the easing
  marker is **not** `ease-in-out`. Reverting must turn it red.
- **Not over-suppressing:** the **7 rows already taking the enum branch** must keep taking it - the marker
  must not capture them. And a block with **no** `transition*` attribute in the DB must produce **no**
  marker, since there is no control to write to; it is a framework gap, not a route gap.
