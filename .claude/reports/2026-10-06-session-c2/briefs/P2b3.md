# P2b3 - Read icon-* only when the element is an SVG or contains exactly one painted SVG

## Diagnosis

`gen-product-4` is **correctly paired** - this is a reader-scope defect, not a mispair.

`scripts/parity/lib/collect.mjs` reads icons with `el.querySelector('svg')` - **the first SVG anywhere
inside** the element. When the pair root is a container (here the whole buybox grid), that picks up whichever
icon happens to come first in document order, and the two sides order differently. The walker then compares
one side's star rating against the other side's basket icon.

## The fix

Read `icon-*` properties **only** when the element either **is** an SVG, or **contains exactly one painted
SVG**. A container holding several SVGs yields no `icon-*` reads at all, which is the honest answer.

"Painted" matters: a hidden or zero-size SVG must not count towards the "exactly one" test, or a decorative
hidden sprite would disqualify a legitimate single-icon element.

## Owned file

`scripts/parity/lib/collect.mjs` (hub - same lane as P3a, P3c, P1).

## Negative control

- **Red on revert:** a case with a container holding two SVGs asserting **no** `icon-*` keys are read.
  Restoring `querySelector('svg')` must turn it red.
- **Not over-suppressing:** an element that **is** an SVG, and an element containing exactly one painted SVG,
  must both still produce their full `icon-*` reads. Also assert a hidden second SVG does not disqualify a
  genuine single-icon element. Losing legitimate icon reads would manufacture new phantom rows rather than
  remove them.

Expected to clear ~8 F rows. **This changes emitted paths, so it interacts with R2 - see that brief.**
