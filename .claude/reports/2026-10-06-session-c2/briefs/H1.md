# H1 - entranceStart must not write sgsAnimationStart: load from an armed pose

## Diagnosis

`scripts/computed-route/lib/entrance.mjs::entranceStart` ends:

```js
return { writes: [ { attr: 'sgsAnimationStart', value: 'load', merge: 'replace' } ] };
```

Its own header comment states the premise: "a block with an entrance that the draft shows at rest while live
still hides". **But live is routinely hidden because the walker read an armed, paused entrance pose**, not
because anything is wrong with the block.

Why the walker is fooled: `scripts/parity/lib/devtools.mjs::unfinishedAnimations` filters on
`( 'running' === a.playState || a.pending ) && ... Number.isFinite( endTime )`. A **paused** pose is
therefore invisible to the settle, and so is an **infinite** animation. The walker declares the page settled
while an armed element still sits at its start frame - `opacity: 0, translate: 0 26px`, exactly what
`animation-observer.js::keyframes` builds.

Verified: the write exists, the filter ignores paused, and the recorded home report shows `gen-home-10` read
at a 26px offset while the walker reported the page settled.

**So Solve can write `sgsAnimationStart: load` onto a client's block because of a measurement artefact.**

## The fix

Narrow `entranceStart` to fire **only when the element's rect at `scrollY 0` is inside the first
viewport** - the first-screen case it was written for. Below-fold armed elements stop producing the write.

## Negative control

- **Red on revert:** a `tests/entrance.test.mjs` case with a below-fold element in an armed pose asserting
  **no write** is produced. Reverting the viewport narrowing must turn it red.
- **Not over-suppressing:** a case with a genuine **first-viewport** element at rest in the draft and hidden
  live must **still** produce the `sgsAnimationStart: load` write. The fix must not silence the real case it
  was written for.
