# N. Real block-editor run of the media controls (local-indus mirror, http://localhost:8083)

Method: Playwright with the installed Chrome (`channel:'chrome'`) drove WP 7.1's block editor on the local-indus mirror. A scratch page was created, blocks were inserted with `wp.data` and every control was then driven through the inspector UI (clicks, selects, typing, drags, the real Media Library modal). Canvas styles were read from the editor iframe; the front end was read from a saved draft preview at 1280px. Scripts: E:/sgs-tmp/ec-r11/media/ed/ (lib.mjs, cat.mjs, a1 to a9, b1). Screenshots: E:/sgs-tmp/ec-r11/media/ed/shots/.

Mirror state: local-indus was already running (MariaDB and Apache up; nothing started, stopped or restarted). Its plugin build is dated 2026-11-09 11:16, no deploy or sync was run. Evidence it matches worktree HEAD 6f2a4326c for media: includes/helpers-media.php is byte-identical to the worktree; the build post-dates f791e433b (10:23) and 4b3c5d95d (11:01), the last commits touching media rendering; the later commits cc6f5ca3a and b74c498fb change only src/shared/effects/fx-marquee.js. JS bundle bytes were not diffed (the worktree has no build/), so "same editor JS" rests on that commit reasoning. It is not older than 2026-11-09's main.

Cleanup: all 36 scratch rows (2 saved drafts, auto-drafts, 2 revisions, 1 scratch mp4 attachment 2114 and its file) were deleted with `wp post delete --force`; `SELECT COUNT(*) FROM wp_posts WHERE ID>=2109` is 0, postmeta 0, no scratch file in uploads/2026/11. The auto-increment counter advanced (not reversible, harmless). Services left running as found. One real attachment was never touched.

Not run: an uploaded (internal) video was exercised only with a 2 s ffmpeg-made mp4 (uploaded, then deleted); a real Lottie JSON and a captions .vtt were not run. Duotone could not be exercised: the theme has no duotone presets, the popover offers only "Clear". Per-device container Background Position/Size were not changed on a device (only the panel was read). The mirror has no Hostinger cache or CDN, so edge behaviour was not tested.
