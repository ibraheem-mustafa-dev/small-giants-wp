# QC of D-per-device-kind-design.md (cold review, 2026-11-09)

Verdict: the core rendering idea (picture with a blank source for images, `data-src` video filled by `matchMedia`) holds in Chrome, Firefox and WebKit. Do not build until rows 1 to 6 are answered; they are scope gaps, not flaws in the idea.

| # | Severity | Finding | Evidence | Improvement |
|---|---|---|---|---|
| 1 | Critical | No migration of saved content. Hero already stores per-device kind (`splitMediaType`, `Tablet`, `Mobile`) and container, hero and multi-button store `bgVideo*`; the design replaces them with a `Source` object and says nothing about existing posts. FP-14 forbids a read-time fallback and `deprecated.js`, so a WP-CLI sweep plus detector is mandatory. The same change in 3+ blocks triggers migration-method. | `src/blocks/hero/block.json` keys `splitMediaType*`; `bgVideo*` in `container/block.json`, `hero/block.json`, `multi-button/block.json` (grep); `.claude/rules/framework-principles.md` FP-14 | Add a Migration section: target shape, detector (survey, fix, check, self-test), batch sweep of existing posts, and order (migrate before the renderer drops the old reads). Decide whether `bgSvg*` and `backgroundImage*` fold in. |
| 2 | Critical | The active-device video loses parser discovery. With the file only in `data-src`, the desktop hero video starts after the deferred `viewScriptModule` runs, not at parse. Today it is `<source src>`, found early. This delays video start on the device that does show it. | Design point 3 (Video); `includes/class-sgs-container-wrapper.php` bg video markup prints `<source src=desktop>`; my case Q/R: `src` is set only by script | Keep a server-printed `<source src>` on a device range where nothing else shows a different file; use `data-src` only where a sibling device differs. Measure start delay on throttled 4G before accepting. |
| 3 | Critical | A video that stops being shown is never stopped. The design says the script "picks the source for the current device" but not what happens to the other one. Today `swapVideoSrc` only swaps `source.src` and calls `load()`; it never pauses or clears. A hidden autoplay video keeps decoding. | `src/blocks/container/view.js::swapVideoSrc` (no `pause`, no `removeAttribute`); `qc-download-result.json` `resize-from-*` (src swaps, nothing clears the unused one) | On every breakpoint change the shared script must `pause()` and clear `src` (then `load()`) on each video not shown and play only the shown one. Add a test on network plus `video.paused`. |
| 4 | Important | "No new renderer" understates the work. `sgs_tier_media_render` emits one sibling per tier with CSS toggles, not a `<picture>`; the image branch calls `sgs_responsive_image` per tier with `loading` and `fetchpriority` from options. Merging devices into one `<picture>` with blank sources rewrites the image branch and the toggle CSS. The file is 408 lines; adding kinds pushes it past the 500-line PHP limit. | `includes/helpers-tier-media.php::sgs_tier_media_render` (img branch `'fetchpriority' => $img_fetchpriority` per tier; video branch `preload="metadata"` desktop, `none` otherwise); Spec 49 FR-49-8 | Describe it as "rewrite the image branch to emit one picture". Reuse `sgs_image_loading_attrs` and `sgs_responsive_image`. Split the video, svg and lottie branches into their own helper files. |
| 5 | Important | Duplicate logic. Two copies of `swapVideoSrc` already exist (container and hero); the design adds a third ("a small view script"). Both copies use `window.innerWidth` with hard-coded 768 and 1024; the design uses `matchMedia`. | `src/blocks/container/view.js::swapVideoSrc`; `src/blocks/hero/view.js::swapVideoSrc` | One shared module (breakpoints from the shared helper, `matchMedia` listeners, no debounce) used by container, hero and media; delete both copies in the same change. |
| 6 | Important | Point 4 depends on unbuilt work and collides with an existing resolver. `sgs_image_loading_attrs` already exists (static `$eager_count`, `sgs_eager_image_limit` 16, `sgs_next_background_image_index()`); the tree-based function "Eye Care round 13 builds" is not in this worktree. The design does not say what happens to the counter (FR-49-15 wants one resolver), or that a multi-device picture must count as one eager image, not one per device. | `includes/helpers-media.php::sgs_image_loading_attrs`; Spec 49 FR-49-15; no tree function found under `includes/` | Name the sequencing: either ship on the current counter (call the resolver once per slot, not per tier) and swap later, or block on round 13. State which. |
| 7 | Important | Lottie is dropped. The registry lets slots allow `image, video, svg, lottie` and `sgs_tier_media_render` has a lottie branch with a per-tier pause control. The design's kinds are photo, video, embed and SVG. "Never cut a feature that works today." | `src/components/media/atoms/registry.js` (`types: [ 'image', 'video', 'svg', 'lottie' ]` at several atoms); `helpers-tier-media.php` lottie branch | Add lottie as a kind (holder per device, poster via picture) or state where it stays and how it keeps working. |
| 8 | Important | Accessibility per device is unspecified. Alt is per tier today (the helper resolves per-tier alt with fall-up) but the design's `{kind, id, url, ...}` has no alt, decorative flag, caption, `<track>` or iframe title per device. | `helpers-tier-media.php` per-tier alt resolution; design points 1 to 3 | Put alt, decorative, caption and track per device inside `Source`, with a missing-alt warning per shown kind. Hidden siblings must be `display:none`, never only `visibility`. |
| 9 | Important | A cover `<picture>` under the video replaces native `poster`. Native poster gives layering, sizing and handover for free; a separate element needs z-order, a hide-when-playing rule and matching box (CLS risk). The original test shows why poster was dropped: it downloads when hidden. | `hidden-download-result.json` case I (poster fetched when hidden, all three) and case L | Set `poster` from the same script that sets `src` (shown device only), and print the cover `<picture>` for no-JS and reduced motion only. Add a handover-without-layout-shift fixture. |
| 10 | Important | Cloning is not covered. Drafts use `display:none` sibling pairs and `<picture>` or `<video><source media>`; the cloner must read the visible kind per width and write per-device `Source`. WP-13 reads at 375, 768 and 1440 but only for images. | Spec 49 WP-13 row ("reads at 375, 768 and 1440, writes width, height and mime") | Extend WP-13: classify the visible element per width (img, video, svg, iframe) and write per-device kind; add a draft fixture with a hero video/photo swap as acceptance test. |
| 11 | Important | Effects per device (point 6) is under-specified. Spec 49 gives per-device on/off for parallax only (FR-49-29). "Each effect runs only on devices whose media can take it" needs per-device scoping for every effect plus the panel message. UNVERIFIED: whether `fx_effects.requires` can be evaluated per device (DB not queried). | Spec 49 FR-49-28 and FR-49-29; design point 6 | List which effects get per-device scoping and how it is emitted (media-query wrapper or `matchMedia` in JS); check `fx_effects.requires` for each. |
| 12 | Important | Reduced-motion and no-JS paths contradict today's markup. Bg video prints `autoplay` in HTML and neither `container/view.js` nor `hero/view.js` contains reduced-motion code (grep: no match), so autoplay starts before script could stop it. With `data-src` the script must read `prefers-reduced-motion` before any `src`. No-JS: a video-only desktop slot with a different mobile kind has no cover on desktop, so it is blank. | grep `reduced` in `src/blocks/hero/view.js` and `container/view.js`: no matches; bg video markup in `class-sgs-container-wrapper.php`; design point 8 | Require a cover for every video kind (or a placeholder colour); do the reduced-motion check in the shared script before any `src`; test with `reducedMotion: reduce` and with JavaScript off. |
| 13 | Minor | LCP with a blank source is only half-tested. A visible `<img>` that is the shown device reported LCP correctly in Chrome and WebKit; a hidden blank-source `<img>` produced no LCP entry. A visible `<img>` holding a blank `data:` source was not measured. Firefox has no LCP entry type. | `qc-download-result.json` `chrome.load@375.lcp`, `webkit.load@375.lcp` (element `p-img`); `load@1440.lcp` empty | Fine as designed while the blank-source image is `display:none`. Add the visible-blank fixture to the build tests if any device can show a "none" image visibly. |
| 14 | Minor | Gaps in the original browser table are now closed (see cases below): script-filled video, picture resize, and lazy iframe in WebKit all behave as the design assumes. Keep them as build tests so the claims stay true. | `qc-download-result.json`; `qc-download-test.mjs` | Add these three cases to the Spec 49 browser gates. |
| 15 | Minor | The blank source is a `data:` URL in `srcset`. A Content-Security-Policy `img-src` without `data:` would block it and show a broken image. Spec FR-49-8 says a "none" device is an empty source, not a data GIF. UNVERIFIED: whether any client site sets a CSP. | Design point 3 (Images); Spec 49 FR-49-8 | Use an empty `srcset` source per FR-49-8 and test it in all three browsers (original case N only tested the data GIF); keep the GIF only if the empty form fails. |
