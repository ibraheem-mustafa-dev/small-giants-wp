## Archetypes found

1. One table generating many blocks' attributes. Best archetype: Stackable. `gambitph/Stackable src/util/attributes/attribute-object.js::AttributeObject` collects attribute groups per feature (`src/block-components/image/attributes.js::addAttributes`, `src/block-components/helpers/size/attributes.js::addSizeAttributes`). A name template (`attrNameTemplate`, e.g. `figcaption%s`) prefixes a shared group per slot, which is Spec 49's `{prefix}{Base}`. Each setting carries flags `stkResponsive`, `stkHover`, `stkUnits`; `src/util/attributes/index.js::expandAttributes` turns one entry into the desktop, `Tablet`, `Mobile`, hover and unit attributes. Every group carries `versionAdded` and `versionDeprecated`. Stackable's `src/block/image/block.json` holds no attributes (grep of `imageWidth` returns 0): they are built at runtime from `src/block/image/schema.js::attributes`. Not verified: how Stackable registers them server-side. Counter-example: `stellarwp/kadence-blocks src/blocks/image/block.json` is hand-written per block and drifts in naming (`marginDesktop`, `marginTablet` beside `tabletBorderRadius`, `mobileBorderRadius`, and a different layout for `borderStyle`). Gutenberg core generates attributes from a support declaration: `lib/block-supports/dimensions.php::gutenberg_register_dimensions_support` adds `style` when `supports.dimensions` is present, and `block-editor/src/hooks/generate-fields-from-attributes.ts` builds inspector fields from attributes flagged `autoGenerateControl`.

2. Per-device value shape and inheritance. Stackable: sibling flat attributes (`imageAspectRatio`, `imageAspectRatioTablet`, `imageAspectRatioMobile`), empty string means inherit. Inheritance is resolved in one place: `src/util/styles/style-object.js` `getAttribute( …, getInherited )` walks `[ 'mobile', 'tablet', 'desktop' ]`; `getAttributeName` in `src/util/attributes/index.js` is the only name builder. Gutenberg trunk: a nested object keyed by device and state inside `style`, `style['@mobile']` and `style['@mobile'][':hover']` (`lib/block-supports/states.php` header comment and `gutenberg_render_block_states_support`). Kadence: arrays `[desktop,tablet,mobile]` in some attributes, suffixed names in others. Display of inheritance in the inspector: not verified in any of the three (Stackable's `src/hooks/use-responsive-control-visibility.js` only hides controls by device).

3. Per-instance CSS, server and editor from one definition. Stackable has one definition and no PHP twin: `src/block-components/image/style.js::addStyles` registers rules with `BlockStyleGenerator`; the same registration renders in the editor and is saved into post content. It has to fork by `renderIn: 'edit'` and `renderIn: 'save'` entries (the `imageAspectRatio` rule is registered twice, with a different selector list), which is the byte-difference problem inside one definition. Gutenberg core: server-only CSS from the style engine (`packages/style-engine`, called by `lib/block-supports/dimensions.php`), with a JS style-engine package for the editor; byte equality is not asserted anywhere I read. Kadence is a true twin: `includes/blocks/class-kadence-blocks-image-block.php::build_css` in PHP and a separate JS copy in `src/blocks/image/image.js` (the mask values `theMaskRepeat`, `theMaskSize`, `theMaskPosition` are computed again). No byte-equality test found in the files read.

4. Showing a control only when it applies. Stackable: per-control inline conditions in `src/block-components/image/edit.js` (`props.hasAspectRatio &&`, `props.hasHeight &&`, `attributes.imageId &&`); no rules file. Gutenberg: `hasDimensionsSupport( name, feature )` in `block-editor/src/hooks/dimensions.tsx` plus `ToolsPanel` `resetAllFilter`; also per-control. No rules-file archetype exists; Spec 49's `rules.js` is novel here.

5. Shape or mask registries. Kadence: SVG files by name in `includes/assets/images/masks/<name>.svg`, referenced by URL in `build_css`, plus `custom` with `maskUrl`, `maskSize`, `maskPosition`, `maskRepeat` as four flat attributes. Stackable: `src/block-components/image/get-shape-css.js` holds a map (`circle`, `square`, `blob1` in this checkout), extensible through the filter `stackable.image.shape.svgs`, and emits a base64 `data:image/svg+xml` mask URL. Its flip handling wraps the SVG's contents in a `<g transform>` rather than transforming the `<svg>`, with a comment that this is a Safari fix. Spec 49's registry with data-URI encoder matches Stackable.

6. Migration across a shape change. Stackable never migrated: v2 blocks are kept whole and shipped beside v3 (`src/deprecated/readme.md`: "left as they are and will continue to be included"; 25 `src/deprecated/v2/block/*/deprecated.js` files), v1 styles are kept to render old v1 posts, and old attributes live on in `deprecatedAddAttributes` (`src/block-components/image/deprecated/index.js`) with `semverCompare( props.version, '<', '3.12.7' )` save filters in `src/block/image/deprecated.js`. Spectra migrated by script: `brainstormforce/wp-spectra classes/migration/class-spectra-migrate-blocks.php` runs `parse_blocks`, edits `attrs`, `serialize_blocks`, in batches of 100 posts through a background queue (`classes/migration/class-uagb-background-process.php`), marks each post with meta `_uag_migration_processed`, and pins the old default into any post that never stored the attribute (`self::$info_box_mapping`, `if ( ! isset( $attributes[ $key ] ) )`). Defect visible in `get_updated_blocks`: it only edits a block that has no `innerBlocks` (the `else` branch), so a container block is skipped. Gutenberg core: per-block `deprecated` entries; not read here.

7. Staging a large rollout. Stackable staged by whole architecture generation (v2 kept, v3 new) and by attribute-group versions, not block by block. Spectra staged by a flag (`uag_enable_legacy_blocks`) plus a queue. Neither shows a sliced rollout like Spec 49's slice gate. Not verified: GenerateBlocks, Kadence.

Also found, relevant to Bean's separate Ratio, Width, Height settings (not a challenge to the ruling): Stackable's Aspect ratio `onChange` in `edit.js` clears Height at that device when a ratio is picked (`values[ attrImageHeight ] = ''`), and `style.js` returns `auto` for width when ratio and height are both set. Gutenberg `block-editor/src/hooks/dimensions.tsx` and `lib/block-supports/dimensions.php::gutenberg_render_dimensions_support` resolve the conflict at render time: an explicit aspect ratio emits `min-height: unset; height: unset`; otherwise a set height or min height emits `aspect-ratio: unset`. Gutenberg's comment says the Cover block and the controls clear the other value manually.

## Where Spec 49 should change

- Area 1: add a per-entry `since` field to the C1 table entry, as Stackable does with `versionAdded`.
- Area 2: one shared inheritance resolver used for the label, the CSS and the tests.
- Area 3: compare parsed declarations, not bytes, between PHP and JS.
- Area 6: WP-14 must recurse into parents, pin old defaults where the new default differs, and be idempotent per post.
