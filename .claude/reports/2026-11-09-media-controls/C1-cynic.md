# C1 Cynic review of Spec 49 v0.5 (SGS Media System)

Reviewed: the working-tree spec (v0.5), commits `d77d85823` and `c2db2791c`, T-merge, S, T7, T8, T11, K, R3, and the code named below. Measurements were taken on 2026-11-09 with Playwright (Chromium, Firefox, WebKit) from a throwaway page using §7.2's exact Fill CSS. No Bean ruling is reversed below; nothing here needed the "choice for Bean" label.

## STRENGTHS

The no-modes sizing model is the right shape: S proved 12 combinations across three browsers, and the cloner gets a one-to-one copy of CSS properties. v0.5 did real cutting (no rules DSL, no separate shape file, no SVG stroke border, emitter kinds call existing helpers per §6.2). R3's coexistence objection is answered by §6.8's single render path. Generated `block.json` with a drift gate (§6.1) leaves 200+ gates undisturbed. §7.9's per-kind table is the most useful addition: it stops "one setting, one code path" from being assumed.

## MUST-FIX

**1. Fill is not Fill: the 3:2 floor overrides the layout, and Fill ignores Width in a row (§7.2 Fill paragraph, FR-49-38, §11 row 1, AC-27).** The `::before` with `padding-top:66.667%` is in-flow content, so it is always a minimum height, not a fallback. Measured with §7.2's CSS, identical in Chromium, Firefox and WebKit, helper 600px wide: definite parent 200px tall gives a 400px helper overflowing its parent; grid row beside 200px-tall text grows the row to 400; flex row likewise 400; min-height 200 grid band grows to 400. `flex:1 1 auto` also defeats Width in a row: Width 300px measured 1000 by 667. S §Q3 missed it because every parent tested was taller than the floor (700px and 600px). §11 row 1 routes a draft's parent-set height to Fill, so any draft row shorter than two-thirds of the media's width clones too tall, while the draft's own fallback applies only when the height is indefinite (T8, `image-slot.js`). Fix: replace the 3:2 padding with a small fixed floor, `::before{display:block;height:12rem}`, and when Width is set print the same value as `max-width` alongside Fill. Measured in Chromium and WebKit with that change: 600x200 in the definite parent, the grid row, the flex row and the min-height band; Width case 300x200; bare parent 600x192, never 0. Change FR-49-38 from "fall back to 3:2" to "fall back to the floor". §11 already sends an indefinite parent to No Height, so the 3:2 protected only a person picking Fill in an empty parent. Add parents shorter than the floor's old value to PS-2 and AC-27.

**2. The cutover order cannot be executed, and the fifth site has no plan (FR-49-36, §13 Site order, §14.1, AC-25).** FR-49-36 requires zero old attributes on every target before old code is removed. §14.1 removes old code in the same release and migrates only mirrors before the merge. §13 then migrates live sites afterwards, one at a time, and makes `eye-care-test` conditional on Bean's agreement. Live sites cannot reach zero first, because old code cannot read new attributes and FP-14 bars a fallback. `eye-care-test` is the site Bean presents and is edited directly (`deploy_common.py::TARGETS`, kind `reference`), so it is the classic forever-old system: it can never again take a framework deploy, and it is the one place a stale deploy destroys rendering. Fix: redefine the check per site as "deploy and migrate are one step per site: back up, deploy, run the detector's fix and check, purge caches, or restore". Add a `build-deploy.py` preflight that refuses a post-cutover build on any target whose detector check is not clean, so a missed site fails loudly. Make `eye-care-test` an explicit, dated step of the release with Bean's agreement obtained before Stage B opens, and pause its finishing stream during that step.

**3. Stage A is not dormant (§6.8, §14.1, §14.4).** "New files only, adopted by nothing" is false for six packages. WP-4 reworks `ResponsiveOverride`, imported by 136 files in `src/`. WP-0b edits `class-sgs-container-wrapper.php`. WP-13 rewrites `fill-media.mjs::imageSlots` and `scripts/computed-route/*`, the live cloner that Mama's and Indus still use, to write attributes no block reads yet. WP-15a's gates (FR-49-26 refuses raw `MediaUpload`) go red on every block on arrival. WP-10a changes motion targets and `render-paths.json`. WP-6 extends `icon-shapes.json`, which `src/blocks/icon/shape-options.js::shapeOptions` lists in full on `sgs/icon` and `sgs/social-icons`, so the new media shapes appear in the icon picker and leave `block.json::attributes.shape.enum` behind; `helpers-icon.php::sgs_icon_outline_shapes` also rejects box-shape slugs, and circle and pill are registry entries under §7.5. FR-49-32's "`sgs/icon.shape` is unrelated" is untrue while they share a file. Fix: split Stage A into "A1 dormant" (genuinely new files) and "A2 live shared changes" (WP-0b, the `ResponsiveOverride` display rework, each deployed and checked as normal work). Move WP-13's route rewrite and the refusing gates into Stage B. Add a `surfaces` field to each `icon-shapes.json` entry, filter icon's list by it, and keep `tests/js/icon-shapes-parity.test.js` proving the icon list is unchanged.

**4. Nothing runs end to end until everything is built (§14.2, §14.3, §14.4).** PS-1 to PS-9 are point proofs. The first time renderer, emitter, fields, rule table, migration and cloner meet is Wave 1 in Stage B, after 12 packages are complete and eight contracts frozen. Dormant JS is imported by no block, so it is not even compiled: a broken import cannot fail a build, and "green on main" proves nothing. This is exactly how a ground-up redesign reaches 80%. C0's "stubs" also breach the no-stubs rule (`rules/code-quality.md`) and leave dead shells on main if work stops. Fix: add a Slice gate after WP-1, WP-2, WP-4 and WP-5, in a throwaway worktree: `sgs/media` image kind plus one container background, migrated on one mirror, one real clone built, editor and front end checked. Only after it passes do WP-6, WP-10a, WP-13 and WP-14 start, and C1 to C8 unfreeze for corrections until then. Replace C0's stubs with signatures in documentation plus the shared fixture files.

**5. Stage B has no stop condition, too small a freeze, and no re-run path (§14.1, §6.8).** The freeze covers "hero and wrapper" only, while Stage B rewrites `block.json`, `render.php` and `edit.js` across about 45 elements. Active plans touch those blocks (`2026-11-03-buybox-configurator.md`, `2026-11-03-mamas-framework-batch.md`, `2026-11-04-mamas-commerce.md`). "Mama's work that touches media waits" has no end date and LEDGER already counts it as blocked. Fix, three lines in §14.1. Freeze every block directory named in Waves 1, 3, 4 and WP-8, enforced by a pre-commit path check while the integration branch exists. Keep adoption as a re-runnable script against fresh `main`, so the branch is disposable and only hand-written specialised controls are committed to it. Add an abort rule: if the branch has not merged within a stated number of sessions (recommend three), delete it, re-run the script later, and release Mama's waiting items as ordinary work on the old code.

**6. Sizing is not `plain`, so the riskiest PHP and JS twin is untested (§8 table, §6.2, §7.2, PS-7).** §7.2 opens "each setting prints its own CSS property", then adds cross-setting logic: default Width depends on Ratio and Height at that device; the helper's `aspect-ratio` depends on Source, Height, Ratio and whether a helper exists; the caption's fit-content depends on resolved Width. §8 marks Width, Ratio and Height `plain`. Shape is also `plain` with `mask-image`, yet draws `border-radius` for Circle. Fit is `plain` yet covers tile, `actual` and an SVG attribute. PS-7 samples five rows, which will be the easy ones. Fix: add one `sizing` emitter kind implemented as a single resolver per device, returning the printed declarations, and one `shape` kind. Drive both through a shared `sizing-cases.json` (S's 12 combinations multiplied by helper and no helper) that PHP and JS must both pass. Make PS-7 cover exactly these two kinds.

**7. The lead image is identified by a hash that identical blocks share (§7.7, FR-49-13, AC-9).** The scope hash comes from the slot's values and AC-9 requires two identical blocks to share one rule, so the same photo used twice (or a repeated card) both match the recorded lead and both take `fetchpriority="high"`, breaking "one per page" (AC-10). The same hashing breaks §10.2: overscan is printed in the "moving element's scoped rule", so two blocks with the same image and different parallax share one class and one overscan. Fix: the renderer consumes a per-request "lead claimed" flag so only the first render matching the hash is high. Pass parallax ratio and basis through the existing `$extra` argument of `helpers-instance-scope-hash.php::sgs_instance_scope_hash`, and name in C3 which emitter prints overscan.

**8. The CSS validator refuses colours and gradients that drafts and saved content use (FR-49-12, §8 Valid column).** FR-49-12 allows brackets only in `calc()`, `min()`, `max()`, `clamp()` and `var()`, and §8 lists colours as "token, hex". Drafts in `sites/*/handoff` contain 612 `rgb(`/`rgba(` and 58 `linear-gradient(` uses, including photo borders such as `5px solid rgba(255,255,255,.92)` (T8) and shadows. Saved `overlayGradient` and `backgroundColourGradient` values are `linear-gradient(...)` (K), and §13 keeps the overlay family unchanged, so they fail on the first render after migration. This breaks "clone anything". Fix: key the grammar by `$type`, allow `rgb()`, `rgba()`, `hsl()`, `hsla()` and the three gradient functions for colour, gradient and shadow types only, and correct §8's Valid column. Add those cases to AC-8's shared fixture as positive controls.

## SHOULD-FIX

1. Circle lies when a Ratio exists (§7.5, AC-6). Picking Circle sets 1:1 only "when no Ratio is set", so a 16:9 photo labelled Circle is an ellipse and AC-6's true circle fails. Fix: while Shape is Circle the surface prints `aspect-ratio:1`, the Ratio field keeps its value and says "Circle is always square".

2. SVG Fit cannot be per device (§7.9, §8 `Fit`). `preserveAspectRatio` is an attribute on one inline element, and S confirms CSS `object-fit` has no effect on inline SVG, yet `Fit` is a responsive value. Fix: SVG Fit is one value for all devices, labelled "Applies to all devices".

3. "Fit is applied only where the box crops" (§8 Defaults) makes CSS depend on knowing the file's shape at each device. `object-fit` is a no-op when nothing crops. Fix: put `object-fit:cover` in the base stylesheet, print Fit only when set, and leave "the box crops" as an editor visibility rule.

4. The default-width rule is a mode nobody can see (§7.2). Adding Height on Mobile where Ratio is inherited flips Width from 100% to `auto`, so the picture narrows without a control changing. Fix: the Width field's placeholder always names the resolved default, for example "Auto (from Ratio and Height)".

5. A Container must inspect its children for Fill (§7.2 "the container emitter prints that automatically"). That is parent-reads-child coupling across PHP and JS, per device, and it misses nesting. Fix: one static base rule on the band using `:has(> .sgs-media-box--fill)` at lower specificity than per-instance layout, proved in PS-2, with the editor's band matching it.

6. §7.3's helper triggers name effects by hand, so every new effect edits the renderer and its JS twin. Fix: a `needsClipParent` flag on each effect's definition in the motion registry, which §7.3 reads.

7. "One table" has a hand-written second half (§9.3, C4). `rules.js` is separate from `media-settings.json`, so a new row can ship with no visibility rule. Fix: the drift gate fails when a table row with a `control` has no function in `rules.js`, and the reverse.

8. PS-6 has no threshold and no listed outcome (§14.2). Fix: state the limit (reseed time and largest `block.json`) and what is cut if exceeded, or delete the proof.

9. AC-23 pixel-tests every mask in three browsers, 12 shapes by 3. Shapes are data. Fix: test one stretch, one keep-proportions and one blob; the rest get a schema check on their path.

10. Cut two small items. §13's "Custom CSS setting focal, size or visibility to Settings" implies a CSS-parsing converter for 27 saved rules in all (K): report them and resolve by hand. §9.5's upload-size advisory with per-slot thresholds serves neither cloning nor controls, and sits oddly with Bean's "no size target": delete it. §13's last sentence on `save.js` can go too, since a grep of `src/blocks/*/save.js` for `<img`, `<video` and `<picture` finds none.

11. §11 has no route for map iframes. `<iframe>` maps to embed, FR-49-17 accepts only YouTube and Vimeo, and §10.4 puts the map in `sgs/business-info`, so Indus's two map iframes (T8) are refused. Fix: a §11 row sending a Google Maps iframe to `sgs/business-info`, others to a reported refusal.

12. Stale text left by the merges. §11 still names `schemas/media-slot.schema.json` as a file while T-merge and WP-1 generate it. §7.2 says "Three rules fill the gaps" and no longer lists three. Fix both in place.

13. AC-25's "Bean checks the five sites by eye" is unbounded. Fix: PS-8 outputs the list of pages whose computed styles changed, and Bean checks those plus each site's home page.

## MISSING

1. A permanent old-shape guard. AC-25 is a one-off, and trees re-pushed by `wp-build-page`, an old handoff or a hand-built page can reintroduce old attributes. Fix: the detector's `--check` over `theme/sgs-theme/patterns/` and `sites/*/build/` becomes a standing entry in `gates.json`.

2. A removal date for the scaffolding. `gate-disposition.json`, `migrate-media-system/`, allow-lists and the freeze check have no end. Fix: WP-15b names what is deleted one release after the last site is clean, and what stays (only the guard above).

3. A one-page recipe for adding a setting or an effect, as a path-scoped `.claude/rules` file, since media has none. It lists every file touched (table, rule, generator, cloner row, migration row, fixture). This is the main defence against the two-year drift this spec exists to remove.

4. A stated rollback boundary for Stage C and D, so deferred items stay named in §14 with their owners, and do not quietly become "the old way".
