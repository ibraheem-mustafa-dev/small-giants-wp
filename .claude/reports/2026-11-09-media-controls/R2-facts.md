# R2 fact-check of Spec 49 (SGS Media System) against E:/sgs-tmp/wt-indus

Method: code-path tracing with rg and python over plugins, theme, scripts and the shared framework DB (opened read-only), plus empirical Chrome 156 (`channel:'chrome'`) tests on injected fixtures. Throwaway scripts are in E:/sgs-tmp/ec-r11/media/r2/ (fill.mjs, fill2.mjs, pic.mjs, paint.mjs, paint2.mjs, mask.mjs, plx.mjs, plx2.mjs, callers.py, scan_attrs.py).

## FALSE OR UNSUPPORTED CLAIMS

**F1. §8.1 "`css_element` becomes `paint_node`" is false as a rename.** `block_attributes.css_element` is a live column holding PART names (wrapper 1448 rows, label, title, item, inner, caption, 'media', 'img', 'split-media', 'overlay', 'video-bg' and others). It is read by about 50 files: scripts/computed-route/lib/resolve.mjs, db.mjs, triage, the calibrate-* and fill-* libs, apply-*; sgs-update-v2.py (Stage 1 reset layer at "for _reset_col in (css_layer, css_element, ...)", the extension-roster routing fields); check_css_property_reseed.py; the behavioural-analyser; and survey scripts. Correction: ADD a `paint_node` column. The precedent is migrations/2026-09-10-add-tier-shape-column.py plus the idempotent ALTER in sgs-update-v2.py (~line 1146), schema.sql, migration-manifest.json, check_schema_drift and the COLS list in computed-route/lib/db.mjs. That is feasible and breaks no reader, because db.mjs selects an explicit COLS list and `css_*` columns are reset to NULL every reseed. `paint_node` therefore needs its own source layer (media-settings.json, like the extension-roster layer 2.6), or it is NULL after every /sgs-update. Note the `css_property` base layer is derived by behavioural-analyser/extract-signatures.py plus scripts/attr-classification-overrides.json, not by any truth table. A third source (media-settings.json) needs a new seeder layer; the spec only says "the DB seeder reads it".

**F2. §8.1 "`tier_shape` object" is not a value.** The closed set is `tier_object`, `flat_sibling`, `box_only` and NULL. It is decided by lib/object_attr_shape.py::classify_object_attr_shape, which regex-scans the block's own render.php, the block's other PHP files and class-sgs-container-wrapper.php for `sgs_responsive_normalise_object( $attributes['x'] )` and similar. The new `SGS_Media_Renderer` and its generic emitter sit outside those files, so there is no evidence. I ran the real classifier on the spec's names. `mediaSource`, `mediaFocal` (empty default), `mediaHeight`, `mediaRatio`, `mediaFit`, `mediaWidth`, `mediaRadius`, `mediaOpacity` and `mediaPlayback` all land on tier_object only "by ELIMINATION" (it prints a NOTE). `mediaPadding` and `mediaBorderWidth` become `box_only`, so the resolver treats Padding as flat box sides, not per device (resolve.mjs checks `box_only === row.tier_shape` for isBox). `mediaFocal` with a default of `{x,y}` and `mediaMask` with a default of `{shape:'none'}` become NULL ("record"). Also `Source` is not caught by the asset-word rule (the final word "source" is not in image/video/media/thumbnail/logo/svg/poster/url/id). PS-1 as written ("through sgs-update, both gate tiers and check_value_identity") will pass or fail on these accidents. The discriminator needs a declared-source branch that reads media-settings.json.

**F11. §10.2 overscan formula: correct on one basis, wrong on the other (measured).** Test: block H=600, viewport 800, per-side overscan = speed/2 of H (+ speed x 50svh for view), offset = ratio x distance with the driver's real definitions (view travel = (progress-0.5) x (innerHeight+H); page distance = absolute window.scrollY, per scroll-driver.js `--sgs-scroll-y`).
- View basis, both signs, speeds 0.1/0.3/0.6/1, block at T=0 and T=1500: max visible gap 0 px in all 16 combinations. It holds only while 50svh equals window.innerHeight. With svh 12% below innerHeight (a mobile toolbar), gap = 3.8 px at speed 0.1, 11.4 at 0.3, 22.8 at 0.6, 38 at 1.0, because fx-parallax.js::viewTravel uses window.innerHeight.
- Page basis, block at the top of the page (T=0), direction sign -1: gap 29 px (speed 0.1), 87 (0.3), 174 (0.6), 290 (1.0), first visible at scrollY 590 (the block bottom is still on screen). Sign +1 shows no gap (the exposed edge is off screen).
- Page basis, block at T=3000: gap 270 to 3290 px for every speed and sign (the image is translated clear of the block), because distance is absolute scrollY, not distance since the block entered. So "overscan = speed/2 of H" is not "overscan >= max travel" for the page basis. Correct values: page basis needs |ratio| x scrollY at the block's furthest visible scroll (about |speed| x (T+H)); the "limit" cap makes the gap worse, not better. Fix by making the page basis relative to the block's rest scroll, or by dropping the page basis for blocks not at page top. Use `svh` only if the driver also uses `svh`; otherwise use `lvh`.

## EMPIRICAL RESULTS (Chrome 156)

**§7.2 Fill fallback `width:100%;height:100%;aspect-ratio:3/2` (helper div with an `<img width:100%;height:100%>` inside; sibling text column 700 px; parent width 600).**
- Passes (fills): definite-height parent (600x300; 600x900); helper whose direct parent is a STRETCHED grid item (600x700); helper whose direct parent is a stretched flex item (600x700); helper that is itself a grid item (600x700).
- Falls back to 3:2 (600x400) and does NOT fill: parent indefinite (sole child, 400), parent with `min-height:500px` only (400 in 500), a `min-height:700px` section (400), flex column with min-height (400), a `flex:1` wrapper in a min-height column (400), grid item not stretched (`align-items:start`, 400), a helper two levels below the stretched grid item (400), and the helper ITSELF being a flex item (400: `aspect-ratio` plus a definite width suppresses stretch). In no case did Fill collapse to zero, so "never invisible" holds; "fills its layout box" holds in only 4 of 13 layouts. The rule `Container content bands MUST pass a stretched height` is therefore load-bearing, and the common hero (min-height section) falls back to 3:2.
- Quirks-mode trap: a fixture without `<!doctype html>` gives 900 (percent resolves to the viewport). Every Fill check must run in standards mode.

**§7.1 `<picture class display:contents>` with the `<img>` as flex or grid item.** Passes: margin (`30px 20px`), `order:2`, `align-self:flex-end`, `margin-left:auto`, `grid-column:2` and `gap` all apply to the `<img>`; picture box is 0x0; `<source media>` picks the right file at 500 px. Failure mode: any rule that targets the picture (a parent `> *` rule, `:nth-child`, `:first-child`, a `margin/order/align-self` set on the child element) is ignored (img stayed at 0,0, 300x200 with `picture{margin:50px;order:5}`). Existing CSS targeting direct children of `.sgs-container__inner`: src/blocks/site-header-row/style.css (lines 23, 93), site-footer-row/style.css (19, 70), includes/sgs-footer-rows-full-width-css.php (50, `> *{width:100%}`). They would hit the picture, not the image.

**§7.4 helper painting (border 10px, radius 60px, overflow hidden, shadow, hover zoom scale 1.3, DPR 2).** Passes: 0 of 124 sampled ring pixels leaked red outside the inner radius; red at distance 49 px from the inner-radius centre, blue border at 51 px; box-shadow still painted outside the overflow-hidden box; Padding on the helper insets the image (260x160 inside 300x200 with padding 20). Padding on a bare `<img width:100%;aspect-ratio:3/2;padding:20px;border:5px>` is 350x250 (content-box) vs 300x200 (border-box): fine here because theme/sgs-theme/assets/css/core-blocks-critical.css sets border-box globally, but the editor canvas and any non-theme context must be checked.

**§7.5 SVG stroke with `vector-effect:non-scaling-stroke` vs mask (non-square box, stretch).** Passes. 400x240 at DPR 2 (4 px stroke): every stroke pixel lies within 4.24 device px of the mask outline (half-stroke is 4), 0 stroke pixels beyond half+1.5, 0 mask-edge pixels without stroke within 1.5; 400x240 at DPR 1 and 200x400 at DPR 2 (6 px stroke) the same; the `keep-proportions` policy (`mask-size:contain` + `xMidYMid meet`) also coincides. Traps: (a) a mask data-URI SVG with `preserveAspectRatio='none'` (the `sgs_end_shape_url` / label end-shape style) silently turns `contain` into a stretch, so the keep-proportions policy needs a different mask encoding with explicit width/height and no `none`; (b) `vector-effect` is NOT in `sgs_svg_kses_allowed_tags` (only used in CSS in icon/diagram-dimension), so the stroke svg must be renderer-authored with the effect set by stylesheet class; (c) reasoned, not run: if the stroke svg sits inside the §7.4 `overflow:hidden` helper, half the stroke is clipped wherever the shape touches the box edge (circle, ellipse, pill), so the stroke layer must sit outside the clip or the path be inset by half the width.

## RISKS

R1. Border and radius on a mask: Radius is omitted with a mask, but the DB classifier will still count it as a setting that can be inert; AC-13's omission rules will need the same table to feed the DB's "claimed" gate. R2. The shared framework DB is one file (memory: "serialise deploys and reseeds", "reseed from HEAD", "second name for the shared DB"); PS-1 runs sgs-update, which writes it for every session. Use `SGS_FRAMEWORK_DB` and prove isolation by sha. R3. `<source media>` cannot see container queries. `SGS_Breakpoints` mobile = max 767 plus an opt-in `@container (max-width:479px)` copy (class-sgs-breakpoints.php::CONTAINER_MOBILE_MAX, `opts['container']` in sgs_emit_responsive_css). Where a block opts in, a narrow box would take Mobile CSS (ratio, fit, focal) with the Desktop file. R4. `sgs_collect_css( string $css )` takes finished CSS, dedupes by md5 of the text and lifts `<style>` tags out of rendered block output at `render_block` priority 99. It is a no-op in the editor/REST (CSS stays inline in the preview), which is the correct parity path but the spec's "scoped by a hash of the slot's values" is the CALLER's job; nothing in the collector scopes. A renderer class that calls `sgs_collect_css` directly instead of emitting a `<style>` bypasses the D303 "custom CSS last" insertion-order contract only if called after the Additional-CSS lift. R5. Existing 9% overscan rule (F10) and `isWrapper` filter (F5) are both load-bearing in other gates; changing either without the matching gate edit fails check-element-manifest-conformance.js or the motion gates. R6. `sgs_media_atom_source_css` URL injection is real and confirmed: `$url = $attributes[...]` is interpolated raw into `--sgs-media-background-image:url("…")` for three tiers, with no escaping and no `esc_url`. Closing it "by removal" is right, but the same unescaped pattern is worth a search in the other atoms (`overlay`, `box-shape`) before declaring FR-49-12 satisfied. R7. Hero `splitMediaType` anchors the cloner's scalar-media role detection (scripts/data/scalar-media-roles.json, check_value_identity.py). Any rename of the media-type family needs both repointed in the same commit (the hero block.json comment records the last time this bit). R8. "Typing a tablet minimum height overwrites desktop" and the "five focal data shapes" were not independently reproduced (not in scope of the code-path trace). The DB shows focal-like storage as: CSS string (container.backgroundPosition, media.objectPosition), {x,y} object (sgsObjectPosition), tier-object of CSS strings (hero.splitMediaObjectPosition) and core/cover.focalPoint {x,y}; that is four shapes.
