# T6: how Elementor, Bricks, Webflow and Framer present media controls (2026-11-09)

Scope: primary vendor docs only. Webflow help-centre pages returned HTTP 403 to WebFetch; a second pass with Firecrawl read the Webflow Image, Video, Background styles, Breakpoints and background-video pages in full (cells marked "read"). Framer's official docs still name almost no image or video panel labels, so most Framer cells stay "not verified". Elementor and Bricks image and video controls were read directly. "no equivalent" means the product's documented controls have none; a control missing from a doc page is marked "not verified", not "no equivalent", unless the page was read in full.

## How each product shows an inherited value

Elementor: a smaller breakpoint shows the larger device's value as a greyed placeholder ("The previous value will be reflected as a greyed placeholder", ER). The page was read in full via Firecrawl; the earlier claim of a clickable grey dot naming the source breakpoint is not on it and stays not verified.

Bricks: desktop is the base and its values flow down; a smaller breakpoint's value wins (BR). The "responsive control indicator" icon on a control is configurable: show if any value exists (default), show if a non-base value exists, show on all, or disable (BR). The page does not describe a muted look for inherited values; it mentions a yellow dot, lines and arrows beside the breakpoint icons when the base breakpoint is changed (BR).

Webflow: styles cascade from desktop in both directions (up to 1280, 1440 and 1920 px, down to tablet and mobile); tablet values cascade down only. To see where a value comes from, open the Style panel and click the blue or orange labels and icons beside a property; a blue or pink label can be cleared with Reset or Opt/Alt-click (https://help.webflow.com/hc/en-us/articles/33961260724243, read). The orange label's exact meaning is not stated on the page.

Framer: a new breakpoint inherits from the primary, and each can override properties; the February 2024 update highlights properties whose values differ from the primary (they no longer inherit changes), and clicking the label then "Reset Override" restores inheritance (F-bp and F-upd, read).

## How each product hides controls that do not apply

Elementor: the Video widget shows controls per source; its documentation lists which source each control "applies to" (Poster and Preload for self-hosted only, Intro Title for Vimeo only, External URL reveals a text box) (EV). The Image widget reveals Lightbox only with Media Files and the gear options only with a custom URL (E).

Bricks: controls are shown only when a parent choice makes them relevant, stated in the docs as "Shown only when ..." or "Only available when ..." (the Video page repeats this per source: YouTube, Vimeo, Media, File URL and Dynamic Data each show their own group): Custom tag when HTML tag is custom, Media query when Breakpoint is Custom, Custom caption when Caption type is custom, Custom mask when Mask is Custom, lightbox sub-settings when Link is lightbox, and Image Overlay is unavailable for autoplay with a preview image on YouTube and Vimeo (B, BV extract).

Webflow: background styles do not apply to image and video elements (W-bg and W-img, read); the Size section's ratio is overruled when width and height are both set, which is a precedence rule, not a hide (W-size extract). Other conditional behaviour not verified.

Framer: Visible can be bound to a CMS field with an "Is set" condition (https://www.framer.com/help/articles/how-to-add-video-components-to-your-cms-pages/). Property-level hiding not verified.

## Cross-product patterns worth copying

1. Choice first, detail only after: Bricks's Caption type and Link To and Elementor's Link dropdown reveal their sub-fields only for the chosen option. This matches the spec's rule table (§9.3).
2. Greyed placeholder for an inherited value (Elementor), plus a per-device override mark and one-click reset per property (Framer). This matches §9.2's "Mobile: using Tablet" line and per-field Reset.
3. Safe defaults with a visible escape: Webflow's play/pause button on by default for background video, and a Decorative option inside the alt control; Bricks's custom alt that overrides the library value.

## Gaps

Still not verified: Framer's image and video panel labels (Academy lessons name Fill, Fit Content and an intrinsic-size right-click but no control labels), Framer alignment, order, shadow and filters; the orange label meaning in Webflow; Webflow's Style-panel Size labels beyond the width-and-height extract; Elementor's grey-dot claim; any product's Order, Blend or fetch-priority control. Webflow's Video element has no poster, playback or ratio controls (read).
