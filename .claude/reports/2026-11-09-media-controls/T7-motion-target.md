## 2. How scroll effects are driven

GSAP ScrollTrigger precomputes start and end positions, watches only scroll position, debounces scroll events and updates on the next requestAnimationFrame; it does not use IntersectionObserver. Scrub is true or a smoothing time in seconds (https://gsap.com/docs/v3/Plugins/ScrollTrigger/, WF). Webflow exposes the same idea as "smoothing" (default 50% in its tutorial, FC).

Scroll-event animation runs on the main thread and can jank; scroll and view timeline animations can run off the main thread, and animating transform rather than width lets them be composited (https://developer.chrome.com/docs/css-ui/scroll-driven-animations, WF). Restrict animation to opacity and transform; use will-change sparingly and only on elements about to change (https://web.dev/articles/animations-guide, WF).

CSS: `animation-timeline` with scroll() or view(); declare it after the `animation` shorthand, which resets it (https://developer.mozilla.org/en-US/docs/Web/CSS/animation-timeline, WF). Support: Baseline Newly available October 2026; Chrome and Edge 115, Firefox 159, Safari 26 (https://web.dev/blog/web-platform-10-2026, WF; https://developer.chrome.com/docs/css-ui/scroll-driven-animations, WF). Firefox 159 default-on per search result (https://developer.mozilla.org/en-US/Firefox/Releases/159, TV). Fallback: `@supports (animation-timeline: scroll())` with the static layout otherwise (MDN page above).

How builders drive parallax: Webflow uses its own scroll-animation timeline with smoothing (FC); Framer Scroll Speed and Elementor Vertical Scroll and Bricks parallax speed variables are documented as controls only, the underlying mechanism is not verified; GSAP uses scrub on ScrollTrigger.

Sub-pixel versus whole-pixel movement: not verified. Two targeted searches returned no primary page on the subject (TV).

Recommended driver (my recommendation, not a vendor statement): CSS `animation-timeline: view()` on transform and opacity only, inside `@supports` and a `prefers-reduced-motion` guard.

## 3. Behaviour every effect must respect

Reduced motion: `prefers-reduced-motion: reduce` means the user wants non-essential motion minimised; large scaling or panning can trigger vestibular discomfort (https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion, WF). WebKit recommends wrapping scroll-driven animations in the query (https://webkit.org/blog/17101/a-guide-to-scroll-driven-animations-with-just-css/, WF). Elementor disables its motion effects when the OS reduce-motion setting is on, and its Mouse Effects affect desktop only (https://elementor.com/help/motion-effects/, FC). Framer troubleshooting says reduced motion can stop Ticker and Appear effects (https://www.framer.com/help/articles/troubleshooting-animation-issues, TV).

WCAG 2.2.2 Pause, Stop, Hide (Level A), exact text: "For any moving, blinking or scrolling information that (1) starts automatically, (2) lasts more than five seconds, and (3) is presented in parallel with other content, there is a mechanism for the user to pause, stop, or hide it unless the movement, blinking, or scrolling is part of an activity where it is essential" (https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html, FC). Applies to marquee, Ken Burns loops, float and background video.

Touch with no hover: hover must never carry content; Elementor mouse effects are desktop only (above); Bricks lists Hover and Click as separate triggers (WF).

iOS video: autoplay without a gesture needs muted or no audio, on screen, and `playsinline` on iPhone; it pauses off screen; `play()` rejects if blocked (https://webkit.org/blog/6784/new-video-policies-for-ios/, WF).

iOS fixed backgrounds: caniuse lists Safari on iOS 15.4 to 26.6, 27.0 and 27.1 to 27.2 as "Partial support", with note 6: "`fixed` is recognized, but has no effect. See bug 275247" (https://caniuse.com/background-attachment, FC). It also notes most mobile devices lag when updating a fixed background after scrolling (same page). Desktop Safari 15.4 onward is listed as supported (https://caniuse.com/mdn-css_properties_background-attachment_fixed, TV snippet). Conclusion: do not use `background-attachment: fixed` for parallax on touch; use the CSS scroll-timeline or a static background.
