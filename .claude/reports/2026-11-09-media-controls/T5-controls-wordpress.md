# T5: what the leading WordPress block tools use for each media setting (primary source, 2026-11-09)

Method: shallow sparse clones of the real repos, then read the control code. Repos confirmed: `WordPress/gutenberg` (trunk), `stellarwp/kadence-blocks` (master), `gambitph/Stackable` (develop), `brainstormforce/wp-spectra` (package name `ultimate-addons-for-gutenberg`, v2.20.6, so it is Spectra). GenerateBlocks has no public repo (`tomusborne/generateblocks` and `GenerateBlocks/generateblocks` return 404), so it was read from the wordpress.org release zip, v2.5.0: compiled code only, in `dist/styles-builder.js` and `dist/blocks/media/index.js`. Its labels carry the text domain `generateblocks-pro`, so some panels may be Pro-only. Every label below was read in the source named. Paths: GU = `packages/block-library/src/` or `packages/block-editor/src/components/`; KB = `src/blocks/image/image.js` (Kadence Image) or `src/blocks/rowlayout/style-controls.js` (Kadence Row background); SP = `src/blocks/image/settings.js` and `src/components/background/index.js`; STK = `src/block-components/image/edit.js` and `src/block-components/helpers/backgrounds/edit.js`; GB = the zip's `dist/` files. SGS paths are under `plugins/sgs-blocks/src/components/`.

Reading guide: "Recommended" is what a non-technical client will find most obvious at a glance. "Not verified" means I did not read that surface, so it is not claimed.

## Findings that change the plan

1. Nobody offers a free-text aspect ratio to clients except GenerateBlocks (a raw `TextControl`, GB `styles-builder.js`, label "Aspect Ratio"). Every client-facing tool uses named presets: Gutenberg a dropdown with a Custom entry, Kadence and Stackable a dropdown of named ratios ("Landscape 4:3", "Square 1:1"). SGS's planned chips with Custom are the clearest of all.
2. No tool shows a visual shape grid drawn with the client's own photo. Stackable has the nearest thing (a thumbnail grid in a popover, static pictures), Kadence and Spectra use a plain dropdown of shape names. The planned `ShapeField` is ahead of the field.
3. Stackable is the only tool that shows an inherited per-device value inside the field itself: `src/components/advanced-range-control/index.js` sets `propsToPass.placeholder` to the Tablet or Desktop value when the field is empty (greyed text). Kadence and Spectra show nothing. Gutenberg has no per-device editing yet. The planned "Mobile: using Tablet" note is stronger than the field (it names the source).
4. Load priority: no tool has a High/Low control. Kadence has a toggle "Prevent Lazy Load", Spectra a toggle "Disable Lazy Loading", Stackable and Gutenberg have nothing in the files read. A four-way priority select would be SGS-original and probably confusing to a client; see the row.
5. Gutenberg's own pattern for optional controls is `ToolsPanel`/`ToolsPanelItem` with `hasValue`, `isShownByDefault` and a per-item reset (Image `dimensions` group, Cover `Settings`). That is the field answer to "hide irrelevant controls".

## Where SGS's planned control is weaker than the field

1. Alt text is a single-line `TextControl` in `media/atoms/meaning.control.js`; Gutenberg and Kadence use a multi-line text area.
2. Fit is a plain dropdown (`ObjectFitField.js`) showing CSS words such as "scale-down"; the plan's icon chips with a plain caption are better, but the plain-language wording must be written (Gutenberg's toggle group is the nearest field control).
3. Shadow in the plan is a layered editor; Stackable alone ships presets (`IMAGE_SHADOWS`), which a client can use without knowing blur or spread. Add preset chips first.
4. Greyscale and Blur have no media-level SGS control yet (`SurfaceGroundControls.js` is for surfaces); Stackable already has sliders.
5. Tile options (repeat, size) are not found in `src/components/media/`.
6. Load priority: do not copy a four-way select; every product offers at most one toggle.
7. The planned inherited display is stronger than all products except it must show the source name in the field, not only below it.

## What could not be verified

1. GenerateBlocks: compiled release code only (v2.5.0), no source repo; control types for Width and Height, and any loading control, are not verified. Some panels carry the Pro text domain.
2. Gutenberg: the border, radius and shadow panel labels and the `ToolsPanel` wiring of block supports (in `packages/block-editor/src/hooks/`, not read); the aspect-ratio preset list; the poster label (`block-library/src/utils/poster-image`, not cloned).
3. Kadence: components under `src/components/` (`KadenceImageControl`, `KadenceFocalPicker`, `ResponsiveRangeControls`) were not cloned, so their internals and how they show inherited values are not verified; min and max sizing in its Advanced tab.
4. Spectra: image link UI, video controls and any aspect ratio control (none found in `settings.js`, but its toolbar file was not read).
5. Stackable: border and hover wiring for the Image block (block-level components not read); the exact control type of `Alignment.InspectorControls`.
6. Nothing was checked against the live editor UI; all findings are from source, so layout and visual quality of each control are not assessed.
