## Dropped, narrowed or reinterpreted

1. "list every block ... found by grepping the code and DB, not from the spec's table": narrowed. Block coverage follows the spec's §10.4 set plus T1's `BackgroundPanel` grep; no all-blocks DB query for media-bearing attributes is cited for T2's set (T1 §0 "Not covered" hands the rest to T2).
2. "end shape (attributes, controls, markup)": narrowed to attributes (§8, §13). Markup and controls are generic (§7.1, §9.4).
3. "what could not be verified" and "what SGS already has" (1c): dropped from the spec and proposal; held in T5/T6 only.
4. "(run them)" (1d(ii)): narrowed. 30 of 66 effect rows were not run; the proposal states this, but no later step runs them.
5. Gap table (1d(iii)): narrowed to 12 rows with a different status vocabulary.
6. Approval question (1e): not in the deliverable.
7. "Mask shapes ship in the first release": read as presets only.

## Five most serious gaps

1. 1b consistency: spec §6.1/§6.2/§14.4 say atoms and PHP twins are extended; T3 §1 says delete 15 twins, replace atom CSS and generators; AT §5 says §8.2 deletes `includes/media/atoms/*`. The spec's §8.2 never lists the atom CSS or stylesheet generator. This must be settled before Bean approves.
2. 1a: per-block "has today", exact change, end shape and reasons exist only in T1/T2. Neither the spec nor the proposal carries them; the proposal groups about 40 blocks into nine rows.
3. 1c: the control tables in the spec (§9.3) and proposal omit the requested reason, "what SGS already has" and "not verified" columns (present only in T5/T6).
4. 1d(ii) to (iii): 30 effects were never run; the gap table has 12 rows, not the requested three-state verdict per target effect; the proposal's "28 work" contradicts T10's 32.
5. 1e: no approval question in the proposal, and no council synthesis (findings, changes made, GO/NO-GO) in the folder; "reading the spec in full" is asserted, not shown.
