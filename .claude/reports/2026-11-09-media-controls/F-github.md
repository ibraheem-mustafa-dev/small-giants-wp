# F-github: responsive backgrounds, focal point, parallax and panel patterns (read via gh, 2026-11-09)
Repos reached: stellarwp/kadence-blocks, gambitph/Stackable, brainstormforce/wp-spectra, WordPress/gutenberg. GenerateBlocks has no public source repo (tomusborne/generateblocks and GenerateBlocks/generateblocks do not resolve), so it is not covered.
## (a) Responsive background image: attribute shapes
Kadence Row (src/blocks/rowlayout/attributes.js): desktop uses flat attrs (bgImg, bgImgID, bgImgSize, bgImgPosition, bgImgAttachment, bgImgRepeat). Tablet and mobile are single-item ARRAY attributes: `tabletBackground: { type:'array', default:[{ enable:false, bgColor:'', bgImg:'', bgImgID:'', bgImgSize:'cover', bgImgPosition:'center center', bgImgAttachment:'scroll', bgImgRepeat:'no-repeat', forceOverDesk:false, gradient:'' }] }` (same for mobileBackground, tabletOverlay, mobileOverlay). An `enable` flag plus `forceOverDesk` decides whether the device override applies. Rendered as CSS background-image on a div, not an element. Stackable v3 (src/block-components/helpers/backgrounds/attributes.js): flat attrs, each flagged `stkResponsive: true`: backgroundMediaId, backgroundMediaUrl, backgroundMediaThumbnailId/Url, backgroundMediaExternalUrl, backgroundPosition, backgroundRepeat, backgroundSize, backgroundCustomSize (stkUnits '%'). Single boolean `fixedBackground` (not responsive) maps to `background-attachment: fixed` via valueCallback. The framework expands stkResponsive into desktop/tablet/mobile keys and emits media-query CSS. This is the cleanest model: one declaration, one flag. Spectra (src/blocks/container/backgroundCss.js): suffix-per-device attributes, backgroundImageDesktop/Tablet/Mobile, backgroundPositionDesktop/Tablet/Mobile, backgroundAttachment*, backgroundRepeat*, backgroundSize*, backgroundCustomSize*, plus xPosition/yPosition with unit-type per device (xPositionTypeTablet). Overlay image repeats the whole set (backgroundOverlayImageDesktop etc). Roughly 60 attributes for background and overlay. Rendered as CSS. Gutenberg core cover (packages/block-library/src/cover/save.jsx): `const isImgElement = ! ( hasParallax || isRepeated );` so a real `<img data-object-fit="cover" data-object-position=...>` is used unless parallax or repeat is on, in which case it falls back to a CSS `background-image` span. Focal point becomes `object-position` (img) or `background-position` (span). index.php::render for useFeaturedImage injects the featured image with the same split (`$attributes['hasParallax'] || $attributes['isRepeated']`).
## (b) Focal point per device
Nobody models a focal point per device in these plugins. Kadence and Spectra use a position string or x/y percent per device (text/select). Stackable uses `backgroundPosition` (responsive string) and a separate FocalPointPicker wrapper for the Image block only (src/components/advanced-focal-point-control/index.js): wraps `@wordpress/components` FocalPointPicker, defaults the display to {x:0.5,y:0.5} because the picker rejects empty values, and adds its own reset button. Core cover has one focalPoint. Gutenberg tracking issue #85243 ("Responsive style states") lists "Cover: Fixed/repeated background and focal point" and "Background image works but can't be unset for a particular viewport" as NOT yet supported. Per-device focal point is a gap to own.
## (c) Parallax and speed
Kadence: attachment value 'parallax' on bgImgAttachment adds class kt-jarallax (save.jsx: `'kt-jarallax': bgImg && bgImgAttachment === 'parallax'`), runtime src/assets/js/kt-init-parallax.js calls `jarallax(element,{ speed: kadence_blocks_parallax.speed, elementInViewport: element })`. Speed is one global localised value, not per block. It also sets `--kb-screen-height-fix` = clientHeight + 200px on resize to hide jarallax gaps. Stackable: `fixedBackground` boolean only; open request #2366 for real parallax movement. Core: `hasParallax` is really `background-attachment: fixed`, no speed.
## (d) Controls and device switcher
Kadence reads the editor preview device via `previewDevice` and `getPreviewSize(previewDevice, desktop, tablet, mobile)` and shows a tab per device. Stackable uses `useControlHandlers(attribute, responsive, hover)` so one control reads and writes the attribute for the current device (the control follows the editor device switcher automatically, with a reset button per control). Core ToolsPanelItem (packages/components/src/tools-panel/tools-panel-item/hook.ts) takes `hasValue`, `isShownByDefault`, `panelId`, `resetAllFilter`, `onDeselect`; optional controls hide behind the panel menu until set, which is the standard answer to overwhelming panels. Dependent visibility is done by conditionally rendering the item or passing `isShownByDefault` false with `hasValue`. Gutenberg is adding breakpoint style states (#85243, #81226) so core will have device-scoped styles in the sidebar.

No core `<picture>` for art direction exists; the only mechanism is the img/background switch above.
## (f) Complaints to avoid
Overlay on device only: Kadence #141 (overlay not shown on tablet or mobile unless also set on desktop), #150 (tablet/mobile overlay image errors), #149 (opacity 0 becomes an unexpected value), #148 (parallax plus force-no-image on mobile), #60 (overlay lacks responsive image sizes). Stackable overlay clipping: #3559, #2913 (overlay or colour fills corners, ignores border radius), #2273 (overflow visible plus border radius loses the clip; fix is border-radius inherit on the overlay pseudo-element), #2959. Shape masks: Stackable #3777 (image shape popover too tall), #3127 (border radius plus shape clash). iOS fixed background: Stackable #133 zoomed in, core #50669. Core overlay controls: #60644, #51625 (opacity in 10 steps), #27809. Focal picker UI: core #68914 (sidebar overflow when dragging to the right), #50503; Stackable #1444 (focal point wrong when image is zoomed), #1454 (block error typing in focal input). Spectra #91 and #54 (breaks layout; asset version bump on every save invalidates site cache).
## Top patterns to adopt
1. One responsive flag per attribute with a device-aware control and per-control reset (Stackable). 2. Render a real img with object-fit/object-position and srcset/sizes by default, fall back to CSS background only for repeat or fixed (core cover). 3. Inherit tablet/mobile from desktop; an override needs an explicit unset (avoid Kadence's enable/forceOverDesk and the core gap that a background cannot be unset per viewport). 4. Put the overlay and shape clip on a wrapper with border-radius inherit and a clip that survives overflow visible. 5. Hide optional controls behind ToolsPanel with hasValue. 6. Parallax: per-block speed, disabled on touch and reduced motion, never raw fixed attachment on iOS.
