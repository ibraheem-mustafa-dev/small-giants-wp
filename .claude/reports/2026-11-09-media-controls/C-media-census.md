## 1. F2/F3/F4: focal point

The good control is `plugins/sgs-blocks/src/components/FocalPositionField.js`, the SGS wrapper around core `FocalPointPicker` (thumbnail with a draggable point plus percentage x and y inputs). It takes `format="xy"` ({x,y} floats 0-1) or `format="css-string"` (an `object-position` string such as "center 20%"); conversion is `utils/objectPosition.js::objectPositionToFocalPoint` and `focalPointToObjectPosition`. The responsive atom wrapper is `components/media/atoms/focal-point.control.js::control` (wraps `ResponsiveControl`, stores per-tier CSS strings, or a tier object on hero); the logic half is `focal-point.js` (`resolvePosition`, `validate`, `disclosure`, `css`).

Data shapes in the framework today: (a) CSS string in three flat keys (`objectPosition`, `...Tablet`, `...Mobile`) on media, decorative-image, product-card, testimonial, before-after; (b) tier object {desktop,tablet,mobile} on hero `splitMediaObjectPosition`; (c) {x,y} floats in `sgsObjectPosition` from `blocks/extensions/image-controls.js` (gallery, card-grid, team-member); (d) {x,y} per item in card-grid items and gallery images through a raw `FocalPointPicker`; (e) untiered CSS string `backgroundPosition` (container family, nav-drawer). Five shapes for one idea.

Where the preset dropdown lives: `blocks/container/components/BackgroundPanel.js` Image tab (`BG_POSITION_OPTIONS`, 9 keyword pairs), reached by container, hero, trust-bar, site-header, site-footer, multi-button and physics-canvas through `ContainerWrapperControls`; and a copy in `blocks/nav-drawer/edit.js` (its own `BG_POSITION_OPTIONS`). The Video tab of the same BackgroundPanel already mounts the real picker (`MediaElementPanel`, atoms object-fit and focal-point, `scope="backdrop"`, labelled "Background position") but without a thumbnail URL and untiered. The SVG tab has a third control also labelled "Position" that means layer order (Background or Foreground, `bgSvgPosition`): same label, different meaning.

Is Position dependent on Size. Element scope (sgs/media and every `mediaElements` block): yes, declared in `components/media/atoms/registry.js` as `focal-point.requires.ObjectPosition = ['ObjectFit:cover|contain|none|scale-down']`; `focal-point.js::disclosure` returns state `disabled` (visible, greyed, reason text) for `fill` or any value outside that list. It is also `disabled` when the block's ObjectFit attribute is unset with no default (media defaults to cover, so fine there). Backdrop scope (container family): no dependency at all. `disclosure()` returns `shown` whenever `scope !== 'element'`, and the Image tab's SelectControl never calls it. By CSS, Position moves the image only along the axis that overflows: cover with a matching aspect ratio is a visual no-op; contain moves it only along the spare axis; auto with no-repeat is active; tiled Repeat makes it an origin offset.

The one hard no-op provable from code: Video tab with Size = Auto. `includes/class-sgs-container-wrapper.php` writes `object-fit:` plus `$bg_size` for the background video (hero `render.php` does the same with `$bg_video_size`); `auto` is not a legal `object-fit` value, so the declaration is dropped, the video falls back to `fill`, and `object-position` then has nothing to move. Inferred from the CSS grammar, not run live.

Owner's theory ("because the setting also serves other media types"): partly right, not the full cause. True part: `backgroundSize` and `backgroundPosition` are one attribute pair driving a CSS background (`::before` path), a real `<img>` (object-fit and object-position) and a `<video>` (object-fit), and the backdrop vocabulary (cover/contain/auto) is narrower than the element vocabulary, so `auto` is legal for CSS backgrounds and illegal for video. False part: SVG does not use these attributes, and for images (the common case) the control is ungated only because backdrop-scope `disclosure()` is hard-coded to `shown` and the Image tab does not call it. For sgs/media, "only works with some Size values" is the element-scope `disabled` rule above; it shows the control greyed with a reason rather than hiding it, so the gap there is a hide-versus-disable policy, not a missing condition.

## 2. B1: Attachment and every parallax-like feature

Attachment (`backgroundAttachment`, enum scroll or fixed, labelled "Fixed (parallax)") renders as `background-attachment:fixed` on the container's `::before` media layer (`class-sgs-container-wrapper.php`, the `$sgs_media_layer_decls` block). `fixed` also forces `$sgs_bg_img_is_simple` false, so the real-`<img>` fast path (fetchpriority, LCP) is abandoned and the image paints through CSS. No strength option exists: the image is pinned to the viewport. Platform limits of the technique (not verified here): ignored on iOS Safari, and broken by any transformed ancestor.

Motion parallax effect (`x-sgs-effects/parallax` in `src/components/motion/generated-motion-defs.json`): speedRatio (-1 to 1, per device), clamp (px, per device), basis (page or view), axis (x or y), background (boolean). Runtime: `src/shared/effects/fx-parallax.js` plus `assets/css/fx-parallax.css` write `--sgs-plx-*` offset properties; `assets/css/motion.css` composes them into `translate` or, with background true, `background-position` on the part. A real `<img>` background is moved through `translate` with 9% overscan (`img[data-sgs-mc~="background-position"]`). This is the speed and basis control Bean says Attachment lacks.

Partly built (CSS reading, not live-tested): when the background paints on the root's `::before` (tiled, size auto, fixed, per-device images), the `background-position` channel in `motion.css` applies to the element carrying `data-sgs-mc`, the root, which has no background of its own; the `::before` rule sets its own `background-position`, so the offset cannot reach it. Parallax with Background on a `::before` image is therefore very likely inert, and the `background` part has no element to attach to.

Other threads: `sgsHoverZoom`, `sgsHoverImageZoom`, `imageZoomHover` are migrated by `includes/motion/migrate/mappers/class-sgs-motion-map-hover.php` into a hover state on the block's `media` or `image` part; per-item zoom (card-grid, gallery, post-grid), `sgsHoverZoomStyle: spill`, grayscale and the `bgHoverZoom*` family are reported with no destination. That mapper's note "the background image layer is no declared part" is stale for container and hero, which now declare a `background` part. Ken Burns (`x-target-level: surface`, writes translate and scale) is offered on surface parts including `background`. fx-parallax is the same module as the motion parallax effect. No block.json outside core/cover carries a `hasParallax` or Ken Burns attribute any more.

## 3. Q4: is the background a motion part in every state

Declared: container and hero `supports.sgs.elements.background` (selector `.sgs-container__image-bg` or `.sgs-hero__background`, `surface: true`) plus `svg-bg` (`.sgs-container__svg-bg`, `svg: true`). Video has no part (`.sgs-container__video-bg`, `.sgs-hero__video-bg` undeclared). sgs/media declares part `media` with `isWrapper: true`, which `components/motion/TargetPicker.js::targetOptions` filters out unless it already holds a layer.

`absentIn` is not read by any editor code: grep over `src/components` and `src/blocks/extensions/motion` finds no consumer. Its only reader is `scripts/check-motion-part-render-paths.py`, a CI gate that demands an `absentWhy` and fails stale entries. So the picker (`TargetPicker.js::targetOptions`, `blocks/extensions/motion/layers/TargetRow.js::targetRowOptions`) always lists "Background image" in the editor, in every state, even when nothing exists to animate. The only editor-side filters are `source-mode.js::elementsForSourceMode` (`notInMode`) and `"motion": false`.

At runtime the entry works only on the real-element path: single desktop image, no-repeat, cover or contain, scroll, no tablet or mobile images, no video (`$sgs_bg_img_is_simple`). In every other state (tiled, size auto, fixed, per-device images) the image is `::before`, so a layer targeted at `background` matches no element and silently does nothing (its own `absentWhy` says a layer on the root reaches the section). Video: no part. SVG: `svg-bg` works. Lottie: the poster reuses the `sgs-container__image-bg` class.

Can it be selectable always: yes, by fixing the renderer, not the picker. Print one real element for the background media in every state (`<span class="sgs-container__image-bg">` painting CSS `background-*` for tile, size, per-device images in media queries and `fixed`, or the `<img>` when simple) instead of the root's `::before`. Then the part selector always matches, the `background-position` parallax channel acts on a real box, and Ken Burns and hover states work. Add parts for `.sgs-container__video-bg` and `.sgs-hero__video-bg`. Keep `absentIn` only for a genuinely absent element (no background set) and make the editor read it to grey the option. Cost: the `::before` stacking design (media z-index -1, overlay span 0, content 1; wrapper comments describe it) must be re-checked for overlays, shape dividers and `fixed`; the PHP twin and the editor preview (`utils/background-preview.js`) change together.

## 4. Q3 groundwork: one panel opening another

Precedent found: none for panel-to-panel. Grep over `src` for `openGeneralSidebar`, `enableComplementaryArea`, controlled `opened=` and `onToggle=` finds nothing. Closest: `blocks/card-grid/edit.js` calls `selectBlock( templateId )` from `CardDesignPanel` (block jump, not panel); `blocks/buybox/sticky-bar.js` and `blocks/choice-flow/flow-routing.js` use `scrollIntoView` on canvas elements. Every motion panel is `PanelBody ... initialOpen={ false }` and uncontrolled; the Effects panel's chosen Target is `useState( ROOT_TARGET )` inside `blocks/extensions/motion/EffectsPanel.js::EffectsPanel` (Hover and Entrance each keep their own local `target` too). Effects renders in `InspectorControls group="styles"` (`MotionPanels.js`), the same group as the Background panel, so no tab switch is needed.

Build for the link (a "Animate this background" button in the Background panel): (1) a tiny shared store, module-level or `@wordpress/data`, `inspector-focus` holding `{ clientId, panel: 'effects', target: 'background', nonce }`; (2) in `EffectsPanel`, make `PanelBody` controlled (`opened` plus `onToggle`) and add an effect that, when the request matches the block's `clientId`, sets the target to `background`, opens the panel and calls `scrollIntoView` on it; (3) the button dispatches the request. Core exposes no stable API to open a specific inspector panel, so do not rely on preferences-store internals. Prerequisite: the background target must be a real, always-matching part (section 3), or the link lands on a layer that does nothing. The same store serves Hover and Entrance and a later "Edit in Effects" shortcut from sgs/media (M2).

## 5. Architecture: consistent versus divergent

Consistent base: the media atom system (`components/media/atoms/*`, registry, `MediaElementPanel`, `MediaPanelLayout`, PHP twins in `includes/media/atoms/*`, `SGS_Media_Element`, CSS `assets/css/media-atoms/*`, parity test `scripts/tests/test-media-atom-parity.mjs`); `FocalPositionField`; `MediaPicker`; `ResponsiveControl`; the motion model (parts in `supports.sgs.elements`, `TargetPicker`); `SGS_Container_Wrapper` for every composite background.

Divergent (hand-rolled copies): (1) five focal data shapes and four focal mounts (atom, extension `image-controls.js`, raw `FocalPointPicker` in `card-grid/components/ItemEditor.js` and `gallery/components/GalleryThumbnail.js`, preset dropdowns in `BackgroundPanel.js` and `nav-drawer/edit.js`); (2) four object-fit surfaces: atom, extension `sgsObjectFit` dropdown, `BackgroundPanel` Size toggle, nav-drawer SelectControl; (3) raw `<MediaUpload>` in 18 files (audio, before-after, buybox ConfiguratorPanel, choice-flow ChromePanel, container BackgroundPanel, media VideoPanel, nav-drawer ChromePanel and edit, product-card, responsive-logo, store-selector, testimonial, timeline, LottieControls, MediaGalleryPicker, MediaPicker, AssetAtom, inline-formats) against the shared `MediaPicker` in 14; (4) per-device source three ways: media's tier override, BackgroundPanel's "Art direction (optional)" (separate `backgroundImageTablet` and `backgroundImageMobile`, painted as CSS on `::before`, which also kills the `<img>` fast path), and nothing elsewhere; (5) backdrop-scope atoms exist (`scope="backdrop"`) but the Image tab ignores them; (6) legacy hover zoom mostly migrated, a few values reported with no home.

Recommended shared file map (all under `plugins/sgs-blocks/`): keep `src/components/media/atoms/focal-point.control.js` as the single focal mount and migrate the other four shapes to its tier-object form, deleting the preset dropdowns; new `src/components/media/MediaSourceField.js` wrapping `MediaPicker` plus per-device override plus type filter (image, video, svg, lottie) for every surface including backgrounds; new `src/components/media/BackdropPanelLayout.js` beside `HeroSplitMediaPanelLayout.js` composing the Image, Video and SVG background tabs from atoms (source, object-fit with a type-aware vocabulary, focal-point, repeat and attachment as atoms with `requires`, overlay) to replace the BackgroundPanel image tab and nav-drawer's copy; one shared hide-versus-disable rule in `focal-point.js::disclosure` and the other atoms (backdrop: hide Repeat unless Size is auto or contain, hide Position for video when Size is auto); PHP twins in `includes/media/atoms/*` updated in the same commits; new `src/blocks/extensions/motion/inspector-focus.js` for the panel link; `includes/class-sgs-container-wrapper.php` printing one real background element in every state.
