# C2 Ship-PM review of Spec 49 v0.5

Scope judged against Bean's goal: clone anything Claude Design gives us, with controls clients find intuitive, by the simplest design. Times are smallest plausible. Build size today: `R5-build.md` wall-clock line sums to 9 hours with 6 to 8 agents, before v0.5's additions; on past actuals nearer 3 hours.

## STRENGTHS

- §7.2's no-modes sizing is the right cost shape: each setting prints one property and the cloner copies across one to one (§6.4, §11 row 3). The three-browser run in `c2db2791c` removed the largest unknown cheaply.
- `T-merge-decisions.md` already cut the real bloat: rules DSL, separate shape file, stroke border on masks, mixed-kind per device, `sizes` parser.
- §6.2 reuses helpers with 77 to 105 callers rather than rewriting them, and §13's table is exhaustive enough to run as a script.
- §14.2 gives most proofs a stated failure outcome, so a red proof does not stall the project.

## MUST-FIX

**M1. The native parallax driver is priced as the fix for a fault the header causes.** Problem: §10.2 "Why" quotes 55.9 px as the script driver's failure, but `T11-parallax-smoothness.md` Summary proves the stall is `header-behaviours/view.js`; blocking that script alone took p95 from 20.0 to 2.5 px at normal speed and 55.9 to 5.5 px at 4x CPU. T11 recommendation 4 says fix the header independently; Spec 49 never names it (`header-behaviours` greps empty). Effect: the cutover carries a new driver, per-block range, `animation-composition`, a Safari branch, PS-9 and AC-30 (painted-frame analysis, 5 runs, 2 widths) for what is mostly a header bug. Fix: add package WP-H ahead of Stage A, scoping `--sgs-header-height` and the three `:root:has(...)` rules (about 15 min; it helps every live site now). Cutover keeps `@sgs/scroll-driver` with §10.2's overscan and proves it with AC-20. The native driver becomes Stage C (see X1); it changes no stored attribute (§10.2 "Stored as today"), so nothing is lost by waiting. Cost: up to about 5 px trailing under heavy CPU load until Stage C. Moves: FR-49-29's last sentence, PS-9, AC-30, WP-10b's driver half. Orphans no §11 or §13 row. AC-30's negative control ("today's script driver with a header collapsing must fail") must be rewritten when it returns, because WP-H changes what it measures.

**M2. Pinned is the only net-new effect, and nothing uses it.** Problem: §10.5 marks it Missing and Build. `T8-draft-census.md` §B7 has `fixed` at 0 across all three drafts, and `K-saved-usage.md` has no `backgroundAttachment` row. `T-merge-decisions.md` kept it because "cloner and migration map them", but there is nothing to migrate. It also depends on M1's driver at strength 1 (§10.3), where script lag would show worst. Fix: Stage C (about 15 min). Replaces it: §11 sends `attachment fixed` to Custom CSS, reported, the pattern §11 already uses for unmapped filters. FR-49-29's removal of `backgroundAttachment` stays. Orphans: §11 last-but-one row's "attachment fixed to Pinned" clause; §13 row `backgroundAttachment: fixed`, which becomes "refused if found"; §10.1 Pinned cells; PS-4; AC-20's "Pinned on WebKit".

**M3. Stage A is not dormant, and one package breaks the live cloner.** Problem: §6.8 and §14.1 say "New files only, adopted by nothing", yet WP-13 rewrites `fill-media.mjs::imageSlots` (consumed by `scripts/computed-route/lib/content-coverage.mjs`), which §11 says reads only the old `Url`, `Id`, `Alt` names, while blocks still have those names until Stage B. WP-4 reworks `ResponsiveOverride` (135 importers), WP-6 extends `icon-shapes.json` (read by `src/blocks/icon/shape-options.js`, `inspector-shape.js`, `includes/helpers-icon.php`), WP-0b edits the 3,842-line wrapper. Effect: Indus and Eye Care clones run against a half-switched cloner, and non-media inspectors change during a stage promised to be safe. Fix, about 5 min each: WP-13 adds the new route as a new file and the switch-over commit moves to Stage B; `ResponsiveOverride` keeps its shared bug fix (the hard-coded "Desktop" and wrong-tier hint) and gets the new display as an opt-in prop only media passes, which also removes AC-14's non-media sample; the icon readers filter to icon entries; WP-0b becomes Stage B's first commit (S4). Orphans nothing.

**M4. Fill's automatic content band has no owner and crosses blocks.** Problem: §7.2 says "the container emitter prints that automatically when any child is Fill". `class-sgs-container-wrapper.php` has no such inspection today (`Fill|inner_blocks` greps empty), the editor needs a second copy, nesting and non-container parents are undefined, and §14.4's WP-8 row does not list it. Added by `c2db2791c`. Fix: one static rule in `media-base.css`, `.sgs-container__inner:has(> .sgs-media-fill)` setting one-column grid at low specificity so a chosen layout wins; front end and editor share it, with no parent logic. Add it to PS-2's 13 layouts (about 5 min). FR-49-38 and AC-27 stand. Orphans nothing.

**M5. WP-2 is secretly the largest package because "thin dispatcher" is untrue for the settings that matter.** Problem: §6.2 says each row maps to an existing helper, and §8 labels Focal, Height, Width, Ratio, Fit, Shape, Greyscale and Blur `plain`. They are not: Focal converts `{x,y}`; Height `fill` prints four declarations plus a `::before`; default Width is resolved per device from two other settings (§7.2); the helper needs the file's ratio per device; Fit has `tile` and `actual`; greyscale and blur merge into one `filter`; Shape is radius or a mask data-URI. WP-4's `mediaPreview` must repeat all of it in JS. PS-7's "five sample rows" can pass on five truly plain rows and prove nothing. Fix: add emitter kinds `sizing`, `focal`, `filter`, `shape` to §6.2 and §8; split WP-2 into 2a markup (§7.1, §7.3, §7.9) and 2b emitter plus validator, about 15 min each; PS-7's sample must include `sizing` and `shape`. Orphans nothing.

**M6. §7.2 contradicts itself on the default width.** Problem: the table's first row prints `width:auto` when nothing is set; the sentence added in `c2db2791c` says "`auto` when both Ratio and Height are set at that device, otherwise 100%". Effect: PHP and JS builders can each pick differently, and a 300px file either stays 300px or stretches. Fix (2 min): "`auto` when nothing sizing-related is set, or when both Ratio and Height are; otherwise 100%."

**M7. `tier_shape: slot-array` exists nowhere.** Problem: §8.3 relies on it for every item-set block, but it greps empty in `scripts/`, `plugins/sgs-blocks/scripts`, `plugins/sgs-blocks/includes` and the `sgs-wp-engine` scripts; PS-1 proves only `tier_object` (§8.1). Effect: gallery fails at Wave 1, the worst moment to learn the resolver cannot read it. Fix: PS-1 includes one item-set block (about 5 min).

**M8. Mama's is last in the queue and the freeze misses its blocks.** Problem: §13 runs mamas-test fourth, behind indus-test and eye-care-clone-test, though §14.1 and `plans/2026-11-02-clone-finishing-streams.md` name Mama's as the client waiting. §14.1 freezes only hero and wrapper, while Waves 1 and 3 rewrite gallery, product card and buybox, which Mama's plans are actively editing (`2026-11-04-mamas-commerce.md`, `2026-11-03-mamas-framework-batch.md`). Fix: site order mirrors, sandybrown, mamas-test, then the others; Mama's resumes when mamas-test passes AC-25, without waiting for the rest. Freeze every block folder Stage B edits from the moment the branch opens, and require Stage B to merge the same session (`rules/git-hygiene.md`).

Fix: `Shape` keeps its data shape and later slugs are additive (about 20 min in Stage C). §11's polygon row already falls through to Custom CSS, reported; §13 rows are unaffected because saved values are radius shapes.
