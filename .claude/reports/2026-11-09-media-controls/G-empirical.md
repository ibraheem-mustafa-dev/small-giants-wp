# Empirical gate: media design fix shapes

Method: Chrome stable via Playwright on the Eye Care site home page (darkcyan), fixtures injected into the response in the browser only (page.route rewrite, nothing written to the site). Scripts and raw output: E:/sgs-tmp/ec-r11/media/q/g.mjs, g.json, wk.mjs.

1. picture with source media (CONFIRMED). Predicted one download per width. Baseline, current hidden siblings (display:none, eager): 3 of 3 images download at 1440, 768 and 375 (reqs sd, st, sm each time). After, picture with three tiers: exactly 1 request at each width (1440 d, 768 t, 375 m); live resize 1440 to 768 to 375 to 1440 fetched only the newly matching tier each time and currentSrc followed. Tier set to none: a source for that tier whose srcset is a 1x1 data URI gives 0 requests at 375 (confirmed); hiding the picture with display:none while the img fallback remains still downloaded the tablet image at 375 (REFUTED as a "none" mechanism). Design change: "none" must be an empty-pixel source (or the picture is not printed at all with a wrapper media rule), never display:none alone.

2. Per-device object-position and source dimensions (CONFIRMED with one correction). Scoped media CSS on the img inside picture applied exactly: 1440 gives 78% 45%, 768 gives 20% 10%, 375 gives 90% 90%. In a fixed-size or aspect-ratio frame the img stayed 400x300 whatever the source dims. Correction to "do not change layout": in an auto-height img, before the image loads, a source width/height of 100x900 produced a 3600px tall box at 375 against 200px without it. After load all heights were identical (267). So each source's width and height must be that tier's true dimensions; wrong values shift layout.

3. Background element with parallax overscan and Ken Burns (CONFIRMED). Element with 120px overscan top and bottom, translate property at -120, 0 and +120, scale animation 1 to 1.15 sampled at 0, 2s, 4s: container edges always covered (gap 0 at both ends, hit test returns the img at top and bottom rows); scale only grows the image so it composes. At translate -150 (beyond overscan) a 30px gap appears, so the overscan must be at least the maximum translate, and the translate clamped.

4. Frame rule (CONFIRMED). Frame with overflow hidden, border-radius 50%, aspect-ratio 1/1, box-shadow, image object-fit cover, red overlay inside: 300x300 true circle, corner pixel white (clipped), centre tinted by the overlay, shadow visible outside (pixels 226 and 24 outside the circle). Hover scale 1.3 on the img stayed clipped, corners clean. Iframe in the frame: corner clean, centre blue. Constraint: the shadow works only because it is on the clipping element itself; clip-path on the frame would cut it.

5. Fixed attachment vs translate on iOS (PARTLY TESTABLE). WebKit and devices['iPhone 13'] are installed, but it is desktop-engine WebKit with an iPhone user agent: background-attachment:fixed behaved as on desktop (pinned to the viewport), so the claimed iOS Safari defect is NOT reproduced and cannot be confirmed here. Translate with overscan is confirmed in WebKit (gap 0 at -150, 0, +150). Design change: keep the iOS fixed claim marked as issue-tracker evidence, not measured; the move to translate stands on its other merits (reduced motion, per-device off).

6. Responsive preload (CONFIRMED). Two preload links (media min-width 641, media max-width 640, imagesrcset plus imagesizes) alongside the picture: each image requested exactly once at 1440@1, 1440@2 (1600w), 768@1 (800w) and 375@2 (640w source), zero preload warnings, same count as no preload. Constraint: the preload media queries must mirror the source media boundaries exactly (640/641 used here).
