# R1 Spec-Lawyer review of Spec 49 v0.1 (E:/sgs-tmp/wt-indus/.claude/specs/49-SGS-MEDIA-SYSTEM.md)

Method: the spec, the register (plans/2026-11-09-media-controls-redesign.md) and evidence A, B, C, E, F, G, I, J, K, L, M, N were read in full (K and C by section plus the saved-attribute tables). Every B control and section 6/11 finding, N row, L and M defect and "missing capability", J section 1 failure, section 3 contract and section 5 open point was ticked against the spec. Only items NOT closed are listed. Locations are spec sections. Register items H1, Q1 to Q4, F1 to F4, B1, B2, M1 to M8 and R1 to R4 all appear in section 16 and are closed in principle; the gaps below are in the detail that two implementers would build differently.

## MUST-FIX

M-01 CONTRADICTION, overlay location (section 7.4 against section 7.5). Section 7.4 puts Overlay on the "helper ::after"; section 7.5 says the mask layer "carries the media and the overlay". With a mask, an overlay on the helper paints square over a shaped photo. Exact fix, replace the Overlay row of section 7.4 with: "Overlay | n/a | Without a mask: helper ::after, inside its radius. With a mask: .sgs-media-box__mask::after, so the overlay takes the mask's shape." Add to section 7.4: "The helper has overflow:hidden only when no mask is set; with a mask the mask layer clips."

M-02 Layout-box properties paint on the wrong element when a caption or link exists (section 7.1 and 7.4). Order, Alignment, margins and a percentage Width act on the flex or grid item, which is the OUTERMOST element (figure, else a, else helper, else media element), but section 7.4 paints them on the "surface" inside it, where they do nothing. Fix: add to section 7.1: "The outermost element is the layout box. It carries {uid}, the anchor, the block classes, motion attributes, Order, Alignment, Width, Max width and, when a caption exists, the caption's width follows it. The surface (helper, else media element) carries Height, Ratio, Min height, Max height, Border, Radius, Shadow, Padding and Background." Replace the first row of the section 7.4 table with two rows: "Width, Max width, Alignment, Order | Outermost element" and "Height, Ratio, Min height, Max height | Surface". Also delete "margins" from that row (see M-14).

M-03 Link, caption and helper nesting is not decided (section 7.1; the "caption plus helper" and "link plus helper" combinations). Exact wording to add to section 7.1: "Nesting is always figure > a > helper > mask > media element, with every level omitted when not needed. The a is display:block, takes no paint, and carries focus-visible outline with border-radius:inherit. The overlay and any ring carry pointer-events:none so the link stays clickable. A caption never causes the helper (section 7.3). A link on an image whose Decorative flag is on is refused: the editor shows an error 'A linked image needs alt text' and the renderer ignores Decorative while a link exists."

M-04 Helper triggers (section 7.3) miss every transform effect that must clip. A parallax, Ken Burns or Pinned effect on an sgs/media part moves or scales the media beyond its box, and nothing clips it unless the helper exists; hover zoom detection is also undefined ("a hover zoom" has no reader, M item 15b). Replace section 7.3 with: "The helper is printed for a slot if, at ANY device, any of these hold on resolved values: Height is fill; OverlayColour, OverlayGradient or either hover form is set; Mask is not none; the media part's Hover state has scale above 1 (read through Sgs_Motion::media_hover_scale( $attrs ), declared in the registry as the zoomOnHover trigger); the media part carries Parallax, Ken Burns, Pinned or a clip entrance. A caption or link never causes it. When printed it is printed at every device and takes box paint at every device; at a device where no trigger applies it is simply a transparent block box."

M-05 Size chips: the write rules break under inherit-down (section 9.2 SizeField, section 7.2). "Writes the right attributes for the current device and clears the other" cannot work: on Tablet, choosing Natural while Desktop has Height 400px clears the Tablet key, so it inherits 400px and nothing changes; choosing Ratio under an inherited Height is ignored because Height wins. It also contradicts FR-49-21 (a hidden value keeps its value) and the Circle shortcut has the same fault. Replace the SizeField bullet with this table: "Chip shown = Fill if resolved Height is fill; Height if resolved Height is a length; Ratio if resolved Ratio is a ratio and Height is empty or auto; otherwise Natural. Choosing a chip at device D writes: Natural: Height auto and Ratio natural (on Desktop the two keys are deleted); Height: the entered length (Ratio untouched); Ratio: the chosen ratio and Height auto (on Desktop Height is deleted); Fill: Height fill (Ratio untouched). Nothing else is written or deleted. A stored value that the precedence of section 7.2 ignores is kept and appears in the hidden-value note." Circle shortcut text: "sets Radius 50% on all four corners, Ratio 1 / 1, Height auto and Fit cover at the current device; it is shown as active when those four resolve."

M-06 Natural sizing has no width rule, and embeds, SVG and Lottie have no natural size (section 7.2 rows 3 and 4). Add: "Natural: width:auto; max-width:100%, so a 300px file draws at 300px and shrinks with its container; Width, when set, replaces it. Every row also carries max-width:100% unless Max width is set. For an embed Natural is aspect-ratio 16 / 9 at width 100%. For an SVG it is the viewBox ratio. For a Lottie it is the animation's own width and height from its JSON, stored in Source.width and Source.height at pick time."

M-07 The crop predicate is undefined, but Fit and Focal omission depend on it (section 9.3 rows Fit and Focal; "the box crops"). It also contradicts itself: the Focal row lists contain, which never crops. Replace those two rows with: "Fit | I V (file) | Omitted when the box does not crop. Focal | I V (file) | Fit is not fill and the box crops." and add a definition under section 9.3: "The box crops at a device when, after section 7.2, any of these hold: Height is fill; Height is a length and Width is not auto; Ratio is a ratio other than natural; Max height or Min height is set. Natural with none of those does not crop."

M-08 Fit default against the cloner (section 8 Fit default "cover when cropped", section 11 row object-fit). A draft img with no object-fit and a crop paints `fill` (stretch); image-slot defaults to cover; section 11 says "never a default" but does not say what is written. Add to section 11: "The cloner writes the draft's computed object-fit at every device where the box crops, including fill; it never relies on the Fit default. A draft with no crop writes no Fit and no Focal. A draft object-position that cannot be held as {x,y} (calc, an offset from an edge, a px length) is written to Custom CSS and reported."

Replace section 13's table with a complete one. Rows to add beyond the current ten: mediaType, videoSource, videoUrl, videoId, thumbnailId, svgContent* and lottie* to mediaSource.kind and fields; imageAlt and per-tier alt (splitMediaImageAlt*) to mediaAlt (desktop value, else first non-empty tier); imageDecorative to mediaDecorative; displayWidth deleted; minHeight plus the SVG min height to mediaMinHeight (the larger when both are set, as the current max() does); opacity multiplied by svgOpacity to one mediaOpacity; imageBlendMode to mediaBlend; style.color.duotone deleted (no presets exist); mediaSizing fill to Height fill, height to Height with Width auto, ratio to Ratio plus Height auto, auto to nothing; splitMedia* to the split prefix; splitMediaObjectPosition, sgsObjectPosition, sgsObjectFit and objectPosition keywords to Fit and Focal (keyword table left 0, centre 0.5, right 1, top 0, bottom 1; an unparseable string is refused and reported); bgVideo*, bgSvg* (including bgSvgPosition layer order) and backgroundRepeat to their new homes (see M-14); photoShape, galleryStickerShape (tag to the tag mask), shape on decorative-image and splitMediaShape to Radius or Mask; sgsColourTreatment, grayscaleHover, scaleHover, imageZoomHover, sgsHoverZoom* to Greyscale or a Hover effect on the media part; chromeLogoTablet and chromeLogoMobile (Spec 36) to a responsive logo Source; container .sgs-container__svg-bg opacity Custom CSS (K, eye-care-clone page 107) to Source none below desktop. State that an unmapped attribute stops the run (already stated) and that the survey output is committed.

M-10 Two required controls have no panel (section 9.4 against section 9.3). M-11 The rule table (section 9.3) mixes kinds and contexts, so three slot types are undecided. "Background (B)" is listed as a kind but a background is image, video, SVG or Lottie; Fit, Focal and Overlay rows exclude B although section 9.4 puts them in the Background panel; Lottie (L) has no Size, Width, Max, Min, Radius or Shadow row so a Lottie cannot be sized at all. Background slots show Media, Fit, Focal, Tile options, Overlay, Loading and the motion line, evaluated on the resolved kind, and never show Width, Height, Ratio, Size, Alignment, Order, Border, Radius, Shadow, Padding, Mask, Caption or Link. M-12 Loading rules 3 and 4 collide (section 7.7). Rule 3 makes everything in the first top-level section eager, so a twelve-image gallery there is all eager and rule 4's cap of 8 never applies. Replace rule 3 with: "3. In the site header or the first top-level section, and not an item of an item-set block: eager." and rule 4 with: "4. An item of an item-set block inside the header or the first two top-level sections: eager up to the block's desktop column count, at most 8 across the page; the rest lazy." Also define "logo, brand mark or ornament": "a slot declared with context logo or layer, or whose block is sgs/responsive-logo, sgs/brand-strip or sgs/decorative-image."

M-13 Lead selection is stated as a one-per-page fact but the spec bans the only mechanism that could pick it (section 7.7: "only one on the page" against "never a request-order counter"). Add: "The lead is found by a pre-pass over the parsed block tree of the template, its template parts and the post content, run once per request on the first media render and cached in the request for the block tree of that page (not a counter). A slot takes fetchpriority high only when its stable identity (the scope hash) equals the lead's. A block rendered outside a page (REST, a cached fragment) takes eager or lazy from its own block context and never high." PS-5 must test exactly this.
