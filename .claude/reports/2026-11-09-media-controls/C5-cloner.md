# C5 Cloner review of Spec 49 v0.5 (§7.2, §7.5, §7.9, §10, §11), 2026-11-09

Method: each T8 draft pattern replayed through §11 top to bottom, first match wins. Evidence read: `sites/*/handoff/image-slot.js`, the Eye Care `heroRef` markup, `scripts/computed-route/lib/fill-media.mjs`, `fill-resolve.mjs`, `T-merge-decisions.md`, `J-cloning-needs.md` §3, `T9-effects-built.md`, Spec 38A.

## STRENGTHS

- Viewport thresholds match the drafts: `SGS_Breakpoints` is mobile up to 767 and tablet up to 1023, and Indus swaps its About hero SVG at `w < 768` and `w < 1024`, so the per-device Source copies the draft exactly.
- The 3:2 Fill fallback is the same fallback `image-slot.js` uses for an indefinite parent, so Fill reproduces its box.
- `image-slot.js` defaults to `shape` rounded and `radius` 12, which matches the §11 row "no shape: Corners 12px".
- Ratio plus Height giving 300 by 300 matches the draft's circle photo (`height:100%;aspect-ratio:1`), and Circle keeping ordinary borders matches the `5px` and `6px` white borders.
- The absorption rule matches the draft's circle and frame wrappers (one image, overflow hidden, ratio, radius, border, shadow).
- Parallax: the `inset:-9% 0` of the Eye Care `heroRef` wrapper equals the §10.2 overscan `|r| × H / 2` at 0.18, so the draft's 18% travel is reproduced.
- None of the cuts in `T-merge-decisions.md` removes a target for a pattern in the three drafts: different kind per device, SVG stroke border on masks, tile `space` and `round`, per-device Greyscale and Blur, uploaded masks, the decorative-image video branch, the click-to-play embed cover and the `%`, `calc` and `clamp` sizes parsing. Each has zero draft use or falls to Custom CSS reported.

## MUST-FIX

1. An absolutely positioned fill image has no row, and row 1 misroutes it. The Eye Care hero (`position:absolute;inset:-9% 0` wrapper holding the image), the Eye Care about strip (`position:absolute;inset:0;width:100%;height:100%`) and the Indus full-bleed map all sit behind sibling content. Row 1 ("`height:100%` of a definite parent") would write Height Fill, which needs a grid or flex-column parent and loses parallax, overlay and stacking. Fix in §11, above row 1: an image, video or iframe with `position:absolute` and `inset:0` (or `width` and `height:100%`) inside a positioned ancestor that holds other content writes that ancestor's Background slot, and absorption must not apply.
2. Row `background-image with children` matches gradients. Indus has 29 gradient backgrounds and Mama's has radial and repeating gradients, and none is media. Fix in §11: the two `background-image` rows apply only to `url()` values; a gradient goes to the container's own background gradient setting, never a Background slot or `sgs/media`.
3. The ground colour behind a cover photo has no reachable control. All three drafts set one (Eye Care `#F3F0EB` tiles, Indus `#EAF4F7` frames, Mama's pastels), while §9.3 shows Background only when "Fit is `contain`, or S". The cloner would write a value the editor hides, which breaks G2 and the "every property has a control" rule. Fix in §9.3: Background is always visible for image and video (it shows while the file loads and behind any transparent file).
4. Map iframes with filters have no target. FR-49-17 refuses Google Maps; §7.9 and §9.3 offer no Greyscale on embeds (`filter:grayscale(.35) contrast(1.05)` on both Indus maps); §11's `<iframe>` row says only "embed". Fix: add a §11 row "Google Maps `<iframe>`: the `sgs/business-info` map; `grayscale()` to a new Greyscale setting on that map; any other filter (the `contrast(1.05)`) to Custom CSS, reported"; offer Greyscale on embeds in §7.9 and §9.3 (a CSS filter works on an iframe); state the target of the full-bleed second map (Container with `business-info` inside, or a named gap).
5. The Fill route cannot write the new shapes. `fill-media.mjs::mediaDecisions` and `imageRecords` have these limits. (a) `imageSlots` returns `[]` for any block with more than one slot, so every multi-slot block (hero background plus split, before-after, product card) is a gap; WP-13 needs a slot chooser from `supports.sgs.mediaSlots` prefix and context (a `background-image` on a parent is `background`; a child `<img>` is `media` or `split`). (b) It writes a scalar trio with `merge:'replace'`; `mediaSource` is a per-device object, so it needs a tier-aware merge or it overwrites other devices. (c) It reads at width 1440 only (`imageRecords` `width: 1440`), so the Indus SVG swap at 375 and 768 can never reach a device tier; read all three widths and write a tier only where the value differs. (d) It never writes width, height or mime, which FR-49-16 requires for a source with no id; the media map entry (`mapEntries`) must carry them. (e) `unset()` treats `0` as unset, so a held Order 0, Opacity 0 or OverlayOpacity 0 (which "clears at a device") is silently overwritten; test `undefined`, `null` and `''` only. (f) A draft `alt=""` only produces a note (`has an empty alt`); it must write Decorative true. (g) Objects (`Focal {x,y}`, `Shape {shape,fit}`, Radius corners) need object writers with `refused.json` rows when parsing fails.
6. One-shot decay on load has two targets. Eye Care Ken Burns (`scale(1.08)` to `1`, 3000 ms, `cubic-bezier(.2,.7,.2,1)`, once) and Indus zoom-out (`scale(1.18)` to `1`, 1600 ms, delay 200) can be Entrance "Scale" or Effects "Ken Burns" (§10.1 offers both), and Ken Burns presets are 104, 108 and 115% with a loop control (`T9` row ken-burns), so "once, easing, settle direction" is unverified. Fix in §11 and §10.1: a transform that runs once on load or scroll is Entrance Scale (from, to, duration, delay, easing); Ken Burns is only a continuous drift. Add the row.
7. The cursor peek has no row. Indus `[data-peek]` (`clip-path: circle(var(--pr) at var(--mx) var(--my))`, 400 ms, `--pr:90px` hover and `150%` on drag) is a card layer, not an image. §10.1 says cursor effects belong on cards but §11 never says which. `T9` shows `cursor-field-reveal.js` and an `image-reveal` type on Container. Fix: add the row "cursor-following `clip-path: circle()` over a second layer: Container Effects, Cursor field, `image-reveal`", and confirm it takes radius 90px, hover radius, 400 ms and the easing; otherwise name it a reported gap.
8. Hover cannot carry two timings on one element. The Eye Care `Frame Card` tile has `transition: transform .9s, filter .4s`; Spec 38A's hover state stores one duration, delay and easing. Fix: a Hover Fine-tune per-property duration for filter versus transform, or the cloner writes the longer value and reports the difference; state which in §10.1.
9. Per-device inline SVG siblings duplicate ids. The Indus About hero SVG (three files, same ids `sunrays_spin`, `sunrays_expand`, A-24 to A-30) would put three copies of each id in the DOM, so `SvgParts` and the animation selectors hit the hidden copy. Fix in §7.1 and §8: the renderer prefixes ids per device sibling; part selectors resolve per sibling; hidden siblings do not animate (`display:none` plus no WAAPI start).
10. The height-on-image reconcile is promised, not decided. §11 ends with "reconciles the `property_equivalents` row" and row 3 says Height as declared. Today that row converts an image height into `max-height` because height alone distorts. Fix in §11: when the draft box keeps the file's ratio at every width (the existing `intrinsic-ratio` condition in `fill-equivalents.mjs`), write Height with Width `auto`, which §7.2 and §13 already define for this; otherwise Height alone crops under Fit.

## SHOULD-FIX

- The Mama's tag sticker (`clip-path: polygon(0 0,100% 0,88% 50%,100% 100%,0 100%)`, "Baked to order") is a text element, so it fails absorption and no media row covers it; Container has no Shape. Fix: state the target (Custom CSS on the container, reported), and define "within 1%" in row `clip-path: polygon` (every vertex within 1% of the registry path's vertices after normalising to the bounding box). Seed the registry `tag` with exactly this polygon.
- `margin: 0 auto` (Indus circle photo) is "Not written", which loses centring. Fix in §11: `margin-inline:auto` writes Alignment centre; only other margins are not written.
- `<image-slot>` in an indefinite parent matches row 2 ("No Height"), but the draft draws it 3:2. Fix: `<image-slot>` with an indefinite parent writes Height Fill, whose fallback is the same 3:2.
- No row for sources swapped by script (the Indus `bp = w < 768 ? 'm' : w < 1024 ? 't' : 'd'`; the drafts use no `<picture>`). Fix: "different file at 375, 768 and 1440 in the computed read: per-device Source (same kind)".
- No row for template or runtime values (`{{ b.ratio }}`, `{{ imgSize }}`, Eye Care lens `{{ t.filter }}`). Fix: read the computed value at the default state; other states are listed as gaps owned by the block (swatch, colour swap), and non-listed filters go to Custom CSS reported.
- Clip reveal fields are unverified. Indus A-22 is one entrance with clip `inset(8%… round 26px)` to `inset(0 round 22px)`, opacity and `scale(.94)`; A-08 is `inset(10% round 24px)` to `inset(0 round 0)` with `rootMargin 0 0 -4% 0`, threshold 0.12. Fix: confirm `sgs-me-clip-path` stores inset and round for from and to, plus the start offset, and state it in §10.1.
- Heights written as `clamp()` (J §3.1b) have no field: §9.4's catalogue lists units only while FR-49-12 allows `clamp`, `min`, `max`, `calc`. Fix: `SgsLengthControl` accepts an expression string (raw box) so a draft value is copied exactly.
- Colour fields say "token, hex"; drafts use `rgba(255,255,255,.92)` and `rgba(20,20,20,.8)`. Fix: state 8-digit hex is accepted and the cloner converts.
- `OverlayGradient` has no grammar: `linear-gradient(180deg, rgba(20,20,20,0) 40%, rgba(20,20,20,.8) 100%)` contains brackets outside the FR-49-12 allow-list. Fix: add a `gradient` type to `css-value-grammar.json` (linear and radial, `rgb` and `rgba`, stop positions).
- Ratio chips lack 4:5, which is in all three drafts (shop tiles, hero card, Indus frame); add it, since Custom is two clicks more.
- `SvgParts` value shape is unstated, and A-27 to A-30 need `scale`, `stroke-dashoffset`, `fill` colour, per-part delay (`1100 + i × 120`) and easing. Fix: list the fields in §8, or A-28 to A-30 have no target.
- Hover zoom on an absorbed circle wrapper scales the wrapper including its border in the draft (`scale(1.04)`, 550 ms spring), but §11 maps it to the media part, so the border stays still. Fix: note the accepted difference in the row, or scale the helper.

## MISSING

- §11 has no output line for the report: each "Custom CSS, reported" outcome needs a `refused.json` or handover row shape, as `unmapped[]` in `fill-media.mjs::mediaDecisions` does, or WP-13 cannot count them.
- §10 never states that each effect carries the draft's duration, delay, easing and distance; it relies on 38A. Add one sentence to §10.1: Hover, Entrance and Effects fields are exact milliseconds, exact easing (custom `cubic-bezier`, including the spring `cubic-bezier(.34,1.56,.64,1)`), exact distance and delay, and name the exceptions (items 6 and 8). Parallax, the two scroll writes (0.18 and -0.06) and the page basis are covered by `speedRatio`, `clamp` and `basis`. Ken Burns once and the Eye Care hover (1.05 at 1400 ms, 1.07 at 1000 ms) are covered if item 6 is fixed and hover stores free scale values.
- Replay result per pattern (target after the fixes above): `image-slot` shapes (rect none, rounded Corners, circle and pill Shape, `mask` Shape or Custom CSS): covered. Circle photo with border: Shape Circle plus Border and Ratio 1:1: covered. Clip-path tag sticker: no media target (text element). Animated clip reveals: Entrance Clip reveal, field detail unverified. Cursor peek: no target (item 7). Image zoom-out on load: two targets (item 6). Parallax 0.18 and -0.06 on the page basis: Parallax, covered. Hover zoom 1.05 and 1.07 with 1.4 s: Hover Zoom, covered; mixed timings not (item 8). Ken Burns once: two targets (item 6). Map iframes with filters: no target (item 4). Per-breakpoint inline SVG: per-device Source, id collision (item 9). `<picture>` absent: row exists, no draft uses it, script-swapped sources lack a row. `background-size: cover`: Fit, but gradients wrongly match and the ground colour is hidden (items 2 and 3). Template-driven values: no row.
- Fill route once rewritten: cannot yet write Source tiers, width and height, Decorative, objects or multi-slot blocks (item 5); sizing, border, shadow and radius go through `fill-resolve.mjs` and the DB `css_property` rows, so they work once the generator seeds the rows (PS-1).
