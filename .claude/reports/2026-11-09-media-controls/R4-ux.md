# R4 Support Realist and editor-UX review of Spec 49 section 9, the register and the standards (2026-11-09)

Read: Spec 49 (sections 5, 7.5, 8, 9, 10, 12, 17), the register plan, Spec 35 (Parts A, B, D, E, O-C, contracts 3, 4, 7, 11, 12, 13), 35A not re-read in full (checked via 35 and block-editor-controls.md), `.claude/rules/block-editor-controls.md`, audit B, editor run N, research E and F. Nothing was run; every finding is from the documents, with N as the only live evidence. Where I say "undefined" I searched section 9 and section 8 for the thing and did not find it.

## WALKTHROUGHS (path complete / confusing / wrong label / undefined)

1. Replace a photo. Path: Styles or Settings, Media panel, MediaSlotField, Replace. Complete on Desktop. Confusing: Replace keeps Focal and Alt, so a different subject inherits the old photo's focal point and the old alt text, silently (see MUST-FIX 2). Undefined: whether Replace on Mobile says "Replace Mobile image"; there is no block-toolbar Replace (Spec 35 A1 puts the most frequent action in the toolbar). N shows the library modal opens on Upload, while the spec says Media Library: confirm it is fixed.
2. Circle photo. Path: Styles, Border and shape, Corners, Circle shortcut (writes Radius 50%, Ratio 1:1, Fit Fill and crop on the current device, which are controls in two other panels). Confusing: a button in one panel moves chips in another; it is a one-way button with no on state and no off; and the Mask grid also has a "Circle" shape, so the client meets two Circles. Undefined: how the Radius control shows 50% if SgsBoxControl corners are px-only.
3. A different mobile crop. Path: switch the global device switcher (bottom of the inspector) to Mobile, then in Size and crop set Ratio chip 3:4, Fit, and move Focal; or in Media choose a different image. Complete. Confusing: nothing says "crop" except the panel name, and the client has two routes (another image, or another focal and ratio) with no guidance. The canvas shows one device at a time, so they cannot compare crops.
4. Arch mask with shadow and border. Path: Border and shape, Mask grid, Arch; Shadow panel; Border. Complete only if PS-3 passes. If PS-3 fails the Border controls are omitted and a note says "Borders don't follow mask shapes", so the stated need (arch plus border) cannot be met. The Shadow control still offers spread, inset and Raw CSS which cannot work as drop-shadow (MUST-FIX 5). Undefined: the Mask `fit` (stretch or keep-proportions) has a stored field but no control in MaskField; an arch on a landscape photo has no helper to fix the ratio (the Circle shortcut sets 1:1, masks do not).
5. Fill in a card. Path: Size and crop, Size chip Fill. Wrong label: "Fill" is also in Fit ("Fill and crop") and in the Stretch description. Undefined: what the client sees when the parent has no set height (N: the image collapses to 0px); no help text, no fallback. Card-grid image slots have no Height or Fill at all (section 10.4: Ratio only), so "Fill" in a card means two different settings in two blocks.
6. Dark overlay that lightens on hover. Path: Overlay and filters, Overlay colour (Hover tab inside the colour popover), Opacity. Broken: OverlayOpacity has no hover form in section 8, and overlay colour has alpha switched off (Spec 35 O-C rule 4), so "dark to light" can only be done by choosing a lighter solid colour, which washes the photo grey instead of lightening it (MUST-FIX 4). The client also looks first in the Hover panel, which does not mention the overlay.
7. Video with a poster and no autoplay. Path: Media panel, Video tab, choose file; Poster; Playback panel, Autoplay off, Show controls on. Undefined: where the Poster control lives (section 9.4 does not list it; section 8 has `poster` inside Source; section 9.2 does not mention it). No Title or accessible name field for video (rule table gives Alt only to images). Labels: "Plays inline" and "Lazy-load" are jargon.
8. YouTube embed with rounded corners. Path: Media panel, Embed tab, paste URL; Border and shape, Corners. Works under the frame rule. Problems: the rule table gives Playback only to V and L, so an embed loses Autoplay, Mute, Loop and Controls that work today (N); an overlay covers the iframe and blocks the play button; no iframe title; no provider-not-supported message; no default ratio stated for an embed (Natural has no height).
9. Phone-only image. Path: Desktop, MediaSlotField, Hide on this device; switch to Mobile, Choose image. Wrong label: "Hide on this device" actually hides from that device down (FR-49-6), so hiding Tablet hides Mobile as well unless Mobile has its own source. At Desktop the block disappears from the canvas with nothing to click. Two different "hide per device" mechanisms now exist (this one cascades; the Visibility conditions toggles are three independent flags per Spec 35 D4), with no cross-reference.
10. Parallax on a hero from the Background panel. Path: Background panel, bottom row "No motion [Add]", Effects opens on the Background target, Effect Parallax, Speed, Direction, per-device. Complete in principle. Confusing: "Add" does not say what is being added; Speed is a 0 to 1 decimal; "basis" and "limit" are undefined jargon; Focal point and parallax interact (the overscan changes the crop) with no hint; focus management on the jump is unspecified; the client is told nothing about reduced-motion visitors.
11. Hover zoom. Path: Hover panel, Zoom preset. Complete if the list is filtered (N shows burger and step presets on media today). Undefined: zoom amount and speed controls, the touch-screen case when Mobile is selected, and keyboard-focus triggering for a linked image.
12. Client on Mobile, confused about what they edit. Path: the switcher is a radiogroup docked at the foot of the inspector; the canvas resizes and a toast appears. Spec 49's "Mobile: using Tablet" line and dots are good. Confusing: Alt, Caption, Border width (Bean-locked not per device), Loading and the Circle button either do or do not follow the device with no signal; "Reset" means two different things (to inherited on Mobile, to default on Desktop) under one label.
13. Reset. Per field it is specified. Panel-level Reset all is not (PanelBody has no resetAll). A multi-write action such as Circle has no single undo or reset.

## STRENGTHS

- One rule table with omit-not-grey, resolved at the active device and the resolved kind; panels that would be empty do not mount. This is the right answer to M4 and matches Kadence and Webflow.
- "Mobile: using Tablet" names the true source tier, fixing N's wrong-tier hint; dots on devices and on closed panels; hidden-but-saved note with Reset.
- Editing one device writes only that device; Replace keeps Focal and Alt; the focal picker shows the resolved image and point; focal has a keyboard path through the X and Y inputs.
- Frame rule (one element takes size, border, radius, shadow, overlay) makes circle, rounded and zoom reliable and fixes the N finding that editor and front end disagree.
- Plain-English Fit chips (Fill and crop, Show all) instead of raw CSS words; Ratio chips instead of a select; one motion line instead of duplicated motion controls.
- Empty, deleted, oversized and missing-alt states are specified, with alt never blocking.

## MUST-FIX

1. Problem: Spec 49 FR-49-20 mandates a new `ResponsiveField` wrapper, but Spec 35 section 12 says `ResponsiveControl` and `ResponsiveOverride` are the only sanctioned primitives and `lint-responsive-controls.py` is a wired build gate naming exactly those two; the same section says the unused `isInherited`/`resolvedValue`/`onReset` API of `ResponsiveControl` is intentional. A third primitive fails the gate or forks the standard. Fix: build `ResponsiveField` as a thin composition over `ResponsiveOverride` (which already holds the object-cascade storage Spec 49 uses) and add its name to the lint gate and Spec 35 section 12 in the same commit; fix the hard-coded "Desktop" in the inherit hint inside the shared wrapper rather than the media copy. Location: Spec 49 section 9.2 and FR-49-20; Spec 35 section 12; `plugins/sgs-blocks/scripts/lint-responsive-controls.py`.
2. Problem: Replace keeps Focal and Alt (section 9.2). A different photo then carries the old photo's description to screen readers and the old focal point into a new composition, silently. Fix: keep Alt only when it is empty or the client typed it for the old image and show a one-line prompt "Alt text still describes the previous photo. Update it." with the Alt field focused; reset Focal to centre unless the client ticks "Keep focal point". Location: Spec 49 section 9.2 MediaSlotField and AC-17.
3. Problem: a device set to none leaves the block invisible on that device in the editor (and the label "Hide on this device" misdescribes the cascade, FR-49-6). The client cannot select or find the block and does not know why Mobile shows an image. Fix: relabel to "Hide from this device down" (Desktop: "Hide on all devices unless set below"), render an editor-only dashed bar reading "Hidden on Desktop and Tablet, shown on Mobile", and state that the frame, caption, link and spacing also vanish on hidden devices. Location: Spec 49 section 9.2 MediaSlotField, section 9.5, FR-49-6, section 7.
4. Problem: "dark overlay that lightens on hover" cannot be built: OverlayOpacity has no hover form and the hover colour has no alpha. Fix: add `OverlayOpacityHover` (the Hover tab inside the overlay control sets colour and strength together), plus a one-line pointer in the Hover panel: "Overlay, border and shadow changes on hover are set in their own panels." Same for Greyscale (grey to colour on hover is the commonest request). Location: Spec 49 section 8 table, section 9.4 Overlay and filters; Hover panel copy.
5. Problem: with a mask the shadow is a `filter:drop-shadow`, which has no spread, no inset and no multi-layer Raw CSS, yet the standard ShadowControl offers all of them; the client sets spread and nothing happens (an inert control). Fix: when Mask is on, ShadowControl hides Spread, Inset and Raw CSS and shows "Shadows follow the mask shape"; likewise omit Padding sides that the mask layer cannot honour. Location: Spec 49 section 7.5, section 9.3 rule table (add a condition on the Shadow row), `ShadowControl.js`.
6. Problem: an overlay on an embed or video with controls covers the player and blocks clicks. Fix: overlay prints `pointer-events:none` on V and E, and the rule table says so; the editor preview already disables pointer events so this will not be caught in the editor. Location: Spec 49 section 7.4 and section 9.3 Overlay row.
7. Problem: Playback is given to V and L only, so a YouTube or Vimeo embed loses Autoplay, Mute, Loop and Show controls that work today (N, audit B section 3), and no Title field exists for a video or embed (iframe title is a WCAG 4.1.2 requirement). Fix: Playback for E (Autoplay, Mute, Loop, Controls, Start at, Related videos off) mapped to URL parameters, and a "Title (for screen readers)" field for V and E in the Media panel, required with a warning like the missing-alt one. Location: Spec 49 section 9.3 Playback and Alt rows, section 9.5.
8. Problem: the Poster control, the Loading control and the Typography caption colour are in the rule table or data model but not in any panel in section 9.4, so they are undefined in the editor. Fix: Poster inside the Media panel under the video source ("Poster image, shown before play"), Loading as "Load priority" (Automatic, Load first, Load later) at the bottom of Media with help text, and list both in 9.4 and AC-12. Location: Spec 49 section 9.4.
9. Problem: the caption colour moved into Typography (register M4, Spec 49 9.4) conflicts with the standing rule that every text colour is a row in one `SgsColourPanel`, never a bespoke colour control (`block-editor-controls.md`, "Colour controls"); only border, media/overlay and shadow colours are exempt. Fix: get Bean's decision between (a) keep a `textRow` in the one SgsColourPanel, shown only when caption text exists, with the panel placed beside Typography, or (b) add "caption colour inside Typography" to the exemptions list with the reason. Do not ship it silently. Duotone's two colours (OQ-2) need the same declaration: a thin swatch row each, listed as a media-colour exemption, never an inline palette. Location: Spec 49 section 9.4, `block-editor-controls.md`, `sgs/media` block.json `supports.sgs.colourExemptions`.
10. Problem: "Fill" is the name of a Size chip, part of the Fit label "Fill and crop", and the meaning of Stretch; and the sizing words Natural (Size), Original (Ratio), Actual size (Fit) and Natural (Background fit) all mean "as the file is". A client cannot tell which Fill they set. Fix: Size chips "Natural size, Set height, Set ratio, Fill the space"; Ratio chip "Photo's own"; Fit "Crop to fill, Show all, Stretch (distorts), Actual size, Never enlarge"; Background "Natural" becomes "Actual size". Add help under Fill the space: "Needs the surrounding block to have a height." and make the editor show a 160px minimum placeholder when it resolves to 0 (N). Location: Spec 49 section 9.2 SizeField and FitField, section 7.2.
11. Problem: the Circle shortcut is a one-way button that writes into other panels and cannot be undone or even shown as active, and Mask also offers "Circle". Fix: make Circle a toggle chip that shows active when Radius is 50% and Ratio is 1:1, writes all three values in one `setAttributes` call (one undo step), restores the prior values when switched off, and remove "circle" from the Mask grid (or label it "Circle mask" and hide the shortcut while a mask is on). Location: Spec 49 section 9.4 Border and shape, `MaskField`, section 7.5.
12. Problem: controls that are not per device (Alt, Caption, Border width (Bean-locked), Loading, Playback if left global) look identical to per-device ones when the switcher is on Mobile, so a client edits "Mobile" and changes every device. Fix: on Tablet and Mobile, global controls show a quiet "Applies to all devices" line (not a "(per device)" label on the others, which Spec 35 section 12 forbids), and Reset label says "Reset to Tablet" on a non-desktop device and "Reset to default" on Desktop. Add the device name to every responsive control's accessible label ("Fit, Mobile"). Location: Spec 49 section 9.2 ResponsiveField; Spec 35 section 12.

## SHOULD-FIX

1. ToolsPanel versus PanelBody: Spec 49 9.1 mandates PanelBody; Spec 35 A5 says use ToolsPanel once a panel has about 6 controls, and Size and crop has 9 plus. Because the rule table already omits irrelevant controls, PanelBody is defensible (and collapsible, which the owner wants), but then say so as an amendment to A5, and give each PanelBody a panel-level "Reset" in its header menu (a ToolsPanel gives that free) so Circle, Mask and similar multi-writes are recoverable. Location: Spec 49 9.1; Spec 35 A5.
2. Length controls: section 9.2 does not say which control Width, Max width, Max height, Min height and Height use. Spec 35 contract 4 names UnitControl, `block-editor-controls.md` says `SgsLengthControl` inside `ResponsiveOverride`, never UnitControl; Spec 35 section 13 lists a preset select on minHeight as "needs a contract". Fix: declare SgsLengthControl with `presets={false}` and a real unit list (px, %, vw, vh, rem) for every media length (names-only spacing presets are meaningless for a width), via the same ResponsiveOverride, and reconcile Spec 35 contract 4 in the same change. Location: Spec 49 9.2 SizeField; Spec 35 section 4 and section 13.
3. Control bands: Fit has 5 labels over 12 characters and Background Fit has 7; Ratio has 9; Mask has about 15. Spec 49 amends Spec 35 only for "a visual chip grid above its option-count bands". Specify the chip contract once: `role="radiogroup"` with arrow-key roving focus, 44px targets, selected state not by colour alone (Spec 35 E2, high-contrast), visible focus ring, hover brightens, labels wrap under the icon, grid not a single row. Mask thumbnails should draw the client's own photo in each shape. Location: Spec 49 9.2 FitField, MaskField; Spec 35 amendment text.
4. Size chips clear the other value when switched (SizeField: "clears the other"). A mis-click from Ratio 16:9 to Height loses the ratio, and N showed today's build keeps both. Keep the stored values and let the chip decide which applies (precedence in 7.2), showing "Ratio 16:9 is saved but not used" via the existing hidden-value note. Location: Spec 49 9.2 SizeField.
5. Panel placement and names: "Size and crop" holds Alignment and Order. Order is jargon and neither is size or crop. Move Alignment to "Position in the layout" (with Order renamed "Order in the row") or to Advanced. "Overlay and filters" holds Opacity and two Blend controls, so "Opacity" competes with "Overlay opacity" (N found two units: 0 to 1 and percent) and "Blend" with "Overlay blend". Rename to "Photo opacity" and "Overlay strength", both percent, and fold the two blends into one "Blend with what is behind" row with a plain-English preview. Location: Spec 49 9.4; section 8 Opacity and Blend rows.
6. Motion vocabulary: Hover, Entrance and reveal, Effects and the Background motion row are four places to put motion and their titles do not tell a client which is which. Give each panel a one-line subtitle ("Hover: when the pointer is over it", "Entrance and reveal: when it scrolls into view", "Effects: ongoing movement and scroll effects such as parallax") and rename Effects to "Scroll and ambient effects". Cross-link in both directions (Effects offers "Overlay and border colour on hover live in their panels"). On Tablet and Mobile, the Hover panel states "Hover has no effect on touch screens" or hides.
7. Motion row: "No motion [Add]" and "Parallax, speed 0.18 [Edit]" use decimals and a vague verb. Use "Background motion: none [Add parallax or zoom]" and "Background motion: Parallax, gentle [Change]" with Speed as chips Gentle, Medium, Strong plus a custom number; define or drop Basis and Limit (move to a collapsed "Fine-tune"); on activation move keyboard focus to the Effects panel heading and announce it in a live region; add a note that Focal point and parallax share the same crop and that visitors with reduced motion see a still image.
8. Parallax per device must be a tri-state in the global-switcher style (Inherit, Off, On), as Spec 35 section 12 describes, not a second device picker; N shows Effects is not per device today, so confirm the wrapper is real before writing "per-device" in the spec. Consider defaulting parallax off on Mobile (iOS fixed-background fault is untested, per the register).
9. Playback is specified as a responsive object with six tri-state toggles, which is 18 states to understand. Per-device playback is a data-saving case (OQ-3), not a general one. Keep Playback global, with one per-device "Show poster only on phones" switch for background video. Relabel: "Plays inline" becomes "Play in the page on iPhones" (default on, no one should turn it off); "Lazy-load" becomes "Load when scrolled into view".
10. `sgs/media` Replace, Link and Alignment should also sit in the block toolbar (Spec 35 A1); caption should be editable on the canvas, not only in a Settings-tab field.
11. Focal point label and help: "Focal point" is not a client word. Keep the label (Kadence and core use it) but add help "Choose the part of the photo that must stay in view when it is cropped". Make the picker thumb keyboard-operable with arrow keys (N: it is not a tab stop; the percent inputs cover it but a screen-reader user gets no live position). Show Focal only when the box crops (already in the rule table) and say why when it is hidden for a saved value.
12. Duplicate "hide on device" mechanisms: Spec 49's `none` cascades; Visibility conditions' sgsHideOnX flags are independent (Spec 35 D4). Add a line in each pointing at the other, and decide which is the recommended route for "phone-only image" (I recommend the media `none`, because it prints no request).
13. Styles tab lands with every panel closed. Open Size and crop by default on the Styles tab (it is the most used), and keep Media open on Settings; section 9.1 says Media only.
14. Advisories: the 500 KB and 2500px threshold fires on every full-width hero. Make the threshold depend on the slot (hero, background and gallery higher) and add the action: "Choose a smaller size in the library" or an automatic size picker line. An advisory that offers no action is noise.
15. Screen reader and keyboard: device switch announces "Editing Mobile" through a live region; the closed-panel dot has an accessible name "Has Mobile settings" and is a shape, not only colour; Circle, Reset and Replace announce what changed; Mask grid and chips use roving tabindex; Tab order in Focal runs thumb, X, Y, quick picks, Reset. Add these to AC-14 and a new AC for keyboard-only completion of walkthroughs 1 to 13.

## MISSING

- Empty placeholder choice of kind: the "No media" state says "Choose" but the spec does not show how a client picks Video, Embed or SVG before any media exists (kind tabs appear inside MediaSlotField only). Placeholder needs four plain buttons: Photo, Video file, YouTube or Vimeo link, SVG.
- Embed states: unsupported provider, private or deleted video, blocked-cookie placeholder, "Privacy-enhanced mode" (youtube-nocookie), start time, and a default 16:9 ratio when Size is Natural.
- Dynamic source: a card, product or post-grid image slot needs "Use the post's featured image" as a Source kind; section 8's kinds have none and Spec 35 Part C lists image sources as table stakes.
- Lightbox or "open larger" with Link, and a link that is keyboard-focusable with a visible focus ring that matches the hover zoom (zoom should also fire on focus).
- Image size choice: Spec 35 Part B "Image" row lists an attachment size dropdown; Spec 49 derives sizes instead. State the decision in Spec 35 so Part B is not read as a missing control.
- Mask fit control (stretch or keep proportions), and a "Match shape ratio" helper when a mask is chosen (arch and pill on a landscape photo).
- Greyscale hover, Blur hover, hover transition duration and easing, hover on keyboard focus.
- Panel-level Reset all, and one undo step for every multi-attribute write (Circle, Size chip, Replace, Reset).
- Per-device compare view: an optional "Preview all three crops" strip in the Focal and Ratio fields, since the canvas shows one device at a time.
- Caption and frame behaviour on a hidden device (does the caption stay?), and the spacing the empty frame leaves.
- Title or long description for non-decorative images beyond Alt (rare), and a "Decorative" explanation in plain English: "Just decoration, screen readers skip it".
- Hover and colour-exemption declarations for SVG text-shadow colour, duotone colours and any new media colour (the exemption list names only border, media/overlay and shadow).
- A named acceptance test for each walkthrough above (replace, circle, mobile crop, arch plus shadow plus border, Fill in a card, overlay hover lighten, poster video, embed with radius, phone-only, parallax from Background, hover zoom, Mobile clarity, Reset). AC-12 to AC-17 test structure, not whether a client can finish the task.
