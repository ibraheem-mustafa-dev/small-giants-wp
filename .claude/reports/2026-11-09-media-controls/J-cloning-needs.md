## 2. How the cloner maps a draft image into attributes today

2.1 Element identity (lib/skeleton-rules.mjs). A draft <img> (and <image-slot>, any custom element matching R.mediaElement) becomes an sgs/media node (verdict mediaElement); an <img> inside an <a> that holds nothing else is the media block with a link (imageLink rule); a link group of image-only links is a logo grid (gallery); an image inside the first h1 section is the hero split media (hero rule, variant split, "choose the image" hand-over); a marquee of images is brand-strip. A "layer that holds nothing" (ring, glow, bar, blob) is a decorative image with its own radius and fill. Skeleton unwrap rules remove centring width wrappers and marquee frames. There is NO skeleton rule that recognises "outer div with overflow:hidden (and radius/aspect-ratio) holding one img"; grep of skeleton-rules.mjs for overflow finds nothing relevant. Today that outer div becomes a sgs/container (carrying the draft's size, ratio, radius, overflow) wrapped around a sgs/media.

2.2 Property routing (Fill, lib/fill-resolve.mjs, lib/resolve.mjs). Every longhand the draft declares or computes on a node at 375, 768, 1440 (FR-48-8 declared values) is looked up in block_attributes by block, css_property and css_state, then written in the setting's own form by formatValue. For sgs/media the routed rows are: height -> height; max-width, max-height; aspect-ratio -> aspectRatio (ratioSetting: "auto" -> empty, a ratio -> "w / h", "auto 16 / 9" cannot be held); object-fit -> objectFit; object-position -> objectPosition; border-radius -> borderRadius (desktop) plus borderRadiusTablet/Mobile (all slot .sgs-media__img); border-width/style/colour; overlay, opacity, shadow via atoms; caption font-size. Calibration slot for all these is .sgs-media__img (cache/media.json), i.e. the img, not the figure.

2.3 What has no routed row for sgs/media (queried, DB shared copy): width (draft width of the image or its wrapper), min-height, shape/clip-path, mediaSizing (mode), imageWidth/imageHeight (intrinsic attributes, role layout, no css_property), displayWidth, alignment (margin-inline on the picture), order (flex order), padding (exists as a tier object, route not verified). The mode attribute is never written by Fill: the only coupling is render.php deriving the mode (ratio set -> ratio; height set -> height; else auto). Fill mode must be selected explicitly and nothing in the route selects it.

2.4 Equivalence row (property_equivalents, 2026-11-09): a draft height on an image, SVG or logo with an intrinsic ratio becomes the setting max-height when the box keeps that ratio at every width (condition intrinsic-ratio, lib/fill-equivalents.mjs::intrinsicRatio, tolerance RATIO_TOL). This exists because writing height from such a draft distorts or breaks the image width at other devices. It is the only place where the route decides "height versus ratio versus fill"; it covers one draft shape.

2.5 Compare side (scripts/parity/lib/compare.mjs, GAP-CHECKLIST 36): aspect-ratio is dropped from a comparison while both boxes agree (ratioHeld), because a declared ratio paints only through the box it sizes. Draft presentational hints (data/presentational-hints.json): an img's width/height HTML attributes map to aspect-ratio and width/height, and border/align/hspace/vspace attributes map to border, float and margins.

2.6 Draft patterns and their current target (this research, from the above):
- img with width and height attributes only, auto layout: no setting; render prints the attributes for CLS (works, nothing to write).
- img/image-slot with explicit width px and height px: height -> height, width has no DB row (written through a path the DB does not list; UNVERIFIED it lands).
- img with width:100%; height:auto; aspect-ratio: aspectRatio plus mediaSizing derived by render; ratio is not per device.
- img/image-slot height:100% inside a wrapper with a fixed height or ratio: no clean target; needs fill mode (mediaSizing = fill), not selected by the cloner.
- wrapper div with aspect-ratio + overflow:hidden + border-radius + img object-fit:cover: wrapper becomes sgs/container (boxAspectRatio, radius, clip), media inside natural ratio unless fill; RC13 shows container-height-to-content-band collapse for the fill case.
- circle (border-radius 50% on a square wrapper or on the img): borderRadius 50% on img works for a square box; shape=circle exists with no DB route; both exist and conflict.
- pill, mask/clip-path from image-slot: no row for clip-path; shape enum has no pill.
- background-image on a div (cover, position, size): not sgs/media; goes to the container or hero background (PROP background-image to the image setting, formatValue accepts one url(...), refuses gradients or several layers) and paints on a ::before except in the simple case (SGS_Container_Wrapper $sgs_bg_img_is_simple), so it has no srcset and motion on it does nothing (audit C 3).
- picture/source art direction in the draft: stored as flat imageIdTablet / imageIdMobile; not per-device ratio, focal or fit except fit and position tiers.
- object-position/focal point: objectPosition per device (css string) works; focal control disabled under fill.
- overlay, mix-blend-mode, filters, hover zoom, caption: separate atoms; zoom forces a frame.
- iframe/video embed with radius or ratio: no .sgs-media-el marker on embeds, so every box setting is dead for them.

## 3. The contract a new media design must give cloner and hand-styling agents

Principle: one drawn box, one rule. Every draft image is described by exactly two things: the FRAME (the box the image is drawn into) and the PICTURE (how the file fills that frame). The cloner and an agent read the draft, decide the frame's sizing source from a fixed table, and write the same attributes in the same way. No attribute may paint only under another setting that the cloner has to guess; the mode must be derived or implied.

3.1 The sizing rule (unambiguous, per device, in this order, first match wins). Read the draft's computed box of the frame element at 375, 768, 1440 (frame = the img itself when there is no clipping wrapper, else the wrapper, see 3.3): (a) FILL: the frame's height is set by something other than the image: its parent is a flex/grid item stretched to a row or card height, the frame has height:100% of a definite parent, or the parent has a declared height/min-height/aspect-ratio and the frame has none of its own. Write size = fill (the frame takes the layout's box; min-height is the floor). Nothing else sizing-wise is written. (b) HEIGHT: the draft declares an explicit height (px, rem, vh, clamp) on the frame and a width that is auto or 100%. Write height (per device). The image covers or contains per fit. Never also a ratio. (c) RATIO: the draft declares aspect-ratio on the frame (or the frame's width and height attributes are a different ratio from the file, i.e. it is cropped to a ratio). Write ratio (per device). Never also a height. (d) WIDTH AND HEIGHT BOTH: write both; ratio is not written (current rule from aa6611517, make it a stated rule). (e) NATURAL: none of the above (width only, or auto): write width only; the picture keeps its own ratio from the file's real width and height (always printed). The max-height equivalence (2.4) stays for a declared height on an intrinsic-ratio box that follows the width. The mode is DERIVED from which of fill, height, ratio, both, none is written. There is no separate mediaSizing setting for the cloner to write; if a UI toggle is kept it only edits those values. Height versus ratio versus fill are one setting with one value kind: `size: fill | height <length> | ratio <w/h> | natural`, tiered per device with inherit-down (tablet empty = desktop, mobile empty = tablet).

3.2 Fit and focal: written only when the picture is cropped, i.e. rules (a) to (d) with a frame ratio different from the file ratio. Fit = the draft's object-fit (cover default; contain, none, scale-down map one to one; fill means stretch). Focal = the draft's object-position, per device, one shape (the existing focal control with float x,y or the css string, one data shape only). Default fit when the draft declares none is the draft's own default (img: fill; image-slot: cover). The cloner writes the draft's value, never the framework default.

3.3 The frame or no-frame decision (made once, by the cloner and by the renderer from the same facts). A frame element exists when ANY of these is true: the draft has a wrapper that carries size, ratio, radius, border, shadow, overflow:hidden or an overlay and holds only the picture (and optional caption/overlay/badge); the media has a caption, link, overlay, hover zoom, blend or per-device sources; the media is a video, embed or svg that needs a box. Otherwise the picture is the block root (naked). The decision must NOT depend on render-time guesses the author cannot see: the frame is always printed when any frame-owned setting (size fill/ratio, radius, border, shadow, overlay, zoom) has a value, and never otherwise. The renderer's requires_box (b7e515b60) already does this per value; the contract states it and the cloner mirrors it.

3.4 Frame ownership (one frame takes all box paint, picture takes only picture paint). Frame: width, max width, height/ratio/fill, min height, border, radius, padding, shadow, overlay, alignment, order, and it clips (overflow hidden + radius inherited so overlay, picture, embed and zoom obey the radius, empirically confirmed in G test 4; shadow stays on the clipping element, never clip-path on the frame). Picture: fit, focal, blend, opacity, filters. The calibration slot for every frame setting is the frame element; the picture slot is the img.

3.5 Radius and shape. One setting: radius, per device, four corners, on the frame. Rounded = a length; circle = 50% with ratio 1/1 (the rule: radius 50% on a non-square frame is an ellipse, as in the draft); pill = 9999px or 50% on one axis as the draft computes. No shape enum, no hard-coded 12px, no clip-path. Preset buttons (Circle, Rounded) only write radius and ratio. A draft clip-path/mask (image-slot mask) has no mapping and goes to a Custom CSS declaration on the frame, reported as handover, not an attribute.

3.6 Detecting a draft wrapper with overflow:hidden plus an inner img. At skeleton time, an element E is the media's frame when all hold: E has exactly one block child that is an img/image-slot/picture/video, plus optionally an overlay/badge/caption child that is positioned absolutely or a figcaption; E has no words of its own; E's computed overflow is hidden or clip, OR E declares aspect-ratio, border-radius, border or box-shadow that the img does not repeat; and the img is the only in-flow content (position static or fills with height:100%/object-fit). Verdict: merge E into the sgs/media node (action absorb: E's box facts become the frame's settings, the img's facts become the picture's), exactly like widthWrapper and marqueeFrame unwrap rules. If E also holds text or several images it stays a container. The same test covers image-slot (its .frame inside is the shadow-DOM clipper, so the host is already the frame). Put the rule in data/skeleton-decisions.json with a negative control (a wrapper that holds text stays a container), and a positive control per variant (radius only, ratio only, overflow only, overlay child).

3.7 Background images. Decision: a div with a CSS background-image that fills its own box and holds content is a background of that container (existing background panel). A div whose only job is to show the image (no children, sized by itself) is an sgs/media (frame = the div, picture = its background, fit = background-size cover/contain mapped to object-fit, focal = background-position). Rule: children present means background; no children means media. The framework must print one real element for the background media in every state (DESIGN-draft decision) so motion and srcset work.

3.8 Per device. Every frame and picture setting above is tiered desktop/tablet/mobile with inherit-down; a device may state "natural" to cancel a desktop height/ratio (a tablet tier of natural must be writable, today an empty string means inherit and cannot cancel). The cloner writes a tier only where the draft's computed value at that width differs from the inherited one (no redundant tiers). Ratio must become per device (it is the one frame setting that is not, today).

3.9 Hand-styling agents. The inspector shows one control group "Size and crop" with exactly: Size (Natural | Height | Ratio | Fill), the value field for the chosen option only (others omitted, not greyed), Width, Max width, Min height (standard length control), Fit and Focal (shown only when the picture is cropped), then "Frame" with Radius, Border, Padding. An agent that reads a draft follows 3.1 to 3.6 in order; the same table is in the media block's CLAUDE.md and the cloning rule file. Rule-table form (one file, shared with the editor disclosure) so the editor, the renderer, the cloner and a gate read the same truth.

3.10 Non-negotiable behaviours learned from the failures: always print real width and height from the file (CLS, 1.11); never write author aspect-ratio:auto on an image with attributes; drop sizes="auto" for cropped images and derive sizes from the drawn width (1.12) without a per-device number the author types; embeds carry the same frame so radius, ratio and shadow apply; fill requires the parent to pass height (RC13 fix in the container band, or fill uses its own height from ratio fallback like image-slot's 3/2 fallback); an unsized sgs/media in a card gets the cloner's rule (b) or (c) from the draft, never natural.
