# U-1 design: de-hardcode the nav surfaces

## 1. Problem

Five values in the nav are fixed in code when the references need them chosen per site or per tier.
Effect: a clone of any of the ten affected references cannot reproduce its own header stacking,
surface look or open behaviour, so it would be a trimmed reference.

| # | Hardcoded today | Where | References that differ |
|---|---|---|---|
| 1 | Mega panel close grace is a literal 170; the dropdown reads `submenuCloseGrace` | `includes/nav-menu-markup.php::sgs_nav_bar_menu_render_items` (mega fork) | the control does nothing on a mega panel |
| 2 | Hover-intent delay is 300 in markup, then clamped to 80 in JS; no attribute; no click-only open mode | `src/shared/nav-interactivity/mega-disclosure.js::enterBridge` | away (68 ms), butcherbox and lamalama (click open) |
| 3 | Header z-index is 100 in three render branches and `style.css` | `site-header/render.php`, `site-header/style.css::.sgs-site-header` | 10 references, 11 distinct values (9 to 10000) |
| 4 | Ground vocabulary diverges: blur is a boolean on the panel and a length elsewhere; radius is a string on the panel and a tier object elsewhere; panel and drawer have no shadow; panel shadow and blur literals | `mega-panel/{block.json,render.php}`, `site-header/block.json`, `nav-drawer/block.json` | halcyon, indus-foods, away, rabbit, fantasy |
| 5 | "Force solid" only cancels transparency; with an empty background nothing paints | `site-header/render.php` | Bean's answer 1a: it must give a solid resting colour |

Plus M-21 (item hover paint): no hover-opacity attribute, panel card lift hardcoded at -3px, no
padding-shift-on-hover.

## 3. Design

Every new attribute is a per-tier object unless noted. No inline styles. PHP allow-list carries the
same values as the JSON enum in the same commit. Names checked against the DB for collisions
(`sgs/decorative-image::zIndex` is a plain number on another block; no nav block has one).

**Commit order inside the unit** (each its own commit, pushed and deployed):

1. **Mega `closeGrace` wiring.** The mega fork reads `$submenu['close_grace']` like the dropdown
   fork. Cause proven by reading both forks (literal 170 vs variable). Inspector help text for
   `submenuCloseGrace` changes from "the dropdown" to "dropdowns and mega panels". PHP test: a mega
   context built with `submenuCloseGrace` 59 carries 59. Negative control: same test against the
   literal fails.
2. **Force-solid resting colour (Bean 1a).** At a tier where `contrastSafe` is `force-solid`, the
   header emits its own resting fill: `backgroundColour` (or its gradient) if set, else
   `var(--wp--preset--color--surface,#ffffff)`. **Council change (proven in source, blocker):** the
   one writer `helpers-responsive.php::sgs_merge_tri_state_declarations` writes every declaration with
   `!important` and cancels a narrower tier with `<prop>:revert !important`, so any emission outside
   it loses. Force-solid is therefore a FOURTH entry in that merge (listed before Transparent),
   contributing `background`, so the single-writer guarantee holds. The live check on a `qa-hdr-*`
   fixture (desktop transparent, mobile force-solid, computed background at 375 wide, headed Chrome)
   is the acceptance test, not the cause proof.
3. **`zIndex` on `sgs/site-header`**: tier object `{desktop,tablet,mobile}`, each a whole number 0
   to 99998 (below the WP admin bar's 99999), default empty which means 100. **Council change
   (blocker):** the value is resolved per tier and passed as the `z-index` value INSIDE the merge,
   replacing the literal `'100'` in all three entries (Float, Sticky, Transparent); a separate rule
   would lose to the merge's `!important` on 8 of the 9 references. `auto` is NOT permitted
   (council: it removes the header's stacking context and re-creates the trapped-mega-panel defect
   `site-header/style.css` fixes; `mega-disclosure.js::needsStackingFix` assumes a numeric header
   z-index). buck's `auto` is a recorded divergence (below).
   **Drawer scale, independent and floored (council change):** the header publishes `--sgs-header-z`
   on `:root`; only the FIRST header in document order publishes it (a static flag in `render.php`;
   studionamma's second strip carries its own scoped z-index and does not publish). Drawer
   `min(90, var(--sgs-header-z, 100) - 1)` floored at 2, scrim one lower. At the default 100 this is
   today's 90 and 89; at fantasy's 10 it is 9 and 8, above page content (`.entry-content` z 1) and
   below the header. A header z-index of 3 or less cannot sit above a non-modal drawer; the control's
   help text says so. The default `modal` drawer is top-layer and unaffected. Mega and dropdown panel
   z-index stay relative inside the header's stacking context.
4. **Surface ground vocabulary.** One vocabulary for blur, opacity, shadow and radius on the three
   surface blocks; fill names are NOT renamed (`backgroundColour`, `panelBg`, `drawerBg` are keyed
   into colour-panel, patterns, stored content and `sgs/cart::panelBg`).
   - `surfaceBlur` (length) on header, panel, drawer (the drawer already declares it, with
     `surfaceOpacity`). Header `backdropBlur` is renamed to it; panel `bgBlur` (boolean, literal
     `saturate(1.5) blur(24px)`) is replaced by it.
   - `surfaceSaturate` (number, percent; empty means no saturate) on all three, so halcyon's
     `saturate(1.4) blur(18px)` and `saturate(1.5) blur(24px)` are both reachable.
   - `surfaceOpacity` on header and panel (drawer already has it).
   - `shadow` and `shadowColour` are DECLARED on panel and drawer. Council change: both wrap
     `sgs/container`, and `SGS_Container_Wrapper` already reads `shadow` / `shadowColour`
     generically, so no block-private `box-shadow` writer is added (that would be a second writer).
     Build-time check: confirm the wrapper is the emitter for each block before declaring; the
     panel's hardcoded literal in `mega-panel/render.php` is deleted and becomes the block.json default.
   - `borderRadius` on the panel becomes the tier object header and drawer already use. Council
     change: `sgs/mega-panel::borderRadius` is a DB row that routes the converter's declarative CSS
     (`css_property=border-radius`, `css_element=wrapper`), so the converter emit and the DB reseed
     land in the same commit as the type change.
   - `surfaceFadeEdge` (`none` | `top` | `bottom`) on the header: a `mask-image` fade of that edge
     to transparent (fantasy). One reference supports it, so it is built last in the unit.
   - **One shared mechanism, not three copies.** Blur, saturate and opacity are emitted by one PHP
     helper (`sgs_surface_ground_css()`) that the three blocks call. Council note: `sgs/container`
     itself has no blur, saturate or surface opacity, so the composite-mirror direction is inverted
     for these three properties. Extending `sgs/container` with them is a separate scope for Bean to
     request; this unit builds the shared helper so that extension is one call.
   Migration: no deprecations pre-production. Every rename is grep-driven. The full rename list
   (15 files, proven by grep): `sgs-header-float-css.php`, `site-header/{block.json,edit.js,render.php}`,
   `FloatControls.js`, `float-preview.js`, `mega-panel/{block.json,edit.js,render.php}`,
   `scripts/consistency/{attr-role-map,setting-types}.json`, `scripts/data/{property-suffixes,roles}.json`
   (the "Blur sub-attribute (backdropBlur)" row), `css-var-bridge-backup.json`, and
   `scripts/nav-qa/build-header-fixtures.py`; no theme pattern stores either name. Run
   `sgs-update-v2.py` afterwards. Fallthrough check for the panel radius (a stored flat string still
   resolves). Editor preview and frontend change together (`mega-panel/edit.js` reads `bgBlur`). Any
   stored `backdropBlur` in sandybrown's `sgs_header` post content is updated by `wp post` search
   before deploy.
5. **Intent delay and open mode (M-43).** On `sgs/nav-bar-menu`: `submenuIntentDelay` (number,
   default 80, range 0 to 400, scalar because only fine pointers hover) and `submenuOpenOn` (`hover`
   default | `click`). The JS clamp is deleted; the attribute's range is the bound, and the JS
   fallback `Number.isFinite(ctx.intentDelay) ? ctx.intentDelay : 300` becomes 80 (council: it would
   otherwise go live at 300 ms). Default 80 is the effective delay today. **`click` is a whole
   mode (council change):** hover no longer opens, `mega-disclosure.js::leaveBridge` no longer
   closes on `mouseleave` after the grace (a click-opened panel stays open until click-outside,
   Escape or a second click), and the `nav-menu-css.php` `__submenu-root:hover > __link` and caret
   "opening" paints are gated off in that mode so the trigger never looks open when it is not.
   Keyboard and tap are unchanged. Spec 36 FR-36-4 is edited in the same commit (it says there is no
   operator attribute for hover-intent and names the clamp).
6. **Item hover paint (M-21).** `itemOpacityHover` (number 0 to 1) and `itemOpacity` (rest) on
   `nav-bar-menu` and `nav-drawer-menu` items; `panelCardLift` (length, default 3px, the value
   hardcoded now) on `mega-panel`; `itemPaddingShiftHover` (length) on dropdown, mega and drawer
   items. Built after the four above because it has the fewest references.

**Editor surface.** Each attribute gets its inspector control in the commit that renders it:
`ResponsiveControl` for tier objects, `SgsColourPanel` for `shadowColour`, `SelectControl` /
`ToggleGroupControl` for enums, `RangeControl` for the two numbers. Round-trip check in the real
editor after each edit.js change.

**Tests.** PHP tests in `tests/php/NavMenuMarkupTest.php` (new), a header render test for the
z-index and force-solid emissions, and a JS test for the intent-delay path. Every test has a negative
control that fails against the previous code.

## 4. Risks

1. `revert` merge wipes the block's own rule at a narrower tier: proven or dismissed in commit 2.
2. Renaming `backdropBlur` touches the floating-pill work and the Mama's header content; the rename
   must update stored content on sandybrown (`wp post` search of `sgs_header` post_content).
3. `bgBlur` boolean to a length: the roster JSONs (`attr-role-map.json`, `setting-types.json`) and
   `scripts/data/roles.json` regenerate; run `sgs-update-v2.py` again after the block.json edits.
4. `sgs/cart::panelBg` shares a name with the panel's fill, so nothing is renamed by name search.
5. The unit is larger than the plan's "medium": six commits. Estimate: 2 to 3 hours in one session.

## 5. Council verdict and recorded divergence

QC council (code-path verifier, haiku; adversarial reader, opus): GO WITH CHANGES. Three blockers
(z-index and force-solid must go through the merge; the drawer scale must be floored and `auto`
dropped) and six design fixes (two headers per page, the panel radius converter row, shadow via the
container wrapper, click mode as a whole mode, the JS fallback, the container-mirror note) are
applied above. Exit-table notes: no reference measures a DRAWER z-index, so the derived drawer scale
is verified live on the fixture only; the halcyon "not gated on owning a panel" cell is a build-time
check that becomes a fix if the code gates it; force-solid has no reference cell (it is Bean's answer
1a), so its exit cell is the live fixture measurement.

**Recorded divergence (needs Bean's acceptance): buck's header z-index is `auto`.** The clone uses
the default 100 instead. Effect: none visible in buck's own layout (nothing overlaps its header), and
the framework keeps a stacking context so open panels are never trapped.
