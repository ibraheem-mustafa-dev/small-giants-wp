# Spec 38A build: unit map for phases M3, M4, M5 and M6

Source of truth: `.claude/specs/38A-SGS-MOTION-MODEL.md` v1.4 §16. Evidence read: the spec in full, `.claude/reports/2026-10-12-motion-effects-audit.md`, the research report headings, the five rule files named in the brief, every file listed under "File decisions" (sizes from `wc -l`, callers from `git grep -l`), and the framework DB read-only (`fx_effects` columns and rows, `motion_presets` and `animation_tokens` existence, block counts per old attribute). Mapped 2026-10-12. Paths are under `plugins/sgs-blocks/` unless they start with `scripts/` at the repo root (the cloning route) or `.claude/`.

Dependencies on the other agent's phases are named "M1 <thing>" and "M2 <thing>". The things these units assume M1 and M2 deliver: M1 `motion.schema.json` with `$defs` field types, the panel structures and the §10 refusal rules; M1 support registration (`supports.sgs.motion`, `sgsMotion`, the `states` key); M1 `motion_presets` table and `scripts/data/motion-presets.json`; M1 `fx_effects.owned_properties` and `panels` columns; M1 DB rows from the schema (FR-38A-3, so a schema entry plus a reseed gives every effect field its `block_attributes` row); M1 shared atoms in `src/components/motion/` (including Replay, the target picker and the stagger-helper atom) and field-type helpers (`src/components/motion/field-types.js`, `includes/motion/class-sgs-motion-field-types.php`); M1 tokens; M2 renderer (one `render_block` filter, collector emission, data attributes), M2 shared motion stylesheet with the §10 composite channels and `@property` registrations, M2 reveal module, M2 WAAPI entrance, M2 scroll driver, M2 paint slots and injected `span.sgs-motion-layer` layers, M2 reduced-motion handling.

## Boundary flags for the main thread (read first)

1. Phase-boundary overlap. The brief says M1/M2 cover "hover and entrance panels", but §16 puts FR-38A-7 (Hover panel) and FR-38A-8 (Entrance panel) in M3. This map owns the inspector panels (M3.3 to M3.6) and assumes M2 owns only the hover and entrance RUNTIME. Reconcile with the M1/M2 map so neither builds the panels twice.
2. M2 done-whens that need M5 effects. FR-38A-23 (composition stacks: magnet + sheen + ripple, tilt + scale + lift, tilt + lift + parallax), FR-38A-47 (the same stacks) and FR-38A-49 (cursor-field ring + ripple + sheen on one card) cannot close until the M5 effect units land. This map adds unit M5.Z to run those acceptance checks; M2 should build the mechanism and mark those three FRs as closing in M5.Z.
3. FR-38A-29 baseline must be captured BEFORE M1's support registration (FR-38A-1) deploys, because the done-when compares "the same page measured before the change". Unit M3.0 is therefore wave 0 and should run now.
4. FR-38A-54 says M1's stagger-helper atom "writes the FR-38A-24 delays", while §16 puts FR-38A-24 in M4. This map puts the delay engine (pure function plus PHP mirror) in M4.1; if M1 already built it, M4.1 shrinks to its acceptance tests.
5. Spec drift found: `src/shared/effects/stagger.js` no longer exists (deleted by commit 01e4b5a5f; `tests/php/run-u5-motion-standalone.php` asserts it is gone). The drawer and submenu item staggers are now an `nth-child` ladder in `src/blocks/nav-drawer-menu/style.css` (`--sgs-i` 0 to 19, with `sibling-index()` where supported), which §8 explicitly rejects. FR-38A-51(c)'s grep passes vacuously today; the real removal target is that ladder. Update §13.1, §13.2 step 4 and FR-38A-51 in the spec.
6. Migration input omission: §13.1 does not list `sgsClickEffect`, `sgsClickRippleColour` or `sgsClickRippleDuration` (registered by the hover-effects extension, `src/blocks/extensions/extension-roster.json`), which feed today's ripple. M5.9's mapper covers them; add them to §13.1.
7. Escape-hatch fx blocks: `sgs/mega-panel`, `sgs/site-header-row` and `sgs/site-footer-row` declare their own `fx*` attributes and use `src/components/{CursorField,FlowingGradient,GridDotField,ParticleTrail}RowControls.js` outside `fx.js`. §13.1's `fx*` line covers the attributes by DB query, but the four RowControls components and `SurfaceTreatmentPanel.js` are not named in §13.2 step 4. This map deletes them in M6.6-G0 and migrates the three blocks' values through M5.1's mapper.

Hard-coded dictionaries that block parallel work. `webpack.config.js` lists every effect entry by hand and `includes/class-sgs-motion-registry.php` maps effect to stylesheet by hand (a hand-written dict, against R-31-1). Unit M3.W replaces both with naming conventions (`src/shared/effects/fx-<effect>.js`, `assets/css/fx-<effect>.css`) and adds folder loaders, so every later effect unit creates only its own files and units in one wave never share an edited file.

## Hotspot rule

After M3.W lands, no unit edits `sgs-blocks.php`, `webpack.config.js`, `package.json`, `scripts/run-gates.py`, `src/blocks/extensions/index.js` or `includes/class-sgs-blocks.php` to register something new. PHP under `includes/motion/` (and `includes/motion/migrate/mappers/`) loads by folder; JS under `src/blocks/extensions/motion/` loads from one import; effect scripts and stylesheets register by name; every `scripts/check-motion-*.py` runs through one runner; every `scripts/generate-motion-*.py` runs in `prebuild` through one runner. Exceptions are named in the unit (M5.8 edits `class-sgs-blocks.php` once to delete a dead enqueue; M6.6-G0 edits the hotspots to remove old code).
