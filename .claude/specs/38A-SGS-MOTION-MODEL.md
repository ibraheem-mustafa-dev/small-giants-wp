# Spec 38A: the SGS motion model

> **One-liner:** every compatible SGS block gets three motion panels (Hover, Entrance and reveal, Effects), each holding stackable layers that store real values per element, per device and per motion type, with presets that stamp token-backed values, a container helper that writes stagger delays, and a mostly CSS runtime.

Spec 38 keeps the tier doctrine (V, G, H, W), the effect roster, the `fx_effects` registry and the `data-sgs-fx-*` grammar. This spec owns how motion is modelled, stored, edited, emitted and played: entrance presets, the hover suite, stagger, effect parameters and the per-block reveal systems. The evidence and the owner's decisions are in `.claude/reports/2026-10-12-motion-system-research.md` (revision 3, section 1); the build sits under Phase 0, step 0.3 of `.claude/plans/2026-10-12-clone-coverage-foundation.md`.

## 0. Plain English

Problem: motion in SGS today is spread over about six reveal and stagger systems and seven hover systems with three incompatible data shapes. Presets hide the real numbers, motion applies to a whole block only, nothing varies by device, and the browser works out stagger delays at run time. Effect: a client cannot fine-tune a fade, the cloning tool cannot write what a draft actually does, and two systems can fight over the same element. Solution: one model. Each element of a block (the whole block, its image, its title and so on) has three panels (Hover, Entrance and reveal, Effects), and each panel can stack several layers on that element, because real designs do: one card magnetises towards the pointer, sweeps a sheen and ripples on press, all at once. Every layer's movement adds up with the others instead of overwriting them. Picking an effect such as "Fade up" copies real values onto the element (distance, duration, delay, easing), and each value points at a named site setting ("token") where one fits, so retuning the site's "fast" retunes every hover. A simple layer shows effect, trigger and intensity; a Fine-tune layer shows every value. Stagger is a helper on containers that writes a delay onto each child once; the page never computes delays. Most motion needs no JavaScript.

## 2. Goals and non-goals

Goals: one motion support on every compatible block; values stored per element, per motion type, per device; presets that stamp token-pointing copies (D2); explicit stored delays everywhere (no browser-computed stagger); a CSS-first runtime; every value an effect hard-codes today exposed as a Fine-tune control (§5.4); every motion field described in the framework DB so the clone coverage test (plan Phase 1) can see it; a migration of every old motion attribute with no legacy fallback.

In scope as well (owner, 2026-10-12: the model covers every motion SGS ships): block-private state-change motion such as the cart count pop and the burger icon morph (FR-38A-53); the nav drawer's and submenus' open and close motion and their item staggers, which move onto the Entrance and reveal panel model and the container stagger helper (FR-38A-51), and looping media animations (Ken Burns, background and logo SVG animation, Lottie), which become Effects-panel effects with their own control sets (FR-38A-52).

Non-goals:

- Colour and shadow hover VALUES. They are compliant per-element styling states set through the shared colour and shadow controls. The Hover panel owns only their transition timing.
- Site-level motion (`scroll-smoother`, `page-transitions`): stays on the SGS Motion settings page (Spec 38 §3.5).
- `carousel-loop`: stays a block-private carousel control (Spec 38 FR-38-26).
- Core blocks' own motion (`core/cover` `hasParallax`).
- Rewriting Spec 38's tier doctrine. New effects (FR-38A-34 to FR-38A-37) join the `fx_effects` roster through the normal seeding path.

## 4. The model

1. **Three panels, each holding layers.** Hover, Entrance and reveal, Effects. Each element (root or declared part) has all three, and each panel holds layers, because the drafts stack motion on one element (Indus cards: magnet, sheen and a pointerdown ripple; tilt with a hover scale and lift; tilt, lift and parallax). The Hover panel holds the element's hover state values (any combination of translate, scale, rotate, opacity and filter, plus timing) and an ordered list of hover-driven effects (tilt, magnet, sheen), each with its own parameters. The Entrance and reveal panel holds one entrance (values, or a preset such as Fade up) and an optional list of text and SVG entrance effects (split-reveal, scramble, draw). The Effects panel holds an ordered list of effects (cursor-field, parallax, ripple, ken-burns, ambient-float and the rest), each with its own parameters. The simple layer of each panel shows one primary choice; further layers are added in Fine-tune with "Add effect". Layers combine by the §10 channel table: contributions to one property add or multiply, and the schema refuses only the combinations §10 lists.
2. **Targets are declared parts.** Each block's targets are its root plus the parts it declares in `supports.sgs.elements` (BEM `sgs-<block>__<element>`), read from the framework DB. A typed selector is never offered to clients.
3. **Custom selector for the cloning tool only (D6).** A cloned draft may need a target no declared part names. Only the cloning tool may write a custom target, only with a review row that records the draft node and why no declared part fits, and the selector is always scoped inside the block root.
4. **Values underneath.** Each layer on each element stores property values per state or keyframe (from and to, or a keyframe list), timing (duration, delay, easing) and type-specific values (distance, scale, angle, effect parameters).
5. **Presets on top (D2).** An effect type (Lift, Fade up, Magnet Standard) is a DB-seeded preset that stamps a full copy of its values onto one layer of the element. Each stamped value points at a motion token where one fits. Editing a preset later never reaches existing blocks; changing a token retunes every value that points at it.
6. **Per device.** The framework's fixed tiers (Spec 32 FR-32-13, Spec 35 D2): Desktop is the stored base value and applies at 1024px and wider; Tablet overrides apply from 768px to 1023px, emitted inside `@media (max-width:1023px)`; Mobile overrides apply below 768px, emitted inside `@media (max-width:767px)`, the same desktop-first max-width cascade as `plugins/sgs-blocks/includes/helpers-responsive.php::sgs_responsive_css_rule`. A blank Tablet value inherits Desktop and a blank Mobile value inherits Tablet. Checks measure at 1440 (Desktop), 768 (Tablet) and 375 (Mobile).
7. **Explicit delays.** Every element stores its own delay. A container helper writes delays to children; query loops get server-written per-item delays. Nothing computes a delay in the browser.

## 5. The three panels

Each panel sits in the Styles tab on every block that declares the motion support. A Target row at the top of each panel lists the block root and its declared parts; a dot marks targets that already carry a layer of that panel's type. The panels are element-first panels (Spec 35 A4): one panel per motion type whose Target row is derived from `supports.sgs.elements`, so every declared part is reachable from each panel without a motion control in each element panel; hover colour and shadow states stay inline in their element panels. Each panel holds layers (§4 item 1): the simple layer shows the panel's one primary choice, and Fine-tune lists every layer in order with "Add effect", per-layer controls and Remove.

Every Fine-tune field that differs from the stamped preset shows a "Customised" tag and its own Reset, which restores the stamped value. Changing a layer's preset or Intensity re-stamps that layer's values and clears its Customised tags after a confirmation that names how many customised fields will be replaced. A layer's position in its list is its paint order (later layers paint above earlier ones); because channel contributions add or multiply (§10), the order never changes the computed movement. An effect slug appears at most once per element per panel; adding a second is refused with "<Effect> is already on this element; change its values instead."

### 5.1 Hover

The Hover panel holds two kinds of layer. **The hover state**: one set of values the element moves to on hover, over any combination of translate x and y, scale, rotate (rest rotate is a styling value, hover rotate the angle it turns to, FR-38A-42), opacity and filter (blur, grayscale, brightness), and a ring (a `box-shadow` spread and colour row, so a glow ring such as Indus's caret ring and form-submit glow is a library-wide hover value, built in M3.4 and closed in M3.9), plus duration, delay and easing; its presets are none, lift, scale, rotate and translate, image zoom (scale on a media part), grayscale to colour, indent (`padding-inline-start`) and border accent, each of which only stamps state values. **Hover effects**: an ordered list of hover-driven effects, each with its own parameters: `tilt` (FR-38A-41), `magnet` (FR-38A-40) and `sheen` (FR-38A-35), plus any later `fx_effects` row whose `panels` column allows the Hover panel. The simple layer's Hover state choice edits the state; Add effect appends hover effects. "Whole block hovered" (`source: root`) makes the root's `:hover` and `:focus-within` drive this element's state and its hover effects, and "Group hovered" (`source: group`, §6.2) does the same from the nearest ancestor block marked as a hover group.

### 5.2 Entrance and reveal

The panel holds **one entrance** (from and to values, extra keyframes, timing and trigger, or a preset that stamps them: fades, slides, scale-in, blur-in, reveal-up and any preset seeded later) and an optional ordered list of **text and SVG entrance effects**: `split-reveal` and `scramble` on text parts, `draw` on SVG parts (load and scroll triggers; a hover redraw is an Effects-panel layer). Triggers: Page load, Scroll into view, Panel opens on a part that a disclosure opens (the nav drawer panel, submenu and mega panels and their items, FR-38A-51), where the entrance also stores close values and a close delay (§8), and State on a part whose block declares named states (FR-38A-53).

**Entrance and text effects compose.** A Fade up and a split-reveal may sit on one part: the entrance animates the element's own channels (opacity, translate and the rest, §10), while split-reveal animates the unit spans it creates inside the element (characters, words or lines), scramble rewrites the text characters and draw animates the SVG stroke, so no two layers write the same property on the same node. The visible opacity is the product of the element's and each unit's opacity, which is the intended look (units fade in inside a block that fades in). Timing: a text effect's own delay counts from the element's entrance delay, so a stagger written onto the element (§8) carries its text effect with it. Refused: two text effects that rewrite the same text (split-reveal and scramble on one part, whether both sit in `entrance.text` or one sits in `entrance.text` and the other in `effects` with the hover trigger), with "Split reveal and Scramble both rewrite this text; keep one of them." The LCP rule (§9) applies to the entrance; split-reveal and scramble keep their Tier G loading.

### 5.3 Effects

The Effects panel holds an ordered list of effects, each with its own parameters, drawn from the `fx_effects` rows whose `scope`, `requires`, `in_picker` and `panels` fit the block and target (element-scoped effects only on parts that can hold them, for example SVG parts for `draw`). The target of each layer is the element it is stored under, chosen with the Target row, so one block can carry parallax on its image, a cursor field on its root and ripple on its button part. Tier G, H and W effects keep their tier, their conditional loading and the `data-sgs-fx-*` runtime grammar (Spec 38 §11); this model only changes where their values are stored and how they are edited.

**The shared control kit.** Every panel's and every effect's Fine-tune is composed from one set of editor atoms (FR-38A-54) over one helper per field type (FR-38A-55), and a gate (FR-38A-56) fails on any bespoke control or sanitiser, so no effect ships its own panel code. The atoms, each written once under `plugins/sgs-blocks/src/components/motion/`, and what each existing component becomes:

## 6. Data model and storage schema

### 6.1 One support key, one attribute

A block opts in with `supports.sgs.motion` (`true`, or an object listing the allowed motion types). The support registers one object attribute, `sgsMotion`, through one editor `blocks.registerBlockType` filter and one PHP `register_block_type_args` filter; no `block.json` declares motion attributes. The attribute is unsourced (it lives in the block comment) and is never written into saved markup.

### 6.2 Shape

```
sgsMotion = {
  "v": 1,
  "elements": {
    "<target>": {                       // "root", a declared part key, or "custom:<n>"
      "selector": "<scoped selector>",  // custom targets only, written by the cloning tool
      "review": { "draftNode", "reason" },  // custom targets only: the draft node and why no declared part fits
      "hover": {
        "state":   { "preset", "intensity", "source": "self|root|group", "trigger": "hover",
                     "values", "devices", "customised" },
        "effects": [ { "id", "effect": "tilt|magnet|sheen|<fx_effects.effect>", "preset",
                       "intensity", "source": "self|root|group", "trigger": "hover",
                       "values", "devices", "customised" } ]
      },
      "entrance": {
        "base":    { "preset", "intensity", "trigger": "load|scroll|open|state", "state": "<name>",
                     "values", "close", "devices", "customised" },
        "text":    [ { "id", "effect": "split-reveal|scramble|draw", "preset", "intensity",
                       "trigger": "load|scroll|open|state", "state": "<name>",
                       "values", "devices", "customised" } ]
      },
      "effects": [ { "id", "effect": "<fx_effects.effect>", "preset", "intensity",
                     "trigger": "load|visible|scroll|hover|pointerdown|click",
                     "values", "devices", "customised" } ]
    }
  },
  "stagger": { "apply", "offset", "step", "order", "perRow", "cap" }   // container helper's last settings only
}
```

- **Layers.** `hover.state` and `entrance.base` are single objects; `hover.effects`, `entrance.text` and `effects` are ordered arrays whose order is the paint order (§5). Each array item carries a stable `id` (written once when the layer is added, so `customised` paths and the inspector survive a reorder) and an `effect` slug naming its `fx_effects` row (the slugs with no row today, `parallax`, `tilt`, `ripple`, `sheen`, `scroll-progress`, `ambient-float`, `marquee`, `ken-burns` and `svg-loop`, are seeded into `fx_effects` by the FR that builds each, FR-38A-35 to 37, 41, 43 to 45 and 52, so every layer that is an effect has a row). An `effect` slug appears at most once per array per element. A layer `id` is 1 to 32 characters: lower-case letters, digits and hyphens, starting with a letter or digit; the editor writes a short slug once and never reuses one within an array.
- **Trigger enum per panel.** Hover state and hover effects: `hover` only (pointer hover on devices that can hover, plus `:focus-visible`, with `source: root` reading the root's `:hover` and `:focus-within`); magnet's proximity or over-element engagement is a value, not a trigger. Entrance base and text effects: `load`, `scroll`, `open` (a part a disclosure opens, FR-38A-51) and `state` (a named state the block declares in `supports.sgs.motion.states`, stored in `state`, FR-38A-53). Effects: `load`, `visible`, `scroll`, `hover`, `pointerdown` and `click`, each layer limited to its `fx_effects.triggers` list (ripple's `pointerdown` and `click` join that list through FR-38A-45).
- `values` holds the property values: for an entrance `from`, `to` and optional `keyframes`, plus `duration`, `delay`, `easing`, `start` and `allowLcpFade` (a boolean that lets a first-section or high-priority element fade from its from-opacity, §9); `close` (for the `open` trigger only) holds the close `to` values, `closeDuration`, `closeEasing` and `closeDelay` (§8); for a hover state the changed properties plus `duration`, `delay` and `easing`, and `restRotate`, the resting angle (a styling value, FR-38A-42, written to `--sgs-rot-rest` and read by the rotate channel in §10); for an effect its parameters, among them the boolean flags `background` on parallax (it moves the part's background image instead of the part) and `proximityFocus` on horizontal-panel (FR-38A-38, FR-38A-39).
- A value is a literal (number with unit, string) or a token reference `"token:<family>.<key>"` (for example `"token:duration.fast"`), which the renderer resolves to `var(--wp--custom--<family>--<key>)`.
- **Source.** `self` makes the element's own `:hover` drive its hover state and effects; `root` makes the block root's `:hover` and `:focus-within` drive them; `group` makes the nearest ancestor block marked as a hover group drive them, through that group's `:hover` and `:focus-within`. A block becomes a hover group by carrying a whole-block link (`sgsBlockLink` or `sgsBlockLinkAuto`, the existing blockLink extension, for example an `sgs/container` with a link on the whole block): the renderer marks its root `data-sgs-hover-group`. A `group` source also drives the element's existing hover colours (text, background, border) through the same group selector, which `sgs_hover_state_rules()` adds for the block's hover colours, so a parent block's hover moves each inner block's own hover values and hover colours together (the Indus footer's Back to top). M2.1 emits the group selector, M2.2 styles it and M3.4 adds the control.
- **Custom targets.** A `custom:<n>` target carries `selector` (one selector inside the block root, at most 200 characters, no list, block or at-rule) and `review` (`draftNode` and `reason`, each 1 to 500 characters), both required.
- **Declared parts.** A part in `supports.sgs.elements` resolves to its declared `selector` (one class, or classes joined by single descendant spaces, read by `Sgs_Motion_Targets::declared_selector`), else to the class `sgs-<slug>__<part>`; a composite's content band is the root's direct child and carries `sgs-container__inner` and `sgs-<slug>__content-band`, printed by `SGS_Container_Wrapper::render`. A nested block of the same type prints a band with the same classes, so a part that resolves to either band class (`content-band`, and `inner` on every composite) is the root's direct child only: its rule is `.<scope> > .<band class>` and `Sgs_Motion_Markup::apply` stamps only the band one level below the root. A layer on `content-band` or `inner` makes the wrapper print the band even without band settings (`Sgs_Motion_Targets::names_band`; a grid, flex or stack layout then moves onto the band, as it does for container queries), except where the block turns the band off (`wrap_inner` false: hero's split layout), where the part matches nothing. A part marked `"motion": false` names something the block does not print itself: an InnerBlocks child, a state or modifier of another element, a pseudo-element, a styling-only grouping, an element built at run time by JS, third-party markup, or markup printed outside the block root (the shared scrim at `wp_footer`). It is never a target: `Sgs_Motion_Targets::parts` leaves it out (a layer on it resolves to nothing), `seed_motion_fields.py` writes no `motion_targets` row for it, `check-motion-db-rows.py` expects none, `TargetPicker.js` does not offer it, and `check-motion-part-selectors.py` counts it as excluded and fails on any other `motion` value or on a part that resolves to nothing.
- `devices.tablet` and `devices.mobile` hold overrides only.
- `customised` lists the value paths the client or the cloning tool changed after the stamp.
- `stagger` is read only by the editor helper to re-run itself; the renderer never reads it.

### 6.3 One JSON Schema

`plugins/sgs-blocks/schemas/motion.schema.json` defines the shape, every value's type, unit, range and enum, and which properties each motion type may write. The cloning tool validates against it before writing; the inspector builds the kit controls from it; the PHP renderer drops any key or value the schema does not allow. A schema check runs in the build gate.

### 6.4 Framework DB

- **Fields.** Two small tables and a view, not a `block_attributes` row per field per target per block (that would add tens of thousands of rows to a shared table and change what every query that reads `block_attributes` without a source filter returns). `motion_targets` holds one row per compatible block's root and per part in `supports.sgs.elements` (block, target, `css_element`, kind, whether it is the wrapper part), seeded from the `block.json` files. `motion_fields` holds one row per schema field per panel layer (panel, layer, effect slug, field path, field type, `css_property`, state, per-device flag, Intensity flag, unit, range, enum), seeded from the `x-sgs-field` annotations of `motion.schema.json`. The view `motion_field_rows` joins them at read time into one row per block, target, field and tier (desktop, tablet and mobile for a per-device field, `all` for any other). `plugins/sgs-blocks/scripts/dbschema/seed_motion_fields.py` seeds both tables from `sgs-update-v2.py` (Stage 1) and replaces them whole, so a retired block or field leaves no row; `plugins/sgs-blocks/scripts/check-motion-db-rows.py` fails when a schema field or a declared part has no row in the view. The calibration, cloner and coverage test read the view; nothing is written to `block_attributes`.
- **Presets.** A `motion_presets` table (slug, motion type, effect slug for Effects rows, intensity, label, values with token references, thumbnail key) seeded through `plugins/sgs-blocks/scripts/dbschema/seed_reference_data.py` from one source file, `plugins/sgs-blocks/scripts/data/motion-presets.json` (the same `scripts/data/` directory the seeder's other reference files use). The inspector and the cloner read the same rows.
- **`animation_tokens` is retired.** Its 8 keyframe rows are reconciled into `motion_presets` (only `fade-up` is in use), pointing at theme tokens instead of literal durations and easings, and the table is dropped.
- **`fx_effects`** stays the effect registry and gains an `owned_properties` column (the §10 channels and paint slots an effect writes) and a `panels` column (which of Hover, Entrance and reveal, Effects may offer it).
- **Tokens** are read from `theme.json`, never copied into the DB.

### 6.5 Emission

The renderer (one `render_block` filter for the support) emits, through the shared collector (Spec 32 FR-32-11): scoped custom properties per target per device, and data attributes on the target element via `WP_HTML_Tag_Processor`. The renderer never writes an owner property (`--sgs-mh-s`); it writes the hover state's to-values, and the shared stylesheet switches each owner on through the hover flag. A scale of 1.04 and a lift of 6px on a card's media part, with Tablet at 1.02 and Mobile at 3px, emit:

```
.sgs-m-<10 hex> .sgs-info-box__media{--sgs-mh-to-s:1.04;--sgs-mh-to-ty:-6px;transition:--sgs-mh-s 250ms var(--wp--custom--easing--ease-out) 0ms, --sgs-mh-ty 250ms ...}
@media (max-width:1023px){.sgs-m-<10 hex> .sgs-info-box__media{--sgs-mh-to-s:1.02;}}
@media (max-width:767px){.sgs-m-<10 hex> .sgs-info-box__media{--sgs-mh-to-ty:-3px;}}
<div data-sgs-mc="translate scale" data-sgs-mh="self" class="sgs-info-box__media">
```

The to-values are `--sgs-mh-to-<tx|ty|s|rot|op|blur|gray|bright|indent>` (the rotate to-value is the hover angle minus the rest angle, which is `--sgs-rot-rest`). A shared stylesheet holds every generic motion rule. No `style` attribute, no `<style>` in the body, nothing in saved markup.

The full emitted contract, shared by the renderer (`includes/motion/`) and the stylesheet (`assets/css/motion.css`):

| Name | Set by | Meaning |
|---|---|---|
| `data-sgs-mh="self\|root\|group"` | renderer, on the target | the target holds a hover state; the value is its source (§6.2) |
| `data-sgs-mc="<channels>"` | renderer, on the target | the union of the `x-sgs-writes` channels of the element's non-entrance owners; the stylesheet declares a channel property only where it is named |
| `data-sgs-me="<trigger> <channels>"` | renderer, on the target | an entrance: trigger `load\|scroll\|open\|state`, then the channels it touches |
| `--sgs-me-from-*`, `--sgs-me-to-*`, `--sgs-me-dur`, `--sgs-me-delay`, `--sgs-me-ease`, `--sgs-me-start` | renderer, in the scoped rule | the entrance's values and timing; to-values default to the identity |
| `data-sgs-me-keyframes` | renderer, on the target | the entrance's keyframes as JSON, read by the WAAPI module (M2.4) |
| `data-sgs-mroot` | renderer, on the block root | a root whose targets use source `root` |
| `data-sgs-hover-group` | renderer, on a block with a whole-block link | the hover group that source `group` reads (§6.2) |

## 8. Stagger and orchestration

- **Every element stores its own delay.** A delay is an ordinary entrance value, per device.
- **Container helper.** Lives in the container's Entrance and reveal panel. It optionally stamps the container's chosen entrance onto each child (or onto each declared repeated item part), then writes each child's delay: Start offset plus position by Order (row first, column first, from centre, reverse, counting from 0) times Step, with an optional Flatten nested items setting that makes one running index cross nested containers (a two-level list staggers as one run, not once per inner container), restarting at each visual row when the column count per device is above 1, capped at Maximum total delay (D7, the cap includes the offset). Column count per device comes from the container's stored grid columns (found by DB role); a single-column stack accumulates up to the cap.
- **Drawer panel children.** In the nav drawer the helper runs on the drawer panel's direct children, non-menu blocks included (a secondary nav block, a search field, a button), not only on the menu's items (FR-38A-51, M4.5).
- **Start offset.** The first child's delay is the Start offset (default 0), so a draft whose sequence starts later than its step is matched exactly: the Eye Care drawer's four primary links are offset 50ms, step 50ms (50, 100, 150, 200ms).
- **No column count.** A container with no stored column count for a device (a flex-wrap row, a masonry layout, a carousel track, or any block whose DB role lists no grid columns) is treated as a single column: each child's delay is its Order position times Step, accumulating up to the cap, with no row restart, and the Restart each visual row toggle is hidden there. The helper never measures rendered rows, so the stored delays do not change with the viewport width.
- **Close delays.** An entrance with the `open` trigger also stores close values (§6.2 `close`): the close `to` values, `closeDuration`, `closeEasing` and `closeDelay`. The helper writes `closeDelay` per child alongside `delay`, in the same order or reversed (the drawer's `itemStaggerOnClose` maps to this choice), under the same cap.
- **Re-run.** The helper re-runs when a child is inserted, moved, removed or duplicated, and on Write delays. It skips any child delay listed in that child's `customised`.
- **Query loops.** `sgs/post-grid` writes each item's delay from its own loop index (`plugins/sgs-blocks/src/blocks/post-grid/render-interior.php` (its `_card_index`)). Core `post-template` and the WooCommerce `product-template` get a `render_block` filter that emits one positional scoped rule per item (FR-32-4a) from the loop item entrance's stored step, row restart and cap. The index restarts per page (enhanced pagination and load-more re-render on the server).
- **Time-based reveals only.** Scroll-linked effects take no stagger; a staggered scrub is Tier G (Spec 38 FR-38-7).
- **Rejected.** `sibling-index()`, stylesheet `nth-child` ladders that derive a delay from position, and any runtime delay computation.

## 9. Runtime per motion type

| Motion | Mechanism | Tier | JS |
|---|---|---|---|
| Hover and focus | CSS transitions on the target; per-element `transition-property` lists only the owners' changed custom properties and the colour and shadow properties; `@property` registers every owner custom property of §10 so each animates on its own timing; `source: root` uses the root's `:hover` and `:focus-within`; all inside `@media (hover: hover) and (pointer: fine)`, with `:focus-visible` parity | V | 0 |
| Page-load entrance | A CSS animation on the entrance's registered custom properties with `animation-fill-mode: backwards`, under the entrance rule below | V | 0 |
| Scroll-into-view reveal | One small IntersectionObserver module sets `data-sgs-in`, which starts the same CSS animation under the entrance rule below; the hidden start state (the from-values on the custom properties and the composite formula) applies only under the `sgs-motion-ready` class the module adds, so no content is hidden if JS fails to run | V | about 1 kB |
| Multi-keyframe entrance | The existing WAAPI code (`assets/js/animation-observer.js`), reading keyframes and the stored delay, animating the entrance's registered custom properties with `fill: 'backwards'` under the entrance rule below, with every delay computation removed | V | shipped |
| Scroll-linked single-property effect | One plain-JS driver on every browser writes a registered `--sgs-scroll-progress` (0 to 1); CSS reads it (D3, the FR-38-35 precedent) | V | small, shared |
| Looping effects (ambient float, Ken Burns, SVG loop, marquee) | CSS animations reading the element's scoped custom properties, with the WCAG 2.2.2 pause control on any loop over five seconds; the marquee's hover rate and pause on touch use one shared module | V | small, shared |
| Pointer-driven effects (magnet, tilt, cursor field, sheen origin, ripple) | One rAF-throttled pointer writer per effect that writes custom properties only; CSS owns every transform and paint (FR-38A-47) | V | per effect, conditionally loaded |
| Tier G, H, W effects | Unchanged: Spec 38 runtime, conditional loading, `data-sgs-fx-*` grammar, now emitted from the effect layers (`hover.effects`, `entrance.text`, `effects`) | G/H/W | per Spec 38 §4.4 |

**The entrance rule.** An entrance always animates its own registered custom properties (`--sgs-me-*`, §10), never a plain property, and always as an animation (a CSS animation for page load and scroll reveal, WAAPI for multi-keyframe entrances), never a transition. Each keyframe also declares every channel the entrance touches with the element's full §10 composite formula, so the channel is set only while the entrance runs and during its backwards-filled delay; when it ends the channel falls back to the stylesheet: `none` on an element with no other owner, or the persistent formula a hover or effect layer declares. Adding a hover or effect layer later therefore only adds that persistent declaration: the entrance's keyframes are unchanged, it still plays, still holds nothing, and both contributions add.

The LCP rule: a page-load entrance on an element in the page's first top-level section, or on an image with `fetchpriority="high"`, renders with its from-opacity at 1 (movement only) unless the entrance sets `allowLcpFade`, which the panel labels with a warning.

## 10. Composition rules

Layers stack (§4 item 1), so no layer owns a whole CSS property. Each owner writes only its own registered custom properties (`@property`, typed `<length>`, `<number>`, `<angle>` or `<percentage>`, with an identity initial value: 0px, 1, 0deg; the one exception is tilt's `--sgs-tilt-persp`, which starts at 800px because a zero perspective is invalid, so it is not an identity value); the shared stylesheet composes each CSS property, its **channel**, from every owner's custom properties. Contributions add (lengths, angles) or multiply (scales, opacities), so a hover lift, a magnet pull and a parallax shift on one card all apply at once. Owners and the custom properties they write (`me` entrance, `mh` hover state):

| Channel | Owners and their custom properties | Composition | Refused, with the error text |
|---|---|---|---|
| `translate` | entrance `--sgs-me-tx`, `--sgs-me-ty`; hover state `--sgs-mh-tx`, `--sgs-mh-ty`; magnet `--sgs-mag-x`, `--sgs-mag-y`; parallax `--sgs-plx-x`, `--sgs-plx-y`; ambient float `--sgs-float-x`, `--sgs-float-y`; ken-burns pan `--sgs-kb-x`, `--sgs-kb-y` (on its surface part) | sum per axis: `translate: calc(var(--sgs-me-tx) + var(--sgs-mh-tx) + var(--sgs-mag-x) + var(--sgs-plx-x) + var(--sgs-float-x) + var(--sgs-kb-x)) calc(… the y terms)` | none (a Tier G tween writes `transform`, which applies after `translate`, so it adds too) |
| `rotate` | entrance `--sgs-me-rot`; hover state `--sgs-rot-rest` (the rest rotate, a styling value, FR-38A-42) and `--sgs-mh-rot` (stored by the renderer as the hover angle minus the rest angle) | sum: `rotate: calc(var(--sgs-rot-rest) + var(--sgs-me-rot) + var(--sgs-mh-rot))` | none |

| `filter` | entrance `--sgs-me-blur`; hover state `--sgs-mh-blur`, `--sgs-mh-gray`, `--sgs-mh-bright` | fixed function list: `filter: blur(calc(var(--sgs-me-blur) + var(--sgs-mh-blur))) grayscale(var(--sgs-mh-gray)) brightness(var(--sgs-mh-bright))` | a hover filter on an element whose Tier G effect tweens filter (scrub blur row): "<effect> sets this element's filter while it scrolls. Put the hover filter on a different part." |
| `padding-inline-start` | hover state `--sgs-mh-indent` (the hover indent a menu or list link slides by) only | sum over the block's resting inline-start padding (its optional rest input, defaulting to 0px): `padding-inline-start: calc(var(--sgs-pad-start-rest, 0px) + var(--sgs-mh-indent))` | none |
| `clip-path` | entrance clip reveal `--sgs-me-clip` (an `inset()` amount) only | single owner | a scrub clip-path row on an element whose entrance uses a clip reveal: "This element's entrance already reveals it with a clip. Use the scrub's clip row on a different part, or choose an entrance without a clip." |

Remove it, or remove the scrub's background position row." |

Remove one to add <c>." |

- **Own timing.** The composite channels never carry a transition. Each owner transitions or animates its own custom properties (the entrance always animates, under the entrance rule), and the element's `transition` lists each owner's properties with that owner's duration, delay and easing, so the entrance, the hover state and a magnet's return each keep their own timing on one element. Pointer and scroll writers (magnet, tilt, parallax, cursor field) write per frame and transition only their own return.
- **Never held.** Every owner's resting contribution is its identity value, and the §9 entrance rule applies: An entrance always animates its own registered custom properties (`--sgs-me-*`, §10), never a plain property, and always as an animation (a CSS animation for page load and scroll reveal, WAAPI for multi-keyframe entrances), never a transition. Each keyframe also declares every channel the entrance touches with the element's full §10 composite formula, so the channel is set only while the entrance runs and during its backwards-filled delay; when it ends the channel falls back to the stylesheet: `none` on an element with no other owner, or the persistent formula a hover or effect layer declares. Adding a hover or effect layer later therefore only adds that persistent declaration: the entrance's keyframes are unchanged, it still plays, still holds nothing, and both contributions add. So no end state is held, an entrance-only element never stays a containing block, and hover is free once the entrance ends.
- **Scroll effects win.** An effect whose registry row owns transform or opacity across a scroll range (`fx_effects.owns_scroll_transform`) suppresses the element's entrance at render time (Spec 38 §4.3), and the Entrance panel shows "<effect> moves this element while it scrolls, so its entrance is switched off."
- **Where refusals happen.** The schema (§6.3) carries each refusal as a rule over one element's layers; the cloning tool's validator, the inspector (which disables the conflicting choice and shows the text) and the renderer (which drops the later layer) all apply it.

## 11. Editor

- **Final state plus Replay (D5).** The canvas shows every element at its final state. Replay plays that target's entrance once in the canvas; hover previews by hovering the canvas.
- **Live thumbnails.** Each preset choice shows a small looping CSS thumbnail; under reduced motion it is static.
- **Assets in the iframe.** The shared motion stylesheet and the reveal module load inside the iframe canvas (`enqueue_block_assets`).
- **Reduced motion in the editor.** Replay and thumbnails respect `prefers-reduced-motion`; Replay then shows a one-line notice.
- **Effects.** Per-effect canvas stories stay as Spec 38 §9.
- **Performance budget.** On a 200-block page, typing latency and memory with the motion support must stay within 10% of the same page before the change (FR-38A-29).

## 12. Reduced motion and accessibility

- Under `prefers-reduced-motion: reduce`: entrances show their final state with no movement and every stored delay is zeroed; hover effects that move do not apply, while colour and shadow state changes apply instantly; effects follow their `fx_effects.reduced_motion` value (simplify or suppress). The reveal module and the scroll driver listen for a mid-session change.
- Anything a hover reveals stays visible by default on devices that cannot hover (degrade to more content).
- Hover effects also apply on `:focus-visible` (and `:focus-within` for root-driven targets), so keyboard users get the same feedback.
- A looping effect longer than five seconds gives a pause control (WCAG 2.2.2).
- No content is hidden without JavaScript.

## 14. How the cloning route uses it

- **FR-48-47** writes each draft element's entrance into `entrance.base` (and its text effects into `entrance.text`): from and to values, extra keyframes, duration, the draft's actual delay per element and device, easing and trigger.
